## 二、设计意图与纪律

1. **画布 = 恒定像素密度**（红警 2 式）：1 画布单位恒等于固定数量的屏幕像素，画布逻辑尺寸随
   分辨率整数倍生长（1080p → 960×540），任何分辨率无分数缩放。**比例换档单点**：画布基本单位的
   换算比是唯一真源，设置面板比例下拉只接它（换算出口实现见
   [Beveled Pixel 九宫格规范](../技术/资产管线/UI九宫格.md)）。
2. **颗粒度 1:1 对齐**：UI 的基本单位与 3D 艺术像素同格（640×360 RT 最近邻放大后一个 3D 像素块 =
   UI 一个基本单位），界面与战场在同一套颗粒语言里。基本单位的取值与可调预设档口径见
   [九宫格规范](../技术/资产管线/UI九宫格.md)。
3. **UI 是全分辨率独立层，不进像素化 pass**（见 [美术.md §5](美术.md)；
   渲染口径见 [渲染管线](../技术/渲染/管线/渲染管线.md)）。
4. **像素纪律由实现层强制，不走资产摆放承载**：顶点像素对齐、字号 = 字体原生档、件禁乘色、整格坐标
   （[架构总览 §8.1](../技术/架构/架构总览.md) 控件层）。
5. **两套语法别互相推广**（对照走查裁决）：条槽（血条/进度条）是**五段**（近黑描边/外环/斜面/内暗线/槽底）；
   面板与按钮是**近黑描边 + 受光侧唇边 + 平脸**（凸起靠一级明度差，不靠每边斜面）。第一版把金框语法
   推广到全部面板被否——量测与走查记录见 [ui-pixel-ref README](../images/ui-pixel-ref/README.md)。
6. **两族共用最外那道近黑描边**：同屏读成一种画风；斜面框架只用同一色相的 3 档明暗（暗/中/亮），
   换主题只换色相。

## 三、机制骨架（跨皮肤有效，换皮不换骨）

1. **令牌单源**：布局数字一律取令牌层（间距语法全表自 Aseprite 参考库登记），**换算出口唯一**——
   参考库数字是设计格，直接当画布像素用 = 比例减半（观感挤的根源），接屏时不手写画布像素数值。
   令牌层与换算出口的实现见 [Beveled Pixel 九宫格规范](../技术/资产管线/UI九宫格.md)。
2. **变体表驱动**：控件类别 → 槽组映射表（槽位表见
   [九宫格规范 §四.2](../技术/资产管线/UI九宫格.md)），调用点零手配色。
3. **分区布局表 + 防撞合同**（战斗 HUD）：
   - 顶部带：小地图占左上角 → 红条/徽章/蓝条以屏幕中轴**镜像等长** → 系统钮（暂停/返回）收右上角贴缘；
     互不侵犯（间隙 ≥8px）；
   - 底部带：[返回] → [武器面板贴底居中] 共享同一条底边线，不悬空、不骑叠；状态条（墨底盘 + 白字）常驻面板正上方居中（两行：状态名 + 键位提示，位置不随面板互斥切换漂移，自由镜头下隐藏）；
   - 中央战场区只准小件（徽章/提示文字），大战场留给 3D；
   - **防撞合同**：装配期对顶层部件两两包围盒检测，相交即警告（曾因此修掉模式钮压血条、
     提示条压面板两起真实事故）；
   - 改布局 = 改战斗 HUD 的分区装配表（实现见 [架构总览 §8.1](../技术/架构/架构总览.md)），
     **不手挪单个部件**。
4. **组件陈列页自检**：组件陈列页场景（承载与入口见[架构总览 §8.1](../技术/架构/架构总览.md)），
   全部件 = 运行时真件、可交互；改令牌/贴图后出一张图即可全貌回归——
   **组件陈列页是设计系统的活文档**。
5. **契约测试锁纪律**（验收锚点）：纹理导入契约测试（`PixelArtTextureImportTests`）、
   文案无英文残留测试（`UiStringsTests`）；九宫格契约测试**待补建**
   （见待办 [ui-九宫格契约测试补建](../项目/待办/ui-九宫格契约测试补建.md)）。
6. **画布层序五层**（从低到高）：z=0 世界视图（3D 战场/背景）→ z=10 HUD 常驻层 →
   z=20 准星与瞄准层 → z=30 提示层（气泡/Toast）→ z=40 模态层（结算/设置/确认框）+ 全屏压暗遮罩。
   高层屏蔽低层输入。

## 四、状态反馈纪律

- **按压反馈**：位移 1px（右下）+ 高光/阴影对调（模拟凹陷），**不用 scale**。
- **焦点/选中 = 色相信号**（蓝阶描边），与按压信号（位移 + 明暗对调）是两套独立信号，
  **不混用在同一控件上**（[ui-pixel-ref §三](../images/ui-pixel-ref/README.md) 结论 2）。
- **四态可辨且可判定**：normal / hover / pressed / disabled 各态有明度差或描边差；
  disabled **禁止 hover 反馈**。
- **选中信号同屏唯一**：当前选中对象的信号只出现一处（页签的「当前页」是位置态，不算选中对象，
  不占用选中信号）。
- **危险态**：不可投掷 = disabled + 文字说明；落水/出局 = 警示摇晃 + 提示条。
  **摇晃只用于状态警示，不用于装饰**。
- **动效纪律**：只做缩放/位移/透明度；时长 0.09~0.24s，不做慢动画；同屏循环动画 ≤1；
  不做背景粒子、常驻呼吸、按钮 hover 回弹。
- **可读性对比度下限**（WCAG 2.1）：文字对底 ≥4.5:1，非文字图形对底 ≥3:1；
  具体明度分级以 Aseprite 参考库调色板为准。
- **Esc 语义统一**（逐层退栈）：确认弹窗 → 关弹窗；暂停 → 恢复；操作中 → 取消操作回浏览；
  选中 → 取消选中回自由镜头；自由镜头 → 暂停菜单。唯一裁决表见
  [操作与交互.md](操作与交互.md) §4，任何组件不得绕表自行消费 Esc。

## 五、界面布局（线框）

> 线框只锁**布局结构**（锚点/相对位置/尺寸关系）；视觉标注（底色/字号/描边）一律以权威库为准，不在线框内标。
> 通用规则：控件一律锚点 + 相对尺寸摆放，**不写绝对屏幕坐标**；角落件锚四角，居中 `(0.5,0.5)`；
> 面板居中时四周留足边距。

## 六、中文文案规范

> **代码真源 = `pirate-crew/Assets/Scripts/UI/UiStrings.cs`**（全界面中文文案表，任何用户可见文本
> 必须从这里取，不在别处散落硬编码文案；含 `{0}` 的是带参模板，配套格式化规则同库）。


### 6.1 通用规则

- **全中文**：任一界面不得出现英文单词；例外 = 品牌名「3D」、按键字母（Esc / WASD / E / 空格）、
  版本号数字。由 `UiStringsTests` 无英文残留断言锁死。
- **术语统一**（英文用语 → 界面中文对照）：Crew→船员、Turn→回合、Roster→名册/编成、Throw→投掷、
  Launch→抛自己、Ally→我方、Enemy→敌方。
- **按钮文案 2–4 字动宾结构**（「出战」「上阵」「返回」），不用「点击这里」。
- **中英混排**：中文与西文/数字之间插一个半角空格（「存活 8/8」「第 3 关」「XP 120」）；
  数字与单位之间不加空格；伤害/血量后缀写中文（「生命」「经验」），不写 HP/XP；
  百分比用半角 % 前不加空格（「78%」）。
- **排版**：中文不适用斜体，强调只靠字号档 + 颜色；全角中文标点；省略号用「……」；
  中文列表用「、」不用英文逗号。
- **符号**：星级符号 ★☆ 不用字符，用图标 sprite（字体是否含此字形未确认）；数字用字体自带半角西文；
  血量/评分/星级/时间用等宽或表格数字防跳动；快捷键字母保留半角大写。

### 6.2 战斗 HUD（官方出处条目）

「抛自己」「结束回合」的语义出自归档逆向静态的官方说明（§8.4），操作提示的键位出自战斗交互
两态重构（2026-10-03 创始人裁决，设计见 [操作与交互.md](操作与交互.md)）：

- **抛自己**——每回合抛自己一次，且必须在用武器之前。
- **结束回合**——不使用武器直接结束回合。
- **{0}%**（操作中力度数字，不标「力度」二字）
- **{0} · 操作中**（状态条·操作中，{0} = 跳跃或武器名）
- **自由镜头 / 已选中单位 / 执行中 / 已暂停**（状态条·其余态第一行）
- **A/D 方向　W/S 仰角　空格/Shift 力度　回车 发射　Esc 取消**（状态条键位·操作中）
- **右键 转视角/飞行　WASD 平移　Q/E 升降　左键 选中单位　Tab 切换取景**（状态条键位·自由镜头）
- **右键 环绕　左键点队友 换人　点武器/跳跃 开始操作　Esc 取消选中**（状态条键位·选中浏览）

### 6.3 边界提示（官方出处条目）

「无法投掷」的语义出自归档逆向静态的官方说明（同 §8.4），「落水警告」基于原版落水即死规则：

- **该船员本回合不能再抛自己了。**（无法投掷）
- **危险：这里落水会直接出局！**（落水警告）

错误不弹模态窗（除破坏性操作确认）：用**原地提示条 + 危险色**，不打断战斗。

其余界面的中文文案以 `UiStrings.cs` 代码真源为准，本文不再登记 AI 起草的文案。

## 八、验收判据（逐条可判定）

1. 任一界面不得出现英文单词（品牌名/版本号/按键字母除外）（判定方法：`UiStringsTests` 无英文残留断言 + 人工读图；适用：全部）
2. 字号只用四档原生档：无放大档、无伪粗（判定方法：核对字体资产档位，口径见 [架构总览 §8.1](../技术/架构/架构总览.md)；适用：全部）
3. 任一按钮四态可辨（判定方法：逐态截图，相邻态底色 RGB 差 ≥12/255 或描边宽差 ≥1px；适用：全部按钮）
4. 选中态信号同屏唯一（判定方法：全图扫描焦点色，聚集为 1 个连通区；适用：战斗 HUD）
5. 摇晃只出现在危险警示，同屏循环动画 ≤1（判定方法：走查；适用：全部）
6. 中文无豆腐块/空白（判定方法：文案真源逐条缺字扫描全绿，截图无 □；适用：全部）
7. 状态反馈明确：选中/hover/禁用/危险在战斗 HUD 各至少出现一次（判定方法：走查脚本——选船员、悬停名册行、武器用完、落水区；适用：战斗 HUD）
8. 回合与双方存活数值正确且与当前局一致（判定方法：与当局战斗实况数据比对；适用：战斗 HUD）
9. 结算弹窗信息完整：胜负 + 星级 + 评分 + 经验 + 招募（判定方法：逐项核对结算接口数据；适用：结算）
10. 小地图与竞技场同比例、队色正确（判定方法：量取面板宽高比 = 竞技场宽高比，扫描点位主色；适用：战斗 HUD）
11. 键盘导航与 Esc 栈行为正确（判定方法：手测——Tab/方向移动焦点 → 回车确认，Esc 逐层退栈；适用：主菜单/设置/结算）
12. 单张验收图入库前压到几百 KB 内（判定方法：文件大小检查，AGENTS.md export/ 入库策略；适用：全部）
