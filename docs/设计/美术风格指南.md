# 美术风格指南（Art Bible）· 等距像素卡通

> **这份文档解决什么问题**：定义本作画面的**唯一口径**——等距轴测 × 卡通赛璐璐 × 模型描边 × 像素纹理 × 像素化后处理，以及 UI 的像素斜面浮雕（Beveled Pixel）风格。所有场景/角色/特效/UI 的美术实现与验收以本文为准。
> **方向来源**：创始人裁决（2026-09-21）——为降低开发难度，整体 3D 画面表现方向转向本风格。主要参考游戏：**For The King**（等距+卡通+描边）、**Tunic**（等距卡通低模）【创始人指定】。
> **技术实现口径**：[渲染管线-等距像素卡通.md](../技术/渲染/渲染管线-等距像素卡通.md)；**资产生产口径**：[像素纹理资产管线.md](../技术/资产管线/像素纹理资产管线.md)；**游戏整体设计**：[游戏设计文档.md](游戏设计文档.md)。

## 1. 视觉定位

### 1.1 一句话印象

> **玩家第一眼应该看到**：一块斜 45° 俯视的加勒比小岛，像一件被精心制作的**像素玩具模型**——粗墨线勾边、2~3 档色带铺面、三十余色的明快调色板；红蓝两台小海盗以粗块像素质感对峙，脚下椭圆阴影把他们"钉"在地面；整个画面被统一的后处理像素化笼罩成一体，UI 是微微凸起的浮雕像素块，像可以按下去的塑料键。

### 1.2 方向构成公式【创始人裁决】

- 游戏内容画面 = **视角（等距轴测，3D 斜 45°）+ 渲染技术（卡通赛璐璐 + 模型描边/卡线）+ 纹理风格（像素纹理）**，整体后处理呈像素画风。
- UI 画面 = **像素斜面浮雕（Beveled Pixel UI）+ 粗块状像素（Chunky Pixel）**——微微凸起的 2D 风格。

### 1.3 为什么是这个方向（降低开发难度的兑现路径）【AI 提案】

- **资产端**：材质从 PBR 参数组降为"平涂色块 + 描边"，贴图从手绘高精度降为低分辨率像素量化（可程序化生成）；
- **渲染端**：正交相机消灭 LOD/透视校正问题；单平行光 + 无实时阴影消灭光照调试；
- **容错端**：像素化天然掩盖低模与贴图瑕疵，"玩具感"是目标而非缺陷。

## 2. 视角与取景

### 2.1 相机【AI 提案·基于项目现状，待首轮试产确认】

- **斜 45° 轴测（dimetric）+ 正交投影**，不用真等距 2:1。依据：① M2 空间契约（[M2-3D空间模型对齐.md](M2-3D空间模型对齐.md)）已按 45° 设计（分路/弹道/AI 落点），零迁移成本；② 2:1 是 2D 手绘像素贴图时代的网格约定，3D+后处理路线下无收益、浅斜面摩尔纹更糟；③ 行业等距 3D 主流即正交/长焦 + 45°~55° 俯角（For The King 同款）。
- 俯角 45° 起步，可试 50°~55°（越俯越"战棋"）；旋转锁死，只平移。
- **正交 size 取整数**（世界半高单位），像素网格在世界空间对齐，减少游动。

### 2.2 地图构成【待定·创始人明示未想好】

- 是否格子拼装：未拍板。倾向方案（**AI 提案**）：**逻辑上格子、视觉上软化**——寻路/占位/AI 走格子（开发难度最大杠杆），观感上用边缘扰动贴片、装饰物压缝、非均匀摆放掩盖接缝（For The King 即此做法）。
- 硬约束【创始人裁决】：**观感必须"非格子块"**——不能一眼看出格子拼缝。

## 3. 光影与色彩

### 3.1 全局光约定【AI 提案】

- 单一平行光，方向**永远固定从左上来**；环境光单一扁平色。
- 所有资产的暗部绘制、UI 斜面高光/阴影方向、blob shadow 偏移一律与该方向一致——风格统一的最大杠杆。

### 3.2 调色板策略【AI 提案·待定稿】

- 全局主调色板 **32~64 色**（明暗各档 + 主题色相），所有纹理量化时锁进这张板（3D 侧的"令牌"——与 UI `StickTokens` 同一思想，风格统一靠板不靠逐图手调）。
- **色相取向沿用旧版 Art Bible 的加勒比主题**：暖白沙地 / 饱和草坡 / 深蓝海水 / 木材棕 / 红蓝阵营对抗色（历史色相档案见 git 历史；天空三档正午/黄昏/风暴对应关卡分组 `参考游戏逆向-海盗军团抢宝藏-静态.md` 的 skyColour 1/2/3）。具体色值随像素量化重新定档入板。

### 3.3 阴影【AI 提案】

- 无实时阴影（cast/receive 全关），一律 **blob shadow**（脚下贴花椭圆）。理由：色带表面接实时投影必脏；贴花方案免费且是像素卡通行业标准。

## 5. UI 方向（概要）

- **Beveled Pixel UI + Chunky Pixel**【创始人裁决】：全分辨率独立层（不进像素化 pass）；像素浮雕 = 基色平涂 + 上/左高光边 + 下/右阴影边 + 外圈墨描边，纯程序化生成（九宫格）。
- 按压反馈：位移 1px（右下）+ 高光/阴影对调（模拟凹陷），不用 scale。
- 字体【待定】：中文像素字体选型（Fusion Pixel 开源 / Zpix 商用授权）或保留 StickHand 手写体混搭（Tunic 先例）。
- 现有 StickUI 底座（令牌层/骨架/装配器/布局）**风格无关、全部沿用**，换皮不换骨；详细规范待换肤实施时重写 [UI设计语言.md](UI设计语言.md)。

## 7. 可读性判据（像素化后的"愿不愿意玩"三要素）【AI 提案】

① **不糊**——单位在 640×360 RT 下仍有一眼可辨的剪影（描边保证）；② **不乱**——两阵营色在调色板里明度拉开，任意角度可分；③ **不碎**——关键交互物（宝箱/掩体/水面边界）在像素化后仍保持轮廓完整，判定不了的资产要加大或提高色相对比。
