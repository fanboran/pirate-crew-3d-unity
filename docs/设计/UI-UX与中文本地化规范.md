- 【原始诉求】当前 Unity 版界面存在两个问题：**术语与界面文案为英文**（用户明确不满）、**视觉是用 `Image` 纯色块拼的**（无美术效果）。本规范解决这两点，并给出可逐图品控的验收判据。

## 1. UI 设计语言

### 1.1 三条铁律

1. 【依据】**暖色金棕深红 + 加勒比蓝**为主色域，材质用羊皮纸 / 木板 / 铁锈（本项目取「黄铜」替铁锈，见 §1.2）；标题用装饰性字体、正文用无衬线/中性体；图标简洁扁平金色描边；动效弹入弹出 + 轻微摇晃（海盗船颠簸感）——逐条对应 `game-3/docs/gdd.md:870-876`（§10.5 旧版 UI 风格保留段）。
2. 【原始诉求】**信息清楚优先于装饰**：任何底纹/材质不得降低文字对比度；正文区禁用高反光材质。
3. 【AI 提案】**视觉与隔壁 game-2（火柴人帝国）必须一眼可分**：本作是「木+纸+铜」的暖色实体材质、有描边厚字；game-2 是「黑玻璃+手绘涂鸦」的冷色极简语言。差异化详见 §7。

### 1.2 材质语言

四段材质各司其职，**不是装饰贴图堆料**：

| 材质 | 用于 | 不用于 | 理由 |
| --- | --- | --- | --- |
| 木板（wood） | 面板外框、按钮底、HUD 条、标题底板 | 长段正文底 | 木纹噪声会吃小字 |
| 羊皮纸（parchment） | 正文区底、名册行、武器说明、结算卷轴 | 主按钮底（无「可按」暗示） | 高亮低饱和底最宜承载文字 |
| 黄铜（brass） | 描边、铆钉、分隔线、数值强调、选中外框 | 大面积填充 | 金属高光面积大则刺眼 |
| 绳索（rope） | 面板四角「吊挂」、卷轴轴头、状态条两端 | 文字附近 | 只做结构暗示，不做内容 |

【依据】GDD §10.5 指定「羊皮纸、木板、铁锈金属的纹理感」（`game-3/docs/gdd.md:874`）；本项目把「铁锈」升级为「黄铜」以提升数值/描边的可读对比（【AI 提案】）。

**URP PBR 参数（3D 世界内物件 / 贴图烘焙目标）**

> ⚠ 【依据】UGUI Canvas 默认走 `UI/Default`，**不参与 3D 光照**，无法直接吃 URP/Lit 材质。因此下表的 URP 参数有两个合法用途：① 世界内 3D 物件（宝箱、炮台、木箱）；② **UI 九宫格 sprite 的离线烘焙目标**（在 DCC/渲染器里按此参数渲一遍再导 PNG）。**禁止**把 `Universal Render Pipeline/Lit` 材质直接挂到 `Image` 上期望出现木纹高光。

| 材质 | Shader | Base Color | Metallic | Smoothness | 贴图 | 备注 |
| --- | --- | --- | --- | --- | --- | --- |
| 木板 | URP/Lit | `#A67B42` 基，`#6B4C28` 暗阶 | 0.0 | 0.25–0.35 | 木纹 albedo + normal(0.3) | 【依据】GDD 木材三级 `#D4A76A/#A67B42/#6B4C28`（`gdd.md:820`） |
| 羊皮纸 | URP/Lit | `#E8D5A3` | 0.0 | 0.08–0.12 | 纸纹 albedo + 轻污渍 | 【依据】GDD 沙地亮阶 `#E8D5A3`（`gdd.md:816`） |
| 黄铜 | URP/Lit | `#C9A227` | 1.0 | 0.55–0.70 | 无 / 轻划痕 | 【AI 提案】金色延用 GDD「金色描边」(§10.5) |
| 绳索 | URP/Lit | `#8B6F47` | 0.0 | 0.15 | 绳索 albedo + normal | 【AI 提案】 |

- UI sprite 烘焙要求：【AI 提案】木板/羊皮纸贴图导 1024×1024 可平铺、九宫格边框 32px；黄铜边框导 9-slice（四角 24px、边 8px）；所有烘焙图**不得带高光渐变**（UI 里要平）——高光只保留在 3D 物件上。
- 边界：正文底一律羊皮纸（`#E8D5A3`），**木纹/绳索不得出现在文字 12px 范围内**。

混排规则（【AI 提案】）：
- 中文与西文/数字之间**插一个半角空格**（如「存活 8/8」「第 3 关」「XP 120」）。
- 数字与单位之间不加空格（「50HP」）；伤害/血量后缀统一小写（`HP`、`XP`）还是中文（「生命」「经验」）——**取中文**，见 §4 文案表，避免半英半中。
- 中文不适用斜体；强调只靠**字号档位 + 颜色 + 加粗**，不用倾斜。
- 标点用全角中文标点；省略号用「……」；不用英文逗号分隔中文列表，改用「、」。

### 1.5 图标风格

- 【依据】GDD §10.5：「图标：简洁扁平，金色描边」（`game-3/docs/gdd.md:875`）。
- 【AI 提案】落地要求：
  - 尺寸基准 64px（同出 32/128 两档）；纯色块面 + 2px 黄铜描边（`#C9A227`）+ 深色内描边（`#2A2A2A`）保可读；
  - 面配色取 GDD 职能色（己方亮蓝/敌方亮红/可选金，`gdd.md:822-827`）；
  - 禁止 3D 渲染软阴影、禁止渐变高光（与 §1.2「UI 要平」一致）；
  - 每个图标必须**在羊皮纸与木板两种底上都可辨**（验收见 §8）。
- 世界观图标语义表（【AI 提案】）：回合=沙漏、计时=怀表、存活=骷髅计数、武器=交叉火枪、名册=卷轴、模式开关=舵轮、准星=罗盘玫瑰。

### 1.6 动效原则

【依据】GDD §10.5 要求「弹入弹出，配合轻微的摇晃（海盗船的颠簸感）」（`game-3/docs/gdd.md:876`）。

| 动效 | 时长 | 缓动 | 用途 |
| --- | --- | --- | --- |
| 面板弹入 | 180ms | `EaseOutBack`（轻微过冲 ≤4%） | HUD 面板/弹窗出现 |
| 面板弹出 | 120ms | `EaseInQuad` | 面板收起 |
| 按钮按下 | 90ms | 线性 | 缩放 0.96 + 下移 2px |
| 数值脉冲 | 240ms | `EaseOutQuad` | HP/力度变化时放大 1.08 再回落 |
| 危险摇晃 | 120ms×3 循环 | 正弦 | 不可投掷/落水警告，位移 ±3px |
| 提示气泡 | 出现 150ms / 停留 3000ms / 消失 200ms | `EaseOutQuad` | 一次性提示（对应 GDD §12.3 教学气泡 3 秒，`gdd.md:1076`） |

【AI 提案】**禁止无意义动效**：同一屏循环动画 ≤1 个；不做背景粒子飘雪/常驻呼吸；不做按钮 hover 弹跳回弹（与 game-2 §1.6「不做弹跳/回弹」的方法论一致）。**摇晃只用于状态警示**（危险/落水），不用于装饰。

### 1.7 形状 / 间距 / 层级

【AI 提案】：
- 基准分辨率 1920×1080，`CanvasScaler` = `ScaleWithScreenSize`，参考 1920×1080，Match 0.5。
- 外安全边距 `SAFE = 24px`；通栏条（顶栏/底栏）是唯一允许贴边的例外。
- 圆角：面板 8px、按钮 4px、图标底板 4px（比 game-2 的 3px 略圆，木器不该像玻璃那样冷硬）。
- 描边宽度：UI 内描边 2px，外框 4px；黄铜框可到 6px。
- 内边距：面板 16px、按钮横向 16/纵向 8、行高 44px（沿用现有 `RowHeight = 44f`，`CrewManagementController.cs:26`）。
- 间距只取 4/8/12/16/24 五档。
- Canvas 层级（z 序，从低到高）：

```
z=0    世界视图（3D 战场 / 背景）
z=10   HUD 常驻层（回合/存活/名册/小地图/武器面板/模式开关）
z=20   准星与瞄准层（准星、抛物线、力度数字、瞄准/聚焦标签）
z=30   提示层（气泡/Toast）
z=40   模态层（结算弹窗/设置/确认框）+ 全屏压暗遮罩
```

【依据】层序方法论借自 game-2 `docs/设计/UI/02-界面框架.md:47-68`（L1 GameWorld → L5 SystemLayer），**但本作精简为 5 层**，不做 UIRoot 槽位系统。

### 5.3 TMP 使用要求（含中文字符集与动态字体集的取舍）

【依据】本工程 `pirate-crew/Packages/manifest.json` **未列 `com.unity.textmeshpro`**（`manifest.json:1-23`），`Library/PackageCache` 里也没有 TMP；现有 UI 代码全部用 legacy `UnityEngine.UI.Text` + 内置 `LegacyRuntime.ttf`（`M2BattleSceneSetup.cs:679`、`M3UiBuilder.cs:45-54`、`SceneSetup.cs:150-152`）。

⚠ 【AI 提案，重要技术结论】**`LegacyRuntime.ttf` 不含 CJK 字形**——继续用它渲染中文会得到空白/豆腐块。因此「全中文」在技术上有且只有两条路：

| 路径 | 做法 | 优点 | 缺点 | 建议 |
| --- | --- | --- | --- | --- |
| A. TMP（推荐） | manifest 加 `com.unity.textmeshpro`，导入 TMP Essential Resources，字体资产用 **Dynamic** 模式 atlas | CJK 动态按需入库、描边/阴影走材质、字号缩放清晰、fallback 链成熟 | 需改 manifest（【待定】需协调者批准）+ 一次导入；现有 `Text` 引用要换成 `TextMeshProUGUI` | **首选**；新增/改造界面直接用 TMP |
| B. legacy Text + 自备 TTF | 把 `Text.font` 换成 `LXGWWenKaiLite-Medium` 动态字体 | 零包变更，改动最小 | 无描边材质、大字号边缘发虚、atlas 由 Unity 黑盒管理、无 fallback 链 | 仅作过渡或应急回退 |

- 【AI 提案】**字符集取舍**：
  - **必须用动态（Dynamic）模式**。理由：本项目文案量约 150 条，覆盖汉字数百个；但设置里「语言」页签未来可能加英文/日文，且玩家昵称/存档名不可预知；静态 atlas 若含全 CJK（约 2 万字形）会生成 20 MB+ 贴图，包体与显存都不划算。
  - 可额外烘一份 **Static 预烘子集**（本规范 §4 全部文案去重后的字符 + 数字 + 标点，约 300–500 字形）作为首屏保证，避免首帧动态生成卡顿；动态 atlas 兜底其余字符。
  - Atlas 尺寸建议 1024×1024，Padding 4，Multi Atlas Textures 打开。
- 【AI 提案】TMP 设置：`Font Features` 开 `kern`/`liga`；标题用一份「Outline 材质预设」（Outline Thickness 0.15、Outline Color `#2A2A2A`），正文用无描边预设——**描边只给标题**，正文加描边会糊（同 game-2 §1.5「描边让字糊」的方法论）。
- 【待定】TMP 包引入需改 `manifest.json`，且 AGENTS.md 规定「改完 manifest 必跑无头验证」；该步骤由协调者串行执行（Library 锁独占）。

### 5.4 数字与特殊符号

【AI 提案】：
- 数字统一用字体自带西文数字（半角）；血量、评分、星级、时间用**等宽或表格数字**（TMP 可开 `tnum`，StickHand 无该 feature 时退回文楷数字），防止数值跳动。
- `★`（U+2605）与 `☆`（U+2606）：**不用字符**，改用图标 sprite（见 §3.4），因两套字体是否含这两个字形未经确认。
- `×` 用全角「×」；HP/XP 不写英文，写「生命/经验」；百分比用半角 `%` 前不加空格（「78%」）。
- 快捷键字母提示（如 `Esc`、`WASD`）保留半角英文大写，包在按键图标框里，避免裸字母被误读为未翻译的英文。

### 5.5 缺字回退策略

【AI 提案】TMP fallback 链（从标题字到正文，最后兜底）：

```
StickHand-Regular  →  LXGWWenKaiLite-Medium  →  LXGWWenKaiLite-Regular
```

- **禁止**把 `LegacyRuntime.ttf` 放进 fallback 链末尾（无 CJK，只会把缺字问题掩盖成豆腐块）。
- 诊断手段：实现期加一个「全文案扫描」编辑器脚本，把 §4 所有文案跑一遍 `TMP_FontAsset.HasCharacter`，缺字即报错（**不得静默回退**）；该脚本属实现任务，不在本规范内。
- 生僻字处理：若确需（如玩家自定名），接受显示为 □ 并在日志报 warning，不静默。

### 5.6 落地步骤（供实现 agent）

1. 【待定】协调者批准后，`manifest.json` 加 `com.unity.textmeshpro`，跑无头验证确认工程可开。
2. 导入 4 个 TTF（`Assets/Art/Fonts/`），TMP 生成 `Font Asset`（Dynamic + fallback 链）；同时把 OFL 许可文本入库（§5.1 前置条件）。
3. 新界面直接用 TMP；旧界面（`M2BattleSceneSetup` / `SceneSetup` / `M3SceneSetup` / `M3UiBuilder`）按 §3.8 对应表逐个把 `Text` 换 `TextMeshProUGUI`。
4. 全部文案按 §4 表替换，跑「全文案扫描」脚本 + 截图验收（§8）。
