# 操作与交互（战斗）

> **定位**：战斗「玩家如何操作」的设计唯一出处——两态交互模型、操作模组体系、键位、Esc 语义、
> 相机控制与轨迹预览的设计意图。玩法数值的历史权威是归档逆向文档，交互与操作的设计权威是本文。
>
> **状态**：骨架经用户确认（两态制取代三模式、自由镜头 = 拖拽绕焦点旋转、操作模组制、
> 投掷数值米制重立、未行动可换人）；**全部细节与数值【提案/待定】**，实机验收前不得当作已确认设定，
> 其他文档引用本文时须带此标注。
> 技术规格的可执行形式（迁移表 / 判定法 / 不变量）= [../技术/交互操作契约.md](../技术/交互操作契约.md)。

## 1. 设计目标与教训

**为什么推翻三模式（移动 / 操作 / 观察）**——旧模式的四类实测病灶（系统审计 ）：

1. **名实不符**：「移动」模式的 WASD 不移动角色（移动手段只有跳跃）；「操作」模式未选武器时是
   按钮无响应的死态；「观察」模式由调试出口转正，鼠标横纵灵敏度相差近 9 倍（0.35°/px 对 3.0°/px）。
2. **隐式副作用**：模式切换与武器装备态互相脱钩，出现「金框亮着、按键无反应」。
3. **一键多义**：空格同时是跳跃发射 / 飞行上升；左键承担选人 / 切人 / 取消 / 转视角四义。
4. **切换跳变**：选人与回合推进瞬切相机方位角与取景档，瞄准参数随相机基向量漂移。

**设计原则**（新体系的四条底线，违反任何一条 = 设计回炉）：

1. **状态语义唯一**：任何时刻「相机归谁管、每个键是什么意思」由且仅由交互状态决定；
2. **无跳变**：状态切换是镜头目标位姿的平滑过渡，任何交互路径不得瞬切取景 / 朝向；
3. **输入归属静态可查**：每个键在每个状态下的含义有且只有一条表项（§3 键位总表）；
4. **操作即模组**：瞄准交互按「操作模组」组织——新武器的操作形态 = 新模组，不改两态状态机。

## 2. 两态模型

```
                左键点选己方存活单位
   ┌──────────┐ ───────────────────► ┌──────────┐ 浏览（操作菜单弹出）
   │ 自由镜头 │ ◄─────────────────── │ 选中 │ ──点武器格/跳跃──► 操作中（模组激活）
   └──────────┘ Esc（取消选中） │ 唯一单位 │ ◄──Esc（取消操作）──┘
                                      │ 为视野中心│
                                      └────┬─────┘
                                           │ 确认（回车/屏幕钮）
                                           ▼
                                      执行中（相机跟随弹体/角色）
                                           │ 落定，按回合经济分流
                                           ▼
                              仍有行动（抛自己后）→ 回「浏览」
                              无行动（用武器/结束回合）→ 回合推进 → 自由镜头
```

| 状态 | 相机 | 输入主题 | 玩家在做什么 |
| --- | --- | --- | --- |
| **自由镜头** | 拖拽绕焦点转方位的自由观察（俯角恒 30°，焦点默认地图中心） | 观察 | 看战场、找目标；左键点选单位 |
| **选中 · 浏览** | 环绕选中单位（俯角回基准 30°） | 决策 | 看装备、选操作（武器 / 跳跃 / 结束回合） |
| **选中 · 操作中** | **锁定**（不接受任何相机输入） | 瞄准 | 按模组键位调参，看预览，确认或取消 |
| **执行中** | 跟随弹体 / 被抛角色（现有跟随表现） | 等待 | 看结果 |

- 人类回合开始时**不自动选人**——回合默认起态是自由镜头（镜头平滑 pan 到行动角色作提示，
  拖拽转方位只改方位角、不与 pan 冲突）。
- 只能选中**一个**单位；选中态是操作的全部语境（跳跃与武器都是选中态的行为，没有「观察模式」）。

## 3. 键位总表

**全局**（任何战斗状态）：

| 键 | 含义 |
| --- | --- |
| Esc | 按 §4 矩阵逐层退栈 |
| P | 暂停 / 恢复（暂停是全局可达的，不被 Esc 矩阵的中间层挡住） |

**自由镜头**（未选中）：

| 输入 | 含义 |
| --- | --- |
| 按住右键拖拽 | 绕焦点转方位角（与选中环绕同灵敏度；**俯仰角恒定不变**） |
| 左键点击 | 选中己方存活单位（30px 屏幕半径最近者，沿用既有判定） |

**选中 · 浏览**：

| 输入 | 含义 |
| --- | --- |
| 右键拖拽 | 环绕选中单位转方位角（拖动距离阈值内视为未拖动） |
| 左键点其他己方单位 | 换选中（仅未行动时，见 §5）；已行动无响应 |
| 点武器格 / 跳跃 | 进入操作中（对应操作模组激活） |
| 点结束回合 | 直接结束本回合 |

**选中 · 操作中**（标准投掷模组；专用模组各自定义键位表）：

| 键 | 含义 |
| --- | --- |
| A / D | 方向角逆时针 / 顺时针 |
| W / S | 仰角升高 / 降低 |
| Space / Shift | 力度升高 / 降低 |
| 回车 或 屏幕确认钮 | 执行（发射 / 起跳） |
| Esc | 取消操作，回浏览 |

**为什么这样分配**：

- 拖拽转方位只在按住右键时生效（超过阈值才算拖拽），光标平时常显，点选单位不需要指针锁定；
- 力度从旧口径的 W/S 迁到 Space/Shift：W/S 腾给仰角（可调仰角是本次新增能力），Space 在
  操作中只此一义（旧口径里空格同时是跳跃发射键与飞行上升键）。
- 相机俯角恒定 30°——操作中的「仰角」是**投掷参数**不是相机参数，不共用输入。

## 4. Esc 矩阵（唯一判定表）

| 优先级 | 当前情形 | Esc 的行为 |
| --- | --- | --- |
| 1 | 确认弹窗开着 | 关闭弹窗 |
| 2 | 暂停中 | 恢复 |
| 3 | 操作中 | 取消操作，回浏览 |
| 4 | 选中 · 浏览 | 取消选中，回自由镜头 |
| 5 | 自由镜头 | 打开暂停菜单 |

优先级自上而下取第一个命中情形；任何组件不得绕过此表自行消费 Esc。

## 5. 换人规则

- **未行动可换**：本回合尚未消耗任何动作（没跳、没开火、没结束回合）时，点其他己方单位 =
  切换选中。
- **动作后锁定**：一旦执行了任何动作，选中锁定到回合结束。
- 为什么：旧规则「选中即锁死」让点击其他单位成为无反馈的死路径，且违背「先观察战场再决定
  谁上」的直觉；回合经济本身（见 §9）已保证换人不会带来额外行动次数。

## 6. 操作模组体系

**模组 = 选定操作后的瞄准交互单元**：一组参数 + 键位映射 + 预览形态 + 执行出口。

- **标准投掷模组**：三参数（方向角 / 仰角 / 力度），服务跳跃与绝大多数抛掷类武器；
- **专用模组**（占位，随武器重做逐个立规格）：轨道轰炸式（扫描带 + 确认）、放置类、
  引导类等——操作形态差异大的武器不再硬套投掷参数，而是声明自己的模组；
- **接入规则**：新模组只新增「操作中」的实现与键位表，不改两态状态机、不新增交互状态；
  操作菜单条目（武器格 / 跳跃）声明自己用哪个模组。

### 标准投掷模组规格（数值【提案/待定】，实机手感验收后定案）

| 参数 | 输入 | 速率 | 范围 | 默认 |
| --- | --- | --- | --- | --- |
| 方向角 | A 逆时针 / D 顺时针 | 90°/s | 全周无界 | 继承镜头当前方位（进入操作时以玩家正对方向起步） |
| 仰角 | W 升 / S 降 | 45°/s | [10°, 85°] | 35°（延续旧口径 atan(0.7) 的等效仰角与手感） |
| 力度 | Space 升 / Shift 降 | 0.45/s | [0.10, 1.00] | 0.60 |

- 初速大小 = 力度 × 最大初速（米制常量，出处见投掷行为契约）；
- 初速方向 = 方向角 × 仰角合成的世界向量（从投掷手高度出发）；
- 力度下限防零向量发射（旧口径同语义的最小初速保护，保留为不变量）。

## 7. 相机设计意图

- **基准取景**：正交、俯角 30°（美术口径，见 [美术.md](美术.md)）——所有相机状态都落在这个
  基准上，出图口径不变；
- **自由镜头**：拖拽绕焦点转方位（与选中环绕同灵敏度，提案 0.25°/像素）；**俯角恒 30°，
  无玩家偏离通道**；焦点默认地图中心（开局机位反推），由回合 pan / 点选血条的聚焦请求平滑引导；
- **选中环绕**：焦点 = 选中单位（抬高到胸 / 头高度的取景点），方位角拖拽环绕，俯角回 30°；
- **操作锁定**：操作中不接受任何相机输入——相机冻结是「操作中」的定义性特征，保证瞄准
  参数与世界方向的映射稳定；
- **执行跟随**：弹体 / 被抛角色的跟随、震屏、顿帧、落水下压等表现沿用现有相机手感体系；
- **平滑铁律**：一切状态切换 = 目标位姿（焦点 / 方位 / 俯角 / 取景档）的指数平滑过渡；
  全工程唯一允许瞬切的地方 = 对局开局的首次落位；
- **恒定取景（禁多镜头距离）**：正交取景恒定一档，像素密度恒定（调试关与战斗关观感一致）；
  **特写 = 从大图里裁小图**，不做推拉镜头。Tab 无相机职责（两档翻转退役）；**滚轮无任何
  相机职责**（反射性输入，误触即翻档—— 走查废弃）；像素比例档调整归设置界面（另立项）。

## 8. 轨迹预览设计意图

- **积分到落点为止**：弧线积到穿地那一步截断（步数上限兜底），不按飞行时长截断、
  任何一段不入地（旧预览高力度时线尾扎进地下）；
- **落点标记恒显**：只要弹道在兜底步数内穿地，落点标记必在（旧预览远射程时标记消失）；
- **起点在投掷高度**：从单位的投掷手高度出发，不从脚底枢轴穿出；
- **方向可读**：珠点沿弧线尺寸与色深递减（大→小 = 起点→落点），落点标记带随水平初速
  方向的指向箭头——弧线往哪飞、落在哪、朝哪去一眼可辨（【提案/待定】）；
- **三维空间实体**：珠点与落点标记都是带深度测试的世界物体，被单位 / 地形正常遮挡，
  不做覆盖式渲染（旧预览线浮在角色上层的病灶根除）；
- **珠点弧线**：像素语言一致的点串风格（观感细则归实现层，契约只锁上述可判定行为）；
- **读数归 HUD**：方向 / 仰角 / 力度的数字读数由操作 HUD 呈现，不在 3D 场景里写字；
- **预览 = 实弹同源**：预览与实弹共用同一积分器与常量（出处
  [../技术/3D空间模型对齐.md](../技术/3D空间模型对齐.md) §3，铁律不因预览重做而松动）。

## 9. 与其他系统的关系

- **回合经济**（不变）：抛自己一次 + 用武器一次、用武器即结束回合、结束回合即结束——
  两态交互只是操作的外壳，不触碰经济规则；
- **武器系统重做**：武器的操作形态 = 声明用哪个模组（标准投掷 / 专用模组），交互层不再为
  单件武器改状态机（见 [武器系统.md](武器系统.md) §4.5）；
- **UI**：操作菜单由武器面板转型、新增操作 HUD；屏幕下方常驻**状态条**（两行式：
  第一行当前状态名——操作中含操作名「跳跃」或武器名，第二行该状态的键位提示，
  暂停态覆盖为暂停提示）——先行纯文字呈现，图像化提示为后续演进（布局与文案见
  [UI设计语言.md](UI设计语言.md) §5.4 / §6.2）；
- **输入采样**：全工程唯一采样点产出「意图帧」，状态机与模组消费——一键多义在结构上
  不可再现（旧病灶的机制性预防）。
