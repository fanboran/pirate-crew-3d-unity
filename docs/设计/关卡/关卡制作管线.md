# 关卡制作管线（章程）

> **定位**：本项目做关卡的一套固定工序——从"想要什么体验"到"封版入库"，每一环都留下
> 可核对的文本与资产。参照行业关卡制作惯例（概念 → 纸面设计 → 灰盒 → 玩法走查 → 美术
> 接入 → 封版）裁剪成单人 + AI 协作的可执行版。
> **角色分工**：关卡策划（AI，产出一律标「提案/待定」）负责设计与落地；用户是制作人兼
> 终审，样板先行——美术方向与体验目标未经用户过目不算数。

## 一、六个阶段

| 阶段 | 做什么 | 产出（文本 + 资产） | 门禁（过了才进下一阶段） |
| --- | --- | --- | --- |
| **1. 概念立项** | 定体验目标：这关想让玩家感受什么、教会什么、记忆点是什么；选地形母题与对称档 | 关卡设计文档的「概念卡」一节（一页以内） | 用户确认方向（样板先行铁律） |
| **2. 纸面设计** | 俯视布局图、编成表、武器投放表、关内节奏曲线、难度定位；对照 R1-R18 建关约束逐条自查 | 设计文档全文 + 布局图 PNG（`tools/level-design/render_layouts.py` 从文档 ASCII 块渲染，文档是唯一真源） | R1-R18 硬约束自查表全绿；有意偏离基准的条目显式标注 |
| **3. 灰盒落地** | 布局译成代码数据：`ShowcaseLevels` 的高度场/编成/武器池/摆位表；视觉先用可站面烘焙件（云场/空岛 prefab，逻辑-视觉按构造对齐） | 可玩关卡 + EditMode 测试（站位实心、编成数、摆位契约、水距/簇数等可测约束） | 无头编译 0 错；EditMode 全绿 |
| **4. 玩法走查** | 出图/试玩（`-artReviewLevel N`），按设计文档的验收清单逐条核对 | 实拍截图（`docs/images/level-design/`）+ 走查记录（验收清单勾选结果写回设计文档） | 用户过目通过 |
| **5. 美术接入** | 按设计文档的资产清单把灰盒观感升级为正式美术（Blender 手作 / 岛壳烘焙 / WorldKit 件） | 替换后的 prefab/FBX + 重烘实拍对比 | 实拍对比无缺件、无洋红；用户终审 |
| **6. 封版** | 锁资产：确定性测试钉住几何、manifest 登记上游、交接文档回写 | 测试绿 + `scene-assets.json` 登记 + 交接指南新条目 | 全部门禁通过 |

**回退规则**：走查或终审不通过 → 回到对应阶段改设计/改数据，不允许"先上线后补文档"。

## 二、每关一份设计文档（模板）

文件名 `L0N-<关名>.md`，章节固定，方便对照走查：

1. **概念卡**——一句话 / 体验目标 / 教学目标 / 记忆点 / 母题与对称档（引用参照基准行号）
2. **关内节奏**——开场 → 发展 → 高潮 → 收尾的强度曲线（附简单示意）
3. **布局**——ASCII 布局块（```layout，渲染成 PNG）+ 分区表 + 尺度实算（簇数/最大水距/人均平台面积）+ R 规则对表
4. **编成与数值**——双方单位表（类型/格位/luck/初始武器），luck 语义见 `pirate-crew/Assets/Scripts/PirateCrew/Data/LevelData.cs:97`
5. **武器与掉落**——初始武器 + 空投池，投放理由引用原作首现节奏
6. **难度定位**——在关间难度曲线（见 [README](README.md)）上的坐标
7. **资产清单**——现有件 / 待产件（注明管线归属：岛壳烘焙 / Blender 手作 / WorldKit）
8. **验收标准**——可测条目（对应测试名）+ 实拍判据
