## 1. 水体表现（最高优先级，创始人自评「可能有点难度」）

### 1.1 创始人原话要点

- 海浪**拍打**沙滩、拍打水泥柱（拍击对象可不同），要有**受力反馈**效果；
- 有**白色泡沫**，也有**半透明**感；
- 目标是"**正常的水体动态表面模拟**"（即物理/形态上像真水）**做成像素风格化渲染**。

### 1.2 现状对照【实测】

| 项 | 现状 | 出处 |
| --- | --- | --- |
| 海面 shader | 写实镜射/透射的 `PirateOcean.shader`（903 行）仍在役；像素版 `PirateOceanPixel.shader` **只有设计、未实现**（F1–F7 未开工） | [像素海面技术方案](../技术/资产管线/像素海面技术方案.md) §1/§4 |
| 海面观感 | 现役是"马平色替身"（取不到源色时按设计不画） | [待办事项](../项目/待办事项.md) 观测行、像素海面技术方案 §1 |
| 水体透明度口径 | **现役裁决 = 水体不透明**，明确「不做半透明混合（半透明 + 点采样 = 与地形色混出板外色）」 | 像素海面技术方案 §3.1 第 6 条 |
| 岸线 / 浅水 | 方案里已有 **L3 岸线带**（岸距用高度场解析算，浅水→泡沫两色带），**未实现** | 像素海面技术方案 §2/§3.2 |
| 潮汐 / 湿沙 | 已有 `AmbientShore`（潮汐斜率、螃蟹水线位）与 SandWet 湿沙槽 | `Ambient/AmbientCreatureRules.cs`、待办「Scene_SandWet.mat 缺失」条 |

### 1.3 与现役口径的两处**冲突**（须先裁决，否则做着做着会撞墙）

1. **半透明 vs 不透明**：创始人要求「半透明感」，而像素海面方案 §3.1 第 6 条已裁决「水体不透明」。
   若改半透明，需重开 [渲染篇] 关于"半透明 + 点采样混出色板外中间调"的红线讨论。
   **建议路线**：不靠真 alpha 混合，而用**两色带/抖动刻意伪造"能看见水下"**（L3 岸线带已预留这条路），
   既保住锁板又给出半透明读感——但这属【提案】，待创始人定夺。
2. **拍击反馈 vs 现役"不做白帽粒子"**：像素海面方案 §4「明确不做」清单里列了 **白帽粒子**。
   创始人新构想（浪打沙滩/水泥柱的受力反馈）需要重开这一项。

### 1.4 拆分建议【提案】

| # | 工作项 | 依赖 |
| --- | --- | --- |
| W1 | 先落地 [像素海面技术方案](../技术/资产管线/像素海面技术方案.md) 的 F1–F3（色带波纹 + 描边 + 岸线带），拿到"平色替身 → 有层级的像素海" | 无（不依赖裁决点 #4） |

| W3 | 拍击反馈（浪打沙滩/水泥柱）：接触线泡沫带 + 可选溅射——先定"必做/不做白帽粒子" | W2 同源 |
| W4 | 泡沫 tile（L2）——**等正交 size 终档（裁决点 #4）定案后才量产** | 裁决点 #4 |

## 2. 环境小动态（海鸥 / 螃蟹等）

### 2.1 现状：**已实现**，不是从零加【实测】

`Assets/Scripts/PirateCrew/Ambient/` 已建成一套完整环境活物层，由
[AmbientDirector.cs](../../pirate-crew/Assets/Scripts/PirateCrew/Ambient/AmbientDirector.cs) 总控（战斗场景已接线）：

- **海鸥**：李萨如轨道盘旋 + 拍翅 + 偶发俯冲 + 爆炸惊飞（`GullFlightRules` + `SeagullAgent`）；
- **螃蟹**：岸边横爬 + 钳子摆动 + 遇单位/爆炸缩沙（`CrabBehaviorRules` + `CrabAgent`，含水线位 `AmbientShore`）；
- **鱼群**：水下 boids（`BoidsRules` + `FishSchoolAgent`）；
- **远景海鸟剪影**、植被/旗帜风摆、灯笼、燕尾旗绳、近岸浮标、昼夜天气档。

### 2.2 现状的硬读数与三个缺口【实测】

| 指标 | 现值 | 出处 |
| --- | --- | --- |
| 海鸥默认 / 上限 | **3 / 4** 只 | `AmbientRules.AmbientBudget.DefaultGulls/MaxGulls` |
| 螃蟹默认 / 上下限 | **3**（2–3）只 | 同上 `DefaultCrabs/MinCrabs/MaxCrabs` |
| 鱼 | 1 群 × 14 条 | `FishPerSchool` |
| 海鸥轨道中心 | **写死的固定坐标**（东侧远海 `w+6`、正上方 `cx,13.6`、西侧近场 `-4`、西侧远海 `-6`） | `GullFlightRules.BuildPlan` 的 switch |
| 布点基准 | 默认按 **50×17 瓦片竞技场**（`arenaWidthTiles`）反推 | `AmbientDirector` 序列化默认值 |

**缺口 1（创始人点名的核心）：布点没跟关卡地形挂钩。** 海鸥轨道中心是**旧 50×17 竞技场**的硬编码坐标，
放到 150–280u 的 8 张海图上等于"围绕一个不存在的旧场地飞"——哪边有岛、岸线在哪、哪里有浅水，
活物层**一概不知**。螃蟹的水线位公式（`AmbientShore`）已就绪，缺的是**喂真实岸线数据**。

> 【建议】布点改**数据驱动**：① 海鸥轨道中心 / 俯冲点从关卡的**岛与岸线几何**派生
> （哪边有岛就绕哪边，俯冲瞄浅水岸线）；② 螃蟹锚到**真实湿沙 / 水线**（复用 `AmbientShore`，
> 输入改成关卡地形而非 arena 尺寸猜）；③ 鱼群/远景鸟同理按水域范围布。

**缺口 2：不够"多样"，而多样不只是"种类多"。**（**创始人 2026-09-30 裁决：数量固定，不按面积缩放**）
现有活物就 4 类，堆同一种动物没有意义——**氛围装饰的价值在"多样性"不在"同种的数量"**。
> 【口径澄清】"多样性"**不等于"种类多样性"**（创始人原话纠正）：它是**种类 × 布点 × 与场景主题的匹配**
> 三者的合力。因此方向是——
> ① **种类**：每个生态带（水域 / 岸线 / 空中 / 场外）备若干不同种；
> ② **布点**：出现在**该出现的具体位置**（鸥绕岛、蟹贴水线、鱼游礁间），不是随机撒；
> ③ **匹配主题**：按关卡母题组队（沉船关配鸥鸟与残骸、红树关配水鸟与浮木），
> 而不是每关都上同一套。
> **静物点缀同样算数**（创始人点名：珊瑚这类静物装点也可以）——参考
> [Sandcastle Demo](file:///F:/SteamLibrary/steamapps/common/Sandcastle%20Demo) 的装饰件清单
> （浮木 driftwood、卵石 pebbles、贝壳 shells、海藻 seaweed），本项目可扩到：
> 珊瑚丛 / 贝壳 / 海星 / 漂浮木 / 玻璃瓶 / 破渔网 / 蟹壳 等**零动画静物**，
> 布在岸线与浅水，比多飞两只海鸥更能提"地方感"。

**缺口 3：像素化路径下的口径。** 像素路径要求"场景里每个 renderer 都用本路径 shader，
否则那片像素的 MRT 有未定义内容"——活物层建于写实期，其几何/材质是否满足锁板与抖动口径**未验收**。
（登记在 [待办](../项目/待办/pixelart-着色路径-v3蓝本.md) "接进真正的 Battle 关卡 1"条。）

**方向小结**【建议】：主攻**多样性**（种类 × 布点 × 主题匹配，见缺口 2），
不是单纯堆种类数。像素风下活物是点缀不是主体，**每个带备 2–3 种、按关卡挑用**即可。

### 2.3 布料 / 飘扬效果【实测：已有基础，建议扩面】

**已有**：一套顶点风摆（`Assets/Art/Shaders/Ambient/PirateAmbientWind.shader` + 其等价 C# 副本
`AmbientRules.WindRules`，含阵风包络 `GustEnvelope`、"离根越远摆幅越大"权重 `SwayWeight`），
目前用于**植被 + 旗帜 + 旗绳垂旗**（燕尾旗绳 2+1+6 面）。
`SwayWeight` 已带"**悬挂向下**"分支（`weightDirection < 0`），注释明说就是给**旗 / 帆 / 垂下缆绳**用的。

> 【建议】布料铺开做，**复用同一 shader 与权重分支**，不新造一套：
> ① 废弃化工厂的 **帆布 / 防雨布 / 破篷布顶棚**；② 晾晒的布 / 破帆布；③ 若海图有船则 **船帆**；
> ④ 旗帜在新时代仍保留。走 Blender 建模出布片几何 + 顶点色标根部权重，shader 口径不变。
> 像素路径下同样要把这类材质纳入"每 renderer 都是本路径 shader"的收口清单。

## 3. 关卡地形自然化（反对"空中大方块"）

### 3.1 创始人原话要点

不要一个大方块悬在空中的感觉，要有**现实感**：

- **破败的道路**塌陷下去；
- **桥梁**一部分塌陷在水里、一部分没塌；
- 水里**散落**着各种东西，水是**浅水**；
- **废弃化工厂**泡在浅水里；
- **几片相邻的沙滩**；
- 海里一堆**水泥圆柱**，向上耸立成**若干个平台**。

### 3.2 玩法耦合（同批口述，须与地形一起设计）

- 角色在**浅水里跳跃**要**有水花**；
- 但跳到**旁边的海（深水）可能直接死**——即**浅水/深水有明确生死分界**。

> 对照：参照游戏已有"水位线落水死亡"机制（[参考逆向-静态](../项目/归档/参考逆向/参考游戏逆向-海盗军团抢宝藏-静态.md)），
> 本工程水位常量 `WaterSurfaceY = -0.4` 见 [3D空间模型对齐](3D空间模型对齐.md) 与
> `LevelGeometry.cs`。【提案】浅水行走/跳跃表现为**新增层**，不改深水即死这条既有红线。

### 3.3 落地路径【提案】

这些点子属**关卡设计阶段**内容，走 [关卡制作管线](关卡/关卡制作管线.md) 六阶段（概念立项 → 纸面设计 →
灰盒 → 走查 → 美术接入 → 封版），母题拆解建议：

| 母题 | 说明 | 现有可复用件 |
| --- | --- | --- |
| 破败道路 / 塌陷桥梁 | 断裂、半沉入水，制造高低差与掩体 | 化工厂 kit（道路/围墙）、岛壳烘焙件 |
| 浅水漫过的工业场地 | 工业场地加浅水层 | 待定（化工厂资产的取舍创始人自行处理） |
| 相邻沙滩群 | 多沙滩 + 浅水湾 | 潮汐/湿沙系统（`AmbientShore`、SandWet） |
| 水泥柱阵 + 耸立平台 | 海面成排圆柱，柱顶成可站平台 | 需新烘焙件（Blender 无头管线） |

### 3.4 地形边界与"切面"（参照 Sandcastle Demo）

**创始人原话**：「游戏地图的地面**有边界**，在边界**能看到切面**」——即整块地形像一块
**放在桌上的沙盘 / 剖面模型**，边缘不是无限延伸，而是**能看到土层的截面**。

**参照物**：本地已安装的 **Sandcastle Demo**（Bubblebird Studio，Steam）
`F:\SteamLibrary\steamapps\common\Sandcastle Demo`（IL2CPP 构建，**只有二进制、无源码**；
其特征：3D 俯视海滩沙盘、9 种海滩布局、水沙物理、装饰件 = 浮木/卵石/贝壳/海藻）。

**对本工程的意义**【提案】：
- 现役竞技场的水面是"无限海"，地形是悬空岛台——**没有"边界"概念**；
- 若要切面，需给地形加**侧壁截面**（土层 / 岩层分层色带，正好契合像素色带口径），
  并让相机能看到侧壁——这是**美术 + 相机取景**两处联动，不是单改 shader。
- 与像素色带口径天然契合：截面 = 几条水平色带（草皮 / 土 / 岩），无需贴图。
- 【待澄清】切面是"**整关四周包一圈侧壁**（沙盘式）"，还是"只在相机可见的低边做"？
  前者更彻底，后者省面数。需创始人示意。

### 3.5 视角移动（参照 Sandcastle Demo）

**创始人原话**：「**视角移动方案学沙堡**」。
