## 1. 定位与原则

### 1.1 武器系统是什么

武器系统是回合制战斗中玩家的**输出手段层**：一个角色在自己的回合里，从武器栈中选用一件武器，经瞄准/放置交互把它送入战场，由结算模型（§3）产生伤害、击退与地形影响。它与相邻系统的边界：

- **回合骨架**（回合交替、行动经济、胜负判定）不属于武器系统——武器系统只消费「本回合是否还能用武器」的判定，并在「用武器」发生时通知回合骨架（接口见 §4.1）。
- **船员系统**只负责武器栈的归属与增删（谁、有什么、还剩几件），不管武器入战场之后的行为（接口见 §4.2）。
- **AI** 是武器系统的**消费者**而非组成部分：AI 评估必须与实弹消费同一份几何/结算代码（铁律①），但不拥有独立的第二套武器规则（接口见 §4.4）。
- **数据承载**沿用数值三层管线（纯 C# 静态目录 → ScriptableObject → 编辑器生成器），该分层结构为已保留决策（[3D空间模型对齐.md](3D空间模型对齐.md) §7）。

### 1.2 三条铁律（占位期实测教训 → 重做红线）

1. **实弹行为与 AI 评估前提必须消费同一份几何/结算代码。**
   为什么：占位期出现过评估与实弹脱节的实锤——海鸥武器实弹在弹体自身高度结算爆炸，按含高度分量的 3D 距离判定，地面目标永远在有效半径外，实战 100% 零伤害；而 AI 评估却按「坠弹落到地面再结算」的完全不同前提打分，持续给这把永远没用的武器高分（证据链见 [代码质量审计报告-2026-10-01.md](../审计/专项/代码质量审计报告-2026-10-01.md) §2）。根因是两处各写了一套几何假设。重做口径：**出现任何一处分叉即验收失败**（验收项见 §5.1）。
2. **规则进纯 C# 静态类，MonoBehaviour 只做胶水。**
   为什么：占位期 `Combat/` 的纯静态纪律是审计认定的全仓标杆（同报告 §5.3「亮点」）：数值出处可注、NaN 边界可防、脱离 Unity 运行时也能在无头验证台（`external/harness/`）秒级断言。重做延续：一切武器规则写成不引用 UnityEngine 的纯静态函数/纯状态迁移；`MonoBehaviour` 层只做输入采集、坐标换算与表现回写。
3. **数值须有用户裁决的出处，不留无背书常量。**
   为什么：占位期武器表（含 id 命名、触发枚举、显示名、对应测试断言，即依据清单 B1–B4/F4 各行）的唯一存在理由是对某个外部基准的逐值对照，该依据已作废——问题不在数值本身好坏，在于理由不成立。重做口径：每个数值要么有已裁决文档背书（背书白名单见依据清单「判据与口径」节），要么显式标注【提案/待定】等待裁决；两者之外的常量不允许存在。

## 2. 武器概念清单（17 格）

**本节全部【提案/待定】**：以下 17 格是占位期概念清单的沿用，格数本身也允许在重做时增删（待裁决）。每格给出「名称 + 机制概念」，作为重做时的裁决清单使用——**一切数值（伤害、半径、帧数、速度、概率、数量）一律不在本文写死，逐值待裁决**。英文 id 保留作对照用名（其命名依据属依据清单 B2 待裁范围，保留对照名不构成对任何外部基准的沿用声明）。

1. **cannonball（炮弹）** — 保底投掷武器：自重极低的直线弹道，接触目标即爆；同时是加农炮（第 16 格）的弹药，由炮的蓄力决定初速、本身不走弹弓。飞出场地或落水即消失。
2. **cherryBomb（樱桃炸弹）** — 最基础的弹弓投掷弹：接触即爆，威力取最低档，定位新手向。
3. **dynamite（炸药）** — 高威力延时弹：抛出后**静止时**才引爆（静止判定的速度阈值待裁决）；落水后的行为语义须重裁（占位实现为「熄灭但仍按静止规则判定」，这条歧义是重做时必须正面回答的问题，不是默认沿用项）。
4. **boulder（巨石）** — 重型碾压弹：无爆炸，靠接触碾压造成与自身速度成正比的伤害，并把敌人推开、让被撞者继承自身速度；自重取全表最重档；静止后淡出消失。
5. **banana（香蕉炸弹）** — 高弹跳投掷弹：弹跳系数取全表最高档；三路引爆——静止、玩家点击、AI 近距条件（第三路的条件语义待裁决）。
6. **mine（地雷）** — 跨回合常驻的感应陷阱：有角色进入感应半径**且在移动**才点燃引信，引信走完起爆；引信期有蜂鸣提示（蜂鸣节奏与引信长度待裁决）；常驻时长与同场数量上限待裁决。
7. **parachuteBomb（降落伞炸弹）** — 可空中操控的飘落弹：下落自带减速；玩家按住鼠标可当「扇子」推动水平漂移（该手势在 3D 瞄准体系下如何映射，见 §4.5 问题清单）。
8. **rumBottle（朗姆酒瓶）** — 接触即爆并生火：落在地面时额外生成向左右两个方向蔓延的地面火焰（生成数量与蔓延参数待裁决；即第 17 格 sweepingFlame，衍生武器）。
9. **piecesOfEight（八枚八里亚尔）** — 可复用的低威力炸弹：同一次装备内可多次复用（复用次数待裁决），爆后自动补弹并短暂锁定武器；「复用」与「用武器即结束回合」的行动经济如何相容，见 §4.1 问题清单。
10. **gunpowderBarrel（火药桶）** — 放置式连锁炸药：一次放置多件、跨回合常驻；被任意爆炸波及时殉爆并可引发连锁。殉爆的施暴者归属语义待裁决（占位实现记为无施暴者、不累计邪恶度——AI 后果是否成立须重裁）。
11. **woodenCrate（木箱）** — 放置式掩体：不爆炸、跨回合常驻，用于遮挡视线/弹道与临时改造地形；箱体的可破坏性与物理属性待裁决。
12. **anchor（船锚）** — 天降直击：点击放置后从高处恒速直落，对命中带内的目标造成**固定伤害**（非爆炸、无随距离衰减）；命中带的几何（半宽/上伸）与落地后的停留时长待裁决。
13. **seagull（海鸥）** — 载具式多点投弹：点击选高度放飞，飞行中再点击投弹，可连投多颗，飞离场地且无弹在飞即结束。**投弹落点必须落在地面结算**——落点几何是占位期「零伤害事故」的原发点，重做时该格是铁律①的标志性验收对象（§5.1）。
14. **tidalWave（潮汐巨浪）** — 全场横扫：从场地一侧推进到另一侧的水墙，对推进带附近、水面以上一定高度带内的**所有角色（不分敌我）**每帧造成固定伤害；3D 下的纵深折叠口径（浪是横跨整个纵深的水墙，还是只在施法纵深线上）沿用 [3D空间模型对齐.md](3D空间模型对齐.md) 的提案口径，待重裁。
15. **voodooDoll（巫毒娃娃）** — 位移嫁接弹：先点敌人锁定目标，再弹弓抛出木偶；木偶落地后镜头切到目标，随后把木偶被抛出时的投掷速度**原样**赋给目标——目标被同方向抛飞，可被抛下水致死。切镜与速度转移的时序延迟待裁决。
16. **cannon（加农炮）** — 放置式火炮：摆位跨回合常驻，拖拽炮尾同时调角度与蓄力，松手发射 cannonball（爆炸结算走第 1 格，不重复计一格伤害）；蓄力—发射阈值与拖拽交互的 3D 手势见 §4.5。
17. **sweepingFlame（蔓延火焰）** — 衍生持续伤害：朗姆酒瓶落地生成，沿可站立地面逐段向左右蔓延，每段对接触目标造成固定伤害并附加随机击退；蔓延的地形判据、是否允许作为独立武器出现，待裁决。

## 3. 结算模型概念

**本节只描述语义，不写数值公式；所有系数与阈值待裁决。** 已裁决的空间合成口径（3D 距离含高度差、爆炸为 3D 球、击退映射到世界坐标轴）见 [3D空间模型对齐.md](3D空间模型对齐.md) §5，重做直接消费该契约。

### 3.1 爆炸

- 一次爆炸 = 爆心 + 爆炸尺寸参数。有效半径由尺寸参数推导（推导式待裁决），对候选目标做**球形范围**判定，含高度差。
- 伤害随距离**线性衰减**：爆心满额、半径边缘趋零，默认**无最小伤害保底**（是否引入保底待裁决）。
- 击退 = 爆心→目标径向向外的速度增量（幅度随衰减同步变小），**并叠加一项固定的向上抬升**——受爆者总是被额外抛向空中，这是击退手感的组成部分而非可选项（该语义保留与否待裁决，占位期与已裁决契约均含此项）。
- 施暴者累计「邪恶度」：对目标造成的衰减比例之和记到施暴者头上，供 AI 后续优先攻击「被打疼过的敌人」。该机制是否保留待裁决。
- 边界处置：目标恰在爆心（距离为零）时取满额衰减、不臆造击退方向——占位实现在此边界有显式防 NaN 处置（防速度变 NaN 后物理失控），该防御语义值得作为惯例保留（【提案/待定】）。
- 爆炸对放置物（火药桶等）以最近点距离判定波及，命中即触发其自身引爆，形成**连锁**。

### 3.2 直击（非爆炸结算）

固定/持续伤害不走路由衰减，现有四种语义，重做时可增删（待裁决）：

- **固定伤害直击**（船锚）：命中带内一律同一伤害，无衰减。
- **每帧持续伤害**（潮汐巨浪）：处在作用带内每帧受伤，伤害不随时间/距离变化。
- **逐段接触伤害**（蔓延火焰）：火焰每段独立结算，附随机方向击退。
- **按速度比例伤害**（巨石碾压）：伤害与弹体当时的速度成正比，并附带推开与速度继承。

### 3.3 触发方式

触发方式是武器数据的一个标志位集合（一件武器可组合多种触发）。语义集合（占位期六种，可增删待裁决）：

| 触发 | 语义 |
| --- | --- |
| 接触引爆 | 碰到瓦片/放置物/敌人即触发 |
| 静止引爆 | 速度满足「静止」判据时触发（判据阈值待裁决；落水体的「永不静止」歧义见 §2 第 3 格） |
| 点击引爆 | 玩家（或 AI 决策）主动点击触发 |
| 感应引信 | 满足感应条件（进入半径且目标在移动）后启动倒计时引信，走完触发；引信期的提示表现（蜂鸣）由表现层消费 |
| 被爆波及 | 被任意爆炸命中即触发（连锁的机制基础） |
| 放置即生效 | 无触发概念，放置/使用即为全部行为（木箱类） |

### 3.4 弹道与物理

- **弹弓初速**：初速大小与拖拽距离成正比、方向与拖拽相反（向后拉 = 向前射），带每武器独立的速度上限；力度系数与限速语义为**已裁决规格**（[docs/技术/投掷行为契约.md](../技术/投掷行为契约.md)），重做直接消费，不另立第二套公式。
- **飞行物理**：重力按武器自重逐帧累积；撞地按弹跳系数反向并受摩擦衰减，撞墙按墙反弹系数反向（各系数待裁决）；坐标、重力与固定步长的等价关系见 [3D空间模型对齐.md](3D空间模型对齐.md) §3，不另设。
- **落水**：过水面阈值即落水（方向无关），见同文档 §4；落水对每件武器的意义（消失/失效/触发）是各武器格的待裁项。

## 4. 与其他系统的接口草案

每小节只列**重做时必须回答的问题**，不预设答案；标注【提案/待定】。

### 4.1 回合系统

现役回合骨架的语义：一个角色每回合可「抛自己一次」+「用武器一次」，**用武器即结束回合**；主动 EndGo 立即结束回合（占位期纯状态语义，见 git 历史 `Combat/TurnRules.cs`；其细节取值在依据清单 A5/A6 范围内，同样待重裁）。重做必须回答：

- 放置类武器（加农炮/木箱/火药桶）如何接入行动经济——放置算一次「用武器」吗？加农炮的「发射」发生在摆位之后的后续输入里，跨不跨回合记账？
- piecesOfEight 的「爆后自动补弹复用」与「用武器即结束回合」如何相容——复用消耗下一次行动、还是同回合内允许连投？
- 跨回合常驻物（地雷/火药桶/木箱）的生命周期与回合推进的关系——存活多久、同场上限、回合切换时是否需要结算快照？
- 「空闲超时推进回合」的计时语义在新武器交互（引信等待、海鸥飞行、木偶镜头）下如何计时——哪些武器行为算「活动」、哪些算「空闲」？

### 4.2 船员系统

武器栈归属船员：每人一个武器栈，关卡编成预置、战斗中拾取入栈；占位期存在「某数量记号 = 无限」的约定（语义待裁决）。重做必须回答：

- 武器栈有无容量上限？同类武器叠放还是逐件展开？
- 拾取入栈的时机与满栈行为？
- 武器切换的交互入口与「武器锁定」（补弹间隙）的状态归属——在船员状态还是回合状态？

### 4.3 关卡资产

关卡侧通过两类字段向武器系统供货：**编成字段**（角色初配武器 id → 数量）与**空投配置**（武器池、同屏宝箱上限、落点安全规则——不砸中角色、不与其他放置物重叠）。占位期语义提炼自 git 历史 `Data/LevelData.cs` 与归档逆向 §5.5（概念来源）。重做必须回答：

- 新关卡资产 schema 里，编成/空投字段叫什么、以什么形式进资产（YAML/Inspector/Blender 导出物）？
- 空投宝箱机制是否保留？保留的话落点安全与重叠判定消费哪个几何查询接口？
- 「保底武器」（cannonball 的保底定位）是否保留为规则（无武器角色自动持有），还是改为编成约束？
- 放置类武器与地形判定（可放置面、重叠、高度场采样）需要关卡几何暴露哪些查询接口？

### 4.4 AI

铁律①在 AI 侧的具体化。**已裁决口径**：AI 的轨迹预测与实弹共用同一份半隐式欧拉积分器（`Battle/ThrowTrajectory.Predict`，见 [3D空间模型对齐.md](3D空间模型对齐.md) §3「预览 = 实弹」的载体声明）——重做不允许出现第二套 3D 积分。重做必须回答：

- 特殊武器（海鸥/巨浪/木偶/放置类/连锁）的**评估前提**如何从实弹几何机械推导，而不是评估者另写一套假设（海鸥案例的反面教材，见 §1 铁律①）？
- 期望伤害计算的高度快照如何贯穿——高台目标与地面目标在评估里必须可区分（占位期评估把高度丢弃导致高台目标伤害系统性高估，见 §5.3）？
- 评估的随机采样（模拟投掷次数、随机种子）如何保证可复现与可测试？
- AI 的行动决策与回合骨架如何同步——不作为（bailout）的判据与「跳过回合」的语义？
- 放置类武器的可行性判定（CanPlace）消费哪个放置查询接口，与实弹放置是否同源？

### 4.5 表现与交互层

分工：规则层输出数值与事件（引信帧序、切镜时刻、淡出曲线的输入），表现/交互层消费；规则不碰渲染与音频。重做必须回答：

- 哪些表现钩子需要进入规则层的输出契约（如引信蜂鸣帧序、切镜时刻），以什么形式（返回值/事件总线）发布？
- 弹弓拖拽、海鸥选高、火炮拖尾蓄力、降落伞「扇风」这些**手势**在 3D 瞄准体系（相机基向量映射，见 [3D空间模型对齐.md](3D空间模型对齐.md) §3）下如何映射？哪些手势要重设计？
- 瞄准预览是否对所有武器可用（占位期只有弹弓类有轨迹预览），预览与实弹是否继续同源（铁律①的预览版）？

## 5. 重做验收清单

以下各项是**占位期实测出的问题**（审计报告 §2/§3/§4/§5.3 与实机验证），作为重做批次的验收门槛，逐条核销须用户裁决。原文底稿：[docs/项目/待办/武器系统重做.md](../项目/待办/武器系统重做.md)。

1. **实弹 == AI 一致性（最高优先）**：每种武器的实弹行为与 AI 评估前提消费同一份几何/结算代码；海鸥炸弹零伤害案例固化为回归验收用例——评估模型与运行时行为再出现分叉即验收失败。
2. **AiController 接线裁决**：敌方 AI 的控制器要么完整接线进战斗装配链、要么整体删除走兜底——不允许「登记了接线点但实际无装配」的悬空状态（二选一，须裁决）。
3. **AI 高度快照贯穿**：评估侧不得丢弃高度分量；高台目标与地面目标的期望伤害必须可区分。
4. **爆炸常数单一真值**：爆炸公式的常数在规则层与平衡配置层只允许一份真值，并以「两处相等」的地基测试锁定（占位期两处各写一份、互不引用，改一处另一处静默失真）。
5. **弹体状态真实传递**：回合/武器结束判定必须消费弹体的真实在飞状态，不允许靠「同帧结算」的时序巧合维持正确性——真实弹体引入后不得静默出错。
6. **AI 侧杂项收口**：魔法数字与规则类单源化（评估侧不得复写规则层常量）、重复出处收敛、功能计数与实际执行路径一致、放置可行性判定补重叠检测。
7. **评估代码职责拆分**：AI 评估不得再聚成数千行多职责单文件；按「会话状态机 / 数据模型 / 特殊武器规划」等职责块分文件（占位期实测拆法见审计报告 §5.3）。
8. **地形载体正名**：「瓦片」属已根除玩法的化石命名，现役地形载体是静态高度场；随重做批次正名，防止新人误读玩法前提。

**完成定义**：重做后的武器表（其逐值裁决完成后）落地 + 上述验收项全绿 + 实机走查通过。

## 6. 明确不做

- **不直搬参照游戏的数值。** 归档逆向文档（[docs/项目/归档/参考逆向/](../项目/归档/参考逆向/)）只作玩法概念与灵感来源，**不是设计依据**：其中一切伤害、半径、帧数、速度、数量数值不得未经裁决直接录入；重做后的每个数值都以「本工程设计值」身份存在，并注明用户裁决出处或【提案/待定】。
- **不搬布局、不搬瓦片、不转写关卡。** 参照游戏是灵感库——取的是概念（例：「有可连投的载具式投弹武器」这一玩法概念），地图/关卡/瓦片布局一律自研；任何文档或代码注释不得把本项目武器内容描述成对参照游戏的转写或移植。
- **不保留无背书常量。** 重做产物中不允许出现「注释里只有对某个外部基准的对照、无已裁决文档背书、也无【提案/待定】标注」的数值常量（铁律③的负面清单）。
