## 0. 口径与方法（所有数字可复算）

### 0.1 瓦片与"实体地形"的判定

原版关卡 XML 的 `<row>` 是**前景碰撞层**：`TileSystem.readXML` 对每个非 `-` 的瓦片
`new Tile(...)` 放进 `tileGrid`（`ffdec-export/scripts/__Packages/com/nitrome/throwgame/TileSystem.as:78-95`）。
`<bgRow>` 是**纯背景层**，只挂 `Clip`，不进碰撞网格（同文件 `:97-117`）。因此：

- **实体地形 = `<row>` 中所有非 `-` 的瓦片**；
- `<bgRow>` 只贡献氛围与一个功能性标记 `antichest`（无宝箱空投列），不参与本文的簇分析；
- 瓦片尺寸 32px（`静态:20`）；坐标格口径 `x/y` 均为瓦片格。

把 `<row>` 按名称归族（实算，33 关共 **11,815 个前景实体瓦片**）：

| 族 | 判定前缀 | 全 33 关总数 | 语义 |
| --- | --- | --- | --- |
| EARTH | `earth_*` / `eartyh_bottom_middle`（原版拼写笔误） | **4,826** | 土层块体（主承重地形） |
| WATER | `tile_ripple_*` / `boat_ripple_*` | **3,665** | 水面波纹（**视觉层，非站立面**） |
| GRASS | `grass_top_*` / `grass_row_*` / `grass_overlap_*` / `single_grass_*` | **1,399** | 草皮（土层顶面皮） |
| SAND | `shell_sand_*` / `blank_sand_*` / `sand_overlap_*` | **951** | 沙滩 |
| SHIP | `ship_*` / `cannon_port_*` | **598** | 船体/甲板/船舷炮口 |
| MAST | `mast_*` / `crows_nest_*` | **376** | 桅杆与瞭望台 |

### 0.2 平台簇（cluster）定义

在**水线以上**的实体地形里做 **4-连通域**：

- 网格：`usable[x][z] = (<row>` 在 `(x,z)` 处的瓦片不是 `-` 且不是波纹`) 且 z < waterY`；
- 一个连通域 = 一个**平台簇**；簇的长宽用俯视包络（bbox）；"层数" = 该簇各列**最高实体格所在行**的**不同取值个数**
  （即顶面台阶数），非 bbox 高度。

> 为什么排除水线以下：水面以下是死亡区，实体地形即使存在也不可站立，参与统计会虚增平台。区分"簇 bbox"和
> "簇内顶面台阶"是因为原版地形是**逐格**的，高柱与薄板可能同属一个 4-连通域（如 L8 的竖柱连到中央横梯）。

**形状分类启发式**（用于 §1 表与 §2.2，判定实算）：

| 形状 | 判定条件 |
| --- | --- |
| 长条 | bbox 高 ≤2 且宽 ≥8 |
| 长条台 | 宽 ≥ 2.5 × 高，高 ≤3 |
| 实心块 | 填充率（格数 / bbox 面积）≥ 0.85 |
| 阶梯峰 | 顶面台阶数 ≥4 |
| 台地 | 其余（填充率 0.42–0.85） |
| 碎岛 | 填充率 < 0.42 |
| 环形/镂空 | bbox 内存在**不连到 bbox 边界**的空洞 |

### 0.3 三个核心度量

| 度量 | 定义 | 用途 |
| --- | --- | --- |
| **水占比** | `vWater = (heightTiles − waterY) / heightTiles`（水面所在行到地图底的纵向占比） | 衡量"水线以下留了多少死区" |
| **最大水距** | 连续**无任何水线以上实体格**的列数最大值（`maxOpenRun`） | 衡量"最宽的一次投掷跨越有多远" |
| **开场水柱** | 完全没有水线以上实体格的总列数（`openCols`） | 衡量"地图被水切开的程度" |

**投掷射程上限【分析推断】**：由 `静态:394-398` 的 twang 公式 `v = 0.25 × 拖拽距离`、限速 `twangMaxForce = 20`
（`静态:313`），及重力 `vy += weight`、`weight = 1`（`静态:309`），得满力 45° 平抛射程
`R = v²/g = 20²/1 = 400px = 12.5 瓦片`（从高台抛可更远）。**这是判断"水距是否可跨越"的量纲基准**。

### 5.2 本项目坐标契约（与现行平台化重构对齐）

现行重构把原版 **Flash 的 py（原"竖直"轴）重投影为世界 Z（纵深）**，竞技场是 XZ 水平面、重力 -Y；
**1 瓦片 = 1 世界单位**、1 块（block）= 0.25 单位（`LevelGeometry.cs` 类头 / `TerrainCatalog.DefaultBlockWorldHeight`）；
平台用**逐格块高 + 簇归属**表达（`PlatformClusterLayout.cs` 的 `PlatformMap`），簇伪装类型 `Ship / SkyIsland /
TerraceIsland`，单簇块高上限 **5**（`MaxBlocksPerCluster`）。因此**本节坐标 = (X 横向 0–49, Z 纵深 0–16, 块高 1–5)**。

**水距约束**：重构代码用 `PlatformClusterLayout.WaterGapTiles`（bbox 沿分离轴的水格数），并把
`MaxThrowRangeWorld` 作为连通性判据。设计目标：**主簇间水距 2–4 格**（原版 L1 是 1 格，因用户要求
"悬空平台 + 平台间是水"而拉宽；4 格仍远小于射程上限 12.5 格）。

## 用户裁决：地图设计总纲（2026-09-14，优先级高于本文其余规则）

**"我想象的地图设计是一个糖豆人那种地图……我指的是它到处浮空的。你现在的布局想象力太低了。"**（2026-09-14 二次澄清：与机关无关）落地为四条硬约束：
1. **每处=一个独立的大空岛**：每块场地是**完整的一座岛**——整块岛体、不规则的岛形轮廓（非矩形瓦片拼盘）、厚重的底部收形（岩锥/船体），悬浮在**海面上方**（往下看是海洋，坠落落水即死）。一张地图=**多个相互独立的空岛**，各自有不同的悬浮高度与大小，散布在大海上空（阶梯上升/环形/对峙等构图按关卡变化）。**反面清单**：贴水薄甲板、1×1 瓦片拼矩形、同层平铺、木板+草方块混搭——全部禁止。
2. **大块可读剪影**：平台=一个可读的整体（整船/整岛），底部有船体/岩锥收底（现已有），禁止"木板+草方块"式混搭。
3. **层间连接可选**：斜坡/跳板/断桥按关卡节奏加（教学关少、后期多），也允许纯靠落差+跨跳；**动态机关不在本裁决范围**（原版潮汐/海鸥等另行立项）。
4. **大色块高可读配色**：能站/会死一眼分清；光照写实质量保留，形状与色彩回到玩具级清晰。

本文 R1-R18 规则继续有效（武器节奏/水距配对等数值层），但**布局形制以上面四条为准**。

## 用户裁决第五轮（2026-09-14，比例与意译总攻）

1. **平台:角色比例必须对**：角色已定 1.85（Godot 真比例），平台相对角色太小——格子世界尺寸 1→2 单位（角色≈0.93 格高，岛 4-8 格=8-16 单位才够厚重）。所有世界单位常量（射程/相机/水 y/物理）随 PixelsPerUnit 32→16 等比联动，格语义不变。
2. **中心构图**：每关 3D 化要有圆心——主船/主岛居中，其余岛围绕布置（原版 2D 的视觉焦点在 3D 里成为空间中心）。
3. **真船建模（意译不直译）**："两艘船就得真的建模两艘真实比例的大船放在那"——船体有船艏曲线/舷弧/艉楼/多段甲板，不是盒子拼的剪影。
4. **船上不长草**（任何途径都不行——含 ScenePropLayout 的全局草散射）。
5. **消灭垂直硬截断**：岛缘/船体与空气的交界必须有收形（倒角/渐窄/悬挑），禁止直上直下的墙。
6. **流程铁律**：重要内容协调者亲自写亲自把关；或先做一个优秀案例（样板关）给用户过目后，subagent 才能按样板批量。
