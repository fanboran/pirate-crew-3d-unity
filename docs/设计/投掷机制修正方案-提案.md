## 一、现状链路（是什么）

一次投掷从输入到结算经过六段，全部有代码出处：

**1. 输入段（AimThrowController）**
- 选中：屏幕空间 30px 内最近本队存活角色（`AimThrowController.cs:704` `PickTeamCharacter`，逆向 §3.4 `minD2=900`）。
- 瞄准：r12 裁决后为**炮台模式**——A/D 转向、W/S 力度、滚轮微调、空格/回车发射
  （`AimThrowController.cs:317` `UpdateTurret`）；合成等效拖拽向量喂给 `ResolveThrow`。
- 鼠标左键在已选角色后交给相机环绕；弹弓拖拽路径见 §三.P0-1（已死）。

**2. 弹道换算段（单一来源）**
- 力度：`Ballistics.TwangVelocity`（`Ballistics.cs:35`）——初速 = 0.25 × 拖拽距离，
  `twangMax` 等比限速（角色 20 / 部分武器 30，逆向 §5.1）。3D 下只取其**模长**。
- 方向：`LevelGeometry.ScreenDragToArenaDirection`（`LevelGeometry.cs:396`）——
  相机基向量投影 + r12「拖向哪扔向哪」直瞄语义，yaw 旋转后仍正确。
- 抬升：`ApplyThrowLift`（`LevelGeometry.cs:369`）——`normalize(水平方向 + UP×0.7)`，
  仰角恒 ≈35°（`ThrowLift = 0.7`，`LevelGeometry.cs:209`）；速度大小不受抬升影响。
- 统一入口：`ThrowVelocityForWeight`（`LevelGeometry.cs:439`）——weight>0 抬仰角、
  weight=0（cannonball 等无重力弹）直线飞行。玩家自抛 / 弹体生成 / 预览 / AI 都经它取初速。

**3. 积分与物理段**
- 半隐式欧拉 + Flash 帧口径：`fixedDeltaTime = 1/25`，重力 `-39.0625 × weight`
  （`LevelGeometry.cs:470` `WorldGravityY`）——与 Flash `vy += w; y += vy` 逐步等价。
- 角色自抛：`PirateBase.ApplyLaunchVelocity`（`PirateBase.cs:391`）→ PhysX 冲量；
  落地反弹 / 摩擦 / 翻滚由 `HandleRollContact` + `RollRules` 忠实转写 Flash（`PirateBase.cs:520`）。
- 武器弹体：`WeaponProjectile.FixedUpdate` 手动施加 `gravity × GravityScale`
  （`WeaponProjectile.cs:282`）；但**接触积分缺口**见 §三.P0-2。

**4. 预览段（TrajectoryPreview / ThrowTrajectory）**
- `ThrowTrajectory.Predict`（`ThrowTrajectory.cs:82`）与 PhysX 同一套半隐式欧拉、同一份初速与重力
  → 预览线第 i 点 = 实弹第 i 物理步位置（「预览 = 实弹」不变量）。
- 步数 15 起步、随力度线性延长到 60（`ThrowTrajectory.cs:39` `StepsForSpeed`）；
  落点环由 `TryGetImpactPoint` 穿地插值（`ThrowTrajectory.cs:54`）。

**5. AI 段（AiEvaluation / AiController）**
- 随机采样：角度 180°–360° + 力度 5..twangMax（`AiEvaluation.cs:867` `RandomThrow`，逆向 §6.2）；
  模拟走 `SimulateShot` → 与实弹同一 `ThrowTrajectory.Predict`（`AiEvaluation.cs:893`）。
- 打分：逆向 §6.2/§6.3 逐行转写 + M2 预期伤害增强项（`AiEvaluation.cs:974` `ScoreSelfThrowSample`）；
  随机源为跨运行时确定的 xorshift32（`AiEvaluation.cs:47` `AiRandom`）。

**6. 回合耦合段**
- `BattleController.IsAnythingActive` 末腿含 `aimController.IsAiming`（`BattleController.cs:519`）；
  `TurnManager` 挂机计数被任何「活动」清零（`TurnManager.cs:137`）。
  该腿已死，见 §三.P2-1。

## 二、已达标、必须保住的（为什么这些不能动）

| 已达标实践 | 证据 | 对应行业实践 |
| --- | --- | --- |
| 预览 = 实弹 = AI 三端同源 | 唯一积分器 `ThrowTrajectory.Predict` + 唯一初速入口 `ThrowVelocityForWeight` | 确定性战棋（预览即结果，如 Into the Breach 的完全确定性设计） |
| Flash 帧口径（25fps 逻辑与刷新率解耦） | `WeaponProjectile` 类头「Flash 帧口径」注记，逐帧逻辑全在 FixedUpdate | 逻辑帧率与渲染帧率分离 |
| 规则层纯 C#、可无头测试 | `Ballistics` / `ThrowTrajectory` / `AiEvaluation` 全静态 | 测试金字塔：规则与胶水分层 |
| 输入意图与表现分离 | 炮台键盘合成拖拽向量走同一 `ResolveThrow`，口径不分叉 | 输入抽象层（一次映射、多设备复用） |
| 相机无关的输入映射 | `ScreenDragToArenaDirection` 用相机基向量，yaw 旋转后正确 | 相机相对输入（camera-relative input） |

**守则**：任何修正都不得引入第二套积分 / 第二份初速换算 / 第二份 Flash 常量；
新参数（如仰角）必须从唯一入口 `ThrowVelocityForWeight` 进，预览与 AI 同步消费。

## 三、问题清单（按优先级）

### P0-1 鼠标拖拽瞄准路径已死，交互契约三处不同源

- `BeginDrag()`（`AimThrowController.cs:466`）**零调用方**（全仓 grep 证实）；
  `Phase.Dragging` 只在 `BeginDrag` 置位 → `Update` 的鼠标拖拽分支（`:157-163`）、
  `ReleaseDrag` 的鼠标路径与 `minDragPixels` 误触阈值（`:534-542`）全部不可达。
- 后果：①类头与注释仍把「拖拽瞄准」写成主要交互（如 `AimThrowController.cs:10-23`），
  与实际行为（纯炮台键盘）不符——违反「实现/测试/文档三处同源」纪律；
  ②`minDragPixels` 等参数成为死配置；③`PirateBase.Thrown` 等下游语义只能被键盘路径触发。
- 性质：**行为规格缺失**（不是数值错）。需要创始人先裁决交互形态（§四.S1），再动代码。

### P0-2 弹体的弹跳 / 摩擦 Flash 口径未接线，与角色落体行为不一致

- 逆向 §5.2/§5.4 给了每武器 `bounce`（0.2 常规、banana 0.8）与 `friction`（0.3–1.7），
  纯函数已备好：`Ballistics.IntegrateGroundContact` / `IntegrateWallContact`（`Ballistics.cs:71-92`）。
- 但二者**零运行时调用方**（仅测试引用，全仓 grep 证实）；全工程无任何 `PhysicMaterial` 配置；
  `WeaponProjectile.OnCollisionEnter` 只置 `_contact` 标志（`WeaponProjectile.cs:354-371`）。
- 后果：通用弹体撞地后按 PhysX 默认材质（弹性≈0）一趴即停——banana 高弹跳、
  boulder 碾压后滚动的手感全部缺失（`WeaponProjectile.cs:50-53` 类头 TODO 已登记一部分）；
  角色自抛却有完整转写（`PirateBase.HandleRollContact` + `RollRules`）——同一张物理表两套落体行为。

### P1-1 仰角不可控：固定 `ThrowLift = 0.7` 锁死 ≈35°

- 原版拖拽竖直分量直接给 vy（2D 全维控制，逆向 §5.1）；3D 化后拖拽只表达水平方向
  （`LevelGeometry.cs:155-158` 决策 3），炮台模式也没有俯仰轴——
  竖直维度玩法（高低岛吊射、越墙、贴地平射）不可表达。AI 同样受限
  （`RandomThrow` 只采角度 + 力度，`AiEvaluation.cs:867`）。
- 行业参考：弹弓/炮台类通用做法是把**方向、俯仰、力度**拆成独立输入轴
  （Worms 系列的仰角+蓄力、Scorched Earth 血统的炮台三参数）。

### P1-2 预览无「超射程」语义，步数上限会截断长弧

- 找不到穿地点时只隐藏落点环（`TrajectoryPreview.cs:109-118`），玩家无法区分
  「超出射程」与「正常瞄准中」；`MaxSteps = 60`（`ThrowTrajectory.cs:32`）按力度线性延长
  是弧长的近似——低力度高抛的长弧超过 60 步（2.4s）时预览截断，实弹却继续飞。

### P1-3 拖拽力度的屏幕像素标定与分辨率 / DPI 耦合

- 满力拖拽 80px = twangMax(20) / 0.25（`Ballistics.cs:61` `FullForceDragDistance`），
  这是 Flash 800×600 屏幕的口径；现代高分屏上 80px 占屏比例过小，力度分辨率随设备漂移。
- 依赖 P0-1 的裁决：若恢复拖拽交互才需要修（输入端按参考分辨率归一化，Flash 数值域不动）。

### P2-1 `IsAiming` 死腿：挂机判定契约腐化（潜伏）

- `IsAnythingActive` 的「玩家正在瞄准」腿（`BattleController.cs:519`）恒 false
  （依赖不可达的 `Phase.Dragging`）。当前无症状只是侥幸：人类队超阈值走 `ContinueTurn`
  的「角色还有动作就不强制推进」兜底（`TurnManager.cs:196-199`）。
  一旦该兜底语义变化，炮台蓄力中（角色静止、无弹在飞）回合会被推进。

### P2-2 炮台蓄力跨回合不重置

- `_turretPower` 初值 0.6、不随选人/发射重置（`AimThrowController.cs:288`）。
  属 QoL 还是缺陷需裁决，先登记（提案/待定）。

### P2-3 非像素化世界空间件与「彻底像素化」方向的冲突

- 已根除（`refactor/pixel-cleanup` 分支）：头顶血条（`OverheadHealthBar`）、
  脚下光环（`TurnMarkerFx`）。
- 待清退清单（逐项**先立像素化替代再删**，避免信息丢失；全部提案/待定）：
  轨迹预览线（LineRenderer → 像素点阵虚线）、落点标记环（→ 像素十字/角标）、
  伤害数字（→ 像素数字精灵）；选中描边由渲染轨的像素化着色路径统一接管
  （口径见 [docs/技术/渲染/像素化着色路径/实现口径.md](../技术/渲染/像素化着色路径/实现口径.md)）。

## 四、修正方案（全部提案/待定，逐条含契约与测试）

> 实施纪律（AGENTS.md 核心行为指令 #4）：每项先立**行为契约**（输入 → 可观察结果），
> 实现 / 测试 / 文档三处同源改；「与旧行为等价」只允许用于已裁决正确的行为。

### S1 交互形态（已裁决：炮台为唯一）

创始人 2026-09-24 裁决选**选项 A：炮台为唯一瞄准交互**（r12 既成事实转正）。已实施：

- 死拖拽路径整体删除：`BeginDrag` / 鼠标 `Phase.Dragging` 分支 / `UpdateDrag` /
  `minDragPixels` 序列化字段与误触分支（炮台下限改具名常量 `TurretMinDragPixels = 5px`，行为等价）；
- `IsAiming` 改指炮台瞄准状态 `_turretAiming`——P2-1 的挂机判定死腿一并收敛，
  瞄准中回合不再推进（原靠 `ContinueTurn` 的人类队兜底）；
- 行为契约落 [docs/技术/投掷行为契约.md](../技术/投掷行为契约.md)（同相机契约体裁，单一事实源）；
- 玩家可见口径对齐（BattleHud 模式注释等）。

S5（拖拽力度的分辨率归一化）随选项 A 失效、撤销——炮台虚拟拖拽不受屏幕分辨率影响；
若未来恢复拖拽交互需重启裁决。

### S2 弹体接触积分接线（解 P0-2）

- **推荐方案**：把 `Ballistics.IntegrateGroundContact` / `IntegrateWallContact` 接进
  `WeaponProjectile` 的接触路径（`OnCollisionEnter/Stay` 判地面/墙接触 → 按 §5.2 表的
  bounce/friction 改写刚体速度），bounce/friction 从 `ProjectileProfile` 取
  （新增字段，来源逆向 §5.2 表，单一出处）。
- 备选方案：每武器配 PhysicMaterial——放弃，理由：PhysX 材质模型与 Flash 积分不等价
  （Flash 是逐帧线性摩擦 `|vx| -= friction`，PhysX 是库仑摩擦），且无法无头测试。
- 测试：`ProjectileProfile` 新字段的推导用例（纯 C#）；接触积分的世界域换算用例
  （对齐 `PirateBase` 的 `RollRules` 换算口径，两者应共享同一组世界域系数）。
- 风险：改变全部弹体现有落地手感（当前 = PhysX 默认）→ 按 §5.2 逐武器回归；
  banana 的 0.8 高弹跳 + 玩家点击引爆的联动需实测。

### S3 仰角轴（解 P1-1）

- 入口改造：`ThrowVelocityForWeight(horizontalDirection, speed, weight)` 增加
  `lift = ThrowLift` 默认参数（或独立 `ThrowAngleRadians` 重载）——**默认值 = 现行为逐值不变**，
  既有测试全绿是验收线。
- 输入绑定（炮台模式，提案）：Q/E（或 Shift+滚轮）调俯仰，HUD 显示仰角读数；
  `ResolveThrow` 把当前仰角传下去，预览同步（三端同源由唯一入口保证）。
- AI 扩维（可选、后置）：`RandomThrow` 的采样空间加仰角维（如 15°–60° 均匀采样），
  采样数与 30ms 时间片预算需复核（`AiEvaluationSession` 分帧结构已支持拆工作单元）；
  不扩维则 AI 维持现状（与玩家共享固定仰角，公平但不完整）。
- `ThrowLift` 常量退化为「默认仰角」语义，文档（3D空间模型对齐.md §3）同步改口径。

### S4 预览语义（解 P1-2）

- 落点环找不到穿地点时**不隐藏，改为显示「超射程」态**（如环变灰 / 虚线延伸到步数上限并加端点标记），
  让「打不到」成为可读信息（行业惯例：预览必须能表达失败态，而不只是成功态）。
- 步数改为「以找到穿地点为准、上限放宽」：`StepsForSpeed` 保留为性能上限，
  预览循环在 `TryGetImpactPoint` 命中后提前收敛——不破坏同源（同一积分器、同 dt）。
- 像素化替代（P2-3）落地时同步改造表现层，本条只定语义。

### S5 输入归一化（解 P1-3，依赖 S1 选 B）

- 拖拽距离按参考分辨率归一（`dragPixels × (参考屏高 / Screen.height)` 之类的一次性输入端换算），
  Flash 数值域（0.25 / 80px / twangMax）不动；炮台路径不受影响（虚拟拖拽量）。

### S6 死代码与状态收敛（解 P2-1 / P2-2）

- `IsAiming` 语义修正（随 S1）；`_turretPower` 是否随选人重置 → 创始人裁决后改一行 + 用例。

### S7 像素化替代节奏（解 P2-3）

- 顺序建议：先立替代物（像素点阵预览线 / 像素数字）再删旧件，逐件小 PR；
  与渲染轨（像素化着色路径）合流时统一验收出图。

## 五、实施顺序与验收门

1. **S1 裁决**（阻塞项，创始人拍板）→ 2. **S2**（纯规则 + 无头 TDD，不动交互）→
3. **S3**（入口默认参数先行，输入绑定随后）→ 4. **S4 / S6** → 5. **S5**（若 S1 选 B）→
6. **S7** 随渲染轨。

每步验收门：纯 C# 规则用例（无头验证台）全绿 → EditMode 全绿 → 涉及交互的加 PlayMode 契约用例
→ MCP 实机出图归档 `export/`。任何一步发现「预览 ≠ 实弹」即回滚重审（§二守则）。
