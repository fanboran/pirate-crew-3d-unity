# 调色板与量化手册

> **这份文档是什么**：全局调色板（板）的**定义规则**、**唯一真源与镜像的一致性路径**、
> **量化算法口径**与**工具用法**。它是 [像素纹理资产管线.md](像素纹理资产管线.md) §4/§5 的操作手册，
> 回答"板长什么样、改板怎么改、一个颜色怎么被锁进板、怎么证明结果可复现"。
>
> **标注约定**沿用 [美术风格指南](../../设计/美术风格指南.md) §0；表内每一项都带**状态**字段
> （裁定 / 提案），板内的状态标注是权威值，本文不重复断言。
>
> **调研依据**：[调研-调色板量化与纹素密度.md](调研-调色板量化与纹素密度.md)（OkLab 选型、ordered-only、密度公式、BC7 除名）。

## 1. 板是什么：59 色 / 19 个族 / 5 个字段

**位置与形态**

| 路径 | 角色 |
| --- | --- |
| `pirate-crew/Assets/Data/Palette/pirate_palette.json` | **唯一真源**。手改只改这里（纯文本、可 diff、Python 与 C# 都能读） |
| `pirate-crew/Assets/Data/Palette/PiratePalette.asset` | Unity 侧**派生镜像**（ScriptableObject，Inspector 里可直接看色值/给编辑器工具取色） |
| `docs/images/palette/pirate_palette_strip.png` | 参考条带图（人眼验收 + 改板的 diff 靶子，见 §5） |

**为什么真源是 JSON 而不是 `.asset`**（这是本手册最重要的一个决定）：板的消费者跨三种运行时 ——
Python 离线量化工具（`tools/palette`）、Blender 无头导出模板（`tools/blender/pixel`）、
Unity 编辑器工具（材质工厂 / UI 派生）。只有把跨语言共享的那一份数据放在**纯文本**上，
离线链才能完全不依赖 Unity 运行；反过来若真源是 `.asset`，任何一次量化都要先开 Unity，
而 `Library/` 锁是独占资源（AGENTS.md 铁律）。`.asset` 因此是**派生镜像**：由 JSON 生成，
用于 Unity 内的取色与 Inspector 审阅，不作为基准。

**槽位字段**（每个槽位 5 个字段，顺序固定）

| 字段 | 含义 | 硬要求 |
| --- | --- | --- |
| `id` | 槽位名（全大写 A-Z/0-9/_） | 唯一；代码里**只**引用它，不引用 hex |
| `group` | 所属**阶梯族** | 同族槽位在文件里必须**连续声明**（校验器会查） |
| `hex` | sRGB `RRGGBB`（无 `#`） | 唯一（重复色 = 量化时的死色，白占板位） |
| `usage` | 这个色该用在哪（写给用板的人） | 非空 |
| `status` | `裁定` 或 `提案` | 非空（项目规范：未确认数值必须标注） |
| `source` | 出处（可核对的文档/代码引用） | 非空 |

**族（group）清单与规模**

| 族 | 槽位数 | 用途 |
| --- | --- | --- |
| `INK` | 7 | 墨线 + 中性灰阶梯（`INK`→`WHITE_HOT`，覆盖 L≈0.20→0.96） |
| `SAND` / `ROCK` / `WOOD` / `GRASS` | 4 / 4 / 4 / 3 | 地形四族明暗阶梯（暗→亮声明） |
| `SHADOW` | 3 | **替换式暗部色**（渲染篇 §4.2）：冷紫/暖棕/深紫三档 |
| `SEA` | 5 | 海水五档（最深深海→泡沫） |
| `FACTION_RED` / `FACTION_BLUE` | 2 / 2 | 两阵营主色 + 替换式暗部 |
| `SKY_NOON` / `SKY_DUSK` / `SKY_STORM` | 2 / 2 / 2 | 三档天空（天顶 + 地平线），对应 `skyColour` 1/2/3 的关卡分组 |
| `EMISSIVE` / `ACCENT` / `METAL` / `CLOTH` / `FARFIELD` / `UI` / `NIGHT` | 2 / 3 / 2 / 2 / 3 / 5 / 2 | 自发光、点缀、金属、帆缆、远景剪影、UI 浮雕、夜色档 |
| **合计** | **59** | 落在美术风格指南 §3.2 的 32~64 区间内 |

**两条结构性规则**（不是审美偏好，是量化质量的要求）：

1. **族内按 OkLCH 明度升序声明**（暗 → 亮）。理由有两条：
   ① 阶梯的"均匀明度梯队"是抖动/明暗过渡干净的前提（调研 §3）；
   ② 最近邻匹配在**距离并列**时按声明序取前者 —— 声明序有序 ⇒ 并列行为可预测、可复现。
2. **族内连续**：同一族的槽位不许被别的族打断；这样"按族读板"和"按声明序遍历"是同一件事。

## 2. 一致性路径（只有一条，别自己发明第二条）

```
 pirate-crew/Assets/Data/Palette/pirate_palette.json      ← 唯一真源（改这里）
        │                                    ▲
        │  BuildFromJson                     │  ExportToJson（把 Inspector 的手改提升回真源）
        ▼                                    │
 pirate-crew/Assets/Data/Palette/PiratePalette.asset      ← 派生镜像（可写，但会被 BuildFromJson 覆盖）
```

| 动作 | 菜单 | 无头 `-executeMethod` |
| --- | --- | --- |
| 真源 → 镜像（生成/覆写） | `PirateCrew/Art/调色板/JSON → PaletteAsset（生成镜像）` | `PirateCrew.EditorTools.Art.PaletteAssetBuilder.BuildFromJson` |
| 镜像 → 真源（提升 Inspector 改动） | `PirateCrew/Art/调色板/PaletteAsset → JSON（回写真源）` | `…PaletteAssetBuilder.ExportToJson` |
| 双侧对账（不一致时打印**首个差异字节**） | `PirateCrew/Art/调色板/对账 JSON 与 PaletteAsset` | `…PaletteAssetBuilder.Verify` |

**改板的正规流程**：改 JSON（或先在 Inspector 改再 `ExportToJson` 提升）→ 跑 `BuildFromJson` →
跑 `Verify` → 跑离线侧 `palette_tool.py verify` → 提交。
两侧都过才算同步：Unity 侧比的是"镜像渲染出的规范文本 vs 磁盘文本"，
离线侧比的是"磁盘文本是不是规范文本"。

**规范文本**（`palette_tool.py` 与 `PaletteJson.ToCanonicalText` 的逐字节镜像实现）：
顶层键各占一行 2 空格缩进、`slots` 数组**一槽一行**、槽内字段固定顺序、UTF-8 无 BOM、LF 换行。
两侧任一漂移都会被 `palette_tool.py verify` 的「板文件是规范文本」用例抓住
（Unity 侧 `JsonUtility.ToJson` 的 prettyPrint 布局与 Python `json.dumps` 不同，拿不到逐字节一致，
所以本仓**手写**了这两个写出器）。

## 3. 量化算法（口径，不是实现细节）

### 3.1 色彩空间：OkLab 加权最近邻

```
d = ΔL² + w·(Δa² + Δb²)        w 默认 1.0
```

- 转换链：`sRGB8 → 线性光 → XYZ(D65) → LMS → cbrt → OkLab`（Ottosson 2021 修订版矩阵）。
- **必须用 OkLab，不能用 RGB 欧氏距离**：RGB 距离系统性偏色，且会毁掉明度层次
  （一张渐变会被切成明度乱序的色块）；实证见调研 §1。
- **暴力 O(N×板色数) 纯函数匹配**，不上 kd-tree/LUT —— 无数据结构差异 = 跨机器逐字节一致的最低风险路径。
- **cbrt 前不钳非负**：XYZ 可落在 OkLab 定义域外（如 `(0,0,1)`），负 LMS 的实立方根是合法解。
  钳 0 会让官方测试表第 4 组偏差从 4e-4 飙到 0.999（实测踩过，`palette_tool.py` 与
  `pixel_export.py` 都按此实现）。

### 3.2 抖动：ordered-only，阶数 = Bayer 矩阵格数

- **只用 ordered（Bayer 4×4 / 8×8），默认关**（`--dither none`）。误差扩散（Floyd–Steinberg 等）
  **全线禁用**：顺序敏感 ⇒ 输入改一个像素其后图案全变（像素级回归 diff 的大敌）。
- 算法（Yliluoma 两板色混合模型的确定性简化）：像素的最近色 `c1` 与次近色 `c2`，
  在 `{0, 1/n², …, 1}` 上选"线性光混合后 OkLab 误差最小"的 α，再由 Bayer 阈值决定该像素画 `c1` 还是 `c2`。
- **混合在线性光里做**（γ=2.2 拆解），否则抖动区整体偏亮。
- **阶数 = 矩阵格子数**（4×4 → 1/16 粒度，8×8 → 1/64）。**这不是可调项**：
  若把两种矩阵都固定成 1/8 粒度，bayer4 与 bayer8 的输出会**逐像素完全相同**
  （同一个 α 下两者选中的是同一组像素）—— 白提供一个选项（实测踩过）。
- 阈值中点归一 `(m+0.5)/16`（直接除 16 整体偏亮，与赛璐璐 shader 同一坑、同一常量口径）。

### 3.3 确定性收尾

零随机数（无 k-means、无误差扩散、无迭代寻优）；PNG 编码锁定 `compress_level=9, optimize=False`；
换行锁定 LF。⇒ **同输入同输出**，`verify` 用 sha256 当场证明。

## 4. 工具：`tools/palette/palette_tool.py`

```bash
# 0) 自证（14 条用例：OkLab 官方表 / 规范文本 / 确定性 / 锁板 / 明度单调 / 幂等 / 真实资产抽查）
python tools/palette/palette_tool.py verify

# 1) 板结构校验（id/hex 唯一、色数区间、组内明度升序、族内连续）
python tools/palette/palette_tool.py check

# 2) OkLCh 表（核色用）
python tools/palette/palette_tool.py oklch

# 3) 归一化板文件到规范文本（幂等；不改语义）
python tools/palette/palette_tool.py fmt

# 4) 参考条带图（入 docs/images/palette/）
python tools/palette/palette_tool.py strip

# 5) 量化任意 PNG 到板上（可选 ordered 抖动）
python tools/palette/palette_tool.py quantize --in a.png --out b.png [--dither bayer4|bayer8] [--weight 1.0]

# 6) 样品像素贴图（口径样板；同时是导入规范那条 EditMode 用例的判定靶子）
python tools/palette/palette_tool.py sample
```

`quantize` 对 RGBA 输入**保留 alpha 原样**：透明是画出来的（halo / 光池 / 泡沫），不是被推导出来的，
所以 alpha 不参与锁板。输出若出现板外色直接返回退出码 1。

## 6. 验收判据

| 层级 | 判据 | 工具 |
| --- | --- | --- |
| 板本身 | 色数 32~64；id/hex 唯一；`usage`/`status`/`source` 齐全；族内明度升序且连续 | `palette_tool.py check`（+ Unity 侧 `PaletteAssetBuilder` 的同口径校验） |
| 板与镜像 | 磁盘文本 = 镜像渲染出的规范文本 | Unity `PaletteAssetBuilder.Verify` + `palette_tool.py verify` |
| 单张贴图 | 唯一色数 ≤ 板色数；出现板外色即失败 | `palette_tool.py quantize`（输出 0 板外色）/ `palette_tool.py sample` |
| 回归 | 量化/出图**逐字节一致**（重跑 diff 零差异） | `verify` 的 sha256 用例 |
| 顶点色（Blender） | 平涂色属性量化后离板 ≤ 1 个 8bit 步长 | `tools/blender/pixel/step_asset.py --self-test` |

**已知边界（不是缺陷，是口径）**：渲染期颜色会漂出板外（光照乘法 / 色带选择 / Bayer 抖动都在
板内色之上做运算），**帧级锁板**是渲染篇 §7 明列的演进项，未实施。资产事故的定义因此只有一条：
**贴图本身的唯一色数超过板**。

## 8. 遗留与风险（登记不改）

1. **`.gitattributes` 没给 `.json` 钉 `eol=lf`**（仓库根共享基建，属其它文件域，登记不改）：
   本仓 `core.autocrlf=true`，白名单只覆盖 Unity 序列化扩展名
   （`.meta`/`.unity`/`.prefab`/`.asset`/`.mat`/`.controller`），`.json` 不在其中
   ⇒ **别的机器或新克隆签出这份板可能拿到 CRLF**。
   现状已有两层容错：`palette_tool.py` 的 `_read_text` 与 `PaletteAssetBuilder.ReadTextLf`
   都先归一行尾再比对，写出侧恒写 LF（已实测：把板转成 CRLF 后 `verify` 仍全过）。
   根治只需在 `.gitattributes` 追加一行 `*.json text eol=lf`，那时这层容错变成冗余但无害。
   **性质与该文件头注释记载的「47 个 .fbx.meta 行尾漂移事故」同族**——所以这里不是说"不会出问题"，
   而是"出问题也只是假报警，不是数据损坏"。
2. **`PiratePalette.asset` 镜像与新增 `.meta` 的落地需要 Unity**：本轨道不启动 Unity
   （`Library/` 锁是独占资源，由协调者串行执行），因此 `.asset` 镜像与 `Assets/Data/**`、`Assets/Editor/Art/**`、
   `Assets/Art/Tests/**`、`Assets/Art/Textures/Pixel/**` 下新增文件的 `.meta` 都要**协调者跑一次 Unity 导入**
   才生成。在此之前 `ToonMaterialFactory` 会明确拒绝工作（而不是静默用空板兜底）。
3. **色值全为 v1 首轮值**：59 个槽位里【裁定】项来自正式文档/逆向记录，【提案】项是 AI 起手值，
   随 M1 样张过审后回写（美术指南待定项 #6「调色板定稿」）。板内 `status` 字段是权威标注，
   不要把提案当基准引用（项目文档规范）。
4. **`--weight`（a/b 权重）默认 1.0**：调研 §1 建议"灰阶发脏"时把 L 权重提到 1.5~2，当前无实拍依据、未改；
   改值是破坏性变更（会改全部量化结果），须同步重跑全部贴图与 hash 基线。
