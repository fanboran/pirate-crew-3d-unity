# 像素纹理导入规范

> **这份文档是什么**：像素纹理在 Unity 侧的**导入约定**——哪些资产算像素纹理、必须带哪几项设置、
> 谁来强制、怎么校验、新增资产怎么接入。它是 [像素纹理资产管线.md](像素纹理资产管线.md) §3
> 的操作手册（§3 给口径，本文给"在工程里怎么落地与门禁"）。
>
> **上游**：量化后的 PNG 从哪来 → [调色板与量化手册.md](调色板与量化手册.md)、
> [Blender导出模板使用说明.md](Blender导出模板使用说明.md)。

---

## 1. 一句话口径

**一张贴图是不是像素纹理，只看它**在不在 `pirate-crew/Assets/Art/Textures/Pixel/` 目录里**（含任意深度子目录）。
在 = 一律按本节第 3 条的五项设置导入；不在 = 本规范完全不管。**

---

## 2. 为什么用**目录**而不是文件名后缀（规则只能有一条）

任务给了两条候选（约定路径 `Assets/Art/Textures/Pixel/**` 与文件名后缀）。本仓**选目录**，理由：

1. **范围一眼可判**：想知道哪些资产受管，看目录树即可，不必对每个文件名做字符串匹配；
2. **不会在改名/导出链路上被丢掉**：后缀约定在 Blender 导出、批量重命名、格式转换里极易丢失，
   丢失后**静默退回写实导入设置**——这是"改了看不出问题"型事故的典型形状；
   而目录属性不会因为改个名字而消失（改名不改路径 = 不改变判定），改路径则会出现在 git diff 里；
3. **迁移是显式动作**：把一张贴图搬进该目录 = 宣布它是像素纹理；搬出 = 宣布它不是。
   git 里看得见，评审时问得出来。

**只保留一条规则**也意味着：`*.px.png` 这类后缀**不参与判定**。若有人在约定目录内用了该后缀，
后处理器会打一条提示日志（提醒"两条规则并存"的误解），但判定结果不受影响。

### 2.1 为什么只对约定目录生效（不回溯存量）

存量 55 张贴图（`Textures/{Crew,Fx,UI,Water}`）是写实期产物（多数开 mip + 双线性过滤），
像素化后处理已经把全局观感兜住了（资产篇 §7「存量资产不回头重做」）。若批量改成 Point/mip off，
改动会**立刻改变现役画面**，而本轮的出图验收由协调者串行驱动、成本高 —— 无法人眼验收的批量画面改动
不接受（[工业级重构总纲](../../项目/工业级重构总纲.md) §7 风险表「美术管线改动影响现有画面」的缓解措施）。
所以规则显式只对新增/约定目录生效，存量走"翻新一批、评估一次"的演进路径。

## 3. 导入设置（五项 + 三项明确不改）

| 项 | 值 | 为什么 |
| --- | --- | --- |
| **Filter Mode** | `Point` | 像素硬边。双线性会把板内色插成板外中间色（同时破"锁板"与"1 纹素 = 1 屏幕像素"） |
| **Generate Mip Maps** | `false` | 正交固定机位没有"远处"；mip 的平均色**同样是板外色**（第二重破板），只带来闪烁与糊 |
| **Compression** | `Uncompressed`（RGBA32） | BC1/BC3 把 4px 以下色块压脏；**BC7 除名**——端点插值的解码色必落在板外（调研 §5），且破坏字节级回归 diff。64/128px 未压缩仅 64KB/张，显存无压力 |
| **sRGB** | `true` | 板色按 sRGB 十六进制定义，编码必须一致（本工程 `m_ActiveColorSpace = 0`（Gamma）下贴图字节即屏幕值） |
| **Alpha Is Transparency** | `false` | **隐藏坑**：开启后 Unity 会把 RGB **膨胀（dilate）**到透明区域，透明像素的 RGB 变成从邻近色插出来的中间值 ⇒ 不在板上 ⇒ 直接破坏「贴图唯一色数 ≤ 板色数」与逐字节回归；而 Point + 无 mip 下根本没有需要膨胀来修的黑边（黑边是双线性/mip 时代的产物）。透明是画出来的，不是被推导出来的 |

**明确不改的三项**（逐资产例外优于全局口径）：

| 项 | 保持 | 理由 |
| --- | --- | --- |
| `wrapMode` | 导入默认（Repeat） | 像素纹理要去平铺岛台/地面大面，强制 Clamp 会把接缝处的结构线截断；单个资产需要 Clamp 时在其 `.meta` 上单独覆写 |
| `maxTextureSize` / `npotScale` | 不动 | 尺寸由资产篇 §2 的尺寸表约束（64/128 主结构、32/64 小物件），不由导入器裁剪；裁剪是静默的尺寸事故 |
| `isReadable` | 不动（默认 false） | 不需要 CPU 读回的资产不占双份内存；确实需要时逐资产开 |

### 3.1 UI 九宫格 Sprite 档（`Assets/Art/Sprites/UI/Pixel/**`）

**它不在上面的约定域内，但共用上面这五项值。** 原因只有一条：域内规则把
`textureType` 定死为 `Default`（"给模型用的贴图"），而九宫格件必须是 `Sprite`——
唯一能带 `spriteBorder` 的类型。并进域内的后果是**后处理器把 Sprite 改回 Default**：
`LoadAssetAtPath<Sprite>` 返回 null、切片边框消失、UGUI 拿到空 sprite，
**画面退化成白块但控制台一声不响**。

于是本族自成一个目录，规则的实现落在 `PixelArtTextureRules` 的同一个类里
（`ApplySprite` / `CheckSprite` / `UiSpriteFolder`）——**值只有一处**，改一处两边都动：

| 项 | 3D 贴图档 | UI 九宫格档 |
| --- | --- | --- |
| `textureType` | `Default` | **`Sprite`**（差异所在） |
| `spriteImportMode` / `PPU` / `spriteBorder` | — | `Single` / `100`（1 贴图像素 = 1 UI 像素）/ 九宫格切片 |
| Five values | Point / 无 mip / Uncompressed / sRGB on / alphaIsTransparency off | **逐字相同** |
| `wrapMode` | 保持 Repeat（平铺大面） | **Clamp**（切片件不平铺） |

生成器与判据见 [Beveled Pixel 九宫格规范](BeveledPixel九宫格规范.md)。
`alphaIsTransparency` 必须关在 UI 档还多一个具体后果：切开后的透明像素若被 Unity 膨胀（dilate），
切角边缘会带出板外色。

## 4. 谁强制它生效：`PixelArtTexturePostprocessor`

| 角色 | 实现 | 位置 |
| --- | --- | --- |
| **规矩**（唯一真源） | `PixelArtTextureRules`（约定目录常量、`IsPixelAsset`、`Apply`、`Check`） | `pirate-crew/Assets/Editor/Art/PixelArtTextureRules.cs` |
| **执行** | `PixelArtTexturePostprocessor : AssetPostprocessor`，在 `OnPreprocessTexture` 里对约定路径强制设置 | `…/Art/PixelArtTexturePostprocessor.cs` |
| **检查（人工）** | `PixelArtTextureValidator`：逐资产断言并打印报告，违规**抛异常**（无头执行退出码非 0） | `…/Art/PixelArtTextureValidator.cs` |
| **检查（门禁）** | `PixelArtTextureImportTests`（EditMode，4 条用例） | `pirate-crew/Assets/Art/Tests/PixelArtTextureImportTests.cs` |

**为什么必须是 AssetPostprocessor 而不是一次性脚本**：导入设置属于 `.meta`，而 `.meta` 会被三条路径
反复重写——资产被重新导入、meta 被误删后重建、Blender 重新导出后覆盖 PNG。一次性脚本改完的设置
在下一次重导就会丢；只有挂在导入管线上才是**收敛的**。`OnPreprocessTexture` 在写盘**之前**触发，
赋值是绝对赋值（不是增量），因此重复导入结果相同（幂等）。

### 4.1 为什么 EditMode 用例放在 `Assets/Art/Tests/` 而**不是** `Assets/Tests/`

因为 `AssetImporter.GetAtPath` 属于 **UnityEditor** 命名空间，而无头验证台的
`-p:HarnessScope=All` 域会编译 `Assets/Tests/**` 却**不引用 UnityEditor 程序集**
（`external/m2-harness/M2Harness.csproj` 里 UnityEditor 只在 `DataEditor` 域条件引用）。
用例放进 `Assets/Tests/` 会把协调者的 1130 条 `All` 域门禁打成编译错误。
放在 `Assets/Art/Tests/`（本轨道自己的域、带独立 asmdef）后：Unity 的 Test Runner 照常发现并执行它，
无头验证台两个域都不碰它 —— 两边都不受伤。

用例通过**装配件限定名反射**读取 `PixelArtTextureRules`（asmdef 汇编不能引用预定义程序集
`Assembly-CSharp-Editor`），因此"约定体被删/改名"会让门禁变红，而不是静默跳过。

## 5. 新增一张像素纹理的步骤

```bash
# ① 量化到板（见 调色板与量化手册 §4）：像素纹理的色值必须先落在板内
python tools/palette/palette_tool.py quantize --in bake_raw.png --out PirateCrew/Assets/Art/Textures/Pixel/Environment/Deck.png

# ② Unity 重新导入（postprocessor 自动套用五项设置）
#    编辑器开着：右键资产 → Reimport；无头：跑一次 -batchmode 让 Unity 导入
#    注意：新建的 .cs / .png / 目录第一次需要 Unity 导入一次才会生成 .meta

# ③ 校验导入设置
#    菜单：PirateCrew/Art/像素纹理/校验约定目录
#    无头：-executeMethod PirateCrew.EditorTools.Art.PixelArtTextureValidator.ValidateAll（违规抛异常 ⇒ 退出码非 0）
```

**新资产接入自查清单**

- [ ] 落在 `Assets/Art/Textures/Pixel/**` 下；
- [ ] 唯一色数 ≤ 板色数（`quantize`/`sample` 会直接报"板外色 0"）；
- [ ] 尺寸符合资产篇 §2 的尺寸表（主结构 64/128、小物件 32/64）；
- [ ] 结构线画进贴图（不靠 shader 判定），线宽按屏幕像素定（1 屏幕像素 ≈ 1/ppm 米，ppm 见渲染篇 §3.1）；
- [ ] Unity 导入后跑一次校验器，五项设置齐全；
- [ ] 确实需要 `wrapMode = Clamp` 的资产，在 `.meta` 上单独覆写并在此处登记理由。

## 6. 验收与遗留

| 判据 | 命令 |
| --- | --- |
| 约定目录内全部资产设置合规（机器判据） | 菜单 `PirateCrew/Art/像素纹理/校验约定目录` / `-executeMethod …PixelArtTextureValidator.ValidateAll` |
| 约定规则自证（范围判定 + 反向对照） | Unity `-runTests -testPlatform EditMode -testFilter PirateCrew.ArtPipeline.Tests` |
| 样品贴图在（用例的非空靶子） | `python tools/palette/palette_tool.py sample`（生成 `…/Pixel/Diagnostics/PixelSpecSample_64.png`） |
| 无头编译（Editor 脚本 + 未破坏的运行时） | `dotnet build external/harness-art/M2Harness.csproj -p:HarnessScope=DataEditor` |

**遗留（登记不改）**：

1. **存量 55 张贴图不在约定域内**、保持写实期导入设置（这是设计，见 §2.1）；翻新它们时按 §5 走；
2. `Assets/Art/Textures/Fx/ToonPilot_GlowHalo.png` / `ToonPilot_GlowPool.png` 由
   `ToonPilotSetup.EnsureRadialTexture` 在编辑器侧**内联**设置了同样的五项（它早于本规范落地）。
   两者语义一致；若将来把它们迁进 `Pixel/**`，内联设置与后处理器会写同样的值，不冲突；
3. 本规范**只管 2D 贴图**。FBX 内嵌贴图与 `.mat` 里的贴图引用不经过 TextureImporter 的这套约定
   （材质换血由 `ToonMaterialFactory` 负责）。
