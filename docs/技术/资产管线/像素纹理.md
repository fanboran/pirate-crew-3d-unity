## 1. 纹素密度（Texel Density）

- **全项目锁一个值：每 Unity 米 = 32px**【AI 提案·待首轮试产校准】。
- 含义：1m 见方的表面分配 32×32 纹素。船员（约 1m 出头）→ 全身贴图 32~48px 覆盖；岛台主结构按此换算贴图尺寸。
- 建模/UV 展开时就按该尺度铺——**密度不统一 = 点采样下闪烁与粗细不均的直接来源**。
- **这个值必须与目标档位的屏幕像素密度对齐**：`ppm = RT高 ÷ (2 × 正交size)`（[渲染篇 §3.1](../渲染/管线/渲染管线.md)）。`1 纹素 = 1 屏幕像素` 是像素质感成立的条件；现役特写档（size 5、RT 高 360）= 36 px/米，与 32 同档（纹素略密 12%）；全场档 10.6、全景档 3.8——**那两个档位下纹素被缩到 1/3~1/8，纹理里的结构线与砖缝必然消失**。翻新验收按目标档位复算 ppm，不按 32 单值验收【AI 提案】。
- 由此**结构线宽度按屏幕像素定、不按绝对纹素定**：§5 的"2px 深色线"在 36 px/米 下是 2 屏幕像素（比手绘像素画的砖缝粗一档），在 10.6 px/米 下只剩 0.6 像素（丢掉）。统一口径写成 **1 屏幕像素 ≈ 1/ppm 米** 的线，密度档变化时随板重画【AI 提案】。

| 用途 | 尺寸 |

## 3. 导入落地（Unity 侧）

### 3.1 判定规则：目录，唯一规则

**一张贴图是不是像素纹理，只看它**在不在 `pirate-crew/Assets/Art/Textures/Pixel/` 目录里**（含任意深度子目录）。
在 = 一律按 §3.2 的五项设置导入；不在 = 本规范完全不管。**

当初有两条候选（约定路径 `Assets/Art/Textures/Pixel/**` 与文件名后缀）。本仓**选目录**，理由：

1. **范围一眼可判**：想知道哪些资产受管，看目录树即可，不必对每个文件名做字符串匹配；
2. **不会在改名/导出链路上被丢掉**：后缀约定在 Blender 导出、批量重命名、格式转换里极易丢失，
   丢失后**静默退回写实导入设置**——这是"改了看不出问题"型事故的典型形状；
   而目录属性不会因为改个名字而消失（改名不改路径 = 不改变判定），改路径则会出现在 git diff 里；
3. **迁移是显式动作**：把一张贴图搬进该目录 = 宣布它是像素纹理；搬出 = 宣布它不是。
   git 里看得见，评审时问得出来。

**只保留一条规则**也意味着：`*.px.png` 这类后缀**不参与判定**。若有人在约定目录内用了该后缀，
后处理器会打一条提示日志（提醒"两条规则并存"的误解），但判定结果不受影响。

#### 3.1.1 为什么只对约定目录生效（不回溯存量）

存量贴图（`Assets/Art/Textures/**` 现役 12 张，实测）是写实期产物（多数开 mip + 双线性过滤），
像素化后处理已经把全局观感兜住了（§7「存量资产不回头重做」）。若批量改成 Point/mip off，
改动会**立刻改变现役画面**，而本轮的出图验收由协调者串行驱动、成本高 —— 无法人眼验收的批量画面改动
不接受（[工业级重构总纲](../../项目/工业级重构总纲.md) §7 风险表「美术管线改动影响现有画面」的缓解措施）。
所以规则显式只对新增/约定目录生效，存量走"翻新一批、评估一次"的演进路径。

### 3.2 导入设置（五项 + 三项明确不改）

| 项 | 值 | 为什么 |
| --- | --- | --- |
| **Filter Mode** | `Point` | 像素硬边。双线性会把像素之间插出中间色——像素画的硬边读感直接被糊掉 |
| **Generate Mip Maps** | `false` | 正交固定机位没有"远处"；mip 的平均色是插值产物，只带来闪烁与糊 |
| **Compression** | `Uncompressed`（RGBA32） | BC1/BC3 把 4px 以下色块压脏；**BC7 除名**——端点插值的解码色产生块内噪点，且破坏字节级回归 diff。64/128px 未压缩仅 64KB/张，显存无压力 |
| **sRGB** | `true` | 色值按 sRGB 十六进制定义，编码必须一致（本工程 `m_ActiveColorSpace = 0`（Gamma）下贴图字节即屏幕值） |
| **Alpha Is Transparency** | `false` | **隐藏坑**：开启后 Unity 会把 RGB **膨胀（dilate）**到透明区域，透明像素的 RGB 变成从邻近色插出来的中间值 ⇒ 半透明边缘带脏色；而 Point + 无 mip 下根本没有需要膨胀来修的黑边（黑边是双线性/mip 时代的产物）。透明是画出来的，不是被推导出来的 |

**明确不改的三项**（逐资产例外优于全局口径）：

| 项 | 保持 | 理由 |
| --- | --- | --- |
| `wrapMode` | 导入默认（Repeat） | 像素纹理要去平铺岛台/地面大面，强制 Clamp 会把接缝处的结构线截断；单个资产需要 Clamp 时在其 `.meta` 上单独覆写 |
| `maxTextureSize` / `npotScale` | 不动 | 尺寸由 §2 的尺寸表约束（64/128 主结构、32/64 小物件），不由导入器裁剪；裁剪是静默的尺寸事故 |
| `isReadable` | 不动（默认 false） | 不需要 CPU 读回的资产不占双份内存；确实需要时逐资产开 |

### 3.3 UI 九宫格 Sprite 档（`Assets/Art/Sprites/UI/Pixel/**`）

**它不在上面的约定域内，但共用上面这五项值。** 原因只有一条：域内规则把
`textureType` 定死为 `Default`（"给模型用的贴图"），而九宫格件必须是 `Sprite`——
唯一能带 `spriteBorder` 的类型。并进域内的后果是**后处理器把 Sprite 改回 Default**：
`LoadAssetAtPath<Sprite>` 返回 null、切片边框消失、UGUI 拿到空 sprite，
**画面退化成白块但控制台一声不响**。

于是本族自成一个目录，规则的实现落在 `PixelArtTextureRules` 的同一个类里
（`ApplySprite` / `CheckSprite` / `UiSpriteFolder`）——**值只有一处**，改一处两边都动：

| 项 | 3D 贴图档 | UI 九宫格档 |
| --- | --- | --- |
| `textureType` | `Default` | **`Sprite`**（差异所在） |
| `spriteImportMode` / `PPU` / `spriteBorder` | — | `Single` / `100`（1 贴图像素 = 1 UI 像素）/ 九宫格切片 |
| Five values | Point / 无 mip / Uncompressed / sRGB on / alphaIsTransparency off | **逐字相同** |
| `wrapMode` | 保持 Repeat（平铺大面） | **Clamp**（切片件不平铺） |

生成器与判据见 [Beveled Pixel 九宫格规范](UI九宫格.md)。
`alphaIsTransparency` 必须关在 UI 档还多一个具体后果：切开后的透明像素若被 Unity 膨胀（dilate），
切角边缘会带出板外色。

### 3.4 强制机制：`PixelArtTexturePostprocessor`

| 角色 | 实现 | 位置 |
| --- | --- | --- |
| **规矩**（唯一真源） | `PixelArtTextureRules`（约定目录常量、`IsPixelAsset`、`Apply`、`Check`） | `pirate-crew/Assets/Editor/Art/PixelArtTextureRules.cs` |
| **执行** | `PixelArtTexturePostprocessor : AssetPostprocessor`，在 `OnPreprocessTexture` 里对约定路径强制设置 | `…/Art/PixelArtTexturePostprocessor.cs` |
| **检查（人工）** | `PixelArtTextureValidator`：逐资产断言并打印报告，违规**抛异常**（无头执行退出码非 0） | `…/Art/PixelArtTextureValidator.cs` |
| **检查（门禁）** | `PixelArtTextureImportTests`（EditMode，4 条用例） | `pirate-crew/Assets/Art/Tests/PixelArtTextureImportTests.cs` |

**为什么必须是 AssetPostprocessor 而不是一次性脚本**：导入设置属于 `.meta`，而 `.meta` 会被三条路径
反复重写——资产被重新导入、meta 被误删后重建、Blender 重新导出后覆盖 PNG。一次性脚本改完的设置
在下一次重导就会丢；只有挂在导入管线上才是**收敛的**。`OnPreprocessTexture` 在写盘**之前**触发，
赋值是绝对赋值（不是增量），因此重复导入结果相同（幂等）。

**为什么 EditMode 用例放在 `Assets/Art/Tests/` 而**不是** `Assets/Tests/`**：
因为 `AssetImporter.GetAtPath` 属于 **UnityEditor** 命名空间，而无头验证台的
`-p:HarnessScope=All` 域会编译 `Assets/Tests/**` 却**不引用 UnityEditor 程序集**
（`external/harness/Harness.csproj` 里 UnityEditor 只在 `DataEditor` 域条件引用）。
用例放进 `Assets/Tests/` 会把协调者的 1300 条 `All` 域门禁打成编译错误。
放在 `Assets/Art/Tests/`（本轨道自己的域、带独立 asmdef）后：Unity 的 Test Runner 照常发现并执行它，
无头验证台两个域都不碰它 —— 两边都不受伤。

用例通过**装配件限定名反射**读取 `PixelArtTextureRules`（asmdef 汇编不能引用预定义程序集
`Assembly-CSharp-Editor`），因此"约定体被删/改名"会让门禁变红，而不是静默跳过。

## 4. 生成路径（**已取消的量化链**，存档）

> **【已取消·创始人 2026-09-29 裁决】**本节的「量化减色锁进全局板」与 §5「调色板纪律」属
> 「纹理量化锁板」层（[风格指南 §3.2](../../设计/美术.md)「先把有限色卡取消吧」）。
> **现行口径**：纹理 bake 直出（不量化），平涂色直接取 `tools/blender/scene/style_tokens.py` 的
> `SLOTS` 槽位色表（Unity 侧镜像见 `WorldMapAssetSetBuilder.Slots` 与 `Assets/Pixelart/` 各装配器）；
> 量化工具链保留在库（[调色板.md](调色板.md) §3~§5），kit 脚本已无调用。§1 密度、§3 导入落地不受影响。

```
Blender 材质照常制作（平涂色块风格）
  → 无头脚本烘焙到低分辨率
  → 量化减色（锁进全局调色板，见 §5）    ← 本步已取消
  → 输出 png（确定性：固定种子/无随机，重跑逐字节一致）
```

- 量化脚本做成**确定性**的——复用仓库既有的 diff 工具即可做纹理回归对账（改了烘焙参数，diff 产物像素级可查）。
- **锁板映射在 OkLab 空间做**（调研 §1）：加权距离 `ΔL² + w·(Δa² + Δb²)`、暴力 O(N×板色数) 纯函数匹配（无数据结构差异 = 跨机器逐字节一致）；RGB 欧氏距离系统性偏色；转换用 Ottosson 公开矩阵并以官方测试表做回归单测。
- **抖动只允许 ordered（Bayer / Yliluoma 任意板混合模型）且默认关**（调研 §2）：手绘按板色作画时映射误差≈0，flat 纹理上的抖动在点采样下是永久噪点；误差扩散（Floyd–Steinberg/Riemersma）全线禁用——顺序敏感 = 像素级回归 diff 的大敌；混合必须在线性光内。
- **确定性收尾**：锁 PNG 编码参数、量化前校验输入文件哈希；k-means 只许用于「一次性生成板」且固定 random_state——**锁板之后整条链零随机数**。
- 法线/金属/粗糙度贴图**全部不要**：Unlit 或自定义 lit + 平涂像素纹理就是全部。

## 5. 调色板纪律（3D 侧的"令牌"）【已取消，存档】

- 全局主调色板 **32~64 色**（明暗各档 + 主题色相，色相取向见美术指南 §3.2），存为可共享的调色板文件（如 png/ase/gpl 任一，脚本可读即可）。
- **板内结构用 OkLCH 明度/彩度阶梯生成**（保证明度梯队均匀，抖动/明暗过渡干净）；现成板素材走 Lospec JSON API（`lospec.com/palette-list/{slug}.json`，调研 §3）。
- 所有资产量化时**锁进这张板**——风格统一靠板，不靠逐图手调。
- **内部结构线画进纹理**：船舷棱线、甲板边缘、木板缝等深色结构线直接画在贴图上，不靠 shader 判定（稳定且省事）；线宽不锁绝对 2px，按屏幕像素定（1 屏幕像素 ≈ 1/ppm 米，换算见 §1）。

## 6. Blender 导出模板新增（一次性，全资产受益）

> **执行体已落地**：`tools/blender/pixel/`（工具用法、参数、实测口径与版本差异见
> [Blender导出.md](Blender导出.md)）。本节是**规格**，那份是**用法**；
> 三条与本节的差异以那份为准并已在其中说明：① `mesh_smooth_type` 在 Blender 5.2 的枚举里
> **没有 "Normals Only"**（2.8x 时代的选项名），自定分裂法线改经 `SMOOTH_GROUP` 传递；
> ② 顶点色数据通道导出必须选 `colors_type = SRGB`（实测 `LINEAR` 会做强制的 sRGB 线性化、污染数据）；
> ③ 现有 FBX **没有 UV**，密度校验落在"缺工序"而非"密度不对"上。

1. **平滑法线烘进顶点色**（custom split normals → vertex color）：反向壳描边的外扩方向数据（渲染篇 §5）；硬边模型不处理会在描边 pass 上裂开。算法=角度加权平均+位置容差合并；编码与通道选型见渲染篇 §5 / 反向壳描边 §3（8bit 必须 `×0.5+0.5` 编码；顶点色属性名 `SmoothNormal`，与平涂色属性 `Col` **互斥不可混用**）。
2. 量化步骤已随锁板裁决取消（§4 注记）；bake 用 Diffuse→仅 Color、1 sample、固定视图变换（Standard）——纯色传递天然确定（调研 §6）。
3. 导出 FBX 的纹素密度检查：`density = tex_size × √(uv_area ÷ world_area)`（px/米；**必须开方**——`uv_area × tex_size ÷ world_area` 的量纲是 px²/m²，只在 world_area=1 时数值碰巧相等），断言 **32px/m ± 0.5%**，外加每面 Jacobian 长短轴比 < 1.01（texel 方正性——点采样下非方形 texel 比密度误差更显眼）【AI 提案·Blender 侧无头校验脚本，可进 CI（调研 §4）】。**区间口径**：聚合密度与每面 Jacobian 是硬失败；单面密度对聚合值的偏离只计数（非均匀 UV 展开天然有分布）。

## 7. 资产翻新策略（演进式，不求一步到位）

- **存量资产不回头重做**：像素化后处理先兜住全局观感（渲染篇 §3），存量 PBR/平涂材质在像素化下已可接受。
- 新资产/翻新资产按本篇规格走；每翻新一批，全屏像素化强度评估调低一档（终点可能是轻像素化或纯像素纹理，美术指南待定项 #3）。
- 优先翻新顺序【AI 提案】：玩家视线焦点资产（岛台地面/船体）> 单位（贴图小、翻新快）> 远景装饰。
