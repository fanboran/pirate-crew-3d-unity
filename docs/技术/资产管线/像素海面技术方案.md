## 1. 为什么必须重做（被退役的是什么）

`Assets/Art/Shaders/Ocean/PirateOcean.shader`（903 行）与 `PirateWater.shader`（约 800 行）都是
写实期产品，它们的四项核心卖点与像素卡通**逐条互斥**：

| 现役特性 | 代码位置 | 与像素管线的冲突 |
| --- | --- | --- |
| 屏幕空间折射（`SampleSceneColor`） | `PirateOcean.shader:250`、`PirateWater.shader:276` | 采样的是**全分辨率**的相邻像素色 ⇒ 降采后产生非板色中间调（渲染篇 §1 红线 4）；且这是 `m_RequireOpaqueTexture` 的唯一消费者 |
| 深度带（`SampleSceneDepth`） | `PirateOcean.shader:247`、`PirateWater.shader:273` | 同上；这是 `m_RequireDepthTexture` 的现役消费者 |
| 白帽噪声 / 镜射 / 地平线雾 | 全文 | 连续明度渐变 + 高频噪声，是**色带与锁板**的一号敌人（资产篇 §4：细节噪声与量化互斥） |
| 顶点位移水体（`WaterTessellator`） | Scripts/PirateCrew/Water/ | 逐顶点连续起伏在点采样下是闪烁源；且正交固定机位下没有透视起伏收益 |

**它们退役后的连带收益**：`_CameraOpaqueTexture` / `_CameraDepthTexture` 的**最后两个消费者消失**
（实测清单见 [Assets/Art/Rendering/README.md](../../../pirate-crew/Assets/Art/Rendering/README.md) §3），
两项开关可以改 0 —— 每帧省两次全屏 copy（渲染篇 §7 性能行）。
这也是为什么像素海面必须**先做**，再关那两个开关（顺序不能反，否则水面当场变黑）。

## 2. 目标：三种候选与裁决建议

任务书裁决点 #7 的提案是「**色带波纹 + 量化泡沫 + 岸线带**」。展开成三个可独立验收的层：

| 层 | 观感目标 | 实现路线 | 依赖 |
| --- | --- | --- | --- |
| **L1 色带波纹** | 海面读作 2~3 档平面色带，波纹是**离散的块状带**（不是连续渐变） | **(a) 着色器算 + Bayer 抖动**：世界 XZ 方向的两三组正弦叠加 → 档位选择值 → `step` 硬切 + 4×4 中点归一 Bayer；本色板取 `SEA_MID`/`SEA_DEEP` | 无贴图；与赛璐璐共用同一套抖动常量（调研-赛璐璐 §4 同一坑） |
| **L2 量化泡沫** | 浪花是**贴图里的色块**（`SEA_FOAM` + `SEA_SHALLOW`），不是程序化噪声 | **(b) 滚动平铺像素贴图**：64×64 或 128×128 的泡沫 tile，UV 匀速平移（两三层不同速度/尺度） | 走资产篇 §3 导入三条 + §5 锁板；`Assets/Art/Textures/Pixel/**` |
| **L3 岸线带** | 岛礁周围一圈**等宽的 2 色带**（浅水→泡沫），在白沙/湿沙交界处读作"描了一层白" | (a)+(b) 混合：岸距**解析算**（见 §3.2），颜色取板 | 需要地形高度场 uniform |

**L1 建议选 (a)**：波纹是"大面积低频结构"，程序化最省资产且能随昼夜档换色（改 uniform 即可）；
Bayer 是抗色带渐变的规定手法。**L2 建议选 (b)**：泡沫是"高频细节"，程序化噪声**违反**资产篇 §4
（锁板之后整条链零随机数；flat 纹理上的抖动/噪声在点采样下是永久噪点），必须走"烘进贴图"这条路。

### 2.1 与纹素密度/ppm 的耦合（决定 tile 尺寸，不是拍脑袋）

资产篇 §1 的密度方程在这里第二次生效：**「1 纹素 = 1 屏幕像素」只在特写档成立**。

| 档位（`BattleCameraController` 正交 size） | ppm = 360/(2·size) | 64px tile 覆盖 2m 时的屏幕边长 | 结论 |
| --- | --- | --- | --- |
| 5（特写，开局默认） | 36 | 64 texel → 72px ⇒ 1.13 px/texel | **≈1:1，泡沫结构线可读** |
| 17（全场/烘焙档） | 10.6 | 64 → 21px ⇒ 3.0 px/texel | 纹理结构缩小 3 倍，只剩大色块 |
| 30~48（全景） | 6~3.8 | 64 → 12~7.6px | 泡沫细节丢失，相位还会闪烁 |

⇒ **【提案】L2 的 tile 尺寸与 UV 尺度必须按"特写档 36ppm"设计，并在全景档退化为纯色**
（用一个 `_DetailFade` 参数按相机 orthographicSize 淡出泡沫层，而不是让它闪）。
这条同时是裁决点 #4（正交 size 终档）的下游 —— 若 #4 把默认档改到 9~10，L2 的 tile 应改成 32px。
**在 #4 定案前不要量产泡沫贴图**（否则按错的密度画一遍）。

## 3. 关键技术设计

### 3.1 L1 色带波纹（着色器骨架）

```hlsl
// PirateOceanPixel.shader —— 本体 pass（LightMode="UniversalForward"）+ 反壳描边 pass
// （LightMode="SRPDefaultUnlit"，独立 LightMode 铁律见 描边Shader调试.md §八）
// 目标：与 PirateToon 共用同一套色带/Bayer 常量，海面不单独发明一套抖动口径。

float4 _WaveDirA, _WaveDirB;   // 世界 XZ 方向（已归一，左上光方向一致 → 波纹也朝左上）
float  _WaveFreqA, _WaveFreqB; // 波数/米（1.0 = 1 米一个完整波）
float  _WaveSpeedA, _WaveSpeedB;
float  _BandLevels;            // 色带档数（2~3，与本体赛璐璐同值）
float  _BandThreshold;         // 档位切分点（默认 0.5，与 _ShadowThreshold 同源）

// 世界空间波高：只用两三个方向，保证"块"够大（高频叠加会退化成噪声）
float WaveField(float2 xz)
{
    float a = sin(dot(xz, _WaveDirA) * _WaveFreqA + _Time.y * _WaveSpeedA);
    float b = sin(dot(xz, _WaveDirB) * _WaveFreqB + _Time.y * _WaveSpeedB);
    return a * 0.6 + b * 0.4;                 // ∈ [-1,1]
}

half4 FragWave(Varyings i) : SV_Target
{
    float t = WaveField(i.positionWS.xz) * 0.5 + 0.5;         // 重映射到 [0,1]（不压缩对比：颜色不乘 t）
    // 4×4 Bayer 中点归一（(m+0.5)/16，与 PirateToon.shader:187-191 同一常量与归一化口径）
    float bayer = (Bayer4x4(i.positionCS.xy) - 0.5) / _BandLevels;
    float band  = floor(saturate(t + bayer) * _BandLevels) / (_BandLevels - 1.0);
    float3 col  = lerp(_SeaDeep.rgb, _SeaMid.rgb, band);
    return half4(col, 1);
}
```

要点（每条都有出处，不是风格偏好）：
1. **抖动加在档位选择值上、不在颜色上**（渲染篇 §4.4）；
2. **Bayer 用中点归一 `(m+0.5)/16`**（直接除 16 整体偏亮，调研-赛璐璐 §4）；
3. **对比度不压缩**：颜色不乘 `t`，只拿 `t` 选档 —— 这与 `PirateToon.shader:184` 的半兰伯特重映射等价，不属条款违背（渲染篇 §4.3 末句）；
4. **波纹方向与全局光方向一致（左上）**：美术指南 §3.1「所有资产的暗部绘制/高光方向一律与左上光一致」是风格统一最大的杠杆，海面不许例外；
5. 海面**不开描边**（`_OutlinePixels = 0`）且 `renderQueue` 必须回到 2000（Geometry）—— 反之会排到描边物之后、fill 全屏盖掉壳环（`ToonPilotSetup.cs` 六轮实测的根因之一）；
6. 水体**不透明**：不做半透明混合（半透明 + 点采样 = 与地形色混出板外色）。水下可见性用 L3 的两色带表达。

### 3.2 L3 岸线带：岸距用高度场解析算，不用深度图

**问题**：写实实现靠 `_CameraDepthTexture` 求"到地形的水深"。像素管线要拆掉深度图依赖，
且深度图在全分辨率域采出来的连续值本身就要被量化。

**方案【提案】**：竞技场的地形是**已知的程序化高度场**（`TileTerrainGrid`，格 = 2u，8×8 或 17×17），
把各格顶面高度作为 `float` 数组一次性上传到 shader（`_TerrainHeights[N×N]`，8×8 = 64 float = 256B，
17×17 = 289 float ≈ 1.2KB —— uniform 充裕）；片元里按世界 XZ 求格子下标，
再算"当前格到海面高度差"作为**水深**：

```hlsl
// 水深近似：水面 y=-0.4，格面高 h ⇒ 水深 = h - (-0.4)；越接近 0 越靠岸
float depth = TerrainHeightAt(i.positionWS.xz) - _WaterLevelY;
float shore = saturate(depth / _ShoreWidth);                   // _ShoreWidth ≈ 1.0m【提案】
float band  = (shore < _ShoreFoamBand) ? 1.0 : 0.0;            // 0/1 两色带（硬切，出图后裁档数）
col = lerp(_SeaShallow.rgb, _SeaFoam.rgb, band * _FoamStrength);
```

要点：
- **不采样深度图** ⇒ 与 `m_RequireDepthTexture` 解耦（这是"能关掉那两个开关"的关键）；
- 格边界是硬台阶（2u 一格），**必须**用 §L2 的泡沫贴图叠加把台阶模糊掉 —— 这正是"量化泡沫"承担的第二职责；
- 岛台边缘的斜壳（`IslandShellGeometry` 的裙边）与格面高不同，岸线带按**格顶面高**算会与视觉边缘错开约半格；
  【提案】用"格顶面高 + 裙边斜率补偿"两项，或直接把 `_ShoreWidth` 定为 1 格的整数倍（2u）以对齐格律；
  **试产时以出图为准**（这是本方案最可能返工的一处）；
- `_WaterLevelY` 必须与水面的实际世界高度（现役 `-0.4`）**同源**：改一处就要改两处，
  实施时把它做成 `PirateCrew/Rendering` 里下发的共享 uniform（与 `ToonLightDriver` 同类）。

### 3.3 相机运动与"游动"（渲染篇红线 1 与 §7）

- 海面 UV 匀速平移 + 固定机位：**慢速移动直接接受复古感**（渲染篇 §7「运动游动」）；
- 泡沫层的 UV 平移必须**按屏幕像素步进**（用 `_ScreenParams` 或相机下发的 texel 尺寸把偏移 snap 到整数 texel），
  否则泡沫会在 360p 网格上爬行闪烁；【提案】这条与 §2.1 的 `_DetailFade` 一起实现；
- 若相机 snap 两步法（M1 工作项 1c）落地，泡沫 UV 的 snap 应与相机 snap **共用同一次 texel 取整**，不要各算一次。
