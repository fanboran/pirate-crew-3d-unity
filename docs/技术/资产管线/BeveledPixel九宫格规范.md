# Beveled Pixel 九宫格规范

> **这份文档解决什么问题**：UI 的「像素斜面浮雕」件**长什么样、怎么生成、怎么取用、怎么判合格**。
> 它是 [BeveledPixelSpriteBuilder.cs](../../../pirate-crew/Assets/Editor/BeveledPixelSpriteBuilder.cs)
> 的书面口径（几何 / 令牌 / 状态 / 切片契约 / 判据），也是界面装配的取用说明
> （运行时取用层见 §四.2 `PixelSkin`）。
>
> **几何从哪来**：不是设计出来的，是**量出来的**——
> 对创始人指定的参照图取竖切，逐像素读出九段色带（见
> [UI 像素化标准参照](../../images/ui-pixel-ref/README.md) §二）。本文只把它转写成生成器的常数，
> 转写过程中每一条都能追到那次测量。
>
> **色从哪来**：本工程**不抄参照图的色相**，一律换成本仓调色板
> [pirate_palette.json](../../../pirate-crew/Assets/Data/Palette/pirate_palette.json) 的槽位，
> 于是"换主题只换色相"这个说法在这里是可执行的：改 tone 的槽位表即可，几何一行不动。
>
> **参照素材的版权边界**（读之前先看这条）：参照图与解包素材只在本地工作区
> （`external/terraria-ref/`），**不入库、不进构建、不得再分发**；
> 本仓发布的只有"用自己色板重新生成的图"（§六）。

## 一、几何：两套边带语法 / 基本单位 u

**基本单位 `u = 3px` = 1080p 下一个 3D 像素块**。3D 侧由
`PixelationRendererFeature` 渲进 640×360 低分 RT 再最近邻放大回 1920×1080，
一个块 = 1080÷360 = 3 屏幕像素；UI 画布是全分辨率（1080p 下 1:1），
于是 **UI 的 u 与 3D 的块 1:1 对齐**（创始人 2026-09-22 要求）。这条对齐是**判据**不是约定：
生成器 `Verify()` 会读两档 URP 渲染器资产里的 `renderHeightPixels` 反算块大小并断言相等——
改 RT 档而不同步改 `PixelSkin.Unit`（并重烘焙）会直接红灯。
（对齐在 1080p 与 4K 下是整倍数；1440p 画布缩放是 1.5× 分数倍，像素件会有半格错位——
已知限制，随"像素完美画布"课题另裁。）

**参照里有互不相同的两套语法，别互相推广**（第一版把它们混成一套，创始人一眼判"和我给的界面
不一样"）：

```
条槽 Track（金框血条语法，实测 ref-bars-life-mana.png）
  ① 外环    S2（受光侧）/ S1（背光侧）    u
  ② 斜面    S4 / S3                       u
  ③ 内暗线  S2 / S1（与外环同色）          u
  ④ 槽底    Floor（比最暗档再压一档）      剩余（九宫格拉伸区）

面板/按钮 Plate（工具对话框语法，实测 ref-pixel-tool-dialog.png）
  ① 描边    INK（近黑，四周同色）          u
  ② 唇边    S4（**只在本状态的受光侧**）    u
  ③ 脸      S3（平涂）                    剩余（九宫格拉伸区）
```

由参照表直接读出的规则：

1. **条槽的"内暗线"与同侧外环同色**（测量原文：外环 `#54481E` / 内暗线 `#54481E`）。
   这两道是"外圈把块勒住 + 内圈把面压下去"的同一条线。**这条只对 Track 成立**——
   对话框的面板/按钮没有内暗线，多画一道就读成"双层相框"。
2. **面板/按钮是近黑单描边**：参照实测描边 ≈ `#000`–`#0A0E12`、脸 `#404448`、
   唇边 `#5F6367`（受光侧才有一道）。**背光侧没有唇边**（实测按钮底缘就是一条更深的描边）。
3. **光永远来自左上**：上=左、下=右，唇边只出现在受光侧。
   〔已知偏差〕参照里顶边比左边还亮一档，本波次不拆（要拆就得给每个 tone 第 5 档明暗），
   登记为复核项（§八）。
4. **外环（描边）是同心环**：必须是一条**闭合圈**（沿切角斜线走）。按"上下横贯 + 左右补边"画
   会把两侧外环截断、四角不闭合——走查记录见 §一.1 与生成器 `CreateTexture` 方法头；
   判据 = 外环 8 连通 1 段且无端点。

### 一.1 三层带是**同心环**，不是"上下横贯 + 左右补边"

判据按**离最近边界的距离**分层（`layer = min(dx, dy) / u`，`dx/dy` = 到左右/上下边界的距离）：
`0 = 外环 · 1 = 斜面 · 2 = 内暗线 · ≥3 = 内容`；受光/背光按"离哪条边更近"定，
**到两边等距的那个角像素归竖直边**。于是外环是一条**闭合圈**（沿切角斜线走），斜面与内暗线是它里面两条更小的闭合圈。

> **这一条是走查改出来的**。第一版把三层带画成"上下横贯 + 左右补边"（依据是实测的**平铺中段件**
> `HP_Panel_Middle.png`——它顶部 6 行确实整幅宽度都是顶边带，但**它根本没有左右带**，
> 那段测量无法决定角上谁赢）。画出来后水平带的**斜面**一直顶到左右外缘，
> 把两侧外环在那 2px 上截断——**四个角的轮廓线不闭合**，创始人看图直接指出"4 角不是连着的"。
> 参照的面板件 `Achievement_InnerPanelTop`（6×22）正是同心结构：竖列 `x=0` 的外环通到顶行，
> 顶行的亮带只铺在 `x=1..4`（内宽），不外扩到竖列里去。
>
> **判据已固化**：外环像素必须 8 连通为 **1 段**、且**无端点**（每个外环像素至少 2 个外环邻居）
> ——生成器自检与契约测试各查一遍。人眼能看出"断"，只有变成这条可复算的判据才拦得住回归。

### 一.2 切角按**整格**切

判据 `floor(dx/u) + floor(dy/u) < 深度`（默认深度 **1 格**，即每个角切掉一个 `u×u` 的格）。
把到边界的距离**量化到基本单位**再相加，切掉的永远是整格，45° 折线落在 u 网格上。

> 同一次走查的第二个坑：按**像素**判（不量化）会得到 `u → u-1 → 0` 的**离格**台阶——
> 几何上是 45° 斜边，但在 u 体系里既不平也不斜，读成"角被啃了一口"。
>
> 深度为什么取 1 格：两处实测摆在一起就清楚了——参照的**面板**角切掉的是**一个格子**
> → 换算到本体系 = 1 格；参照的**条状件端头**是 2 格的阶梯，但那是"条的斜切端"，不是面板角。
> 试过 2 格：整块看起来开始"变圆"，与 chunky 的取向相抵。
>
> 改 `ChamferDepthUnits` 一个常量即全族生效：`2` = 条状件的斜切端档，`0` = 方角。

**为什么要切角**：三件参照里两件有切角（条状件斜端、成就内板切角），一件方角
（`ButtonBacking` 22×22）。像素浮雕件的方角在深色底上会读成"没做完"，故取有切角。

### 一.3 内部（Piece）：凸起块 / 凹槽 / 页签

| 结构 | 内部色 | 用在哪 |
| --- | --- | --- |
| `Plate` 凸起块 | `S3`（同色相中间档，**平涂**、无渐变） | 面板 / 按钮 / 列表行 / 标题条 |
| `Track` 凹槽 | `Floor`（比最暗档再压一档） | 条状件的空槽底（血条/施法条/进度条），填充件画在它上面 |
| `Tab` 页签 | `S3`（同 Plate） | 页签：**底边无带**（border 下=0），底边与宿主面板顶边贴合连成一体 |

`Floor` 从 `S1`（而非 `S2`）再压：否则底内暗线与槽底同色，**槽内那道线等于没画**。
〔已知偏差〕实测槽底贴着一道 2px 次生亮带（`#801034` 压 `#551B1C`）；本实现**有意压平成单色**
（满格时它整条被填充盖住、半格时才露 2px），登记为复核项（§八）。

**页签的画法**：到**下**边界的距离不参与分层（`dy` 只算上边界），左右带一路通到底、
底边是平底；切角只切**上**两角（贴面板的那条边要直）。判据 = 中列最下 3u 行必须同色（平底），
外环闭合检查用"底边开放"口径（U 形、1 段、0 端点）。
〔已否决〕曾在 Frame 四角钉过黄铜铆钉——参照里没有这个元素，随"和参照不一样"的走查一并去除；
不加装饰是这套语言的一部分（面板靠描边与唇边立起来，不靠点缀）。

### 一.4 填充件（Fill）

上 `u` 亮沿 / 中 `4u` 主体 / 下 `u` 暗沿（贴图 6u×6u，与实测 `HP_Fill.png` 逐段同构），
**右端 `u` 列整列提亮**（前缘）——那是"条在生长"唯一的视觉锚点：
没有它，半格的条两端一样暗，读不出方向。左端**不切片**（尾端要硬边，跟槽的起点贴合）。

### 一.5 语义件（Singles）：只有一种画法的小件

| 件 | 尺寸 / 切片 | 画法 | 色 |
| --- | --- | --- | --- |
| `Ring` 选人圈 | `8u×8u`，border `u` 四边 | 1u 厚方环（同款切角），外 1px 亮、内侧主色 | `GLOW_WARM` 往白提 30% / `GLOW_WARM` |
| `Focus` 焦点框 | 同上 | 同 Ring 画法 | `HERO_BLUE` / 往白提 45% |
| `Pip` 位点 | `6u×6u`，不切片 | u 格菱形（45° 对角线推到底）；on = 左上受光三档宝石 + 顶端 1px 白高光；off = **中心对称**空插座（均色暗菱 + 中心 2×2 格压深） | on：SAND_LIGHT/BRASS/WOOD_DARK/WHITE_HOT；off：UI_BEVEL_LO/压深档 |
| `Sep` 分隔线 | `4u×2u`（水平）切 `(0,u,0,u)` | 蚀刻槽线：暗 `u` 压亮 `u`（暗贴上/左）——凹槽读法，与面板的凸浮雕**互补**（同一光模型的一体两面） | UI_BEVEL_LO 压墨 / UI_PANEL 提白 |
| `Shadow` 投影 | 与 Plate 同尺寸同切片 | Plate 同款轮廓（含切角）的**纯 INK 剪影**；装配垫在面板下、按 `ShadowOffset=(1u,-1u)` 右下错开——硬边无渐变的错位剪影是像素 UI 表达层次的标准件 | INK 单色 |

环/位点/投影只有一族一色板，不走 tone 表；锁板判据按各族色表查。

## 二、令牌：色阶怎么从调色板派生

### 二.1 tone 表（7 个色身份）

每个 tone = 一条同色相的 4 档明暗阶梯，三档取自板内槽位，第四档派生：

| tone | S4 亮 | S3 中（= 块底色） | S2 暗 | S1 更深 | 用途 |
| --- | --- | --- | --- | --- | --- |
| `Frame` | `#63686F` | `#3B4046` | `#23282D` | `#191A1C` | 主面板（中性灰，对齐参照对话框的灰调） |
| `Dense` | `#3B4046` | `#23282D` | `#191A1C` | `#141313` | 内容片 / 列表行（比面板明显暗一档） |
| `Light` | `#F0F0F0` | `#E8D5A3` | `#999999` | `#5A5958` | 暖白牌 / 羊皮纸标题板 |
| `Sea` | `#4DA6D9` | `#2B7AB8` | `#1A4F7A` | `#143047` | 小地图 / 海图 |
| `Primary` | `#E8D5A3` | `#C9A227` | `#6B4C28` | `#412E1A` | 主行动点（黄铜） |
| `Danger` | `#FF3A29` | `#CC2222` | `#2E2A44` | `#1F1C29` | 危险动作 |
| `Warn` | `#FFD98A` | `#E8A33D` | `#7A5C34` | `#493720` | 警告 / 冷却 |

槽位对应关系（代码里只写槽位 id，不写 hex）：`Frame` = UI_BEVEL_HI / UI_PANEL / UI_BEVEL_LO；
`Dense` = 面板整体低一档；`Light` = WHITE_HOT / SAND_LIGHT / NEUTRAL_LIGHT；
`Sea` = SEA_SHALLOW / SEA_MID / SEA_DEEP；`Primary` = SAND_LIGHT / BRASS / WOOD_DARK；
`Danger` = HERO_RED / UI_DANGER / SHADOW_DEEP；`Warn` = GLOW_WARM / UI_WARN / SHADOW_WARM。

### 二.2 两条派生规则（只有这两条）

- `S1 = mix(S2, INK, 0.45)` —— 板内 UI 族只有三档，第四档往本仓统一墨色 `INK` 压一步。
- `Floor = mix(S1, INK, 0.5)` —— 凹槽底。

按 **sRGB（Gamma 直存）逐通道线性混合**，与 `SceneArtPalette` 同口径；
OkLCH 那套（`ArtPaletteMath`）是**量化**用的，不要拿到这里来"更正确"。

### 二.3 为什么要有"相邻档分得开"这条判据（走查事故记录）

第一版把 `Light` 的中间档取成 `SAIL_CANVAS`、`Danger` 的暗档取 `HERO_RED_DEEP`，
四档**严格单调**（单调性判据放行），但：

- `Light`：`#F0F0F0` 与 `#F5E8C8` 亮度只差 7.6（比值 0.97）；
- `Danger`：`#CC2222` 与 `#6B3352` 比值 0.93。

**单调 ≠ 看得出来**。参照条实测的相邻档亮度比全部落在 **0.55~0.74**，于是本规范加了
判据 `相邻档亮度比 ≤ 0.90`（`RampStepRatio`）：超过就是两档几乎同亮，斜面读不出来、等于没做浮雕。
用**比值**而不是绝对差，是因为亮度感知是相对的：深色档差 10 个单位是一大步，浅色档差 10 个单位几乎看不见。
上述两个 tone 因此换成了 `SAND_LIGHT` 与 `SHADOW_DEEP`。

### 二.4 填充色（5 种）

主体与暗沿取槽位，亮沿**派生**（`mix(主体, WHITE_HOT, 0.55)`；中性档直接取 `WHITE_HOT`）：

| 填充 | 亮沿 | 主体 | 暗沿 | 前缘 |
| --- | --- | --- | --- | --- |
| `Red`（血量/红队） | `#F79E96` | `#FF3A29` | `#6B3352` | `#FD5648` |
| `Blue`（魔法/蓝队） | `#9BB2F7` | `#3366FF` | `#345085` | `#507BFD` |
| `Warn`（冷却/蓄力） | `#ECCD9F` | `#E8A33D` | `#7A5C34` | `#E9AF58` |
| `Sea`（水量/航程） | `#97BBD7` | `#2B7AB8` | `#1A4F7A` | `#498CC1` |
| `Neutral`（中性进度） | `#F0F0F0` | `#C4A76A` | `#8B7355` | `#D0BB90` |

亮沿为什么要派生而不是加槽位：实测的亮沿（`#FFA68B`）是主体往白里提的暖调，板里没有这一档，
**硬加槽位是拿"条状件专用色"去占全局板位**。
〔已知偏差〕实测亮沿的青通道抬得比蓝通道多（提亮偏黄），本规则给的是中性提亮；
差异只在"提亮是否偏黄"这一档，登记为复核项（§八）。

## 三、状态：常态 / 悬停 / 按压

| 状态 | 画法 | 承担方 |
| --- | --- | --- |
| 常态 | 上/左受光 | 贴图 `Pixel_Plate_<Tone>` |
| 悬停 | **整条色阶上抬一档**：S1~S3 与 Floor 各向亮侧邻档混 25%（`HoverLift`），S4（受光外环）不动——轮廓保持锐利、内部"点亮" | 贴图 `Pixel_Plate_<Tone>_Hover` |
| 按压 | **高光/阴影整组对调**（创始人裁决，不用 scale），"凸"读成"凹" | 贴图 `Pixel_Plate_<Tone>_Pressed` |
| 按压位移 | 右下 1px（`PixelSkin.PressOffset`），**不进贴图**（进了九宫格切片就错位） | 装配侧（`UiPressSink` 平移模式） |
| 失效 | 不烘图：CanvasGroup alpha ≈ 0.55（灰化靠透明度，不靠乘色） | 装配侧 |

- 悬停就是当初三选一里"hover = 换一档明暗的整套贴图"那条的**派生实现**：
  不用多造 tone（tone 阶梯升一档会改变色相身份），也不用乘色（必出板外色）。
  抬升后的 5 档自成一个锁板集合，判据照锁。
  代价是相邻档距压到 75%——悬停阶梯只查**单调**与**抬升可见**，不查档距
  （档距判据服务的是常态浮雕可读性）。
- 装配侧状态机制：UGUI `Button.transition = SpriteSwap`
  （highlighted/selected = Hover，pressed = Pressed）。ColorBlock 乘法**退役**——
  乘色会破坏烘焙死的明暗关系，这是本族与玻璃族的分水岭。
- 常态块的按压贴图里，顶边斜面会与块底同色（因为底色就是 `S3`）——**这是对的**：
  高光已移到右下，顶面读作"压平"。判据对按压态只查"明暗是否反向"，不要求顶边仍有亮带。

## 四、九宫格契约（装配侧必须遵守）

### 四.1 尺寸与切片

| 件 | 贴图尺寸 | 切片边框 `(left, bottom, right, top)` | 最小可渲染 | 违反后果 |
| --- | --- | --- | --- | --- |
| `Plate` / `Track` | 12u×12u（36×36） | `(4u, 4u, 4u, 4u)` | **8u = 24px**（`PlateMinRender`） | 角切进内容区 |
| `Tab` | 12u×12u | `(4u, 0, 4u, 4u)` | 宽 8u / 高 4u | 底边不再平底 |
| `Fill` | 6u×6u（18×18） | `(0, u, u, u)` | 高 **2u = 6px** | 亮/暗沿被压没；要读出主体层建议 ≥ 4u |
| `Ring` / `Focus` | 8u×8u（24×24） | `(u, u, u, u)` | 2u | 环被压断 |
| `Pip` | 6u×6u | 不切片（原生渲染） | — | 拉伸会破坏菱形 |
| `Sep_H` / `Sep_V` | 4u×2u / 2u×4u | 长轴 `(0,u,0,u)` / 短轴 `(u,0,u,0)` | 粗 2u | — |
| `Shadow` | 同 Plate | 同 Plate | 8u | — |

装配侧纪律：

1. **尺寸不低于最小可渲染值**（九宫格只保证四角四边不拉伸，中心区均匀缩放）。
2. **Filter Mode 必须是 Point**（生成器已把导入设置写死，别在 Inspector 手改）。
3. **可见包边件的 width/height 取 u 的整数倍，anchoredPosition 至少取整**——
   分数像素会让 u 宽的带忽厚忽薄；**像素件禁止 `Image.color` 乘色**（icon/文字不受限）。
4. 文字色取 `PixelSkin.TextColorOn(tone)`（浅底给墨字、深底给本 tone 亮档），
   别在装配侧手挑颜色。

### 四.2 取用：运行时图集 `PixelSkin`（装配侧唯一入口）

- 生成器在 Editor 程序集（烘焙器岗位），运行时与动态 UI（头顶血条等）经
  **`Assets/Resources/UI/PixelSkin.asset`**（`PixelSkinAsset`）取图：烘焙末步自动生成，
  内含 tone×state 整网格 + 全部语义件 + tone 取色令牌（亮/中/暗、墨、暖白）。
- 运行时 API：`PixelSkin.Plate/Track/Tab/Fill/Ring/Focus/Pip/Separator/ShadowSprite/
  LightOf/MidOf/DarkOf/Ink/PaperWhite/TextColorOn`，另有常量 `Unit` / `PlateBorder` /
  `PlateMinRender` / `PressOffset` / `ShadowOffset`。
- Editor 装配（`BattleHudBuilder` 等）也走同一 API（Resources 在编辑器同样可载），
  Image 直接持有 Sprite 引用、场景序列化，播放器零加载。
- **槽位语义映射**（手绘槽 → 像素件）：`panel`→`Plate(Frame)+Shadow`；
  `panel_light`→`Plate(Light)+Shadow`；Dark 面板→`Plate(Dense)`；`cell`→`Plate(Dense)`
  （选中态 = 外包 `Focus` 环，不再乘色）；`groove`→`Track(Frame)`；`progress_bg`→`Track`；
  `fill/progress_fill`→`Fill`（血 Red / 蓝 Blue / 冷却 Warn / 进度 Neutral）；
  `btn_normal`→`Plate(Light)`、`btn_primary`→`Plate(Primary)`、`danger`→`Plate(Danger)`、
  `accent`→`Plate(Warn)`、`ink`→`Plate(Dense)`；`tab_selected`→`Tab(Light)`、
  未选中→`Tab(Dense)`；`ring`→`Ring`；`pip`→`Pip(on)`；`sep_h/sep_v`→`Separator`。

## 五、判据：怎么证明它合格

三层，**两套独立实现**（生成器自检 / 契约测试各一份，两边都过才算数）：

| 层 | 判什么 | 实现 |
| --- | --- | --- |
| 生成器自检 | 阶梯单调且分得开、悬停单调且抬升可见、**盘上资产与生成器输出逐像素一致**（改参数忘重烘焙会被抓）、色带边界落 u 整数倍、透明像素数 = 该族已知形状、外环 1 段闭合圈无端点（页签按底边开放口径）、页签底边平底、**锁板**（每个不透明像素都在该族色表内）、**u ↔ 3D 像素块对齐**（读 URP 渲染器资产反算）、图集满格无空槽 | `BeveledPixelSpriteBuilder.Verify()` |
| 契约测试 | 目标表逐张：资产在、尺寸对、切片对、PPU/Point 对、导入五项合规；**直接读盘上 PNG** 量色带、按族复算透明形状（切角/环/菱形）、外环闭合、"光来自左上"（按压态反向）、内暗线 = 同侧外环、页签平底、投影单色/分隔线两色/暗位点中心对称；**图集满格 + PixelSkin 全入口非空** | `Assets/Art/Tests/BeveledPixelSkinTests.cs` |
| 导入设置 | Point / mip off / Uncompressed / sRGB on / alphaIsTransparency **关**（+ Sprite 四项） | `PixelArtTextureRules.CheckSprite` |

**核心判据两条**：

1. **色带边界必须落在 u 的整数倍上**（出现非整带宽即参数写错）——直接来自
   [参照 README](../../images/ui-pixel-ref/README.md) §六 的判据口径；
2. **外环必须是 1 段闭合圈且无端点**（8 连通分量数 = 1、每个外环像素 ≥2 个外环邻居）
   ——把"四角的轮廓线要连着"变成可复算的数字，见 §一.1 的走查记录。

## 七、为什么 UI 九宫格件不并进像素纹理的约定目录

像素纹理的约定域是 `Assets/Art/Textures/Pixel/**`，域内一律按
[像素纹理导入规范](像素纹理导入规范.md) §3 的五项导入，**其中包括 `textureType = Default`**。
UI 九宫格件必须是 **`Sprite`**（唯一能带 `spriteBorder` 的类型）：

> 并进域内的后果：后处理器把它们改回 Default → `LoadAssetAtPath<Sprite>` 返回 null →
> 切片边框消失 → UGUI 拿到空 sprite → **画面退化成白块但控制台一声不响**。
> 这正是本项目定义过的"改了看不出问题"型事故。

所以本族自成一个目录 `Assets/Art/Sprites/UI/Pixel/`，**共用同一份五项值**
（`PixelArtTextureRules.ApplySprite` / `CheckSprite`，规格只有一处），
只在 Sprite 专有项上不同（`textureType` / `spriteImportMode` / `PPU 100` / `spriteBorder` / `wrapMode Clamp`）。
`alphaIsTransparency` 必须关还多一个具体后果：切开后的透明像素若被 Unity 膨胀（dilate），
切角边缘会带出板外色。
