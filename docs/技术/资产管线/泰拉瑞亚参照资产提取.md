## 二、XNB 格式：实测出来的字段布局

**头 10 字节**：`"XNB"` + 平台字符（`w`=Windows）+ 版本（5）+ 标志位 + 磁盘大小（int32 LE）。
标志位 `0x80` = 已压缩（本目录下所有文件都是）。

**压缩档在头之后多 4 字节**：`int32 LE` = **解压后总大小**；LZX 流从 **偏移 14** 起。

**解压后的内容布局**（实测全部可解文件一致）：

```
[7bit 小端 varint : typeReaderCount]
[7bit 小端 varint : 名长][ASCII 名]        ← 全限定名，如
                                            "Microsoft.Xna.Framework.Content.Texture2DReader,
                                             Microsoft.Xna.Framework.Graphics, Version=4.0.0.0, …"
[int32 : reader 版本]
[2 字节]                                    ← 实测固定存在，含义未定（值如 00 01）
[int32 : 表面格式]                          ← 0 = Color（RGBA8888）
[int32 : 宽][int32 : 高][int32 : mip 数]
[每个 mip: int32 大小]
[mip0 数据…]
```

**两个容易踩的坑（都实际卡了很久）**：

1. **7 位变长整数是小端**（.NET `BinaryReader.Read7BitEncodedInt` 口径：低 7 位在前，续位在最高位）。
   按"大端 7 位"解会让后面所有字段整体错位，而**前几字节看起来仍然像文本**，极难发现。
2. **reader 版本之后那 2 字节必须先跳掉**再读表面格式；不跳的话 `format` 会读成 256、
   宽高读成天文数字。

**自校验判据（强烈建议保留）**：`mip0 的 int32 大小` 必须**精确等于**内容剩余长度。
实测 72×72 RGBA 的边框：`177 + 20736 == 20913` ✓。不自校验就会静默解出垃圾。

## 三、用什么解 LZX（关键选型）

- 游戏本体的 XNB 用 **LZX** 压缩（`libmspack` 的 `lzxd` 是权威实现，且 `pylibmspack` 的 wheel 里
  带着完整源码 `vendor/libmspack_0.11.orig.tar.gz`，本机又有 MinGW gcc，**可以自己编译**）。
  **但 CAB 口径的 `lzxd` 解不了**：它按 LZX 规范先读 E8 转换头，而 XNB 的流里没有那一位，
  一跳就落到非法块类型。
- **能解的是 MonoGame 内置的 `MonoGame.Framework.Utilities.LzxDecoderStream`**（XNA 解码器的移植，
  内部类，反射调用）：`new LzxDecoderStream(stream /*已定位到偏移 14*/, 解压后大小, windowBits: 16)`。
  NuGet 可达，`dotnet add package MonoGame.Framework.DesktopGL` 即可拿到。
- 解不了的 4 个文件就是在这个解码器里报 `Decompression failed`；换 windowBits 15/17/18 无效。
  **未查明的方向**：XNA 压缩器可能在超过某个长度后重置窗口（reset interval），
  而 `LzxDecoderStream` 不暴露该参数。要拿下成就图标总表，下一步应从这里查。

## 四、怎么复现

```bash
cd external/xnb-export
dotnet new console -o xnb2rgba && cd xnb2rgba
dotnet add package MonoGame.Framework.DesktopGL          # 拿到 LzxDecoderStream
# Program.cs：按 §二 的布局解析；LZX 走反射调 LzxDecoderStream
python ../export.py achievements resources chrome          # 批量导出到 external/terraria-ref/
```

`export.py` 里 `SETS` 就是"导出哪些件"的清单，加一行即可扩。
失败件会逐条打印原因，不会静默跳过。
