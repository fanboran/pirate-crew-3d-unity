# 调研 · 调色板量化与纹素密度（Palette & Texel Density）

> **这份文档是什么**：像素纹理资产管线（[像素纹理资产管线.md](像素纹理资产管线.md)）的技术调研依据——锁板映射的色彩空间选型、量化+抖动方式、纹素密度校验实现、导入格式裁决与行业先例。
> **调研时间**：2026-09-21，「已核」来源均实际抓取；访谈类如无技术披露则如实降级为观感佐证。
> **标注约定**：沿用 [美术风格指南](../../设计/美术风格指南.md) §0；「采纳」结论均【AI 提案】，随 M-B/M-C 落地转正。

## 1. 锁板映射的色彩空间：OkLab，不用 gamma sRGB 欧氏距离

- **OkLab**（Björn Ottosson【已核】）：感知均匀、明度/彩度/色相正交解耦、优于 CIELAB/CIELUV；实现仅「3×3 矩阵 → LMS → cbrt → 3×3 矩阵」，解析可逆、数值稳定；**作者公开 XYZ↔Oklab 三位小数测试表，可直接做量化脚本的逐字节回归单测**。
- **RGB 空间匹配的系统性偏色实证**（Evil Martians【已核】）：浏览器在 RGB 里 clip 蓝域颜色明显偏色，规范要求在 OKLCH 里降彩度保色相——「在 RGB 空间做最近邻/截断会系统性偏色」的直接证据。
- **工业先例**：okolors（Rust）【已核】用 **Oklab 空间的 k-means** 生成调色板，并提供 `lightness_weight` 明度加权旋钮；ImageMagick【已核】自认其 `-remap` 仅在 RGB 空间做最近邻（内建偏色风险）。

本仓规格【AI 提案】：
1. `srgb8 → linear → LMS → Oklab`，转换用 Ottosson 公开矩阵（2021 修订版），官方测试表做回归单测；
2. 距离 = 加权平方欧氏 `d = ΔL² + w·(Δa² + Δb²)`，`w` 从 1 起步，「灰阶发脏」时把 L 权重提到 1.5~2（okolors 同思路）；
3. 板只有 32~64 色 ⇒ **暴力 O(N·64) 纯函数匹配**，不上 kd-tree/LUT——无数据结构差异 = 跨机器逐字节一致的最低风险路径。

## 2. 量化 + 抖动：ordered-only，禁误差扩散

- **任意固定板 + ordered 抖动的正解是 Yliluoma 混合模型**（bisqwit【已核全文】）：Bayer 类 ordered 抖动默认调色板均匀分布，对任意板不成立；解法是**为每像素找「最佳两个板色 + 混合比」，Bayer 阈值决定该像素画哪个**；误差度量作者实测从 RGB → RGBL → CIELAB/CIEDE2000 逐步演进（结果依图像而定）；**混合必须在线性光内做（γ≈2.2），否则抖动区偏亮**；**输出是 (像素值, x, y) 的纯函数 ⇒ 天然确定性 + 动画安全**；8×8 矩阵是性价比甜点；64 色板两两组合 ≈2k 项，预计算完全可负担。
- **误差扩散（Floyd–Steinberg/Riemersma）三项否决理由**（ImageMagick usage【已核】+ Surma Ditherpunk【已核】）：① 顺序敏感——输入改一个像素，其后图案全变（**像素级回归 diff 的大敌**），序列帧会「抖动噪声翻滚」；② 32~64 色小板上有「斑点」污染实录（蓝渐变里冒白点）；③ 本质顺序过程，不好并行也不确定。
- **Bayer 偏亮坑**（Surma【已核】）：直接用 Bayer 阈值整体偏亮——中点归一化/翻转矩阵修正（与[调研-赛璐璐](../渲染/调研-赛璐璐与色带.md) §4 同一坑，两个域共用一份 4×4/8×8 常量与归一化口径）。
- **本仓默认 `dither = NONE`**【提案】：工作流是「手绘/烘焙时已按板内色作画」，锁板映射误差应 ≈0；flat 像素纹理上抖动噪声在点采样下会变成**永久噪点**。抖动只作为「渐变面/大面积材质」的按材质开关。

**顺序铁律**：先几何/bake 低分辨率直出（32/64/128px，不做缩放）→ 量化映射 → 抖动发生在映射决策内（Yliluoma 式）。**绝不许**「高分辨率抖动后缩小」或「对已抖动图再量化」（ImageMagick：再抖动严重劣化）。

**确定性收尾**：固定 PNG 编码参数（Pillow 默认不写时间块，锁 `compress_level`）；k-means 只允许出现在「一次性生成板」阶段且固定 `random_state`（scikit-learn 文档【已核】：int 入参使随机性确定）；**锁板之后整条量化链零随机数**；量化前先校验输入文件哈希（改动敏感教训）。

## 3. 调色板本身的设计与生态

- **板内结构**【提案】：用 **OkLCH 明度/彩度阶梯**生成 32~64 色（Evil Martians 的锚点+公式方法）——保证板内有均匀明度梯队（抖动时明暗过渡干净），色相按 [美术风格指南](../../设计/美术风格指南.md) §3.2 加勒比档案定档。
- **格式与获取**（Lospec【已核】）：4400+ 现成板；下载格式 PNG/PAL/ASE/TXT/GPL/HEX；**API `https://lospec.com/palette-list/{slug}.json`**（字段 `name/author/colors[]`，hex 无 #）——脚本走 JSON 端点最稳，GPL 纯文本可自写解析。板文件入库格式三选一（png/gpl/json），脚本可读即可（资产篇 §5 维持）。
- 生成算法先例：pngquant/libimagequant【已核】= 改良 Median Cut（按方差选盒）+ k-means 精修——验证「Median Cut 起步 + k-means 精修」是业界标准，但其面向逐图生成、不承诺确定性，不进我们的确定性链路；NeuQuant【已核】64~256 色区、事实上确定性（素数驱动学习序列），但我们锁板不需要逐图生成，了解即可。

## 4. 纹素密度：32px/m 是「无人区」，护栏自建

- **业界 regime 对比**（Polycount wiki【已核】）：通用 PBR 资产 ≈256px/m、英雄资产 ≈512px/m，且要求全项目统一——本仓 **32px/m 比通用流程低一个数量级，没有公开像素风项目披露过此值**（FTK/Tunic/Octopath/Dead Cells 均无）。规格本身就是创新点，护栏必须自建。
- **密度约束的真实重点**：不是「够不够密」而是「**处处严格相等 + texel 方正**」——点采样下非方形 texel 比密度误差更显眼。
- **校验公式**【提案，Blender 无头脚本，可进 CI】：
  1. 每个面/UV 壳：`density = (uv_area × tex_size) / world_area`（world_area 用含缩放的多边形面积和，负缩放取绝对值；uv_area 用鞋带公式）；
  2. 断言全项目 `density ∈ 32px/m ± 0.5%`；
  3. 第二断言：每面 `UV 边长/世界边长` 的 Jacobian 长短轴比 < 1.01（各向同性，防「密度对了但 texel 是长方形」）。
- **对照工具**：Texel Density Checker（Blender addon）【已核】可把密度烘成顶点色人工巡检；无头管线不依赖 GUI addon，抄算法自写（32px/m = 0.32px/cm 可直接当目标值）。
- **内部结构线**按密度反推：2px 线 = 6.25cm 世界宽；线宽恒为 2 texel 由各向同性断言保证。

## 5. 导入格式裁决：BC7 除名，固定不压缩

- **BC7 的本质**（Microsoft Learn【已核】）：固定 16 字节/4×4 texel 块，每块存**两个端点连线的插值调色板**——解码色落在 {0,9,…,64}/64 等离散比例上，**几乎必然不在 32~64 色全局板里**。
- 推论【提案·修正资产篇 §3】：小尺寸调色板纹理（64px² 的 4×4 块只有 16 像素、块内常只有 2~3 色）压缩收益极小而「破板」风险 100%，且破坏字节级回归 diff——**「不压缩或 BC7」二选一改为固定 Uncompressed(RGBA32)**；128px 未压缩仅 64KB/张，显存无压力。BC7 仅在显存压力实测超预算且接受破板时重议。
- mip 维持关（等距固定机位 minification 有限；**mip 平均色同样是板外色**，第二重破板）+ FilterMode.Point（官方原文 "blocky up close"）+ sRGB 勾选——官方参数依据均【已核】（Unity 2022.3 TextureImporter 文档组）。
- **闪烁边界情形**：themaister 伪带限过滤文【已核】指出 NEAREST 在 3D 曲面上「运动中闪烁」，等距固定机位 + 低纹素密度下屏幕:纹素比近似恒定、风险可控；闪烁时在 shader 内加 2x2 伪带限（一次 bilinear fetch 的低成本版），不重开 mip。

## 6. Blender 侧与行业先例

- **无头烘焙**（Blender 手册 Render Baking【已核】）：Diffuse → **仅勾 Color**、1 sample（纯色传递无光照噪声，天然确定性）、固定 Margin；bake 写入线性值，导出 PNG **固定视图变换（Standard）与 colorspace 标签**，否则量化输入随色彩管理漂移。
- **FBX 导出**（Blender 手册【已核】）：Geometry → Smoothing: **"Normals Only"** 保证自定义分裂法线（平滑法线烘顶点色的前置）不丢；Apply Scalings: FBX Units Scale + Forward -Y/Up Z；密度校验必须在 Blender 脚本层做（FBX 只有 UV，无密度概念）。
- **行业先例**：Dead Cells（Game Developer 深度文，标题/摘要级核实）——「动画 timing 成立后，**一次且仅一次**通过 3D 管线渲染」固化像素资产，与本仓「bake→量化→png」离线固化同构，是自研量化工具的最强先例；Octopath HD-2D（Unreal 官方 Spotlight，引文级核实）证明「3D 几何 + 点采样像素纹理」在商业大作成立（他们用 DoF 糊掉采样瑕疵，我们没有这个便利，更依赖 §5 的纪律）。

## 7. 对资产篇的回写结论汇总

采纳【AI 提案】：Oklab 加权距离暴力锁板映射（官方测试表做回归）；Yliluoma 两板色混合模型做按材质抖动开关、**默认 dither=NONE**；误差扩散全线禁用；PNG 编码参数与输入哈希校验入确定性纪律；纹素密度校验公式（±0.5% + Jacobian 各向同性断言）进 Blender 无头脚本；压缩改固定 Uncompressed(RGBA32)、BC7 除名；Lospec JSON API 作为板素材获取通道。
维持：POT 尺寸表、Point/mip off、结构线入图、bake→量化→png 主链。
