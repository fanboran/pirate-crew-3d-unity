# M4：大海域世界化——语义地图重设计 / 操控手感 / 精细资产 / 仿真海面

> **本文是什么**：M4 里程碑的总设计契约。用户 2026-09-17 口述需求的设计落档：
> 地图按语义重做（**不再参考原版布局与场景数量**）、地图尺度大幅放大、操控手感参考《战舰世界》、
> 角色落地翻滚（按 Flash 逆向实现）、Blender 统一风格参数批量建模（多 subagent 并行）、
> 大号地形站立面平直专门优化、不可达区域放远景装饰、仿真化海面（可引入开源实现，不考虑性能）。
>
> **裁决与提案的区分**：§0 各条为【用户裁决】；地图集内容、间距数值、镜头档位等具体取值为
> 【AI 提案/待定】，落地后以实测与用户验收为准。本文只写「是什么/怎么设计/为什么」，变更过程看提交历史。

---

## 0. 用户裁决（2026-09-17，优先级高于既有关卡设计规则）

1. **语义建图**：地图按「这片海是什么地方」的语义设计，不参考原版 33 关的布局、母题配比、场景数量。
2. **尺度放大**：此前地图相对角色太小，与双方角色数量不匹配；要有「大世界」感。
3. **操控手感参考《战舰世界》**：重量感、瞄准仪式感、长弧线、镜头呼吸。
4. **落地翻滚**：角色落地后按俯冲惯性翻滚——以 Flash 逆向代码为准确出处（§3）。
5. **资产管线**：Blender 无头管线 + **统一风格参数**批量生产，不同资产类型交不同 subagent 并行；
   各资产保持低多边形，但精细度要求高（不许随手搓）。
6. **站立面平直**：大号地形件必须保证顶面严格平整（专门优化，见 §4.2 manifest 机制）。
7. **连通性硬约束**：地图各区域必须能来回跳过去（跳跃链可达，见 §2.2）。
8. **远景装饰**：不可达区域放装饰物（用户明确鼓励）。
9. **海面仿真**：游戏发生在茫茫大海上，当前水太不仿真；**不用考虑性能**，可以引入开源实现。
10. **角色模型不动**（沿袭既有铁律，AGENTS.md）：船员低模即最终风格，放大的是世界不是角色。

与既有文档的关系：本文在「地图内容」维度**取代**《关卡设计语言-参照游戏全场景分析》的构造约束
（该文仍作为原版事实档案保留）；战斗公式、武器数值仍以《参考游戏逆向-静态》为准。

## 1. 尺度契约（全 M4 的量纲地基）【提案，经用户方向性确认】

| 量 | 取值 | 说明 |
| --- | --- | --- |
| 长度单位 | 1 unit = 1 m | 与现行 `LevelGeometry.PixelsPerUnit=16`（`LevelGeometry.cs:181`）不冲突：新世界地图不再走 px 换算，直接以 unit 撰写 |
| 角色身高 | 1.85（**不变**） | `CrewVisualPrefabBuilder.cs:115`；角色模型铁律 |
| 地图可玩跨度 S | 140–280 u | 约为现行 level_1（100×34）的 2–8 倍；「大世界感」由 §5 无界海面 + 远景环补足，不无限摊平可玩区（回合制节奏保护） |
| 站面高度档 | 0.5 u 的整数倍，≥ +0.25 | 水面 y=-0.4、湿沙带 -0.5~-0.2；岛顶最低 +0.25 保证干站面 |
| 岛间跳跃间距 | 主链 6–12 u，极限 ≤ 13 u | §2.2 连通性预算的来源 |
| 上跳高差 | ≤ +3.5 u；下跳不限 | 满力抛射的射高约束 |
| 双方角色数 | 每方 3–6 名 | 大地图 + 稀疏布防（战舰世界的「少量单位感知大片海」）；原版 14 人上限不适用 |
| 相机 | 近档 8 u / 全景档 clamp(S×0.55, 60, 160) / 手动上限 160 u | 现行 12/30/50（`BattleCameraController.cs:163-178`）按 100 u 图定档，必须随图放大 |
| 远裁剪 / 雾 | far ≥ 2200 u；雾终点 ≥ 900 u（按氛围档覆盖） | 地平线视距配套 |
| 海面域 | 近场细分网格 + 远场环带至地平线（≥ 4000 u） | §5 |

**为什么跨度不直接上 km 级**：回合制 + 弹弓式位移下，单回合位移 ≈ 满力射程 25 u；地图跨度/射程比超过
~12 会让「走过去」占用过多回合，节奏崩坏。「大」由三件事共同构成：可玩区 2–3 倍放大 + 无界海平线 +
远景装饰环。这是提案权衡，实测后可调 S 上限。

## 2. 地图集（8 张，语义设计）【提案：名单与内容；裁决：语义化+数量自由】

### 2.1 设计原则

- **一片海一个故事**：每张图回答「这是片什么海、谁在这里活动过」；地形从叙事长出来，不从母题表长出来。
- **跳跃链是骨架**：先画连通图（岛=节点、跳跃=边），再给岛填形状与陈设；每张图所有出生岛必须同一连通分量。
- **不对称但有公平性**：双方出生群的地形「资源对等」（可用面积/高度/掩体量），形状不必镜像。
- **远景是舞台幕布**：不可达区放 HorizonKit 装饰（远岛/鲸/沉船/云带），让地平线永远有内容（对应美术品控 B-3）。

### 2.2 连通性规则（测试断言，硬约束）

1. 节点 = 站面 box（§4.2 manifest）；边 = 两 box 顶面水平间隙 ≤ 13 u **且** 高差 ≤ +3.5 u（上行方向）。
2. 全图所有承载出生点的 box 必须同连通分量。
3. 每张图至少一条「环线」（两条独立路径往返），避免单桥断点死局（爆炸可毁桥面时保底）。
4. 连通性由纯 C# 测试校验（`WorldMapConnectivityTests`），数据来自 `WorldMapStandables` 转写表。

## 3. 操控手感：落地翻滚 + 战舰世界式瞄准

### 3.1 落地翻滚（忠实转写 Flash 逆向，【裁决：按逆向实现】）

原版无翻滚动画状态机，是三段涌现逻辑（出处见逆向档案）：

| 原版行为 | AS2 出处 | Unity 转写（单位换算） |
| --- | --- | --- |
| 每帧 `rotation += vx×3`（空中+地面滚动同源，恒转） | `Character.as:151-154` | 转速 = 48°/s × 水平速度(u/s)，绕「水平速度×up」轴；换算 1 px/frame = 1.5625 u/s（`LevelGeometry.cs:209`），3°/帧×25fps |
| 落地 `vy *= -0.2`（弹跳不清零） | `Solid.as:263-276`，bounce 默认 0.2（`Solid.as:13`） | 接触法线朝上且 vy<0 时 vy 反向 ×0.2 |
| 落地 `|vx| -= 2` 线性摩擦（逐接触帧） | `Solid.as:269`，friction=2（`Character.as:50`） | 地面线性减速 78.125 u/s²（2 px/帧 ÷ 0.04s × 1.5625） |
| 落地接触 `rotation ×= 0.5`，归一 (-180,180]，<1° 归零 | `Character.as:685-697` | 接地期间每 0.04s 滚动角减半，<1° 归零 |
| 落水 `v×0.8`、vy 钳 ≥1.5 下沉、`rotation += (vx+vy)×4` | `Character.as:164-180` | 落水死亡演出：64°/s×(v合) 旋转下沉 |

**实现口径【提案】**：刚体旋转**保持冻结**（不破坏胶囊对位/AI/瞄准），翻滚作用在**视觉子变换**上——
`RollRules`（纯 C# 静态规则 + 单测）+ `PirateBase` 接地分支驱动。这样忠实还原观感且零物理风险。
抛自己与投掷武器共用同一抛物线系统这一原版事实（`Solid.twang()`，`Solid.as:58-73`）在 Unity 侧已成立，不变。

### 3.2 战舰世界式瞄准【提案：数值待手感实测调参】

| 侧 | 改动 |
| --- | --- |
| 重量感 | 蓄力用平滑包络（起手缓、中段快、临满缓），开火后相机不立刻回收，看弹走完 |
| 瞄准仪式 | **Scope 模式**（Shift 切换）：FOV 60→28 平滑收敛、瞄准灵敏度 ×0.4、弹道预览延长并加落点标记 |
| 力度-镜头耦合 | 蓄力越大相机越拉远（WoWs 转炮时拉镜头的等价物），满力时自然回到全景 |
| 弹道追焦 | 抛出后镜头轻跟弹体（带迟滞），落点震屏已有（`CameraFeelRules.cs:118-127`）保留 |
| 档位 | 相机距离上限 50→160、全景档随地图跨度自适应（§1） |

## 4. 资产管线：统一风格参数 + 多 subagent 分工【裁决：管线与分工方式；提案：槽位扩展与 manifest 格式】

### 4.1 统一风格参数（`tools/blender/scene/style_tokens.py`）

单一事实源，所有 kit 脚本 `import style_tokens`，**禁止在脚本内散写色值/预算**：

- **调色板**：沿袭《美术风格指南》§2.1 三档纪律（亮:中:暗 ≈ 1:0.75:0.5），全部 hex 进 tokens；
- **材质槽**：`Kit_` 前缀语义槽（每件 ≤8 槽）。既有 5 槽（WoodMid/WoodDark/Sail/Brass/Rope，
  `build_scene_kit.py:55-59`）扩展：Sand/Grass/Rock 各三档、Foliage、WetSand、Ember、FarNear/FarFar（远景两级）等；
  Unity 侧 `SceneKitPilotSetup` 槽位表同步扩（未知槽品红兜底纪律不变）；
- **面数预算**：大号地形件 ≤15k tri、道具 ≤3k（多数 ≤600）、远景件 ≤3k；全场景 ≤150k、材质 ≤30 的总预算不变（`美术风格指南.md:507-510`）；
- **网格纪律**：顶面高度 0.5 u 档、顶面平面度误差 ≤ 1e-3、原点约定（地形件=顶面中心；道具=落地接触面中心；船=船长中点水线）；
- **预览渲染**：`view_transform='Standard'`、灰底三灯（沿袭 `build_scene_kit.py:694,734-736`，防 AgX 洗色）；
- **FBX 导出**：统一走 tokens 里的导出参数（`useFileScale=false` 等已踩坑项，`tools/blender/scene/README.md:56-62`）。

### 4.2 站立面平直机制（大号地形专门优化）

- 每个可站立地形件随 FBX 产 `<Asset>.standable.json`：`{"boxes":[{"c":[x,y,z],"s":[sx,sy,sz]}]}`（FBX 本地系、米、Y-up）。
- **Unity 侧碰撞不读网格**：`WorldMapAssetBuilder` 按 manifest 生成 BoxCollider（顶面严格水平、高度精确 0.5 档），
  视觉网格另走烘顶点色/AO 的低模——「视觉自由、碰撞平直」两解耦，这是大号地形的专门优化。
- Blender 侧由 `style_tokens` 提供断言工具：建模参数生成的顶面若偏离 0.5 档 / 平面度超标，脚本直接报错退出。
- manifest 经编辑器步骤转写为 `WorldMapStandables.cs`（沿袭 `LevelTileMaps` 的「外置数据→入库转写」模式），供运行时与无头测试双消费。

### 4.3 分工（文件域互不重叠，Unity 导入由协调者串行收口）

| subagent | 域 | 产出 |
| --- | --- | --- |
| 地形件 | `tools/blender/scene/archipelago/` | 环礁弧/梯田岛/海蚀柱/沙洲/礁阶/红树墩/火山缘/龟甲岛/沉没广场等大件 + manifest |
| 道具 | `tools/blender/scene/props/` | 棕榈/岩块/浮木/桶箱/篝火/炮位/残柱/舵轮/宝堆/草丛等 |

| 远景装饰 | `tools/blender/scene/horizon/` | 远岛剪影/云带/巨鲸/利维坦触手/巨肋拱/远帆船队（无站面、无碰撞） |

## 5. 海面：茫茫大海的仿真化方向【裁决：仿真化+开源可用+不计性能；提案：技术路线】

现状：水面 = 地图外扩 400u 的 Cube + 自写 Gerstner（4 波 + FBM + 128² 波动方程扰法线，
`PirateWater.shader`）——域小、波感弱、无白帽与浪涌层次，是「太不仿真」的主因。

路线（按优先级）：

1. **开源评估**：Crest Ocean System（URP 支持、行业标杆）license 与 Gamma 色空间/低多边形风格的兼容性；
   合适则整库引入，不合适则作参照库吸收技法（AGENTS 参照库纪律）。
2. **自研升级（保底路线，风格可控）**：
   - **域**：近场细分网格（跟随相机、网格对齐防泳动）+ 中场环带 + 远场裙边至地平线（≥4000u），替换「外扩 Cube」；
   - **浪**：两组长涌（swell，波长大、振幅大）+ 现有 4 波 chop，波峰陡度驱动的**白帽泡沫**；
   - **色**：深度渐变 + 波背次表面散射 tint + 太阳耀斑高光（现状已有基础）；
   - **交互**：`WaterSimulationDriver` 的爆炸/落水涟漪注入保留，与新域适配；
   - **约束**：波峰最高点仍 < -0.10（不穿岛基湿沙带），`Tests/Water` 契约同步更新。
3. 风格底线：低多边形flat着色的美术身份不因「仿真」让位——仿真的是**运动与光的物理感**，不是照片级贴图。

## 6. 验收与门禁

1. 每 kit：Blender 预览图（1024² 三视角）+ STAT 行（面数/槽/包围盒）入库 `export/`；
2. Unity 侧：`WorldMapAssetBuilder` 导入（品红零容忍）→ showcase 场景 → 播放器实拍（`-worldMap` 参数）；
3. 连通性测试 + 操控测试（EditMode/PlayMode + m2-harness 双轨）全绿；
4. batchmode 编译 0 error、grep `shader error` 0 条（水体改动的唯一算数标准，AGENTS 图形学铁律）；
5. 用户过审地图观感后，才做战役 UI 重绑与批量铺量（沿袭「样板先行」精神：本轮批量是用户直接授权的例外，
   但**接入战斗场景的最终开闸仍以用户看图为准**）。

## 7. 未决项（提案，等用户/实测裁决）

- 满力抛射上限 20 是否随大图上调（影响与原版数值基准的偏离度）；
- 战役进度（星级/解锁）如何映射到 8 张图（3 章 × 2-3 图？自由序？）；
- 风暴图的雨/闪电特效范围（Ambient 档只有光/雾，无降水系统）。
