# M4：海面选型与实现（茫茫大海的仿真化）

> **本文是什么**：M4 §5「海面仿真化」的选型裁决与实现契约。用户裁决：游戏发生在茫茫大海里、
> 当前水太不仿真、**不计性能**、可并鼓励引入开源实现；随后指定了两个参照库
> （HPWater / FLIP，`external/fluid-ref/`）作为选型锚点。
> 本文只写「是什么 / 怎么设计 / 为什么」；【提案/待定】标注的数值未经用户验收。
>
> **结论先行**：主实现走**自研 URP 大海域海面**（`OceanRig` + 分级域网格 + 长涌/白帽/深度渐变），
> 从 HPWater **吸收光照技法**（背光透射/薄层散射），FLIP 记为局部交互液体的后续候选，
> Crest 降级为对照项（免费开源版不支持 URP，见 §4）。

## 1. 主实现：自研 URP 大海域海面（已落地）

### 1.1 组成与分工

| 件 | 路径 | 职责 |
| --- | --- | --- |
| 域/波规则（纯 C#） | `Assets/Scripts/PirateCrew/Water/OceanRules.cs` | 波峰硬约束、长涌波表、近岸包络、白帽规则、远场/地平线淡出、几何解析淡出 |
| 网格梯子规则（纯 C#） | `Assets/Scripts/PirateCrew/Water/OceanGridRules.cs` | 近场均匀格 → 中场增长环带 → 远场裙边的分级网格数学 |
| 运行时载体 | `Assets/Scripts/PirateCrew/Water/OceanRig.cs` | 自建 GameObject/Mesh/材质、相机跟随（步进对齐）、发布全局 |
| 海面 shader | `Assets/Art/Shaders/Ocean/PirateOcean.shader` | 6 波 Gerstner + 分层光照（含 HPWater 技法吸收，见 §2） |
| 材质落盘 | `Assets/Editor/WaterAssetBuilder.cs` → `ApplyOceanMaterialDefaults()` | `Assets/Art/Materials/Environment/Ocean_Water.mat` |
| 测试 | `Assets/Tests/Water/OceanRulesTests.cs` + `WaveRulesTests.cs`（契约更新） | 无头可断言的数值契约 |

沿用不动：`WaterWaveField2D`/`WaterSimulationDriver`（波动方程涟漪注入）、`WaterRules`（chop 波表参考实现）、
`PirateWater.shader` + `Water_Ocean.mat`（旧水面，留作 A/B 档案）。

### 1.2 域分层（替换"外扩 400u 的 Cube"）

一张**径向圆盘网格**（中心顶点 + 同心环，单 DrawCall、无接缝无重叠），跟随相机：

| 层 | 参数（`OceanGridRules`） | 值 | 为什么 |
| --- | --- | --- | --- |
| 近场 | `CellSize` | 1.6 u | 最短 chop 波长 4.8 → 每波 3 顶点（旧 `WaterMeshRules.IsSamplingAdequate` 达标线） |
| 近场 | `UniformRadius` | 128 u | 覆盖竞技场核心区（与模拟域同尺度） |
| 中场 | `RingGrowth` | ×1.25/环 | 远处波的几何位移被淡出（见下），粗网格只承载法线/颜色 |
| 远场 | `HorizonRadius` | 4200 u | M4 §1/§5 硬契约 ≥ 4000 u |
| 精度 | `Segments` | 256 | 圆盘一周顶点数 |
| 规模 | ~109 环 | ~28k 顶点 / ~56k 面 | 16 位索引内（`Needs32BitIndices` 兜底）；不计性能也不失控 |

**防泳动**：相机移动按 `SnapStep`（=近场格距 1.6u）取整对齐——步进之间网格原地不动；
位移场由世界坐标驱动、逐像素解析法线与网格无关 → 明暗永不泳动，只有几何边缘存在亚格距级误差。
**网格密度 LOD**：波长跌破 2.1 顶点/波的短波，几何位移按 `OceanRules.WaveGeometricFade` 淡出
（法线不受影响）——远处粗网格不出现欠采样"boiling"。

### 1.3 波形契约（长涌 + chop，与 shader 双源同式）

| 波 | 波长 | 振幅 | 陡度 Q | 备注 |
| --- | --- | --- | --- | --- |
| S1 长涌 | 120 u | 1.10 | 0.75 | 方向 (1, 0.15) |
| S2 长涌 | 72 u | 0.65 | 0.70 | 方向 (0.55, 1) |
| W1–W4 chop | 26/15/8.4/4.8 u | 0.278 合计 | 0.50–0.65 | 沿 `WaterRules.DefaultWaves`（格 1→2 单位 ×2 口径） |

- 全浪表 Σ Q·A·k ≈ 0.164 ≪ 1 → 永不自交（充分条件，测试断言）。
- 长涌取值落在任务书"波长 60–120u、振幅 0.5–1.2"内【提案/待定：观感数值待实机验收】。
- 注意：旧 `Water_Ocean.mat` 落盘的 chop 是换算前遗留值（`_W1Length=13`），新海洋材质与 C# 契约对齐用 ×2 值；旧材质不动。

### 1.4 波峰硬约束与长涌近岸包络（用户裁决的落地方式）

**硬约束**：竞技场附近波峰最高点 **< -0.10**（不穿岛基湿沙带；岛顶最低 +0.5、静水面 -0.4）。
换算：近岸振幅预算 = -0.10 − (-0.4) = **0.30**（`OceanRules.ShoreAmplitudeBudget`）；
chop 振幅和 0.278 → 近岸波峰 **-0.122** ✓（比旧口径 0.278<0.4 略放宽，`WaveRulesTests.Defaults_CrestStaysBelowGroundLevel` 已改到新阈值）。

长涌（1.75 振幅和）远超预算，**只允许出现在外海**：`OceanRules.SwellEnvelope` 以竞技场中心为圆心，
≤ 保护半径（`arenaRadius + 24`）时长涌振幅压 0，保护圈外 260 u 内 smoothstep 升到 1。
默认 `arenaRadius=200` 罩住 M4 最大 280 u 跨度的半对角（≈198，测试断言）。
外海没有岛/角色，全振幅涌浪（波峰可达 +1.6）正是"茫茫大海"想要的东西；波矮的近岸自动平静也与浅水耗波的物理直觉一致。

### 1.5 白帽、透光、深度渐变、地平线

- **白帽**：雅可比（陡度）阈值 J<0.85 触发、软区 0.15、只出现在波高处（heightNorm>0.35）、
  世界空间双层噪声碎化边缘、近岸降权 0.35（`OceanRules.WhitecapMask`，shader 同式）。
  陡度主要由外海长涌贡献 → 白帽集中在外海（物理正确：外海浪大）。
- **波背透光**：HPWater diffT 技法吸收，见 §2.1。
- **深度渐变**：三档海水色按场景深度过渡（沿用旧件机制，需 URP Asset 的 Depth/Opaque Texture，已开），
  调色板守美术风格指南 §2.1：浅 `#4DA6D9` / 中 `#2B7AB8` / 深 `#1A4F7A`。
- **地平线**：顶点位移 2000→3000 u 淡出到 0（远场只留法线扰动，海天线不闪）；
  2600→3900 u 颜色融进雾色 `#B0D4F1` 且 **alpha→1**（海天线干净、无裙边硬边露头）。
  高频细节法线 600→1600 u 淡出（远处 FBM 闪点噪声压掉，留 Gerstner 法线 + 太阳光路）。

### 1.6 接线 API（协调者在 Battle 场景挂载，一行）

```csharp
var ocean = PirateCrew.Water.OceanRig.Create(
    PirateCrew.Water.OceanConfig.ForArena(new Vector2(w * 0.5f, d * 0.5f), w * 0.5f, d * 0.5f),
    material: null,      // null = 按 "PirateCrew/Ocean" Shader.Find 现场建运行时材质
    parent: waterRoot,   // 可选
    followCamera: battleCamera); // 可选，缺省每帧 Camera.main
```

- `OceanRig.Create` 自建物体/网格/渲染器；换地图时 `ocean.Configure(config)` 只更新包络半径。
- **与 `WaterSimulationDriver` 零适配兼容**：驱动发布的是全局纹理/向量（`_WaterHeightField` 等），
  新 shader 按世界 XZ 采样、与水面网格域无关——爆炸/落水涟漪注入照常生效。
- 旧 `Water` Cube（`BattleSceneSetup.CreateWaterPlane`）退役由协调者收口：删 Cube + `WaterTessellator` 挂载，
  `WaterSimulationDriver` 可保留原物体或移挂到 OceanRig 物体上（驱动自寻 `Instance`，与挂点无关）。
- `OceanRig` 与旧水面并存也不冲突（只是两片水叠加），给渐进收口留了余地。

## 2. HPWater 技法吸收表（`external/fluid-ref/HPWater`，MPL 2.0）

> 出处：github.com/AshenOneArt/HPWater（本地 `external/fluid-ref/HPWater`，`LICENSE` 首行为
> "Mozilla Public License Version 2.0"）。MPL 2.0 是**文件级** copyleft：只有逐字拷贝其源文件才触发
> 传染义务；本项目只吸收**技法**（读懂后用自己的 URP 单文件实现重写），license 干净。
> 注意其 README 明示该仓库是 Source Code Preview、**不是完整 Unity 工程**，不可直接打开。
> HDRP + RenderGraph 深度集成 → **管线壳层不搬**（本项目 URP 2022.3 前向透明单 Pass）。

### 2.1 判定表

| HPWater 技法 | 出处（仓库内路径） | 判定 | 理由 |
| --- | --- | --- | --- |
| BSDF 背光透射（diffT Part3）：`G_backlit=saturate(-NdotL) × exp(-σ·d·scale) × Henyey 相位(dot(V,-L), g≈0.9998)` | `HanPiWater/Deferred/HPWaterBSDFLibary.hlsl`（Part 3 注释块） | ✅ **已吸收** | 正是"向阳侧波背透光感"的物理骨架。适配：厚度用绝对波高近似（HPWater 同样"thickness 由高度场近似"），相位 g 降到 0.6（0.9998 的窄峰在低模上不可见），落进 `_Sss*` 材质参数 |
| BSDF 薄层 SSS（diffT Part2）：`G_sss = 1 - G_entry` 入射分工、线性+非线性光程 | 同上（Part 2） | ✅ 部分吸收 | 取"侧面入射"项（0.15 权重地板）保持入射分工；非线性光程修正是为对齐其体积 ray-march 累积，我们没有 S_volume，整段搬会失真 |
| 宏观体积散射（diffR）：水下 ray marching + 屏幕空间模糊前向散射色 | 同上（Part 1）+ `HPWaterVolumetrics.hlsl` | ❌ 不做 | 依赖 HDRP 体积累积管线；我们的水体色是三档调色板 + 深度渐变 + 假焦散（风格化裁决），物理体积散射会把水色拉离美术纪律 |
| 3-MRT GBuffer 打包（法线/粗糙度/散射色/吸收/泡沫） | `HanPiWater/Gbuffer/HPWaterGBufferEncode.hlsl` | ❌ 不做 | HDRP 延迟 + RenderGraph 专属结构；URP 前向透明水不写 GBuffer，结构不匹配 |
| 光线追踪折射：指数步进 + IGN 抖动 + thickness offset（修"水下物错位"） | `HanPiWater/Refraction/HPWaterRefraction.cs` | ❌ 本轮不做，**升级候选** | 当前屏幕空间 UV 偏移折射保守可用且已验证；步进 ray march 要对 `_CameraDepthTexture` 重构世界位置，无头环境不可验证，风险/收益不划算 |
| 体积光：低分辨率累积 + MV 时域去噪 + À-trous + 联合双边上采样 | `HanPiWater/Deferred/HPWaterVolumetrics.hlsl` | ❌ 本轮不做 | 需要 RenderFeature + compute + 多 RT 管线（协调者资产/收口范围）；与"不计性能"无关，这是**管线风险**问题 |
| 交互焦散：compute 光子累积 + 色散双模式 | `HanPiWater/Caustic/HPWaterCausticCompute.compute` | ❌ 本轮不做，**升级候选** | 现有假焦散（域扭曲脊状噪声 + 深度衰减）保留；compute 焦散需要 RT 管线接入 |
| 波动方程交互波浪 | `HanPiWater/FluidDynamics/HPWaterWaveEquation.compute` | ➖ 已有等价实现 | 同一方程（u_tt=c²∇²u、ping-pong、障碍置零）的 CPU C# 版 `WaterWaveField2D` 已在工程内接线与测试（含诺伊曼反射/海绵层/泡沫场）；GPU 化仅在将来有性能诉求时立项（当前明确不计性能） |

**shader 组织**：HPWater 按 include 分块是框架需要；本工程惯例是"刻意重复以免 include 链"
（`PirateWater.shader` 头注释），且新 shader 未经 Unity 编译验证——include 链自洽恰恰是无头环境验不了的，
故保持**单文件**，只在注释里标注吸收出处。

## 3. FLIP 交互液体（`external/fluid-ref/FLIP`，MIT）——后续候选，本轮不实施

> 出处：github.com/lamp-cap/Unity_FLIP_Fluid_Simulation（`LICENSE`："MIT License, Copyright (c) 2026 lamp-cap"）。
> 4M 粒子 + UAAMGPCG 求解器 + Narrow Band + GPU Marching Cubes 表面，Unity 2022.3.57
> （与本工程 2022.3.62 同版系，compute shader 管线无关，URP 可直接用）。

- **判定：海面主路线不用它。** 它是"容器内液体"模拟（有限体积 + 边界），对无尽海面是错误工具——
  海面的运动形态由风驱动的波谱（Gerstner/涌浪）刻画，不是自由表面流体重建。
- **后续候选【提案/待定】**：炮弹落水飞溅、船体沉没进水演出、港口小范围液体。MIT 可整库借鉴；
  触发条件：M4 之后若立项"沉船/进水"演出，再按局部区域（几米见方）接入，与海面 shader 解耦。

## 4. Crest Ocean System——对照项（降级一段带过）

github.com/crest-ocean/crest：**MIT license**、要求 Unity 2022.3.62+，但**免费开源版只支持内置渲染管线**
（repo 自述 "targets the built-in renderer"）；URP 支持在付费 Asset Store 版（Crest Water 4 URP）里。
→ 付费版不满足"开源引入"前提，免费版管线不匹配；其物理化外观与本项目 Gamma 色空间 +
低多边形 flat 风格也需要大改。结论：不引入。对照价值：它的 per-LOD 波形切片思路与本文
`OceanRules.WaveGeometricFade`（网格密度 LOD）同构，思路互证。
另：Gerstner 波形的经典出处是 NVIDIA GPU Gems 1 ch.1（Effective Water Simulation from Physical Models），
本工程 `WaterRules` 的实现即按该公式自写；社区教学参照可看 leonjovanovic/water-shader-unity
（MIT 之类以仓库 LICENSE 为准，未入库未深核）。
