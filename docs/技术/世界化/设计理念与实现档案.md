## 1. 总设计理念

### 1.1 语义建图：一片海一个故事【裁决→理念】

用户裁决"按语义做图，完全不参考原版布局甚至数量"。转译成三条可执行原则：

1. **先叙事后几何**：每张图先回答"这是片什么海、谁在这里活动过"（搁浅巨舰的墓场、
   沉没港口、巨龟背甲……），地形从叙事长出来，而不是从"母题配比表"长出来。
2. **先连通后装饰**：跳跃链（岛=节点、跳=边）是骨架，先保证"能来回跳"，再往节点上
   长细节。这条被测试化（`WorldMapConnectivityTests`），**连通性破产 = 构建失败**。
3. **不对称但有公平性**：双方出生群"资源对等"（可用面积/高度/掩体量），形状不镜像——
   比起原版的镜像对称，不对称更出"地方感"。

### 1.2 尺度理念：大世界感的三件套【理念】

"大"不等于无限摊平（回合制单回合位移≈满力射程 25u，摊太大节奏就死）。大世界感 =：

- **可玩跨度放大 2–8×**（100u → 150–280u，8 张图 150/180/190/200/220/240/260/280 阶梯）；
- **无界海**：海面裙边铺到 4200u 融进雾色，地平线永远有内容；
- **远景幕布**：不可达区放远岛/鲸/利维坦触手/巨肋拱/远帆船队（用户明确鼓励），
  相机随便转都有"画"。

### 1.3 碰撞与视觉两解耦【理念，本里程碑最重要的架构决定】

大号有机地形件（梯田岛/龟甲/环礁）的顶面若直接用网格当碰撞，站立面必然坑洼。
因此拆成两层：

- **站面层（玩法真理）**：每件可站立资产随 FBX 产一份 `.standable.json`（轴对齐 box 表，
  顶面强制 0.5u 档 + 平面度 1e-3），Unity 侧**按 box 生成 BoxCollider**——顶面绝对水平；
- **Kit 层（视觉自由）**：FBX 网格随便有机（裙边/节理/鳞纹），不参与碰撞。

这解决了"有机造型 vs 站得稳"的矛盾，代价是数据管线（见 §3.1）。灰盒块在 kit 未接入时
兜底成地形本体，接入后沉到 kit 之下当底座。

### 1.4 数据驱动的 prefab 拼装【理念】（回答"地图怎么拼起来的"）

一张图 = **三个层的运行时拼装**，全数据驱动、零手摆：

```
WorldMapCatalog（8 张图的 placement 表：kit 件 id/位置/朝向 + 出生点 + 空投池 + 氛围档）
   │
   ├─ WorldMapRules.AllStandBoxes   摆放 × manifest → 世界系站面 box（yaw 合成）
   │     ├─ BoxCollider×N（Stands 层，玩法碰撞）+ 分色灰盒（kit 缺位时兜底）
   │     └─ TryRasterize → 2u 栅格 → TileTerrainGrid（AI/小地图/出生高度共用）
   ├─ WorldMapComposer.Kit 层：kit FBX 预制件按摆放表实例化（地形/船坞/远景，根 y=0）
   │     Props 层：道具按表落地吸附（y 自动吸附到所在站面顶高，浮标吸附水面）
   └─ Battle 接线：-worldMap <id> → BattlePlan（出生/武器）→ 单位生成走既有链路
```

用户的预想"空岛/船/物体预制件放在海平面上"与此一致——kit 预制件根在海平面 y=0
（岛体自带水下裙边到 −3m），道具站上平台，远景件挂在不可达外海。**悬空空岛**变体
（Showcase 关 3 有先例）本轮 8 图未用，留作后续图池扩展。

### 1.5 手感：忠实逆向 + 现代层【裁决→理念】

- **落地翻滚不做动画状态机**——原版就没有，是三段涌现逻辑（恒转 + 落地反弹 + 接触阻尼），
  忠实转写成 RollRules 纯 C#（48°/s×水平速度、反弹 0.2、线性摩擦 78.125 u/s²、
  接触阻尼 ×0.5），作用在视觉子变换上（刚体保持冻结，不破坏瞄准/描边/AI）。
- **瞄准层现代化**（战舰世界感）：Scope（FOV 28 + 灵敏度 ×0.4）、力度-镜头耦合、
  弹体追焦、全景档随地图跨度自适应（clamp(span×0.55, 60, 160)）。
- 逆向常量的单位换算全部集中在 RollRules 一处 + 测试钉死（1 px/frame = 1.5625 u/s）。

### 1.6 海洋：仿真的是运动与光的物理感，不是照片【理念】

低多边形身份不让位。五层结构（PirateOcean.shader + OceanRig + OceanRules）：

| 层 | 内容 | 契约 |
| --- | --- | --- |
| 域 | 跟随相机的径向盘：近场 1.6u 细分 → ×1.25 环带 → 4200u 裙边 | 网格步进对齐防泳动 |
| 波形 | 2 长涌（120u/1.1m + 72u/0.65m）+ 4 chop，Gerstner 顶点位移 | 近岸包络：波峰 < −0.10 不穿岛 |
| 色彩 | 深度三档（美术板海水色）+ 破碎噪声 + HPWater 背光透射吸收 | Gamma 色空间直写 hex |
| 泡沫 | 岸沫 + 波峰白帽（雅可比陡度阈值 + 噪声碎化 + 近岸降权） | 陡度公式 C#/HLSL 双侧同式 |
| 地平线 | 位移 2000-3000u 淡 0，颜色融雾 + α→1 | 海天线干净 |

**交互涟漪**沿旧 WaterSimulationDriver（波动方程 + 爆炸/落水注入），域适配后接新 shader。

### 1.7 多 subagent 流水线【裁决→理念】

6 个 subagent 并行（地形/道具/船坞/远景 4 组建模 + 水体 + 手感），关键机制：

- **文件域互不重叠**（各 kit 一个目录、水体/手感各管各的代码域），协调者独占 Unity 串行收口；
- **统一风格参数** `style_tokens.py` 是唯一事实源（色板/槽位/预算/站面校验/导出参数），
  kit 脚本禁止散写；
- **验收闭环**：每件资产 Blender 预览图 → agent 自己 Read 看图迭代 ≥2 轮 → 用户过审 →
  才进 Unity 管线；
- **数据一致性 > 视觉打磨**：建模 agent 反复重渲染可以，但 manifest 变了必须重导出并
  触发 `sync_standables.py` 重生成 C# 表。

## 2. 资产与数据管线（as-built）

```
[Blender 无头] tools/blender/scene/<kit>/*.py（bpy 程序化，style_tokens 同源）
   ├→ pirate-crew/Assets/Art/Models/WorldKit/<Kit>/<Asset>.fbx
   ├→ <Asset>.standable.json（站面 manifest：c/s/top/yaw，Blender Z-up）
   └→ docs/images/worldkit-<kit>/<Asset>-{front34,side,back}.jpg（预览，人工/agent 判图）
        │
[sync] tools/blender/scene/sync_standables.py
   └→ Assets/Scripts/PirateCrew/Battle/WorldMaps/WorldMapStandables.cs（GENERATED，
      坐标转换 Unity(X,Z)=(Blender X, −Blender Y)、TopY=Blender Z、yaw 同值）
        │
[Unity 换装] Assets/Editor/WorldMapAssetSetBuilder.BuildAll（菜单/无头双入口）
   ├→ FBX 导入参数修正（useFileScale=true / bakeAxisConversion=true / materialImportMode=None）
   ├→ Kit_* 材质生成（23 槽，色值与 style_tokens 同源；草/帆/绳双面；余烬自发光）
   ├→ WorldMapAssetSet.asset（资产名 → FBX 引用）
   └→ Battle.unity 接线（worldMapAssetSet + worldOceanMaterial 字段赋值）
```

辅助工具：`fix_spawns.py`（出生点按 manifest 自动吸附合法站面）、
`WorldKitScaleProbe`（导入包围盒实测，对照 Blender STAT）。

## 3. 实拍暴露的 bug 与修法【实测，全部已修】

第一批实拍（播放器 `-worldMap` 自动出图）暴露 4 个集成级 bug——静态门禁
（编译 0 错 + shader error 0 条 + 1114 测试全绿）**一个都抓不到**，只有真渲染才现形：

### 3.1 FBX 导入 ×100 放大（最严重）

- **症状**：全屏巨型灰色几何体糊脸，地图"全是白模"。
- **根因**：Blender `apply_scale_options='FBX_SCALE_NONE'` 导出把 (100,100,100) 挂在 FBX
  **根节点**上（补偿 UnitScaleFactor=100）。Unity `useFileScale=false` 不走单位换算，
  节点缩放原样进来 → ×100。
- **修法**：`useFileScale=true`（换算路径吃掉节点缩放，实测断舷船 6.20×6.38×16.97 = 米制 ✓）。
- **教训**：`SceneKitPilotSetup` 里"useFileScale=true 会 ×0.01"的旧注释来自**另一种导出模式**
  （缩放已烘进顶点的默认导出）——导入参数必须与导出参数配对验证，不能跨管线抄。

### 3.2 海洋 shader 没进构建包（"白海"）

- **症状**：海面是一块纯白圆盘。
- **根因**：OceanRig 运行时 `Shader.Find` 现建材质，但没有任何构建内资产引用该 shader →
  打包剔除 → Find 返回 null → 兜底 Sprites/Default（白盘）。日志实锤：
  `[OceanRig] 找不到 shader PirateCrew/Ocean`。
- **修法**：`WaterAssetBuilder.ApplyOceanMaterialDefaults` 烘 `Ocean_Water.mat` 资产 →
  Battle 场景序列化引用（`worldOceanMaterial` 字段，WorldMapAssetSetBuilder 接线）→
  shader 随包入库。
- **教训**：**运行时 Shader.Find 的 shader 必须有构建内资产引用**——美术资产管线里
  "场景引用"本身就是资源收录声明。

### 3.3 整海染成暖金（光路带整屏饱和）

- **症状**：海洋修出来后是沙金色，不是蓝的。
- **根因**：太阳光路"宽瓣"数学按老版 45° 固定机位调参；高机位俯视时平水面镜射方向≈天顶、
  与太阳仰角天然接近 → broadLane 全屏饱和，`lerp(color, _SunSpecColor=暖金, w)` 整海生效；
  `_SunSpecCrestBias=0.70` 又让所有波峰无条件偏金。
- **修法**：光路权重加**方位物理门**——视线水平投影与太阳方位对齐才有光路
  （`azimuthFacing²`），背对太阳归零；波峰偏置 0.70→0.25、宽瓣强度 0.8→0.5，
  由 ApplyOceanMaterialDefaults 钉住。
- **教训**：风格化光效若隐含"机位-太阳相对几何"假设，换机位必炸；补一个与几何无关的
  物理门（方位对齐）比调参数鲁棒。

### 3.4 近场看穿海床（"雾玻璃海"）

- **症状**：debug 档 1（纯水色）确认水色链正确后，正常档海面仍透出沙色海床矩形。
- **根因**：`_Opacity` 默认 0.82，俯视时菲涅尔项≈0 → 近场 α≈0.82，老场景烘的海床板
  （Sand 色）透过海面可见。
- **修法**：`_Opacity=0.94`（材质烘焙钉住）。远场"透视感"由菲涅尔+折射项承担，
  不靠压基础不透明度。

### 3.5 几何层三连（连通性测试阶段抓的）

- 旋转矩形 `Contains/Distance` 必须用**逆变换**（写成正变换时 yaw≠0 全镜像；
  yaw=0 的图碰巧无症状——这类 bug 只有用带旋转件的图才能抓到）；
- box **内部余量**用 `EdgeClearance`（=min(hx−|lx|, hz−|lz|)），`Distance()` 在内部恒 0，
  不能当余量判据；
- manifest 镜像轴（Unity Z = −Blender Y）会**翻转长轴件的台阶顺序与弧段朝向**——
  手抄站面表不可靠，站面表现在是 `sync_standables.py` 的 GENERATED 产物，
  出生点用 `fix_spawns.py` 按 manifest 自动吸附。

### 3.6 小坑清单

| 坑 | 一句话 |
| --- | --- |
| `List<struct>` 索引器 | 不能写字段（CS1612），整体替换元素 |
| `namespace PirateCrew.EditorTools` 内写全限定 `PirateCrew.X` | 首段被解析成 `PirateCrew.PirateCrew`，第二段必炸；用 `using` + 短名 |
| style_tokens `curves.new(type="TEXT")` | Blender 5.2 枚举改名，已删死代码 |
| 播放器采集 | 不能带 `-batchmode -nographics`（那是 Editor 的规则；播放器带了只出黑帧） |
| 后台命令退出码 | `grep -c` 零匹配返回 1，别把链尾 grep 的退出码当构建结果 |
| 烘焙材质时机 | shader 默认值改了之后，已序列化的 .mat 不会自动跟——参数必须由 C# 烘焙入口显式钉住 |

## 6. 可玩性重构与有限色板修正（2026-09-17 早上，用户二轮反馈）

### 6.1 布局可玩性重构【用户裁决 → 已落地】

用户指出初版布局"核心循环变成运兵过河"：双方出生点隔 100-200u 水、中间跳台链，
接敌前先跑图好几回合，且每跳都可能溺亡。修正原则（`tools/worldmap/compact_layouts.py` 迁移脚本）：

1. **接敌距离 ≤110u**（1-3 跳）：双方主战场岛贴身或压上主轴（wreck 的 M 岛与断船/桅桥
   重叠成连续陆块；atoll 本阵压环礁带；gate 西岛压沙洲/礁阶/广场、东岛压心岛链）；
2. **连续陆块 + 内部高差**是主战场，水只留中央水道与边缘死区；
3. 装饰群岛推到外海当幕布（远景环不变）；
4. 例外：`spiral_throne` 保留"远征图"身份（螺旋爬升即玩法，本阵内收一格减半接敌距离），
   `mangrove_veil` 保留迷宫穿越身份。

出生点余量标准回归本义：`SpawnEdgeMargin 1.2 → 0.35`（防悬空出台沿即可，
1.2 会把贴台沿的合法出生全判死；0.35 仍盖过角色宽 0.375）。

### 6.2 有限色板修正【用户裁决 → 已落地】

初版"逐块明度抖动"是错误方案（低多边形的行业实践是**有限色板**：色彩层次来自色板本身、
植被散布与光照，不是随机扰动；且逐块实例化材质会击穿 ≤30 材质预算）。已回退为：

- 灰盒只用 3 档色板共享材质；
- 密度与色彩层次改由**程序化散布**承担：`WorldMapComposer.ScatterDecorations` 按确定性哈希
  向每块站面撒 2-4 个 Kit 植被/碎岩（低带=草/碎岩/蕨，中带=蕨/斜棕榈/中岩，高带=岩），
  全部走 Kit_ 色板材质；
- 灰盒视觉顶面下沉 0.06u 治与 kit 甲板的 z-fighting（白模闪烁元凶）。
