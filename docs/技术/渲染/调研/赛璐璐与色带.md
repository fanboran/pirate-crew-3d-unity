# 调研 · 赛璐璐与色带（Cel-Shading）

> **这份文档是什么**：等距像素卡通 Toon shader（[渲染管线-等距像素卡通.md](渲染管线-等距像素卡通.md) §4）的技术调研依据——经典论文、GDC 工作流与 URP/HLSL 实现向资料的结论提炼。
> **调研时间**：2026-09-21，所有「已核」来源均实际抓取阅读；个别被反爬拦截的来源如实标注并降级为佐证。

## 1. 色带框架的理论出处

| 来源 | 结论 | 对我们的价值 |
| --- | --- | --- |
| **X-Toon**（Barla et al., NPAR 2006）【已核全文】 | 传统 toon = 「1D ramp 由 **2~3 段常量色块**构成，以 N·L 索引」——档间纯色跳变不做渐变；可扩展 2D ramp 绑深度/LOD | 「2~3 档色带」的最经典定义出处；ramp 纹理（3~4 px，点采样）与 HLSL 分段常量**等价**，选实现方便的 |
| **Lake et al. 2000**（NPAR）【已核摘要】 | 实时卡通渲染开山：把连续光照**离散成少数 tone** + 轮廓 inking | 确立「光照量化」范式；我们= 其「只有 tone」子集（轮廓走反壳描边，见[调研-反向壳描边](调研-反向壳描边.md)） |
| **Unity 官方 UTS3**（Toon Shader 文档）【已核】 | 产品级三色域模型：Base / 1st Shading / 2nd Shading，**每档独立贴图×独立颜色的替换式配色**，而非主色乘系数 | 官方背书 2~3 档；**暗部色相偏移在产品级管线里全部靠「暗部独立配色」实现**，不在 shader 里跑颜色空间变换 |

## 2. 档位实现手法（URP/HLSL）

- **窄 smoothstep 切档**（Roystan【已核】）：`smoothstep(0, 0.01, NdotL)`——窄区间 smoothstep 保边抗锯齿，是最稳的 1~2 档写法。
- **等宽 N 档公式**（Ronja "Improved Toon Light"【已核】）：`t = NdotL / stepWidth; i = floor(t); i += smoothstep(0, fwidth(t), frac(t)); i /= stepAmount;`——floor 配 frac 上平滑亮度才正确。
- **本仓规格**【AI 提案】：2~3 档用**显式非等宽阈值阶梯**（每档阈值 + 每档颜色独立暴露给美术），不用等宽循环公式；等价形态可选 1D ramp 纹理（X-Toon/UTS 框架，美术改色方便）。
- **边界过渡**：主路径 `step()` 硬切——640×360 nearest 会把亚像素过渡自动像素化，fwidth 平滑反而被低分辨率吞掉并引入过渡灰阶；fwidth 版保留为高分屏预览宏。
- **URP 取光**（Cyanilux【已核】）：单固定平行光 + 无实时阴影 ⇒ **完全跳过 `_MAIN_LIGHT_SHADOWS` 关键字族与 shadowCoord**，`GetMainLight()` 或自定义 `_LightDirection/_LightColor` uniform 即可（砍掉全部 shadow variant）；`Lighting.hlsl` 仅为雾/GI 才需要 include，且**关键字必须定义在 include 之前**。
- **线性空间**（Catlike Coding【已核】）：色相偏移与抖动的数学必须在线性空间做（色相偏移暗部见 §3，抖动见 §4）。

## 3. 暗部色相偏移：替换式暗部色，不做 shader 内 HSV

所有已核实的**产品级做法都是「预制暗部色 + lerp/查找」，没有一家在 shader 里跑 HSV/YIQ 变换**：

- UTS3：三色域各自独立配色，可独立于场景光色设置明暗颜色；
- Xrd 工作流复刻（GabrielToonShader【已核】）：所谓 SSS 贴图实际是「暗部专用配色贴图」——暗部**整块替换成预制暗色**，不是乘暗；
- Ronja【已核】：`color = lerp(albedo * shadowTint, albedo, band) * lightColor`，并强调**光色要乘在亮暗两侧**，否则光弱时暗部反而比亮部亮。

本仓规格【AI 提案】：`shadeColor` 做成材质参数（或 3×1 ramp 的对应档），偏冷/偏紫程度由美术在板内选色表达（暗部色本身就是调色板成员，见[调研-调色板量化](../资产管线/调研-调色板量化与纹素密度.md)）；shader 只做 lerp/查找。数学在线性空间。

## 4. Bayer ordered dithering 的三个坑（均已核实）

来源：Surma "Ditherpunk"【已核】、FrostKiwi【已核】、Ronja "Dithering"【已核】。

1. **归一化偏亮**：Bayer 4×4 阈值直接除以 16 会整体偏亮（1/255 的亮度被抖出 25% 平均亮度）——用**中点归一化 `(m+0.5)/16`** 或 0 中心化。
2. **作用对象**：抖动加在「档位选择值」上——`t = NdotL + (bayer - 0.5) * (1/levels) * strength` 再切档；**不是**抖动最终 RGB（FrostKiwi：dither 必须作用在即将被量化的值上、幅度 ≈ 1 个量化步长）。
3. **空间与频率**：在线性空间比较（sRGB 上抖动渐变亮得过快）；屏幕空间映射若走纹理，必须**关压缩 + Point filter**，且用**低分辨率 buffer 尺寸**做 UV 映射（Catlike Render Scale 坑：`_ScreenParams` 与 RT 实际尺寸可能不一致）。矩阵用 16 个标量的 HLSL 常量数组即可，无需纹理。
4. **时间稳定性**（Obra Dinn 案例，Zucconi【已核】）：纯屏幕空间 Bayer 在**相机移动**时 pattern 会游动——但本项目正交+锁旋转+将配相机 snap（见[调研-全屏像素化](调研-全屏像素化与像素完美.md)），时间游动基本不存在；物件自身移动时 pattern 相对表面滑动在像素画语境下是复古正确的表现，不必上世界空间映射。

## 5. Guilty Gear Xrd 工作流的可迁移件

GDC 2015 "GuiltyGearXrd's Art Style"（会话页已核；细节经由两个代码可读的复刻仓库核实：GabrielToonShader、GodotToonShader）：

- **顶点色 R = 明暗阈值偏移**【采纳·提案】：美术在模型上刷顶点色即可逐区域改色带切分点（1 默认 / 0.5 不受光 / 0 永远最暗）——Xrd 工作流里性价比最高的一条，专治「脸/下颌/披风色带切错位置」，低模近乎零成本。
- **光向量是美术参数不是物理光**（Xrd 每角色独立光向量）【采纳】：我们的「单平行光固定左上」等价于把方向烘成静态 uniform，无需 URP 光源查询。
- 高光通道 / 内线 UV / 法线整体修改：不采纳（无高光规格；内部结构线画进纹理；低模改法线价值有限）。

## 6. 参考游戏校准警告【重要】

- **For The King**（Siliconera 2015 访谈，摘要级核实）：核心是「低模致敬早期 3D + 手绘贴图」，**色带感其实很弱**，主要靠手绘质感与饱和配色。
- **Tunic**（GamesRadar 2023 访谈【已核】）：水彩感、软过渡、强配色；等距相机被当作**玩法工具**；无渲染管线披露。

⇒ 若目标观感以 FTK/Tunic 为锚，**纯硬切 2 档 + 冷紫暗部其实更接近日式赛璐璐（Xrd 系）而非它们**。规格建议：每档边界留 5%~10% 的 smoothstep feather 并做成 0~1 参数（UTS 的 Step/Feather 概念），M-B 样张时用两档对比图交创始人裁决。

## 7. 半兰伯特与高光

- 半兰伯特（`NdotL*0.5+0.5`）：默认**不用**（Ronja/Roystan 均从原始 N·L 切 0；半兰伯特会把背光面抬进中间档、压缩两端对比）。若剪影内部死黑成片再作为可调选项打开。
- 高光：维持无高光。日式工艺里高光是独立设计元素（Anjyo 2003，摘要级核实），如需回摆预留关闭分支即可。
