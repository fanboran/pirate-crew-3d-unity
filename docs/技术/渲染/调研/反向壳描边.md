# 调研 · 反向壳描边（Inverted Hull Outline）

> **这份文档是什么**：等距像素卡通描边（[渲染管线-等距像素卡通.md](渲染管线-等距像素卡通.md) §5）的技术调研依据——方案选型、硬边裂线根因、平滑法线烘焙、正交下线宽公式与深度处理。
> **调研时间**：2026-09-21，「已核」来源均实际抓取（含 Toon RP 生产级源码与 bgolus 附完整烘焙脚本的论坛长帖）。
> **标注约定**：沿用 [美术风格指南](../../设计/美术风格指南.md) §0；「采纳」结论均【AI 提案】，随 M-B 样张裁决转正。

## 1. 方案选型：为什么是反向壳

Ameye "Rendering Outlines"【已核】五法对比：① Rim/Fresnel（尖角失效）② **Vertex Extrusion 反向壳** ③ Blurred Buffer ④ Jump Flood（超宽线首选）⑤ Edge Detection 后处理（深度/法线 Sobel/Roberts）。

本仓选反向壳的依据【提案】：
- 正交相机下壳外扩天然**等宽**（数学见 §4）；
- 统一墨色 + 1px 细线 + 低模场景，反向壳最可控；后处理边检在 **640×360 低分辨率 RT 上做 1px 检测会抖动/断续**（KYRIOTA/bababuyyy 线索），且我们在管线顺序上要求「描边画进低分辨率域」（渲染篇 §1 红线 1），后处理方案要自己接 RT；
- 现有 `PirateOutline` shader 已有反壳 pass（`SRPDefaultUnlit`、Cull Front）骨架可复用。

## 2. 硬边裂线的根因与解法排序

**根因**（bgolus，Unity Discussions 长帖【已核全文】）：反向壳自 Jet Set Radio（2000）以来原理未变，硬性要求**网格水密 + 平滑法线**——硬边两侧是被拆开的重复顶点、法线不连续，壳沿各自法线外扩就在接缝处裂开。原话：「**你可以用带硬边的网格，前提是把平滑法线数据以某种形式编码，比如编码进顶点色或网格切线——Toony Colors Pro 2 就是替你做这件事**」。

解法排序（bgolus + Toon RP wiki【均已核】）：
1. **平滑法线烘进顶点色/切线/UV2**（首选——不改变本体光照，本体的着色法线原样保留）；
2. 导入器 Normals=Calculate + 大 Smoothing Angle（**会改变本体光照，不采纳**）；
3. 手工加倒角（成本高，不采纳）。

## 3. 平滑法线烘焙（本仓要落的管线）

三个生产级先例【均已核】：

| 实现 | 算法 | 存储通道 | 触发方式 |
| --- | --- | --- | --- |
| bgolus 论坛脚本 | 同位置顶点法线**等权平均**归一化 | 顶点色 RGB（float 通道，原值直存免编码） | 手动 |
| AleFeng OutlineSmoothNormalsGenerator | **角度加权平均 + 位置容差合并** | 顶点色 RGB / 切线 / TEXCOORD；UV 通道 1.7.0 起改**两分量八面体编码** | AssetPostprocessor 按文件名后缀 |
| danbaidong SmoothNormal | 角度加权 + Compute Shader | 顶点色 RGB/RG 或切线 | 导入期按 `_SN` 后缀 |
| Toon RP（Delt06）wiki | — | UV2 或切线；**蒙皮网格推荐切线**（Unity 蒙皮自动变换切线） | 文件名约定（如 `Character_=SmoothedNormals=Tangents=.fbx`）+ 编辑器工具 |

本仓规格【AI 提案】：
- **算法**：角度加权平均 + 位置容差合并（优于 bgolus 等权）。
- **通道**：静态网格首选**顶点色 RGB**。⚠ 但本仓顶点色 R 已规划给 Xrd 式色带阈值偏移（[调研-赛璐璐](调研-赛璐璐与色带.md) §5）——**两者可共存**：阈值偏移用 R，平滑法线用 GBA？【提案：平滑法线写 GBA 三通道、阈值偏移占 R，编码 `normal*0.5+0.5`】；或平滑法线走 UV2 八面体编码（锁死编码/解码成对演化——AleFeng 警告裸 `normalize(uv.xyz)` 在格式升级后整体错乱且 GPU 侧无法检测）。M-B 试点时二选一定案。
- **8bit 编码**：写 `Color32` 必须 `normal * 0.5 + 0.5`、shader 内 `* 2 - 1`（bgolus 用 float 通道免编码；我们烘焙器输出网格用 float 顶点色亦可，导入 FBX 则必然 8bit）。
- **两条烘焙路**：程序化件（船员胶囊+三角帽、烘焙器产网格）在 Unity 侧生成时直接算平滑法线 `SetColors`（顶点少，成本可忽略）；Blender 手作 kit 走**文件名后缀 + AssetPostprocessor 自动烘焙**（Toon RP 式约定，防手工漏烘）。
- **跨网格接缝**（帽与身体若为独立网格）：接缝处壳会各画各的——要么合并网格再烘，要么接受接缝断线（像素风下通常可接受，样张裁决）。

## 4. 正交相机下的线宽公式

Toon RP 生产级源码【已核】两种模式：

```hlsl
// 固定屏幕空间厚度：clip space 外扩，预乘 w 抵消透视除法，x 乘纵横比修正
float4 positionCs = mul(worldToHClipMatrix, float4(positionWs, 1.0));
float3 normalCs = normalize(mul((float3x3)worldToHClipMatrix, normalWs).xyz);
normalCs.x *= _ScreenParams.x * _ScreenParams.w;   // aspect 修正
return positionCs + float4(normalCs, 0) * thickness * positionCs.w;

// 世界空间厚度（受透视影响，正交下等价于常数偏移）
return mul(worldToHClipMatrix, float4(positionWs + normalWs * thickness, 1.0));
```

要点：
- **正交相机 `positionCS.w ≡ 1`**，clip space 公式自动退化为常数屏幕偏移——「RT 空间恒定 1px」的数学基础；
- **1px 换算**：NDC 高度跨 2，RT 高 `H_rt` ⇒ `thickness = 2 / H_rt * desiredPx`；RT 尺寸变化时由 C# 每帧下发（Ameye 的 `/_ScreenParams.xy` 写法则是 thickness 直接以像素为单位，两法等价）；
- 法线朝向屏幕（z 分量大）时 `normalize(normalCS.xy)` 数值不稳——Toon RP 不做 xy 二次归一、直接用整个 normalCS 的 xy，更稳【采纳】；
- 描边必须发生在低分辨率域（640×360）里定义线宽，否则全分辨率 1px 壳线被降采样后粗细不均（bababuyyy 架构结论，见[调研-全屏像素化](调研-全屏像素化与像素完美.md)）。

## 5. 状态位与深度

- 壳 Pass：`Cull Front` + `ZWrite Off` + `ZTest LEqual`（默认）+ 纯色 `ColorMask RGB`；
- **斜面 z-fight**（壳与本体近平行处描边渗透/断裂）：`Offset 1, 1`（Toon RP 的 Depth Bias 参数同用途）；
- **相邻物体漏线**：反向壳会在 A、B 重叠处互相画线（固有限制）；如需抑制用 Stencil（本体写 Ref、壳 `Comp NotEqual`，Toon RP 式）——注意多物体共享 Ref 会互相吞线，按层规划；像素风下「物物之间有线」通常反而是想要的效果，样张裁决；
- Toon RP 为壳配了 DepthOnly/DepthNormals/MotionVectors 四 Pass 防 SSAO/TAA 在壳上出 artifact——本仓目标管线无 SSAO/TAA（立项任务书 M-A 退役），**优先级低**，仅 DepthOnly 随本体保留即可；
- 只作用于不透明队列（`RenderQueueRange.opaque`）；UI 走 Overlay Canvas 天然无关。

## 6. 对渲染篇 §5 的回写结论汇总

采纳：平滑法线角度加权+位置容差烘焙、顶点色/UV2 通道选型与 8bit 编码规则、文件名后缀自动烘焙、ToonRP clip-space 线宽公式（thickness=2/H_rt·px + aspect 修正、不二次归一 xy）、Offset 防 z-fight、Stencil 备而不默认。
维持：独立 LightMode=`SRPDefaultUnlit`（本仓血泪教训，[描边Shader调试.md](描边Shader调试.md) §八）；RT 空间 1px；INK 墨色统一。
