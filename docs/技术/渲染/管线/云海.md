# 云海

> **本文是什么**：第 1 关「云端漫步」空岛下方那片海的技术口径——清澈透明的水面、起伏海床、
> 水下生态、水下生物（骨架 + 运动学动画）与水面点缀各自怎么画 / 怎么动、资产怎么接线、
> 尺寸按什么比例尺换算、调参从哪下手、有哪些坑。只写「是什么 / 怎么设计 / 为什么这么设计」。
> **口径来源**：[渲染管线.md](渲染管线.md)（PostLine 链与描边机制）、
> [01-云端漫步.md](../../../设计/关卡/01-云端漫步.md)（观感与验收）。全海域的大洋不在本文
> （[海面.md](海面.md)）；本关不铺全局 OceanRig。

> **结论先行**：海面拆成**互不抢活的三层**，各一支自带标准前向 pass 的 shader——
> ① 透明水面（岛影两档 + 像素折射 + 阳光区亮带碎金）从不透明贴图透出水下；② 海床（高度分档沙色 +
> 阳光区焦散 + 岛影）；③ 水下生态与水下生物（平面两档色 × 岛影）。水下生物**不在 Blender 里烘动画**：
> Blender 只建静止姿态与关节，Unity 侧的运动学控制器每帧用 IK / 链 / 弹簧解出关节姿态，
> 顶点着色器自己蒙皮。水下物**不描边**（没有深度 / 法线预通道）；
> 水面的波浪不直接画，由**岛影与水面、海床的交界线沿一道行波起伏**来体现。
> 水面 / 海床 / 生态 / 生物都是「颜色不乘光照」的定色画法，改观感只动材质上的颜色与阈值。

## 1. 画面结构

| 层 | 件 | 画法 | 渲染队列 / 通道 |
| --- | --- | --- | --- |
| 水面 | `Cloud_Sea_Surface` → `CloudSeaClearWater` | 从不透明贴图透出水下，叠「阳光水色 / 岛影水色」两档；折射偏移取整到艺术像素；阳光区有漂移亮带与碎金；顶点微起伏 | 透明（`Transparent+1`），不写深度 |
| 海床 | `Cloud_Sea_Bed` → `CloudSeaSeabed` | 按世界高度分档的沙色、斑块、沙纹、藻斑、卵石；阳光区焦散亮网；背光坡面另乘一档色 | 不透明；带深度 / 法线通道（云台立柱的水下段照常描边） |
| 水下生态 | `Cloud_Sea_*` / `Cloud_Bubbles_*` → `CloudSeaUnderwater` | 固有色 ×（受光面乘色 \| 背光面乘色）两档硬切，再乘岛影冷色；海草按「离根高度比」摆动 | 不透明；带投影通道，**不带**深度 / 法线通道（不描边） |
| 水下生物 | `Cloud_Creature_*` → `CloudSeaUnderwater` | 同上的两档色；顶点按骨架蒙皮（§3） | 不透明；带投影通道，**不带**深度 / 法线通道（不描边） |
| 水面点缀 | 涟漪（`CloudSeaRipple`）、雨 / 云隙光 / 彩虹（`CloudSeaRain`）、云台水洼与玻璃（`CloudSeaWater`） | 涟漪是单位方片上的硬边同心环，相位全在 shader 里走时间 | 透明（`Transparent+1` 起） |

四层的颜色都是**定色**：shader 里不采样光照强度，只读主光方向定明暗档、读主光阴影图定岛影。

## 2. 关键取舍

### 2.1 取样板：一切在艺术像素中心求值

PostLine 把全分辨率画面降采样到艺术画布再做描边与放大。程序纹理若逐片元求值，同一个艺术像素
内的片元会得到不同结果，降采样后边缘落在像素格中间，色块发虚、细纹理糊成噪点。

云海家族的做法（`CloudSeaCommon.hlsl`）：用屏幕导数把片元位置折算到**所在艺术像素的中心**，
再在该中心的世界位置上求值。于是同一艺术像素内的片元同色，色块边缘天然落在像素格上，
纹理粗细随缩放自动保持整数个艺术像素。两档色的明暗切点也在像素中心判定，没有半透明过渡带。
消耗的全局（像素比例、单元尺寸、主光方向）由 PostLine 每帧下发，见渲染管线.md。

### 2.2 水下物不描边

`CloudSeaUnderwater` **不带**深度 / 法线预通道，只有前向与投影两个通道。PostLine 的描边读的是深度 / 法线
预通道，水下物在描边判据里不存在——鱼、珊瑚、蟹、海草周围都没有线。理由有两条：隔着水色的小件本来就小而碎，
描一圈深线会把它们吃掉；海草逐帧摆动，进了预通道就会每帧描出抖动的墨线。

**别给这支 shader 加 `DepthOnly` / `DepthNormals` 通道，也别开 Fallback**：加了（或回退到内置 Lit），水下物
全部进描边预通道，整片水里冒出墨线。给水下域另配线色的几种做法也都试过，创始人逐个否决（§7）。
云台立柱插进水里那一段与海床之间的线照常有——那来自海床的深度 / 法线通道。

不描边的代价是小件失去轮廓。现行的生物靠体色与体量隔水可读（§2.8）；早年「反向外推的墨线壳」的做法已弃用：
壳的边缘经降采样必成过渡色，读成「高清打了马赛克」。

### 2.3 平面两档色，颜色不乘光照

水下生态与生物的明暗只分「受光面 / 背光面」两档（半兰伯特过一个切点），不做连续渐变；鳍、
眼白、瞳孔这类要纯平的件把两个乘色配成同值。理由有两条：连续渐变降采样后会产生非板色中间调；
「隔一层水色还读得出固有色」要求水下小件足够亮，乘真实光照会把它们压暗。

### 2.4 岛影：本关专属的主光硬阴影；交界线就是水面的波

战斗主光创建时不投影（见渲染管线.md）。第 1 关在 CloudWalk 根上挂 `CloudSeaSunShadow`，
启用时把主光切成硬阴影、阴影强度置 1，停用时原样还回去——云台、单位、海鸥、海面、海床、水下物
查的是同一张主光阴影图，全场只有一套影子。

- **水面**在水面位置采阴影图：落在水面上的是云岛与飞行物的影子。水下物在水面之下，
  物理上不可能在水面投影，所以不需要任何排除逻辑。
- **海床与水下物**各自在自己的位置采同一张阴影图：云台的影子落在沙面上，影区里没有焦散。
- 两档硬切：`step(切点, 距离衰减 × 阴影衰减)`。主光没开阴影时衰减恒为 1，整片算阳光，不报错。

阴影强度必须是 1：岛影两档按阴影衰减硬切，衰减不到 0 就会被整片误判成阳光。主光由战斗装配链
生成、重跑装配会重建灯光，所以开关是挂在场景件上的运行时组件，只在云端漫步这一关生效。
正交相机下主光级联的约束（§7）对全场一视同仁，海面一族也在其内。

**影边起伏是一道开关，默认关**。`CloudSeaShadowProbe` 采阴影图之前先把查点沿光线**推到光线入水
的那一点**；入水点的水平坐标再叠一道行波与低频噪声时，查点沿光线方向平移，影子与水面的交界线随之
起伏——水面色、海床影、生物身上的明暗边走同一个函数，三层上是同一条波。波的参数在海面材质的
`_ShadowWave*` 上（`CloudSeaWater` 每帧读出下发成全局），幅度为 0 时查点不偏移，影子是云台轮廓的
直投影。现行取 0：水面的动态只有漂移的亮带、碎金与折射晃动。

水面与海床的岛影在屏幕上有视差错位（两层高度不同），这是真实投影的必然结果，保留。

### 2.5 折射：偏移取整到艺术像素

折射不是连续的 UV 偏移，而是「世界格内同值 + 时间分格」的低频噪声给出方向，偏移量**取整到
艺术像素**。水下画面成片缓移、按固定帧率跳格，不产生亚像素抖动，也不逐帧闪烁。

**深度安全门**：折射点的场景深度若比水面还近（云台、立柱），该像素回退为不偏移，
不把前景物体的边拽进水里。

### 2.6 深浅靠海床高度，水色不随深度变

水色不透明度是常数（岛影区另加一档），「浅处暖沙、深处偏青」全部由**海床的高度分档**给出：
沙脊顶暖沙色，洼地偏青绿。这样水色的职责只有「是一层水」，深浅读数交给海床自己，
两者不会互相打架，也不会出现按屏幕深度推算的渐变带。

**水色与光影分开调**。阳光区的水色不透明度极低——海床原样看得见，水只留一点点青。岛影区另加的
那一档不随它变：影区是水面上一整块深色（深青罩在水下画面上）。亮带也是独立的一个浓度。三者的取值
以海面材质为准。

### 2.7 活物贴床：海床高度格

海床是起伏沙丘，脊顶与洼底相差近一个单位。活物若按固定深度带走，要么扎进沙脊，要么整群被顶到
水面附近。烘焙时从海床网格采样出**两张**同规格的均匀方格（`CloudSeaBedGrid`，纯 C#、无头可测），写进
`CloudSeaLife`：

- **净空格**：格点取周围半格内**最高**的顶点。对活物而言「最坏情况的高度」才是不能穿的那条线。
- **贴地格**：格点取离它**最近**的顶点，也就是沙面在这一点实际多高。

两张的空格都由四邻逐圈填满。净空格在斜坡上比沙面高出小半格的坡降——拿它放脚，蟹和海星会悬在沙面
上头，所以它只管净空。运行时：

- 游泳者（鱼群 / 剑鱼 / 魔鬼鱼 / 海龟 / 河豚）：查净空格。下沿 = 中心与前后左右四个偏移点里最高的沙丘 +
  自身下伸 + 余量；上沿 = 自身上伸不高于巡游带上沿。两者冲突时以不出水优先。
- 水母：查净空格。巡游带 = 触手尖不插沙到钟顶不出水，控制器把钟体推在这段里。
- 踩地的（蟹腿、海星腕、章鱼腕）：查贴地格。落点取脚下沙面高度，走路时随沙丘起伏。

上下沿都按**网格的真实尺寸**换算到对象原点，生物变大变高不用回头改巡游带。尺寸必须取渲染器的
世界包围盒，再换回父空间：`sharedMesh.bounds` 是网格本地系的数，群原点（巡游高度基准）不一定
在包围盒正中，所以上沿、下沿各取中心到盒顶 / 盒底的真实距离，不取对称半高。

### 2.8 生物为什么卡通放大

生物要隔着水色读得出，在屏幕上至少约 20 艺术像素。按相机契约的恒定密度（1 单位 ≈ 24 艺术像素），
真实比例的小鱼不到 12 像素。现行做法是把整套生物卡通化放大到「小鱼体长约 1 单位、剑鱼约 3 单位、
魔鬼鱼翼展约 4 单位、蟹腿展约 1.5 单位」这一档夸张，与 1.75 m 的角色站在同一个世界里读得出、
又不抢主体。尺寸全部在 `mod_creatures.py` 的建模函数里定。

## 3. 水下生物：骨架 + 运动学控制器 + 自定义蒙皮

生物的动画分三层，各管一件事：

| 层 | 在哪 | 管什么 |
| --- | --- | --- |
| 骨架 + 蒙皮权重 | Blender（`creature_kit.py` / `mod_creatures.py`） | 只建**静止姿态**、登记关节、把顶点绑到关节上；不烘关键帧 |
| 运动学控制器 | Unity 纯 C#（`CloudSeaBrains.cs` / `CloudSeaCrawlers.cs`） | 每帧解出每个关节的矩阵：脚踩在哪、身体怎么弯、触手怎么拖 |
| 蒙皮 | 顶点着色器（`CloudSeaAnim.hlsl` 的 `CloudSeaSkin`） | 按顶点权重把静止姿态变形；前向与投影两个通道同函数 |

### 3.1 数据契约（Blender ↔ Unity）

| 项 | 约定 | 读它的 |
| --- | --- | --- |
| 对象名 | `Cloud_Creature_<物种>_<序号>` | `CloudSeaCreatureSpecies`（物种 → 行为族与巡游参数）、`CloudSeaBrain.Create`（物种 → 控制器） |
| 关节空物体 | 平挂在生物对象下，名字 `J<关节号>_<角色>`；有父关节时 `J<关节号>_P<父关节号>_<角色>`。位置 = 物体空间的静止位置，无旋转、缩放 1 | `CloudSeaLife.ReadRig` → `CloudSeaRig` |
| uv |（关节号 A，权重 A） | `CloudSeaSkin` |
| uv2 |（关节号 B，权重 B）；没有第二个影响时权重 0 | `CloudSeaSkin` |
| uv3 |（1，个体种子）：`x = 1` 是「这个顶点要蒙皮」的标记；海草 / 珊瑚 / 岩石没有这一层 | `CloudSeaSkin`（没有标记就不蒙皮） |

关节号是**全场景统一编号**（`creature_kit.bind_joints` 按对象名排序分配），蒙皮缓冲按它寻址，
所以两只生物不能重号。父关节号一定小于子关节号——骨架按关节号排完就是「父在子前」。
**物体空间是「x 前、y 上、z 侧、米」**：`CloudWalk.fbx` 导出时把 Z-up → Y-up 的轴向转换烘进了
顶点（`ST.export_fbx(..., bake_space_transform=True)`，只有这个套件这样导），对象变换只剩偏航。

**角色名是两边共用的关键字**，控制器按它找关节，改了名字两边要一起改：

| 物种 | 关节（驱动链的节点按从头 / 从根到梢排） |
| --- | --- |
| 鱼类（小丑鱼 / 蓝吊 / 黄吊 / 银鱼 / 剑鱼） | `s0…` 脊链 · `finL` / `finR` 胸鳍根（挂在 `s0` 上）；鱼群里每条鱼前面加 `f<i>` |
| 河豚 | `body` · `spike` 刺（挂 `body`）· `finL` / `finR` · `tail` |
| 魔鬼鱼 | `body` · `wL0…3` / `wR0…3` 翼（翼根 → 翼尖，逐级父子）· `tail0…4` 细尾 |
| 海龟 | `body` · `n0…2` 颈（根 / 头基 / 吻）· `fL0…2` / `fR0…2` 前鳍 · `bL0-1` / `bR0-1` 后鳍（挂 `body`） |
| 海马 | `p0…9`（卷尾 → 颈）· `head`（挂 `p8`）· `fin` 背鳍（挂 `p5`） |
| 水母 | `rim` / `mid` / `apex` 钟口 / 中段 / 钟顶 · `t<i>_0…` 触手 · `a<i>_0…` 口腕 |
| 章鱼 | `body` · `mantle`（挂 `body`）· `w<a>_0…` 八条腕 |
| 海葵 | `base` · `f<i>_0…` 触手 |
| 螃蟹（横爬 / 挥钳） | `body` · `eyeL` / `eyeR` 眼柄根 · `aL_0…2` / `aR_0…2`（肩 / 肘 / 螯）· `lL<i>_0…3` / `lR<i>_0…3`（髋 / 膝 / 踝 / 尖） |
| 海星 | `centre` · `w<a>_0…2`（中心 / 腕中 / 腕尖） |

**链**：一条链是一串节点关节，第 k 节骨骼从节点 k 指向节点 k + 1、绕节点 k 转。放样身体（鱼身、
翼面）的顶点沿链连续插值，弯出来是平滑曲线；管（腿、触手、腕）按截面站给，中间的站对前后两节
各一半；眼、鳍、刺这类小件整件刚性挂在一个关节上。

### 3.2 Blender 侧

- `creature_kit.Creature` 是建模累加器：`joint` / `chain` 登记关节，`add(skin=…)` 给顶点绑权重，
  `append` 把一只建好的生物整体搬进来（鱼群用：关节角色名前加 `f<i>`、蒙皮随顶点一起搬），
  `to_object` 把权重落成三套 UV。每个顶点都必须绑到关节上，没绑当场抛。
- `mod_creatures.py` 是各物种的建模函数与摆放表（放哪一片水、几只、什么种子），固定种子重跑同图。
- 总装（`assemble_cloudsea.py`）在导出前跑 `bind_joints`：统一编号、把网格里的本地关节号换成全局号、
  给每个关节落一个空物体，随生物一起导出。
- 自检工具：`preview_creatures.py` 出每个物种一件的排排坐图；`preview_gameview.py` 按默认机位出
  整景图与「哪片水读得到」的可见性图，摆放按它定——云台的裙摆会挡住它后下方的水，默认取景下
  读得到的有三片：西南前湾、东南湾、南侧前带。
- 俯视下挑朝向的生物朝向不随机（`FACING_YAW`，固定成横对默认机位）：侧扁的（海马）只有侧面朝着
  机位才读得出，背对镜头就是一根竖条；放射状的（海星）一条腕正对镜头会被压成竖条，整只读成三叉戟，
  让一条腕横对画面才是干净的星形。镜头能拖拽旋转，这条只对默认机位负责。

### 3.3 Unity 侧数据流

```
CloudSeaLife.Start
  子树里按前缀找 Cloud_Creature_* ─→ ReadRig（空物体 → 静止位置 / 父关节）
                                     ─→ CloudSeaBrain.Create(骨架, 种子)
                                     ─→ 按最大关节号建 ComputeBuffer，绑成全局 _CloudSeaJoints
CloudSeaLife.Update（每只）
  挪对象（鱼群 / 游泳者 / 水母的水平路径）→ 装帧信息（位姿 / 速度 / 海床采样 / 巡游带）
  → Brain.Step：解骨架，关节矩阵写进缓冲的暂存
  → 全部生物写完后整块 SetData + SetGlobalBuffer
CloudSeaUnderwater 的前向与投影通道
  CloudSeaSkin：读 uv 上的关节号与权重，从 _CloudSeaJoints 取矩阵，自己蒙皮
```

**关节的两种驱动方式**（`CloudSeaRig`）：

- **绝对**（`SetPose`）：求解器直接写关节在物体空间里的矩阵。链上的节点都是这样，没有父关节。
- **局部**（`SetLocal`）：只写自己相对静止姿态的形变（绕自己的静止位置转 / 缩放），合成时乘上父关节
  的矩阵。挂在别的关节上的小件用这种方式——鳍跟着鱼头、刺跟着河豚身体、翼尖跟着翼根。

关节矩阵是一个仿射，三行 =「旋转 × 缩放」的行加平移，与缓冲里一个关节的三行同构，解出来原样上传。

**蒙皮缓冲**（`CloudSeaSkin`）：全局 `StructuredBuffer`，不走 SkinnedMeshRenderer、不用
MaterialPropertyBlock——水下材质按颜色共享（橙色既是小丑鱼也是海星），蒙皮数据不能挂在材质上；
MaterialPropertyBlock 还会让渲染器掉出 SRP Batcher。全局槽位上永远绑着一份合法缓冲：没人在驱动
生物时（编辑器预览、脚本重载后）是一份单位矩阵关节，开关 `_CloudSeaSkinOn` 为 0，shader 直接跳过。

### 3.4 运动学工具（`CloudSeaKin.cs`，纯 C#）

| 工具 | 解什么 | 用在哪 |
| --- | --- | --- |
| `CloudSeaAffine` | 关节矩阵：绕支点旋转、把一个方向转到另一个方向的最小旋转、绕支点缩放、节段映射 | 所有关节 |
| `TwoBone` | 两骨解析 IK：够得着末端落在目标上，够不着停在伸直能及的位置，中关节鼓向提示的一侧 | 蟹腿、螯、海龟鳍肢与颈、海星腕 |
| `Fabrik` | 多节链迭代到目标，每轮把中间节点往一条「提示线」拉一段 | 章鱼腕（拱起来）、海马身（保持卷曲） |
| `CloudSeaStrand` | Verlet 质点链：只靠位置推进，节段长度靠约束保持 | 水母触手、海葵触手、魔鬼鱼细尾 |
| `CloudSeaSpring` | 阻尼弹簧的闭式步进，帧长再大也不发散 | 车身悬挂、鼓胀、升沉、眼柄滞后 |
| `CloudSeaFoot` | 一只踩地的脚：踩实钉在锚点上，迈步沿弧线到新落点 | 蟹腿、海星腕尖、章鱼腕尖 |
| `CloudSeaFollowChain` | 追随链：头两节钉在头架上，其余节点被自己上一帧的位置拖着走，只允许相对前一节弯有限角度，再叠一道从头往尾走的尾波 | 鱼身 |

### 3.5 各物种怎么解

| 物种 | 怎么动 |
| --- | --- |
| 鱼群 | 每条鱼是一个有质量的点：被弹簧拉向自己在群里的位置、和同伴互相避让、各自游移——群不是一块刚体，拐弯时外侧的鱼会被甩开一点再追回来。身体是追随链：头真的在空间里走，身后被拖着走，拐弯就弯进弯里；摆头带出尾波，游得越快摆得越快越大。胸鳍划水 |
| 剑鱼 | 头钉在对象上，身体是同一条追随链（节更多、更慢） |
| 河豚 | 划水到最低点给身体一个上冲，升沉是弹簧的响应；隔一阵鼓一次——身体与刺各挂一个关节、刺放得更多，鼓起来刺先冒头；鼓着的时候推不动水，巡游跟着慢下来 |
| 魔鬼鱼 | 翼沿翼展一道行波（每节相对前一节绕前向轴摆，越靠翼尖越大、越滞后）；转弯时两翼一起偏，配合对象自身的侧倾；细尾是 Verlet 链，被水阻甩在路径上 |
| 海龟 | 前鳍两骨 IK 绕肩划一圈（下划往后扫、上抬往前送，左右自然交替）；后鳍小幅打舵；脖子两骨 IK 追一个慢慢游移的张望点，隔一阵缩一次脖子 |
| 海马 | 尾尖锚定，身体 FABRIK 弯向张望的方向、每一轮都被静止体形往回拉一点（保持卷曲）；管吻慢慢扫过一片 |
| 水母 | 钟体是「发放—松弛」：慢变量攒满就发放一下，收缩量走弹簧（带一点过冲）；收缩得越快推力越大，自身略重于水又受水阻——每收缩一下往上窜一截再慢慢沉，整体停在巡游带里（离水面越近推得越轻）。触手与口腕是 Verlet 链：钟体上窜时张开，缓沉时收拢 |
| 章鱼 | 身体慢逛。八条腕 FABRIK：腕尖踩在沙上，身体走远了才抬起来迈到前方的落点，相邻的腕不同时抬；每轮迭代后把中间节点往拱线拉，腕是拱着的、不进沙。同一时间有一条腕不踩地，腕尖贴着沙面往前游移到几乎整条臂长——伸出去摸，不是举过头顶 |
| 蟹（横爬） | 八条腿两骨 IK，脚踩在锚点上；锚点离「该在的位置」越过阈值才迈步，同侧相邻的腿和另一侧的同序号腿都踩着才许抬（交替步态），够不着了必须立刻迈。迈的是小碎步：一步约 0.1 秒、抬不到 0.1。车身挂在弹簧上：高度跟脚下的沙面、每次落脚被压一下、左右与前后的沙面高差让它侧倾 / 俯仰。膝盖朝外上，向上的分量压着，不冒出壳顶。眼柄顺着速度往后倒（有滞后）。螯端在身前随车身轻晃 |
| 蟹（挥钳） | 腿踩着不动，两只螯按节奏一上一下地举（两骨 IK），车身跟着摇 |
| 海星 | 中心慢逛。五条腕两骨 IK，腕尖各踩一个锚点，按一条慢转的步态时钟绕着五条腕轮一圈依次迈（又慢又低的一小步）。关节在沙面平面里弯向**行进方向的反侧**、只略微离沙：踩着的腕尖不动、中心往前走，腕就被拖弯；迈一步伸出去又拉直——一条弯沿着五条腕轮着走，翻着往前挪。不让它往上拱，理由见 §7 |
| 海葵 | 每根触手一条 Verlet 链：受浮力站着、被水流的阻力推着走、又被「顺着上一节直着长」的回复力拉回；水流是慢慢游移的场，整丛各摆各的 |

### 3.6 谁管整只的位移

- **鱼群 / 单体游泳者 / 水母**：水平路径在 `CloudSeaLife`（解析的圆 / 8 字 + 漂移，没有碰撞体、
  没有刚体），朝向由速度推出、以有限角速度追随；控制器只管肢体。水母的**升沉**反过来，由控制器
  推出来、`CloudSeaLife` 套到对象上。
- **蟹 / 海星 / 章鱼 / 海马 / 海葵**：对象不动，整只的位移在骨架里做——脚要踩在**世界里的锚点**上，
  对象一动锚点就跟着跑。代价是没人替自定义蒙皮更新渲染器包围盒，所以贴底生物的包围盒按物种表的
  活动半径放大一圈。

### 3.7 为什么自己写求解器、为什么自定义蒙皮

- **求解器自己写**：开源的 IK 库操作的是 Transform，接不进纯 C# 核心。云端漫步的核心逻辑一律写成
  纯 C# 静态类以便无头测试，运动学工具也照这条口径——只用 `Vector3` / `Mathf` 的托管数学，
  验证台里能直接跑上千帧。
- **自定义蒙皮**：SkinnedMeshRenderer 要 CPU 侧读得到网格数据来建骨骼与权重，而导入网格在运行时
  不可读；把权重留在 UV 上、让顶点着色器自己读，运行时一行网格数据都不用碰，骨架也不必是
  Transform 层级。前向与投影两个通道调同一个蒙皮函数，
  影子和身体自然同步。

## 4. 比例尺与尺寸

换算基准：**角色造型总高 2.0321 世界单位 = 1.75 m**（`CrewMeshLibrary.TotalHeight`），
即 **1 单位 = 0.861 m**。场景里的「米」都按这个口径读。生物的尺寸以 `mod_creatures.py` 为准，
量级如下：

| 项 | 单位 | 米 |
| --- | --- | --- |
| 水面到沙脊顶 | 1.85 | 1.59 |
| 水面到洼底 | 2.65 | 2.28 |
| 小鱼（小丑鱼 / 蓝吊 / 黄吊）体长 | ≈ 1 | ≈ 0.9 |
| 银鱼体长 | 0.62 | 0.53 |
| 剑鱼体长（含吻） | ≈ 2.9 | 2.5 |
| 魔鬼鱼翼展 | 3.2 | 2.8 |
| 海龟壳长 | 1.4 | 1.2 |
| 水母全高 | 1.5 | 1.3 |
| 螃蟹壳宽 / 腿展 | 0.34 / ≈ 0.77 | 0.29 / 0.66 |
| 海星直径 | 0.92 | 0.79 |

螃蟹在 `mod_creatures.py` 里按原尺寸建模，整件再乘 `CRAB_SCALE`；Unity 侧的步态常数按身体高度
换算到当前尺寸（§3.5），所以改它的大小只动这一个系数和物种表里的半径。

## 5. 资产与接线

### 5.1 管线

| 步 | 入口 | 产物 |
| --- | --- | --- |
| 建模 | `tools/blender/scene/cloudsea/assemble_cloudsea.py`（分件 `mod_sea` / `mod_clouds` / `mod_sky` / `mod_life` / `mod_creatures`；材质槽与基色在 `tools/blender/scene/style_tokens.py`） | `CloudWalk.fbx`（材质内嵌，槽名一律 `Cloud_*`；生物带关节空物体与三套 UV） |

烘焙器每次从 FBX 重新实例化根，所以**根组件的参数一律是脚本默认值**；要改运行时行为改脚本的
字段默认值，再重烘。手调值只留在材质资产上（烘焙器不覆盖，见 §5.4）。

### 5.2 材质分流：对象名即契约

`CloudSeaMaterialRoute.Of(对象名)` 决定一件东西走哪条着色路线（纯 C#、有契约测试）：

| 路线 | 判据 | shader |
| --- | --- | --- |
| 水面 | 对象名 = `Cloud_Sea_Surface` | `CloudSeaClearWater` |
| 海床 | 对象名 = `Cloud_Sea_Bed` | `CloudSeaSeabed` |
| 水下生态 | 对象名以 `Cloud_Sea_` / `Cloud_Creature_` / `Cloud_Bubbles_` 开头 | `CloudSeaUnderwater` |
| 其余（云体、云台、道具） | 不匹配以上 | 物体 shader（运行时由 `PostLineMaterialSwapper` 换到 ToonLit）；水洼 / 玻璃 / 云瀑水墙走透明趟 |

同一个源材质名落在不同路线上时，烘焙器按路线分别建材质，资产名加路线后缀
（如 `Cloud_Sand_Underwater` / `Cloud_Sand_Seabed`）；只落一条路线的保留原名。

### 5.3 运行时组件

| 组件 | 职责 |
| --- | --- |
| `CloudSeaWater` | 云台水洼、玻璃、云瀑水墙的材质装配；域闸门全局、岛影交界线的波、水面高度每帧下发 |
| `CloudSeaWeather` | 太阳雨、云隙光、彩虹；涟漪（单位方片 + `CloudSeaRipple`，逐涟漪一份材质带相位与周期） |

### 5.4 烘焙器写什么

对每个材质槽，烘焙器只重写三类内容，其余参数留在材质资产上不被覆盖：
**shader**、**固有色**（取自源材质）、**路线开关**（海床图案开关、海草的双面受光与摆幅、薄片的
纯平乘色）。海面材质是专用资产，水色在材质上直接配、不从源材质取色。落盘后逐槽复检 shader 口径，
不对就整次烘焙报错。

烘焙器还有两道**硬门禁**，不过就带着问题清单收口、不出 prefab：

- **变换口径**（`VerifyCreatureAxes`）：生物对象的本地旋转必须是纯偏航、缩放等比。关节矩阵按
  「物体空间 x 前、y 上、z 侧」写，导入器一旦在对象上留下别的轴向后，鱼会侧着躺，而且不报错。
- **骨架契约**（`VerifyCreatureJoints`）：每只生物身下要有 `J<关节号>_…` 的关节空物体，位置是米级
  的纯平移；网格三套 UV 齐全，每个顶点的关节号必须是这只生物自己的、是精确整数、权重和为 1；
  全场景关节号不重号；父关节排在子关节之前。运行时按同一套读法解骨架，这里不拦，错了的表现是
  鱼头和身体分家、或者两只生物互相带动。

全部在材质 Inspector 里（分组标题是英文——见 §7 的 ASCII 约束），中文说明在属性名上。

| 想改什么 | 动哪里 |
| --- | --- |
| 看清海床的程度 | 水面 `_WaterOpacity`；岛影里再加深多少 ↔ `_ShadowOpacity` |
| 水色 | `_SunWaterColor` / `_ShadowWaterColor`；亮带 ↔ `_CrestColor` + `_CrestCoverage` + `_CrestScale`；碎金 ↔ `_SparkleColor` + `_SparkleThreshold` |

## 7. 约束与坑

- **Inspector 分组标题只能写 ASCII**：ShaderLab 的 `[Header(...)]` 不接受中文，写了整段 Properties
  解析失败、shader 名字为空、全场景不渲染且不报编译错。分组标题用英文短语，中文写在属性显示名上。
- **颜色是 sRGB**：ShaderLab 颜色默认值、材质里的颜色属性、Inspector 取色器同一口径——按 sRGB 写，
  引擎上传时转线性。脚本 `SetColor` 不要先 `.linear`。
- **取色链的双重转换（既有问题，未处理）**：烘焙器经 `PixelartMaterialFactory.TryGetAlbedo`
  取源色，`GetColor` 返回线性值后被原样 `SetColor`，等于多转了一次——云海家族的固有色实际比
  Blender 色卡上写的更深更饱和。改这条链会连带改变全场景配色，须创始人裁决。
- **`CloudWalk.fbx` 的导出口径与别的套件不同**：这个文件用 `bake_space_transform=True` 导出，物体空间是
  「x 前、y 上、z 侧、米」，对象变换只剩偏航；别的套件仍是「轴向转换留在对象变换上」。给这个套件写
  顶点着色器或朝向代码时按前一种口径，烘焙器的变换门禁兜底。
- **关节空物体必须平挂**：Blender 导出嵌套的空物体会换一套约定（位置用米、带旋转与缩放），和平挂的
  对不上。父关节写在名字里（`J<号>_P<父号>_…`），不靠层级。
- **Blender 脚本抛了异常，进程退出码仍是 0**：判断总装成没成看 `ASSEMBLE_OK`，别只看退出码。
- **关节号存在 float 里**：导入器若把 UV 压成半精度，两千以上的关节号会失真。关节总数要留余量；
  骨架门禁会拦住不整数、不属于本生物的关节号。
- **可变结构体字段不能声明成 `readonly`**：对只读的结构体字段调方法改的是一份副本，状态永远不更新，
  编译器不报。弹簧状态（`CloudSeaSpring`）一律用普通字段。
- **`TryGet(role, out index)` 失败时也会把 `index` 写成 0**：不判断返回值就把 0 当关节号用，会改到
  第一个关节（比如把鱼头骨骼当成鳍）。只在返回 true 时赋值。
- **链的节点从头 / 从根排到梢**：节段矩阵按「静止方向 → 现在方向」转，头尾颠倒就是尾巴朝前游。
  `CloudSeaKinTests` 有一条用例专门守这个。
- **两骨 IK 的弯向提示只给方向**：`TwoBone` 把提示去掉沿链分量后取单位向量。链只要有余量，中关节
  就一定鼓出完整的一截，提示只决定鼓向哪边。所以「往上拱一点」做不到——链有 0.12 的余量，中关节就
  拱 0.12，俯视下海星读成一只撑在地上的手。要它低：把弯向放在沙面平面里，余量只占很小一点向上。
- **弯向提示要逐链取**：拿一个固定方向做提示，和它平行的那条链取完垂直分量只剩「向上」，照样立起来。
  提示得是「垂直于这条链」的方向，符号另选。
- **`CloudSeaFoot.Lift` 的参数是（落点，时长，抬高）**：调用处按这个顺序写。时长与抬高都是零点几的
  数，传反了不报错，表现是步子忽然变得又慢又低（或反过来）。
- **贴底生物的落点别用净空格**：净空格取半格内最高，斜坡上比沙面高。控制器找落点用的采样必须是贴地格。
- **出图模式开局有大帧**：抓帧、回读让前几帧很长（实测峰值 0.29 秒）。控制器每一步都要对大帧长稳健
  （弹簧用闭式步进、Verlet 用时间校正），别按「每帧 1/60 秒」写假设。
- **FBX 对象的本地量不可当世界量**：要世界尺寸取 `Renderer.bounds`，再用 `InverseTransformPoint`
  换回要用的那个本地空间。
- **透明队列用 `Transparent+1`**：标准透明趟的收件下界是 3001（口径见 `CloudSeaRain.shader` 头注）。
- **海床高度分档用世界 Y**：`_HighY` / `_LowY` 以 CloudWalk 根的世界高度 0 为基准，整件 prefab
  上下挪了位置要同步改。
- **海草摆动写在两个通道里**：前向与投影各自调用同一位移函数，影子才和草同步摆。
- **像素级平移补偿未接线**：PostLine 上采样的亚纹素补偿由相机 snap 侧负责，目前不在范围内
  （见渲染管线.md），镜头拖动时像素格可能有半格漂移。
- **阴影只在本关打开**：别的关卡要投影照 `CloudSeaSunShadow` 另接。
- **正交相机下别把主光级联当成「谁给谁投影」的保证**：级联按离相机多远切球，遮挡物与受影物沿视线方向
  一错开就不同级，受影点在画面外围还会落到所有级之外，查到的都是「没被挡」、也不报错。海面、海床、水下物与
  ToonLit 受影物一样在约束之内，单列在待办。
- **世界位置要逐分量拼**：`float3(ws.xz + 偏移, ws.y)` 拼出来的是 (x, z, y)，不是 (x, y, z)——探点被换到
  十几米外，查阴影永远「没被挡」，还不报错、画面上只是「影子没出现」。写 `float3(ws.x + o.x, ws.y, ws.z + o.y)`。
- **水下物不描边，别给它加预通道**：给 `CloudSeaUnderwater` 加 `DepthOnly` / `DepthNormals`（或开 Fallback），
  水下物全部进 PostLine 的描边预通道，整片水里冒出墨线。给水下域另配线色（统一深蓝、淡蓝软边、本色混浅蓝、
  本色偏蓝）也都试过，创始人逐个否决。再想动之前先拿参照图问清；下面三条是当时踩出来的事实。
- **出没出线按高度算，别靠看图猜**：30° 俯角的正交相机下，高出沙面 h 的物体，剪影判据量到的是 2h
  （它挡住了身后 1.7h 远的沙面）。细管（蟹腿、触手）背光面本来就是暗色调，缩略图里像一圈线。
- **沙面上起断线只有两个来源**：折射把相邻像素错开（连续坡面被当成落差），和海床上高出阈值的小台阶
  （被当成物体）。给水下域降阈值、让描边跟随折射，都会把它们带出来。
- **落在水面上的线像素，深度取到的是海床**：水面不写深度。只按「像素在不在某条高度线以下」判断，
  会把云台、船员衬着水面的线也算成水下线。

## 8. 验证与出图

- **纯逻辑**（无头验证台，秒级，不开 Unity）：运动学工具与各物种控制器（`CloudSeaKinTests`：
  IK 的可达与伸直、链长保持、弹簧在任何帧长下收敛、踩地的脚踩实后不动但确实迈步、每个物种跑上千帧
  矩阵有限且链不断开、鱼身拖在运动方向的反侧）、物种表（`CloudSeaCreatureSpeciesTests`）、
  材质分流（`CloudSeaMaterialRouteTests`）、海床高度格（`CloudSeaBedGridTests`）、水洼材质开关
  （`CloudSeaWaterMaterialTests`）。
- **烘焙**：`tools/headless/run.sh chain "PirateCrew.EditorTools.CloudSeaAssetBaker.BuildAll;PirateCrew.EditorTools.SceneSetup.BuildAll"`
  （改了 manifest / 程序集定义才需要另跑 `open` 档）。日志里的「生物变换抽样」「水下生物骨架核对」
  两行是导入后实际数值的对照点。
- **出图**：`BattleHudScreenshot.CaptureHeadless`，必须带图形设备（禁 `-nographics`）。
  环境变量：`PC3D_CAPTURE_LEVEL=1`、`PC3D_RENDER_STYLE=postline`、`PC3D_PIXEL_SCALE=2`、
  `PC3D_CAPTURE_DIR=<输出目录>`；序列模式加 `PC3D_CAPTURE_FRAMES=<帧数>`，帧数用完序列就结束。
  诊断用：`PC3D_CAPTURE_HIDE=Cloud_Sea_Surface` 出「干图」（只看海床与生态，看影子和贴地最清楚）；
  改取景要三件一起给——`PC3D_CAPTURE_CENTER`（非空才生效）+ `PC3D_CAPTURE_CENTER_XZ=x,z` +
  `PC3D_CAPTURE_VISIBLE=<可见米数>`（直接定像素密度），受相机驱动的正交下限约束；
  `PC3D_CLOUDSEA_POSE_DUMP=<文件>` + `PC3D_CLOUDSEA_POSE_TIME=<秒>` 到时刻把全部生物的关节坐标落盘
  （时刻必须早于序列结束，否则落不出来）。
- **看什么**：无洋红、无 shader 报错；水下物没有描边（云台、船员的线照常）、沙面上没有断线；云台的影子在
  水面与海床上都看得到（隔着水面有视差错位），海床那块里没有焦散，影边随云漂移逐帧连续移动；焦散与碎金只在阳光区；生物立着、肢体连续、鱼头朝前、踩地的脚不滑；
  静帧看不出动画，验收出 GIF。

## 9. 已知不足

- **折射很轻**：偏移量在 1–2 个艺术像素量级，静帧里几乎看不出，动态下是「缓慢晃动」而不是
  明显的水面扭曲。要更夸张直接加 `_RefractionPixels`。
- **生物之间不互相回避**：剑鱼会从鱼群里穿过去，蟹与海星各走各的。
- **步态与链的参数是手调常数**：只有蟹的控制器按身体高度把长度、速度换算到当前体型；其余控制器
  的阈值、频率、幅度是绝对值，换一种尺寸的物种要重新调。
- **贴底生物的活动范围写了两处**：控制器里的巡逻 / 慢逛常数，与物种表里放大包围盒用的半径。
  后者盖不住前者时它会走出包围盒被剔除（验证台有一条用例兜着几个主要物种）。
- **涟漪环很小**：涟漪半径不到一个单位，在默认机位下只是水面上的几个小圈。
- **正交相机下主光级联的问题还在**（见 §7）：画面外围、或遮挡物与受影物沿视线错开时，影子会缺；海面一族与 ToonLit 受影物都在约束之内。
- **贴地格是「最近顶点 + 双线性插值」**：格距一米，两个顶点之间的沙面是弯的时候，贴地的脚最多离地
  或入地几厘米。
- **朝向表只对默认机位成立**：`FACING_YAW` 是按默认相机的视线方位挑的，镜头拖到另一侧，海马可能又
  读成竖条、海星的腕又会压向视线。
