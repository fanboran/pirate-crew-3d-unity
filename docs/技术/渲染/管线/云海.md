# 云海

> **本文是什么**：第 1 关「云端漫步」空岛下方那片海的技术口径——清澈透明的水面、起伏海床、
> 水下生态与水面点缀各自怎么画、资产怎么接线、尺寸按什么比例尺换算、调参从哪下手、有哪些坑。
> 只写「是什么 / 怎么设计 / 为什么这么设计」。
> **口径来源**：[渲染管线.md](渲染管线.md)（PostLine 链与描边机制）、
> [01-云端漫步.md](../../../设计/关卡/01-云端漫步.md)（观感与验收）。全海域的大洋不在本文
> （[海面.md](海面.md)）；本关不铺全局 OceanRig。

> **结论先行**：海面拆成**互不抢活的三层**，各一支自带标准前向 pass 的 shader——
> ① 透明水面（岛影两档 + 像素折射 + 阳光区亮带碎金）从 `_CameraOpaqueTexture` 透出水下；
> ② 海床（高度分档沙色 + 阳光区焦散 + 岛影）；③ 水下生态（固有色三档色带 + 海草摆动 + 投影）。
> 程序纹理一律在**艺术像素中心**求值；水下物不进描边后处理，鱼靠自带的墨线壳保证隔水可读。
> 水面/海床/生态都是「颜色不乘光照」的定色画法，改观感只动材质上的颜色与阈值。

---

## 1. 画面结构

| 层 | 件 | 画法 | 渲染队列 / 通道 |
| --- | --- | --- | --- |
| 水面 | `Cloud_Sea_Surface` → `CloudSeaClearWater` | 从不透明贴图透出水下，叠「阳光水色 / 岛影水色」两档；折射偏移取整到艺术像素；阳光区有漂移亮带与碎金；顶点微起伏 | 透明（`Transparent+1`），不写深度 |
| 海床 | `Cloud_Sea_Bed` → `CloudSeaSeabed` | 按世界高度分档的沙色、沙纹、藻斑、碎石；阳光区焦散亮网；坡面两档 × 岛影两档 | 不透明；带深度/法线通道（云台立柱的水下段照常描边） |
| 水下生态 | `Cloud_Sea_*` / `Cloud_FishSchool_*` / `Cloud_Crab_*` / `Cloud_Bubbles_*` → `CloudSeaUnderwater` | 固有色 × 三档色带 × 岛影乘色；海草按「离根高度比」摆动；鱼身带反向墨线壳 | 不透明；带投影通道，**不带**深度/法线通道 |
| 水面点缀 | 涟漪（`CloudSeaRipple`）、雨 / 云隙光 / 彩虹（`CloudSeaRain`）、云台水洼与玻璃（`CloudSeaWater`） | 涟漪是单位方片上的硬边同心环，相位全在 shader 里走时间 | 透明（`Transparent+1` 起） |

水面、海床、生态三层的颜色都是**定色**：shader 里不采样光照强度，只读主光方向定明暗档、读主光阴影图定岛影。

## 2. 关键取舍

### 2.1 取样板：一切在艺术像素中心求值

PostLine 把全分辨率画面降采样到艺术画布再做描边与放大。程序纹理若逐片元求值，同一个艺术像素
内的片元会得到不同结果，降采样后边缘落在像素格中间，色块发虚、细纹理糊成噪点。

云海家族的做法（`CloudSeaCommon.hlsl`）：用屏幕导数把片元位置折算到**所在艺术像素的中心**，
再在该中心的世界位置上求值。于是同一艺术像素内的片元同色，色块边缘天然落在像素格上，
纹理粗细随缩放自动保持整数个艺术像素。消耗的全局（像素比例、单元尺寸、主光方向）由 PostLine
每帧下发，见渲染管线.md。

### 2.2 水下物不描边；鱼自带墨线壳

PostLine 的描边读的是深度/法线预通道。海草逐帧摆动，进了预通道就会每帧描出抖动的墨线；
所以 `CloudSeaUnderwater` **不带**深度/法线通道——水下物在描边判据里不存在。

不描边的代价是小件失去轮廓。隔着一层水色，浅色鱼和沙面几乎同值，所以鱼身的剪影由网格自己带：
Blender 侧给鱼身加一圈**反向外壳**（顶点沿平滑法线外推、绕序反转），配 `Cull Back` 只留远侧，
在鱼身剪影外露出深色一圈。墨线色在烘焙器里定值（`CloudSeaAssetBaker.InkLineColor`），不从
源材质取色——它是可读性设计的一部分，不跟调色板的取色链走。海草、珊瑚不额外加外壳。

### 2.3 岛影：本关专属的主光硬阴影

战斗主光创建时不投影（见渲染管线.md）。第 1 关在 CloudWalk 根上挂 `CloudSeaSunShadow`，
运行时把主光切成硬阴影、阴影强度置 1——云台、单位、海鸥、水下物全都投真影。

- **水面**在水面位置采阴影图：落在水面上的是云岛与飞行物的影子。水下物在水面之下，
  物理上不可能在水面投影，所以不需要任何排除逻辑。
- **海床与水下物**各自在自己的位置采同一张阴影图：鱼、蟹、珊瑚的影子落在沙面上。
- 两档硬切：`step(切点, 距离衰减 × 阴影衰减)`。主光没开阴影时衰减恒为 1，整片算阳光，不报错。

水面与海床的岛影在屏幕上有视差错位（两层高度不同），这是真实投影的必然结果，保留。

### 2.4 折射：偏移取整到艺术像素

折射不是连续的 UV 偏移，而是「世界格内同值 + 时间分格」的低频噪声给出方向，偏移量**取整到
艺术像素**。水下画面成片缓移、按固定帧率跳格，不产生亚像素抖动，也不逐帧闪烁。

**深度安全门**：折射点的场景深度若比水面还近（云台、立柱），该像素回退为不偏移，
不把前景物体的边拽进水里。

### 2.5 颜色不乘光照

水面、海床、生态的颜色都是对着调色板配的定色：明暗只分档（水面的阳光/岛影、海床的坡面两档、
生态的三档色带），不做连续渐变。理由有两条：连续渐变降采样后会产生非板色中间调；
「隔一层水色还读得出固有色」要求水下小件足够亮，乘真实光照会把它们压暗。

### 2.6 深浅靠海床高度，水色不随深度变

水色不透明度是常数（岛影区另加一档），「浅处暖沙、深处偏青」全部由**海床的高度分档**给出：
沙脊顶暖沙色，洼地偏青绿。这样水色的职责只有「是一层水」，深浅读数交给海床自己，
两者不会互相打架，也不会出现按屏幕深度推算的渐变带。

### 2.7 活物贴床：海床高度格

海床是起伏沙丘，脊顶与洼底相差近一个单位。活物若按固定深度带走，要么扎进沙脊，要么整群被顶到
水面附近。烘焙时从海床网格采样出一张均匀方格（`CloudSeaBedGrid`，纯 C#、无头可测：格点取
周围半格内**最高**的顶点，空格由四邻逐圈填满），写进 `CloudSeaLife`。运行时：

- 鱼：下沿 = 中心与前后左右四个偏移点里最高的沙丘 + 鱼群半高 + 余量；上沿夹在巡游带上沿之内
  （不出水）。两者冲突时以不出水优先。
- 蟹：脚底 = 脚下沙丘高度 + 建模时贴床的高差。

**半高必须用渲染器的世界包围盒换算回根空间**：FBX 导入的鱼群对象带 90° 轴向旋转与 100 倍缩放，
`sharedMesh.bounds` 是网格本地系的小数——拿它算净空会出错（把水平半宽当成半高，整群被顶出水面）。

## 3. 比例尺与尺寸

换算基准：**角色造型总高 2.0321 世界单位 = 1.75 m**（`CrewMeshLibrary.TotalHeight`），
即 **1 单位 = 0.861 m**。场景里的「米」都按这个口径读。

| 项 | 单位 | 米 |
| --- | --- | --- |
| 角色造型总高（基准） | 2.0321 | 1.75 |
| 水面到沙脊顶 | 1.85 | 1.59 |
| 水面到洼底 | 2.65 | 2.28 |
| 鱼——体干（真实比例） | 0.29–0.42 | 0.25–0.36 |
| 鱼——含尾长（现行，卡通化放大后） | 0.83–1.22 | 0.71–1.05 |
| 鱼——背鳍尖到腹鳍尖 | 0.30–0.45 | 0.26–0.39 |
| 鱼身墨线壳厚度 | 0.05 | 0.04 |
| 螃蟹（壳宽） | 约 0.8 | 约 0.7 |

**鱼为什么放大**：鱼群要隔着水色读得出，体长在屏幕上至少约 20 艺术像素。按相机契约的恒定密度
（`CameraFraming.WorldPerPixel = 1/24`，1 单位 = 24 艺术像素），体长要接近 1 单位；真实比例的鱼
只有 0.33–0.47 单位长，在屏幕上不到 12 像素。现行做法是把鱼卡通化放大到体长约 1 单位，
与约 0.7 m 宽的螃蟹是同一档夸张。倍率是 Blender 侧的单个常量（`mod_sea.FISH_SIZE`），
群内散布随之间距不变地放开（`FISH_SPREAD`），跃水鱼按同一比例同步放大。

## 4. 资产与接线

### 4.1 管线

| 步 | 入口 | 产物 |
| --- | --- | --- |
| 建模 | `tools/blender/scene/cloudsea/assemble_cloudsea.py`（分件 `mod_sea` / `mod_clouds` / `mod_sky` / `mod_life`；材质槽与基色在 `tools/blender/scene/style_tokens.py`） | `CloudWalk.fbx`（材质内嵌，槽名一律 `Cloud_*`） |
| 烘焙 | `CloudSeaAssetBaker.BuildAll` | `CloudWalk.prefab`（FBX 嵌套实例 + 材质覆写 + 根组件）→ `RuntimeSceneArt.cloudFieldPrefab` |
| 运行时 | 战斗场景实例化 `CloudWalk.prefab` | 根上四个组件：`CloudSeaWater` / `CloudSeaWeather` / `CloudSeaLife` / `CloudSeaSunShadow` |

烘焙器每次从 FBX 重新实例化根，所以**根组件的参数一律是脚本默认值**；要改运行时行为改脚本的
字段默认值，再重烘。手调值只留在材质资产上（烘焙器不覆盖，见 §4.4）。

### 4.2 材质分流：对象名即契约

`CloudSeaMaterialRoute.Of(对象名)` 决定一件东西走哪条着色路线（纯 C#、有契约测试）：

| 路线 | 判据 | shader |
| --- | --- | --- |
| 水面 | 对象名 = `Cloud_Sea_Surface` | `CloudSeaClearWater` |
| 海床 | 对象名 = `Cloud_Sea_Bed` | `CloudSeaSeabed` |
| 水下生态 | 对象名以 `Cloud_Sea_` / `Cloud_FishSchool_` / `Cloud_Crab_` / `Cloud_Bubbles_` 开头 | `CloudSeaUnderwater` |
| 其余（云体、云台、道具） | 不匹配以上 | 物体 shader（运行时由 `PostLineMaterialSwapper` 换到 ToonLit）；水洼/玻璃/云瀑水墙走透明趟 |

同一个源材质名落在不同路线上时，烘焙器按路线分别建材质，资产名加路线后缀
（如 `Cloud_Sand_Underwater` / `Cloud_Sand_Seabed`）；只落一条路线的保留原名。

### 4.3 运行时组件

| 组件 | 职责 |
| --- | --- |
| `CloudSeaWater` | 云台水洼、玻璃、云瀑水墙的材质装配与域闸门全局下发 |
| `CloudSeaWeather` | 太阳雨、云隙光、彩虹；涟漪（单位方片 + `CloudSeaRipple`，逐涟漪一份材质带相位与周期） |
| `CloudSeaLife` | 鱼群巡游与贴床、螃蟹横爬与贴床、停栖海鸥摆动、飞行海鸥与掠水、远景云漂移 |
| `CloudSeaSunShadow` | 打开本关主光硬阴影；光源取 rig 的 sun，否则 `RenderSettings.sun` |

### 4.4 烘焙器写什么

对每个材质槽，烘焙器只重写三类内容，其余参数留在材质资产上不被覆盖：
**shader**、**固有色**（取自源材质；墨线壳与海床沙色另有定值/增益）、**路线开关**
（海床图案开关、海草的双面受光与摆幅）。海面材质是专用资产，水色在材质上直接配、不从源材质取色。
落盘后逐槽复检 shader 口径，不对就整次烘焙报错。

## 5. 调参速查

全部在材质 Inspector 里（分组标题是英文——见 §6 的 ASCII 约束），中文说明在属性名上。

| 想改什么 | 动哪里 |
| --- | --- |
| 看清海床的程度 | 水面 `_WaterOpacity`；岛影里再加深多少 ↔ `_ShadowOpacity` |
| 水色 | `_SunWaterColor` / `_ShadowWaterColor`；亮带 ↔ `_CrestColor` + `_CrestCoverage`；碎金 ↔ `_SparkleColor` + `_SparkleThreshold` |
| 水下画面晃动的幅度 / 快慢 | `_RefractionStrength` / `_WobbleFps`；块的大小 ↔ `_WobbleCell` |
| 岛影边界 | `_ShadowStep`（水面与生态同名；海床是同一个阈值语义） |
| 沙丘起伏读不读得出 | 海床 `_BaseColor`（脊顶）对 `_LowColor`（洼地）的冷暖差；沙纹 ↔ `_RippleSpacing`；藻斑 ↔ `_AlgaeCoverage` |
| 焦散网眼 / 亮线粗细 / 多少 | `_CausticScale` / `_CausticWidth` / `_CausticThreshold` |
| 某件水下物看不清 | 调亮它的材质 `_BaseColor`；暗面太死 ↔ 提 `_ShadowColor` |
| 海草摆幅 / 快慢 / 定帧 | 材质 `_SwayAmplitude` / `_SwaySpeed` / `_SwayFps` |
| 鱼的大小 / 墨线粗细 / 墨线色 | `mod_sea.FISH_SIZE` / `FISH_LINE_W` / `CloudSeaAssetBaker.InkLineColor`（改完重跑总装 + 烘焙） |
| 鱼的巡游带上沿 / 贴床余量 | `CloudSeaLife.fishYMax` / `fishBedClearance`（改脚本默认值后重烘） |
| 涟漪环粗细 / 扩散快慢 / 淡出档数 | `CloudSeaWeather` 的涟漪字段（半径、环宽、寿命、颜色） |

默认值以 shader 的 Properties 与材质资产为准；本文不复述数值。

## 6. 约束与坑

- **Inspector 分组标题只能写 ASCII**：ShaderLab 的 `[Header(...)]` 不接受中文，写了整段 Properties
  解析失败、shader 名字为空、全场景不渲染且不报编译错。分组标题用英文短语，中文写在属性显示名上。
- **颜色是 sRGB**：ShaderLab 颜色默认值、材质里的颜色属性、Inspector 取色器同一口径——按 sRGB 写，
  引擎上传时转线性。脚本 `SetColor` 不要先 `.linear`。
- **取色链的双重转换（既有问题，未处理）**：烘焙器经 `PixelartMaterialFactory.TryGetAlbedo`
  取源色，`GetColor` 返回线性值后被原样 `SetColor`，等于多转了一次——云海家族的固有色实际比
  Blender 色卡上写的更深更饱和。墨线色与海床沙色增益在烘焙器里另配，不受它影响；
  改这条链会连带改变全场景配色，须创始人裁决。
- **FBX 对象的本地量不可当世界量**：导入对象带轴向旋转与单位缩放，`sharedMesh.bounds`、
  `localScale` 都不能直接当米用；要世界尺寸取 `Renderer.bounds`，再除以根的缩放。
- **透明队列用 `Transparent+1`**：标准透明趟的收件下界是 3001（口径见 `CloudSeaRain.shader` 头注）。
- **海床高度分档用世界 Y**：`_HighY` / `_LowY` 以 CloudWalk 根的世界高度 0 为基准，整件 prefab
  上下挪了位置要同步改。
- **海草摆动写在两个通道里**：前向与投影各自调用同一位移函数，影子才和草同步摆。
- **像素级平移补偿未接线**：PostLine 上采样的亚纹素补偿由相机 snap 侧负责，目前不在范围内
  （见渲染管线.md），镜头拖动时像素格可能有半格漂移。
- **阴影只在本关打开**：别的关卡要投影照 `CloudSeaSunShadow` 另接。

## 7. 验证与出图

- **纯逻辑**：材质分流（`CloudSeaMaterialRouteTests`）、海床高度格（`CloudSeaBedGridTests`）、
  水洼材质开关（`CloudSeaWaterMaterialTests`）——走无头验证台，秒级，不开 Unity。
- **烘焙**：`tools/headless/run.sh chain "PirateCrew.EditorTools.CloudSeaAssetBaker.BuildAll;PirateCrew.EditorTools.SceneSetup.BuildAll"`
  （改了 manifest / 程序集定义才需要另跑 `open` 档）。
- **出图**：`BattleHudScreenshot.CaptureHeadless`，必须带图形设备（禁 `-nographics`）。
  环境变量：`PC3D_CAPTURE_LEVEL=1`、`PC3D_RENDER_STYLE=postline`、`PC3D_PIXEL_SCALE=2`、
  `PC3D_CAPTURE_DIR=<输出目录>`。诊断用：`PC3D_CAPTURE_HIDE=Cloud_Sea_Surface` 出「干图」
  （只看海床与生态）；`PC3D_CAPTURE_CENTER` + `PC3D_CAPTURE_CENTER_XZ` + `PC3D_CAPTURE_ORTHO`
  改取景（受相机驱动的正交下限约束，拉不进到下限以内）。
- **看什么**：无洋红、无 shader 报错；水下物只有鱼自带的一圈墨线、海草无墨线；岛影在水面上
  是一整块深色、海床上同位置也偏冷；焦散与碎金只在阳光区；鱼群隔着水色读得出轮廓。

## 8. 已知不足

- **折射很轻**：偏移量在 1–2 个艺术像素量级，静帧里几乎看不出，动态下是「缓慢晃动」而不是
  明显的水面扭曲。要更夸张直接加 `_RefractionStrength`。
- **浅色鱼靠墨线辨认**：骨白、米黄的鱼与水下沙面明度接近，轮廓全靠墨线壳；若要更跳，
  候选是把群主色往珊瑚橙偏（旧色卡「黄白为主、橙做点缀」是按会吃红通道的旧水体定的）。
- **涟漪环很小**：涟漪半径不到一个单位，在默认机位下只是水面上的几个小圈。
- **海草摆动、鱼群巡游是动态量**：静帧验收看不出摆幅是否合适，需实机看。
