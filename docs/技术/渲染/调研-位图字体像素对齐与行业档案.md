# 调研-位图字体像素对齐与行业档案

> **这份文档是什么**：位图文字像素对齐的行业实践五环链条，与两个商业先例（Balatro / RACCOIN）
> 的实地档案——UI 重构波与「像素密度可调档」待办的参考依据。来源：2026-09-25 UI 审计会话的用户
> 问询调研；本仓口径的权威在 [架构总览 §8.1](../架构/架构总览.md)（画布栈与字阶裁决），
> 本文只回答「行业怎么做、我们处在哪条路线上」。

## 一、位图文字像素精准 = 五环链条（全部整数才成立）

| 环 | 要求 | 本仓状态 |
| --- | --- | --- |
| ① 字形栅格 1:1 | 显示字号 = 字体原生档；TMP 位图模式非整数倍 = 重采样糊 | ✅ 四档原生字体（16/12/10/8），禁翻倍 |
| ② 图集 Point 采样、无 mipmap | Bilinear 渗邻字 = 乱码元凶之一 | ✅ 图集 Point 已钉 |
| ③ 字形落位整数 | 画布坐标整数；半画布px 在 ×2 整数放大下恰好规整为整屏px（整数缩放自愈） | ✅ `PixelSnapText` 按画布空间相位取整 |
| ④ 画布 → 屏幕整数倍 | 任意分辨率下不出现 2.67× 之类分数缩放 | ✅ 已由恒定像素密度画布裁决解决（`ConstantPixelSize × Unit`：1 画布单位恒 = Unit 屏幕像素，画布逻辑尺寸随分辨率生长——天然无分数缩放） |
| ⑤ 全屏/分辨率锁定 | 窗口三态 + 按显示器枚举 + 整数倍开关 | ❌ 未做（与「MC 式像素密度可调档」同批，见 [待办/ui-收尾与打磨](../../项目/待办/ui-收尾与打磨.md) 步骤 4e） |

## 二、三条行业路线（字与件怎么同栅格）

- **A. 单栅格同层**（Stardew / Terraria）：字和 UI 画进同一低清 RT，整体整数放大；字号锁死。
- **B. 分层栅格**（Aseprite screenscaling=2）：字和件同在 theme 空间，一起 ×2。
- **C. UGUI 低清画布（本仓路线）**：字 1 画布px 与件 2 画布px **不同相位**——这是与 A/B 的本质差异，
  也是「字体像素不锚定艺术像素」裁决的代价：合法，但需要自觉（对齐判据要分字/件两套相位算）。

## 三、Balatro 实地档案（LÖVE 引擎）

**走的是非整数缩放路线**：`TILESCALE=3.65` 连续重算、坐标不取整、2× 图集 + linear 过滤做
「柔像素」，再叠 `CRT.fs` 单 pass 滤镜（桶形失真 / 色差 / 扫描线 / bloom）。
滑条映射公式可直接抄：`intensity = 0.16n/100` 等（n = 滑条 0–100）。

**取舍**：学它的**设置项组织与 CRT shader**，不学它的缩放模型（本仓已裁决整数倍纪律）。

## 四、RACCOIN 实地档案（Unity 6 + URP）

- 3D 像素化走 **ProPixelizer**（3D 像素化 + 调色板），文字走 **TMP SDF**——
  CJK 字体 = **Fusion Pixel 12px Prop zh_hans（与本仓 12 档同源！）**，Latin = Perfect DOS VGA 437；
  SDF 图集 + 独立 Outline/标题材质。这是本仓待办里「SDF 分支提案」的**商业先例**。
- 设置页清单（可抄的项组织）：窗口三态 / 分辨率枚举 / 帧率上限 / VSync / CRT 滑条 /
  Flashing 闪烁保护 / FX / HDR / 像素化级别。
