# CellShade 库能力总览

> 一句话：这是「像素化渲染管线」的完整实现——双相机 + 多缓冲 G-buffer + 五趟着色 + 调色板量化 + 描边 / 边缘光 / 棱线 / 抖动，所有视觉细节都由独立缓冲和材质参数控制。本文件是**单文件能力清单**，持续补齐。
>
> **与其它文档的分工**：本文件 = **操作手册**（库里有什么、参数在哪、默认值、怎么调、坑）；[CellShade着色代码图解.html](CellShade着色代码图解.html) = **原理图解**（每块着色代码产生什么视觉细节，含中间缓冲逐张讲解）；[调研/v3蓝本.md](调研/v3蓝本.md) = **移植蓝图**（怎么把本仓改造成这套架构、分阶段路线）。

## 2. 相机与画布

- **双相机**：主相机（`SloanePixelartCamera.m_ThisCamera`）`clearFlags=Nothing`、`cullingMask=0`、`farClip=0.02`，只负责把 `ResultBuffer` blit 到屏幕；投影相机（Cast Camera，正交）负责全部像素化渲染，`targetTexture=ResultBuffer`。
- **画布**：`m_TargetResolution`（画布像素） × `m_DownSamplingScale`（默认 5）= G-buffer 分辨率。投影相机正交尺寸在运行时新建时写死 **6.125**（"Celeste"）；**若场景里存盘了 Cast Camera 则用场景值**（005 存的是 4）。
- **单位格对齐**（BeforeRender 趟）：把视图矩阵的平移按 `UnitSize = orthoSize×2/画布高` 取整 → 相机移动时像素形状不抖。
- **转盘**：Demo 场景的 `SpinDisplay` 挂在相机的父物体上，**转的是相机**；石头与光静止。

## 3. G-buffer 缓冲清单（每相机约 16 张 RenderTexture）

| Albedo | 画布×5 | 底色 | 着色乘色 |
| Normal0 | 画布×5 | **屏幕空间面法线** `cross(ddy,ddx)` | 连通域深度预测 → 棱线/描边 |
| Normal1 | 画布×5 | 顶点插值法线 | 实际着色法线 |
| PhysicalProperty | 画布×5 | 光滑度、金属度 | 高光/GI |
| ShapeProperty | 画布×5 | 优先级、法线边缘阈值 | 棱线压暗、遮挡 |
| PaletteProperty | 画布×5 | 主光档数、抖动灰度、边缘级数、描边标志 | 色带/抖动/描边 |
| RimLightProperty | 画布×5 | 材质 `_RimLightColor`（RGBA） | 边缘光 |
| UV | 画布×5 | 优先级 UV 偏移 | 遮挡时的像素偏移 |
| ConnectivityDetail | 画布 | 连通域中间结果 | 调试 |
| ConnectivityResult | 画布 | 8 位打包：四向连通 + 四向更近 | 棱线/描边/AA |
| Diffuse | 画布 | 漫反射着色结果 | 合成 |
| Specular | 画布 | 高光结果 | 合成 |
| GlobalIllumination | 画布 | GI（SH + 环境反射） | 合成 |
| RimLight | 画布 | 边缘光结果 | 合成 |
| ResultBuffer | 画布 | 最终量化结果（HDR，线性） | 上屏 |

## 4. 渲染趟（Cast Renderer 资产里的**实际**顺序）

1. **BeforeRender**：单位格对齐、写单位尺寸/矩阵全局量、清 UV 缓冲。
2. **RenderOpaqueObject**：对象趟，写 G-buffer（LightMode `PixelartOpaque`），清 ResultBuffer。
3. **ConnectivityMapGeneration**：连通域（阈值 `m_Threshold 0.25`、`m_IterationScale 1.5`）。
4. **PriorityManagement**：优先级/遮挡（`m_CenterDistanceAttenuation 0.6`，读连通域缓冲）。
5. **Shading**：四趟着色（Diffuse / Specular / GlobalIllumination / RimLight），`m_EnableAA 1`、`m_AAScaler 1.5`。
6. **Combine**：四趟相加（`clip(diffuse.a-1)` 丢弃背景）。
7. **Outline**（出厂关）：屏幕空间描边，见 §6。
8. **Debug**（出厂关）：`m_TargerBuffer 11` 可看任意缓冲。
9. **ColorCorrection**：16³ 调色板 LUT 量化。

> 注意：口述常把 Priority 放在 Connectivity 前面，**资产里是 Connectivity → Priority**，且优先级 compute 读连通域缓冲。

## 5. 材质属性总表（`Default.shader` / `Leaves.shader` 相同部分）

| 属性 | 类型 | 出厂默认 | 视觉作用 | 往大改 |
|---|---|---|---|---|
| `_BaseMap` / `_BaseColor` | 贴图 / Gamma 色 | 白 | 底色 | 整体变亮/变色 |
| `_BumpMap` / `_BumpScale` | 贴图 / 0~1 | bump / 1 | 法线扰动 | 表面细节 |
| `_DiffuseDitherPalette` / `_DiffuseDitherStrength` | 贴图 / 0~1 | gray / **0** | 色带边界抖动 | 色带交界越斑驳 |
| `_PriorityMap` / `_Priority` | 贴图 / 0~1 | white / 1 | 遮挡优先级 | 越容易被前景挤 |
| `_LocalUnitScale` | Float | 1 | 物体级像素格缩放 | 像素颗粒更粗/细 |
| `_Smoothness` | 0~1 | 0.5 | 高光大小与强度（指数 `exp2(5s+1)`，振幅 ×s） | 高光更小更亮 |
| `_Metallic` | 0~1 | 0.1 | 高光取底色、GI 反射 | 越金属 |
| `_NormalEdgeThreshold` | 0~1 | **1（关）** | 棱线压暗阈值（`normalDiff >` 才压） | 越小越多棱线 |
| `_MainLightLevel` | Float | **2** | 主光色带档数（`multiStep` 均匀分档） | 档位越多越细腻；**1 是退化（除零）会全黑** |
| `_AAScale` | 1~255 | 1 | 逐物体 AA 强度 | 边缘越软 |
| `_EdgeLevel` | Float | **-1** | 棱线压暗级数（负=压暗） | 正=提亮 |
| `_ApplyOutline` | Int | 1 | 是否参与屏幕空间描边 | 0=不描边 |
| `_RimLightColor` | 色 RGBA | (1,1,1,**0**) | 边缘光颜色与强度（alpha） | alpha>0 才出边缘光 |
| `_LeavesCount` / `_Progress`（仅 Leaves） | Float / 0~1 | 32 / 0 | 叶簇数量与生长进度 | 叶量/展开 |

## 7. 视觉能力清单（能做出什么 / 靠什么）

| 能力 | 机制 | 关键参数 | 默认 |
|---|---|---|---|
| 像素化与画布降采样 | 双相机 + 画布×降采样 | `m_TargetResolution` / `m_DownSamplingScale` | 320×180 / 5 |
| 色带分级（卡通分色） | `multiStep(ndotl, level)` | `_MainLightLevel` | 2 |
| 逐像素抖动纹理 | 屏幕空间采 `_DiffuseDitherPalette` 微移色带 | `_DiffuseDitherStrength` | 0 |
| 面法线棱线（随光变深的暗边） | Normal0 深度预测 → `normalDiff` → `ndotl` 降档 | `_NormalEdgeThreshold` / `_EdgeLevel` | 关 / −1 |
| 屏幕空间描边（两种样式） | 轮廓外侧 1 画布像素填色 | `m_Active` / `m_SolidColor` / `m_OutlineColor` / `_ApplyOutline` | 关 / 纯色 |
| 边缘光（最多 32 盏） | 场景 `SloanePixelartRimlight` 对象 + 材质 `_RimLightColor` + 轮廓门控 | 对象方向/颜色、材质 RGBA | 无对象 |
| 高光（两档量化） | `pow(NdotH, exp2(5s+1))` + 两档 | `_Smoothness` / `_Metallic` | 0.5 / 0.1 |
| 环境光 GI（SH） | `SAMPLE_GI` + 金属 `EnvironmentBRDF` | 场景环境光/探针 | Skybox 模式 |
| 环境反射（菲涅尔边） | GI 趟：`NoV = multiStep(saturate(N·V), 2)` **两档硬切** → `fresnelTerm = lerp(Pow4(1−NoV),0,reflectivity)` → `EnvironmentBRDF` 抬掠射角镜面项 | 反射源（天空盒/自定义立方图）、`_Smoothness`、`_Metallic` | 开（光滑度>0 即有） |
| 轮廓外圈 1 像素亮边 | 上一行的实际观感：只在 `N·V→0` 的最外缘成环，因 NoV 两档化而是硬边；颜色 = 反射源颜色经色板吸附 | 同上 | 开 |
| 优先级遮挡（像素级前后关系偏移） | 优先级缓冲 + UV 偏移 | `_Priority` / `_PriorityMap` / `m_CenterDistanceAttenuation` | 1 / 0.6 |
| 调色板量化（帧级限色） | 16³ LUT，**明度主导吸附** | 特性 `m_Palette` | Test_2（76 色） |
| 叶簇（树） | `Leaves.shader` 专用趟 | `_LeavesCount` / `_Progress` | 32 / 0 |
| AA | `_AAScale` + `m_EnableAA/m_AAScaler` | 逐物体/管线 | 1 / 1.5 |

## 8. 参数速查（视觉细节 → 参数 → 位置 → 方向）

| 想要的视觉细节 | 参数 | 位置 | 方向 |
|---|---|---|---|
| 色带更细腻 / 更平涂 | `_MainLightLevel` | 材质 | ↑档更细，2~4 常用 |
| 高光更小更亮 | `_Smoothness` | 材质 | ↑更小更亮（黄→白） |
| 高光偏黄 | 方向光颜色更暖 | 场景 Light | 降 B 通道 |
| 暗边随光变深 | `_NormalEdgeThreshold` ↓ + `_EdgeLevel=-1` | 材质 | 阈值越小棱线越多 |
| 轮廓外一圈暗线 | Outline `m_Active=1`、`m_SolidColor=0` | 渲染器特性 | 本体色样式随物体变色 |
| 亮侧细亮边 | 边缘光对象 + 材质 `_RimLightColor.a>0` | 场景 + 材质 | 只在 `dot(方向,法线)>0` 的轮廓边 |
| 斑驳纹理 | `_DiffuseDitherStrength` | 材质 | 越大越斑驳 |
| 整体限色 | ColorCorrection `m_Palette` | 渲染器特性 | 换色板资产 LUT |

## 10. 色板系统

- 6 套：`TestPalette0`(46) / `1`(64) / `2`(76) / `3`(124) / `4`(4) / `_5`(8)；对应 LUT 贴图 `Test_0~5.png`（**六张都是有效 LUT**，`(r,1-g)` 切 16³ 格）。
- 烘焙：`SloanePixelartPalette.GenerateTexture2D(16)`（compute `PaletteGenerationCIEDE`）；无头入口我们自建 `SloanePaletteBaker.Bake3`。
- **吸附是明度主导**：烘焙 compute 把 Lab 的 a/b 归一化后再算 CIEDE2000，色相差被压得极小 → 输入明度小变化就可能跳到另一个色相。地面随视角「翻格」是正常现象。
- **一期一套色板**（实测）：v3 岩石 = P3；绿球方块参考 = P1；金属锭参考 = P0。参考图都不是限色图，判定口径是「每个像素离哪套色板的最近色最近」：金属锭参考图 94.6% 的像素归 P0，其余五套合计 5.4%。
- **色板不在场景里，在渲染器资产里**：场景文件不带色板信息，出厂渲染器接的是 Test_2，所以任何场景「按库里现状打开」都是 Test_2 的观感，换 LUT 才是另一期。同一个 006 场景换色板前后的样子见 §11A「006 的几种状态」。
- **颜色数硬上限 = 4096**（16³ LUT 的格数）：合成均匀色板 4096 色全部可达；8000 色只可达 4043 个；32768 色只可达 4096 个，其余是永不输出的死色。烘焙耗时不是瓶颈（4096 色 4.5 ms、26 万色 191 ms，RTX 3050 Laptop）。
- **几套色板取并集 = 有损**（实测见 §11A）：三套并集后 005 岩石组只有 62% 的岩影像素保持原色，连「只并各场景实际用到的颜色」也保不住。要同时保住几套观感，只能一个场景一套 LUT 运行时切换（`m_Palette` 每帧读，换 LUT 就是换一张贴图引用），或者重新设计一套主色板并在它上面重新拟合材质。

## 11. 已知限制与坑（全部实测）

1. **批模式环境光探针不自动生成**：`unity_SHA*` 全零，暗面/投影全黑；须在场景加载后连调 `DynamicGI.UpdateEnvironment()` 数帧，且亮度约为编辑器的 **1/1.4**（截图按 1.4 倍补偿后 005 投影区与视频一致率 0%→84.6%）。**同一缺陷也波及反射探针**：实测把 002 的反射源换成纯红/蓝灰/暖白立方图后，地面与球体轮廓环**整块跟着变色**（地面 `(98,85,101)`→`(205,104,61)`/`(155,171,178)`/`(178,186,144)`），说明该场景的色彩有很大一部分来自 GI 环境反射，而批模式的自动反射探针是坏的（偏暗偏暖），参考图的蓝灰轮廓边在我们这里被色板吸成橄榄 `(103,102,51)`。绕开办法：用一台只清天空盒、`cullingMask=0` 的相机 `RenderToCubemap` 现场烘一张，再设 `defaultReflectionMode=Custom` + `customReflectionTexture`（纯配置，不改库）。
2. **`sharedMaterial` 会写脏资产**（批模式播放里改完退出会落盘）；实验必须用 `mr.material` 实例副本。
3. `_MainLightLevel = 1` 退化（`1/(level-1)` 除零）→ 全黑。
4. 附加光（非主光）档数**硬编码 3**，不吃材质档数。
5. 源码小 bug：`ShadingPass.hlsl:93/222` 的 `applyAA` 把 `rimLightInfo.g` 判了两次（应为 `b`）。
6. **002 的材质在上游没有序列化** `_NormalEdgeThreshold/_EdgeLevel/_DiffuseDitherStrength/_RimLightColor` → 走 shader 默认（1 / −1 / 0 / alpha 0），即棱线默认关、无边缘光。
7. **录制状态未入库**：005 视频的机位（半径 9、方位 190°、俯角 16°、放大 1.03）与场景存值不同；002/006 参考画面的地面/材质也与仓库不同。
8. Outline 出厂关；本地已按裁决改为「开 + 本体色样式」（与上游唯一功能性差异）。
9. 「超级多 RenderTexture」= §3 的 16 张 G-buffer，这是能逐项调参的代价与前提。
9a. **Debug 各缓冲的调试视图长相**（005 实拍）：Depth=红底淡剪影；Albedo=灰底米色剪影；Normal0/Normal1=绿底彩色岩体；Physical=橄榄纯色；Shape=品红底+品红剪影；Palette=青色纯色；RimLightProperty=白底剪影；UV=黄色纯色；ConnectivityDetail=浅灰底+极淡线稿；ConnectivityResult=黄底白线；Diffuse=深灰底+岩体与黑影；Specular=黑底灰体；GI=深蓝底剪影；RimLight=黑底金/蓝细线。**纯色图就是属性打包缓冲**（Physical/Shape/Palette/UV），存的是参数不是颜色。
10. 场景 Canvas 比例各不同（见 §9），截图必须按各场景原生画布整数倍出图，否则变形。
11. **轮廓边上的亮环有三种可能来源，`_RimLightColor.a` 不是唯一开关**：① GI 趟的掠射环境反射（任何光滑度>0 的材质都有，最外圈 1 画布像素，颜色=反射源色经色板吸附）；② RimLight 趟（**必须**场景里有 `SloanePixelartRimlight` 对象，`_RimLightsCount=0` 时材质 alpha 再大也全黑）；③ 屏幕空间描边（在轮廓**外**的背景像素，不在物体上）。另注 **002 场景的 `SloanePixelartRimlight` 对象数为 0**，所以 002 里任何轮廓亮环都只能是 ①。
12a. **参考图球体上方那道额外分界是描边，不是色带**：像素扫描发现参考球体顶部轮廓**外侧**有 1~2 像素浅蓝灰 `(155,171,176)`——背景像素只有 Outline 趟会写。实测把球 `_ApplyOutline=1` + 特性 `m_SolidColor=1` + `_OutlineColor≈(0.61,0.67,0.69)` 后，轮廓外出现同样的浅灰环；本体色样式与关闭都不会出现。棱线压暗（阈值 0.82/0.60）实测只加宽下方暗带，不会产生上方分界。
12. **球体的「双月牙」不是特效叠加**：`_MainLightLevel=3` 的 `multiStep` 已给出亮/中/暗三档，球面曲率把中档变月牙、暗档变内圈月牙；`shadowAttenuation` 在量化**前**乘进 `N·L`（只能压档，不生成新层）；棱线压暗（`normalDiff > _NormalEdgeThreshold`）是第三条独立的压档路径，002 材质阈值=1 即关闭。

**缓冲重建会泄漏**：`SloanePixelartCamera.ReleaseBuffers()` 在 `foreach` 第一轮就把列表字段置空，结果每次只归还第 1 张，其余 14 张 RenderTexture 一直占着显存。实测不补救直接重建一次，驱动侧显存多出约 85 MB（与 320×180 ×5 下 14 张的理论值吻合），GC + 60 帧不回落。改分辨率、关像素画相机、换场景都会触发。移植时把 `m_TargetBuffers = null` 挪到循环外即可；在参照库里只能从外部先用反射把缓冲逐张还掉再重建（`SloaneStressMerge.ReleaseBuffersButFirst`）。

## 12A. 打光经验（002/005/006 实测）

**三盏「灯」的分工**

| 光源 | 控制什么 | 入口 |
|---|---|---|
| 方向光（主光） | 色带明暗与终止线位置、高光点、投影方向 | 场景 Light |
| 环境 / GI（含反射探针） | 暗部亮度、地面大色、掠射亮环 | `RenderSettings` + 反射源 |
| RimLight（0~32 盏） | 轮廓单侧亮边、颜色分侧 | 场景 `SloanePixelartRimlight` + 材质 `_RimLightColor` |

**方向光**

- **俯角 X 决定终止线位置**：光越陡，中档带越大、分界越往腰部走。实测 002（中档像素）：60°→2300、70°→2975、78°→3900、85°→4575；反直觉的是把光放平（X 变小）中档反而缩到 1400~1600。
- **方位角 Y 让色带绕球转**，不改变朝上的面（顶面法线朝上，绕 Y 不改变 `dot(up, L)`）；002 方块方位 −10°~40° 顶面颜色恒定。
- **强度不是「亮度」而是「色板落格」旋钮**：002 俯角 78° 时，强度 1.20 → 地面 `(150,108,108)` 粉、0.95 → `(103,102,51)` 橄榄、**0.75 → `(98,85,101)` 紫灰**。正确用法：先定角度，再用强度把**大面积色**推进目标格。
- **颜色 B 通道 = 高光黄度**：`(1,0.93,0.62)` → 高光点 `(251,255,134)`；出厂 `(1,0.98,0.88)` → 纯白点。

**环境反射**

- 掠射环 = `NoV = multiStep(N·V, 2)` 硬切 + `EnvironmentBRDF`；环的颜色就是反射源的颜色。
- 地面与球**共用同一个反射源**，必须用各自的 `_Smoothness` 解耦：地面 0.10、球 0.82。
- `reflectionIntensity` 是悬崖不是旋钮：002 下 0.8 → 地面掉暗格 `(62,53,70)`、**0.9 → 环浅灰 `(199,220,208)` 且地面正确**、1.0 → 环纯白。

**RimLight**

- 两盏即可做「左金右蓝」：005 实测 Front `(1,0.824,0.392)`、Back `(0,0.271,0.783)`。
- 输出 = 材质 `_RimLightColor` **再乘**灯色，所以材质 B 低会把蓝灯压成暗青（005 的 `(0.584,0.577,0.412)` 就是这样）。
- 灯色是唯一能改环颜色的旋钮；亮度低到一定程度会被色板整段吞掉（002 α≤0.3、005 低光滑度）。

**距离向光「档位占比」的实测（005，读 Diffuse 缓冲而非成片）**

Diffuse 缓冲把结论说清楚了：矿石表面其实**有**三档（亮 (148,125,91) / 中 (123,103,74) / 暗 (88,74,52)），问题在**占比**：

| 光俯角 X | 亮档 | 中档 | 暗档 |
|---|---|---|---|
| 30° | 1309 | 561 | 164 |
| 45° | 1419 | 466 | 144 |
| 60°（场景默认附近） | 987 | 741 | 127 |
| 75° | **519** | **1075** | 114 |
| 参考视频（换算画布像素） | 440 | **707** | 464 |

原因在着色公式：`pow(ndotl, 1/2.2)` 会把低角度值抬得很高，多数面因此落进上档；**只有光接近掠射（X 75°+）时中/暗档才会占多数**。另外视频的暗档比我们多得多（464 vs 114），说明它不只有主光分档，暗面还有另一层压暗来源（棱线压暗 `_EdgeLevel=-1` 在曲面上的作用范围比我们大）。这解释了「正面和顶面一个色」：默认光位下 60% 的岩面都在亮档。

**005 白色点状高光的公式条件（实测验证）**：边缘光输出 = 灯色 × 材质 `_RimLightColor` × specular × 门控(0/1)，与漫反射相加后再过色板。出厂材质 `_RimLightColor (0.584,0.577,0.412)` 把 B 通道锁在 0.14，即使用金+蓝两灯叠加，线性总和也只到 (0.559,0.386,0.191) → sRGB (197,167,121)，**数学上到不了奶油白**。把两盏 `SloanePixelartRimlight` 的 `m_Color` 改成白、材质 `_RimLightColor` 取 0.88（白）后：边缘出现 `(245,229,216)`（≈127 画布像素）与 `(255,241,232)`（≈31 画布像素），**与视频的最亮两格完全一致**（视频为 12 / 1 画布像素）——说明作者录像时的边缘光就是白光，金红色来自暖色漫反射，白点来自白光在门控打开处叠加。我们亮像素比视频多约 10 倍，是门控覆盖的棱线更长，属灯方向差异。

**005 边缘那条 1 像素暗线的归因（排除法实测）**：关 `_AAScale`、关棱线阈值（=1）、关阴影（`shadows=None`）三态下该暗线**仍然存在且颜色不变**（(60,56,53)），说明它既不是 AA 压档、也不是棱线压暗、也不是自遮挡阴影 —— 是 **Outline 趟**按「本体色 × `_OutlineColor`」画出来的，因此它**本来就随光照变化**（亮面侧浅、暗面侧深），只是倍率 0.2547 太暗，看上去像一条固定黑线。把 `_OutlineColor` 提到 `(0.55,0.62,0.72)`（冷调，抵消暖底色）后，描边渲出 **`(101,81,82)`**，视频是 `(121,113,106)`，亮度差 6、饱和差 8，是乘法能做到的极限。另：X=80 那版打光虽让三档比例接近视频（501/718/486 vs 440/707/464），但把明暗对比压平了，观感反而更差，**不回退到默认光位**。

**005 打光收口配置（实测命中）**：方向光欧拉 **X=80°、Y=25°**、强度 1.0；`ambientIntensity 1.7`；地面底色 **0.30**（渲出 `(95,95,103)`，与视频地面同色）；Rock 底色 `(0.642,0.553,0.452)`、`_RimLightColor (0.65,0.64,0.60)`、`_NormalEdgeThreshold 0.82`、`_EdgeLevel -1`、`_MainLevel 4`；描边本体色 0.30。Diffuse 缓冲三档像素 **亮 501 / 中 718 / 暗 486**，视频为 **440 / 707 / 464** —— 比例基本一致（此前默认光位是 987/741/127，亮档独大）。

**005 顶部轮廓高光线的做法（实测有效）**：出厂两盏边缘光（Front 金 / Back 蓝）在默认朝向下，顶部横梁轮廓没有可见亮线；RimLight 缓冲里虽有 169 像素覆盖上部，但颜色经材质 `_RimLightColor` 后被锁在暖格，看不出。**加第三盏 `SloanePixelartRimlight`，朝上（euler X≈-70°）、色 `(0.95,0.93,0.88)`**，顶部边缘立刻出现一条奶油白线（放大图确认），其余面不受影响。这盏灯的 `m_Color` 是场景参数、不改材质。

**005 「金光」的加法（实测）**：金光源自场景前侧 RimLight 的金色 `(1,0.824,0.392)` × 材质 `_RimLightColor`。把**灯色整体乘一个系数**（HDR，>1）即可让亮侧边缘发金而不影响地面：系数 1.0 → 金色像素 19（几乎看不出）；**1.6 → 98**；**2.2 → 169**；地面与岩石本体颜色三档完全不变（仍 `(95,95,103)`）。建议 1.6~2.2 之间，取 1.6 时是「隐约金边」，2.2 时横梁顶缘与立柱左侧明显发金。

**批模式 GI 的实测结论与教训**

| ambientMode | SHAr | SHAg | SHAb |
|---|---|---|---|
| Skybox | (−0.014, −0.006, −0.004, **0.174**) | (−0.022, 0.041, −0.006, **0.217**) | (−0.038, 0.128, −0.010, **0.298**) |
| Trilight（冷天空） | (0, 0.061, 0, **0.163**) | (0, 0.094, 0, **0.190**) | (0, 0.181, 0, **0.300**) |
| Flat | (0,0,0,**0.171**) | (0,0,0,**0.233**) | (0,0,0,**0.380**) |

GI 缓冲渲出 `(24,32,43)`（Skybox）/ `(32,37,50)`（Trilight），虽然弱但不为零。**教程清单**：

1. **必须等探针**：场景加载后先跑 ≥30 帧 `DynamicGI.UpdateEnvironment()` 再拍；不等就会出现「第一张图地面颜色莫名不对」——同一会话里第一次切环境状态时尤其明显（实测同一配置第一次拍到错的格）。
2. **切换色板/环境状态后要等帧**：批模式里 `SetPalette` 与 `RenderSettings` 的改动生效有延迟，拍下一张前留 ≥4 帧，否则会拍到上一态（曾把 P5 的紫地面误当成"顶部灯的效果"）。
3. **Skybox 环境在批模式偏暖偏暗**：地面会落暖棕格 `(101,81,82)`；改用 **Trilight 冷天空**（天 `(0.55,0.65,0.85)`、中 `(0.45,0.46,0.55)`、地 `(0.22,0.20,0.18)`，强度 1.0）后地面落到视频的 `(95,95,103)`。这不是材质问题。
4. **不要把作者的材质当拟合旋钮**：Rock / RockGround 的底色、rim 色属于"观察指标"，改它们等于改标准答案；可调的只有灯（方向/强度/影子强度/颜色）、环境光模式与颜色、场景里的 RimLight 对象。
5. **结论要用缓冲验证**：只看成片单像素容易误判，必须配 `Diffuse / GI / RimLight` 缓冲的数值与像素计数；同一文件名被后续实验覆盖会造成假结论（顶部亮线那次）。

**「全都吸到黄格」的机理与解法（实测）**：P3 的高亮区有 4 个相近的格：`(255,241,232)` 奶油 / `(245,229,216)` 暖白 / `(244,232,193)` 淡黄 / `(229,201,96)` 饱和黄。视频的亮像素落在前三格（12 / 9 / 1 个画布像素），几乎不进饱和黄（1 个）；我们此前全落在 `(229,201,96)`——原因是**金灯色的 B 太低（0.392），输出是饱和金**，在色板里最近的就是饱和黄格。把前侧金灯的 B 从 0.392 提到 **0.65**（灯色 (1,0.90,0.65)×1.6）后：饱和黄 19→**4**，淡黄 `(244,232,193)` 3→**14**，`(255,204,170)` 0→**18**，与视频的"淡金/暖白"一致。注意 B=0.85 时反而跳回饱和黄 166——色板落格非单调，必须逐档验。

**色板本身没有纯白（LUT 实测）**：P3（Test_3.png，124 色）最亮格是 **(255,241,232)**（H23 S9 奶油白），其后是 (244,232,193) 淡黄、(243,239,125) 黄、(245,229,216) 暖灰白、(255,201,214) 粉、(201,210,233) 冷蓝——**没有任何中性纯白**；对比 P1 有 (255,255,255)。所以「白少黄多」首先是色板分布决定的：P3 的高亮区本来就偏奶油/黄。视频最亮的 (255,241,232) 正是 P3 的第一亮格。

**005 主光强度与档位占比（实测）**：光照角度固定（pitch 65）时，强度直接改变亮/中/暗档占比，且**地面色稳定在 (95,95,103) 不跳格**：强度 1.00 → 亮324/中1058/暗229；**1.15 → 亮454/中474/暗243**；1.30 → 亮612/中603/暗306。视频为 亮440/中707/暗464 —— **强度 1.15 的亮档像素与视频几乎相同（454 vs 440）**，就是"石头暗一截"的修法。

**005 顶部偏暗与地面偏暖的根因（实测）**：① **顶部光弱** = 场景方向光默认俯仰只有 **50°**（四元数换算：yaw 76°、pitch 50°），侧面吃光多、顶面吃光少；抬到 **65°** 后顶面亮档像素从 3472 涨到 5184。② **地面颜色不对不是材质问题** —— 同材质的四态对照：天空盒环境光 1.4 下地面 `(101,81,82)`（暖），把环境光改成 **Trilight 冷天空**（天 `(0.55,0.65,0.85)`、中 `(0.45,0.46,0.55)`、地 `(0.22,0.20,0.18)`）后地面渲出 **(95,95,103)**，与视频逐像素相同；俯角 75° 又会过亮到 `(121,113,106)`。所以地面色是被**环境光颜色**决定的（批模式天空盒探针偏暖偏暗），不是地面底色。最终：**pitch 65° + Trilight 冷天空 + 出厂材质**。

**通用规律**

- 所有参数最终都被 16³ 色板裁决：任何改动都要看「是否跨格」，不是线性变亮。
- 一个参数常同时影响多个面：先锁住「面上不该变的量」（例如顶面颜色锁底色 B），再调角度。

## 12B. 005 调参工作纪律（踩坑后固化）

**已认可基准 BASE-V1（不得在后续实验中丢失）**：`Export/sloane-base/BASE-V1`，由 `SloaneSceneCapture.BaseV1()` 复现——P3 色板、Trilight 冷天空 `(0.55,0.65,0.85)/(0.45,0.46,0.55)/(0.22,0.20,0.18)` 强度 1.0、场景原方向光、材质全出厂、本体色描边 0.254717、前侧金灯 `(1,0.90,1.0)×2.2`、顶部灯 `(0.95,0.93,0.86)` 朝上、机位半径 8 / 方位 190 / 俯角 16 / 正交 4÷1.03。**每次新实验必须以它为唯一变量基线，结果并排对照。**

**已否决（不要再提）**：
- 纯色样式浅描边（0.20）——用户判"太浅、跟没有一样"；
- 两盏边缘光全改白——整圈发白；
- 方向光俯角 X=80——三档比例对了但明暗压平，观感更差；
- 改 Rock/RockGround 的 `_BaseColor` 凑色板——材质是观察指标，不是拟合旋钮；
- ambientIntensity 1.8+——地面跳格保不住。

**已确认有效**：
- GI 用 Trilight 冷天空（Skybox 批模式偏暖偏暗，地面会落暖棕格）；
- 金灯色 B 从 0.392 提到 ~0.65~1.0 才能从饱和黄格换到淡黄/奶油格；
- 顶部轮廓线靠单加一盏朝上的 `SloanePixelartRimlight`；
- 外描边用本色样式保留左右深浅差；纯色灰会把两侧抹平。

**失败模式记录（防止重犯）**：① 把"用户认可的版本"当口头反馈而不固化成可复现基线；② 不维护否决清单，导致被否的方案反复出现；③ 把现象描述直接映射成某个参数就开跑，没有先验证"这个参数是否真驱动该现象"；④ 用单像素/单文件下结论，未做交叉验证；⑤ 一次改多个变量导致无法归因；⑥ 解释只讲机制不讲"所以我们差在哪"。
