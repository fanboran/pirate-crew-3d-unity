## 1. 这条路径是什么

**一句话：几何照常在屏幕档渲进 7 张全分辨率 G-buffer，描边、着色（四趟 + 合成）与帧级调色板全部跑在
艺术画布（屏幕 ÷ `pixelScale`）上，最后一次点采样放大上屏。**

### 1.1 两个分辨率域（契约 §0）

| 域 | 尺寸 | 谁在这里算 |
|---|---|---|
| **屏幕档** | `FineW × FineH` = 艺术画布 × `pixelScale` | **几何 + 7 张 G-buffer + 深度**；连通域的 Check / Flood |
| **艺术画布**（低分辨率域） | `ArtW × ArtH` = 屏幕 ÷ `pixelScale` | **描边 / 四趟着色 / 合成 / 帧级调色板 / 结果** |

**为什么几何在屏幕档**：照 v3——它的 G-buffer 就是常规延迟渲染的**全分辨率** G-buffer，
省 fill rate 的是**着色那几趟**（只有画布那么多像素）。降采是隐式的：着色趟点采样取到的就是
"块中心那个纹素"，与"直接在艺术画布上光栅化"逐点等价（块中心连续坐标 `id*k + k/2`
同时是画布像素中心的放大像）。

**像素档位**：`pixelScale` 锁"一个艺术像素占几个屏幕像素"这个**整数倍数**（现取 **3**，
`PixelartPilotScene.cs:36`——与 UI 的基本单位同网格，创始人 2026-09-22 裁决），画布尺寸由实际屏幕反推：
1080p → 640×360、1440p → 853×480、2160p → 1280×720，块边长恒为 3 屏幕像素。
**不要退回"锁画布高度"**：那套只在屏幕高恰好是画布高的整数倍时成立，非整数倍时块边长在
相邻整数之间混排，症状是"全屏像素不齐、放大到 1:1 看却正常"。

**取景锚**：`worldPerPixel`（每艺术像素多少米）= 可见米数 ÷ (1080 ÷ k)；**可见米数是美术锚、不随 k 变**
（广角 28m / 中景 18m / 近景 8m，`PixelartPilotScene.cs:62-68`）——所以分辨率越高看到的范围越大
（1080p 宽机位 28m、1440p 同档 37.3m），这是"艺术像素的世界尺寸固定"这条口径的直接结果。

### 1.2 与旧链的分野

旧链（`PirateToon` 全分辨率前向着色 + `PixelationRendererFeature` 事后降采 + 反向壳描边）
经创始人 2026-09-22 裁定**整条作废、不再当基准**（退役处置待定，文件仍在工程里），本路径不引用其任何实现：

| | 旧链（已作废） | 本路径 |
|---|---|---|
| 物体 pass 的产出 | 最终颜色（全分辨率前向） | **数据**（7 张 G-buffer + 深度，屏幕档） |
| 着色发生处 | 全分辨率（物体 pass 内） | **艺术画布**（四趟全屏 + 合成） |
| 描边 | 反向壳几何（沿法线外扩） | **屏幕空间 4 邻域膨胀**（§4.1） |
| 色带边界 | 靠"逐像素操作与 RT 块对齐"这条纪律兜住 | 天然落在艺术像素上，不需要块对齐补丁 |

代码位置：`pirate-crew/Assets/Scripts/PirateCrew/Rendering/Pixelart/`（程序集 `PirateCrew.Rendering`，
命名空间 `PirateCrew.Rendering.Pixelart`）；shader 在 `Assets/Pixelart/Shaders/`，
连通域/调色板 compute 在 `Assets/Pixelart/Compute/`。

## 2. 执行顺序（双相机 + 七个 Feature）

一台相机的"视野"与"渲染分辨率"被拆成两台：

| | 主相机（上屏器） | Cast 相机（渲染代理） |
|---|---|---|
| 是什么 | 场景里那台相机（本路径的宿主） | **主相机的子物体、local 恒等** ⇒ 自动继承 Transform（v3 同一手法） |
| 相机设置 | `clearFlags = Nothing`、`cullingMask = 0`、后处理关 ⇒ **什么都不画** | 正交、`targetTexture = ResultBuffer` |
| 渲染器 | `PixelartScreen_Renderer`（只有上屏 blit） | `PixelartCast_Renderer`（另外七个 Feature） |
| 层掩码 | 0（不参与剔除） | **主相机被清掉之前的那份**（⇒ 几何只被 Cast 相机看到一次） |

> **为什么必须是两个渲染器**：两台相机若共用同一个渲染器，主相机会把刚画好的 G-buffer 清掉再着色一遍，
> 画面退化成纯背景色（且不报错）。这是结构性的，不是配置疏漏。

Cast 渲染器里七个 Feature 的时机与职责（**数组顺序 = 同一 `RenderPassEvent` 内的入队顺序**，
装配器每次重建列表，不让历史残留改掉次序）：

| 序 | Feature | 时机 | 干什么 |
|---|---|---|---|
| 1 | `PixelartBeforeRenderFeature` | `BeforeRendering` | 视图矩阵平移分量 snap 到整艺术像素（`cmd.SetViewProjectionMatrices`——标准 URP 通道都吃 snap 过的 `UNITY_MATRIX_VP`）；下发 `_PixelartUnitSize`/`_PixelartFineUnitSize` 与四个尺寸全局。上采样 UV 反补偿**未接**（常量已预留，见 §7） |
| 2 | `PixelartObjectFeature` | `AfterRendering` | 清屏幕档颜色/深度目标 → `DrawRenderers(ShaderTagId("PixelartOpaque"))` **一批**写 7 张 MRT + 深度 → 7 张 + 深度发布成 shader 全局 |
| 3 | `PixelartConnectivityFeature` | `AfterRendering` | Check（屏幕档）→ Flood × `max(1, RoundToInt(k×1.5))`（k=3 ⇒ 4 次，ping-pong）→ Result（艺术画布） |
| 4 | `PixelartOutlineFeature` | `AfterRendering` | 屏幕空间 4 邻域膨胀描边（艺术画布）→ 写 `Outline` 缓冲（§4.1） |
| 5 | `PixelartRimLightFeature` | `AfterRendering` | 清 `RimLight` → 累加 blit → `RimLightCorrection.compute` 3×3 去孤立点（就地） |
| 6 | `PixelartShadingFeature` | `AfterRendering` | 清四张着色缓冲 → Diffuse → Specular → GI → **Combine**（四项相加写进 Cast 颜色目标 = `ResultBuffer`） |
| 7 | `PixelartColorCorrectionFeature` | `AfterRendering` | 帧级调色板 LUT 映射（就地）；**默认整趟跳过**（§4.3） |

主相机侧：`PixelartScreenCopyFeature`（`AfterRendering`）用 URP 自带 `Hidden/Universal/CoreBlit` 的
**pass 0 Nearest** 把 `ResultBuffer` 点采样放大上屏——这就是"像素化"这个观感的物理来源。

**先后是契约的一部分**：边缘光早于 Diffuse（Diffuse 的 applyAA 门控要读 RimLight 缓冲）；
描边早于着色（着色读 Outline 判墨线像素）；合成晚于四趟；调色板最后。

> 旧版（P1–P3 时代）的"逐物体提交 + 远→近手工排序 + 壳/本体成对"已随描边改屏幕空间一并删除：
> 几何现在只是一批 `DrawRenderers`，前后遮挡全靠深度测试（`ZTest LEqual`），
> 大平面的 `renderQueue` 前后景分段也不再需要。

## 3. 缓冲

分配在 `PixelartCameraRig.EnsureBuffers`，分三组（名字/格式/语义的**权威表在契约 §1**，下面是速览）：

**屏幕档（7 张 MRT + 深度）**——物体 pass 一批写完：

| 缓冲 | 格式 | 语义 |
|---|---|---|
| `Albedo` | ARGB32 | rgb = 亮部色（墨线像素里是墨色）；**a = 覆盖标记**（着色趟据此 clip 出背景） |
| `Normal0` | ARGBHalf | **屏幕空间几何法线** `normalize(cross(ddy(positionWS), ddx(positionWS)))`（连通域输入） |
| `Normal1` | ARGBHalf | 切线空间法线贴图 → 世界法线（无贴图 = 平滑法线；着色用） |
| `Physical` | ARGBHalf | r = 光滑度；g = 金属度 |
| `Shape` | ARGBHalf | r = 优先级（预留 0）；g = 未用（写 0）；b = 法线边阈值；a = AA 缩放 |
| `Palette` | ARGBHalf | r = 主光档数；g = 抖动标量（0..1，中心 0.5）；b = 边光档数；**a = applyOutline（0/1，逐物体描边开关）** |
| `RimLightProperty` | ARGBHalf | rgb = 逐物体边缘光色 |
| `Depth` | depth 24（**可采样**） | 着色趟重建 `positionWS`（阴影坐标与附加光都要） |

**艺术画布（描边 / 着色 / 合成 / 调色板）**：

| 缓冲 | 格式 | 语义 |
|---|---|---|
| `ConnectivityResult` | ARGB32 | r = 单元内连通比例；g = 连通或更近比例；b = 单元内最大法线差；a = 打包四方向 connected/closer——**位序见契约 §8 #2，一位之差 = 描边整体不出现或乱长** |
| `Outline` | ARGB32 | **r = 墨线标记**（1 = 本像素是墨线；描边趟写） |
| `Diffuse` / `Specular` / `GI` / `RimLight` | ARGBHalf | 四趟的输出缓冲；`Diffuse.a` 恒 1（合成趟 `clip(a-1)` 区分"没着色"的背景） |
| `PaletteLut` | RGB 条带 | 帧级调色板 LUT（默认不生成不绑定，§4.3） |
| `ResultBuffer` | ARGB32、**`FilterMode.Point`** | 最终结果；Cast 相机的 `targetTexture`，上屏时点采样放大 |

连通域中间档（屏幕档）：`ConnectivityDetail`（逐方向打包 bit）与 `ConnectivityPrev`
（Flood 的 ping-pong 备份，**只作 kernel 纹理绑定、不发布成全局**）。

**与 v3 的 15 张的关系**：v3 的 8 个输出本仓做 7——`_LightmapUVBuffer` 不做（v3 自己也没接通，
蓝图 §7.3 第 7 条）；优先级仲裁 / `_UVBuffer` 不移植（v3 的死 pass，蓝图 §4.1），`Shape.r` 写 0 预留。
**为什么不用 v3 的 `SNorm16` + `PackFloatInt8bit` 字节打包**：那套与 MRT 格式强耦合，
随手换格式（哪怕换成 `UNorm`）就静默失效（蓝图 §2 注意 1）；本仓直存，**编解码一步都不需要**。

## 4. 着色数学（画布上的四趟 + 合成）

`PixelartShading.shader` 的四个着色 pass + 合成，逐条对应 v3 `ShadingPass.hlsl`。

**Diffuse（色带本体）**——v3 `DiffuseShading`（`ShadingPass.hlsl:37-63`）全文 + 三行本仓口径：

```
ndotl = saturate(dot(L, N))
ndotl = pow(ndotl, 1/2.2)                 // 让色带边界落在感知均匀的位置
ndotl += singleLevel * dither             // 抖动：偏移量 = 一个色带步长 × 逐物体图案值
ndotl = multiStep(ndotl, level, 0, 0)     // 量化成 level 档（= "色带"本体）
if (ndotl > singleLevel && connect < _PixelartAAThreshold) ndotl -= applyAA * singleLevel  // 连通域降档 = "内线"
if (normalDiff > normalEdgeThreshold)     ndotl += singleLevel * normalEdgeLevel          // 法线边加成
ndotl = clamp(ndotl, 0.0, 1.0 + singleLevel)
颜色 = ndotl × 光色 × albedo + 环境色 × albedo
```

- `multiStep` 是 v3 `Math/Step.hlsl` 的逐行翻译；`level`（档数）与抖动偏移**逐物体**给（走 `Palette` 缓冲）——
  远景大平面与近景角色需要不同档数，全局常量做不到，这正是 v3 把它们放进缓冲的理由。
- **`applyAA` 三项**：`RimLight` 缓冲三通道**都判**（v3 原版把 `g` 判两次、`b` 一次没判——不继承，
  蓝图 §4.4 第 2 条）× `Shape.a`（AA 缩放）。
- **附加光**：`LIGHT_LOOP_BEGIN(_PixelartAdditionalLightCount)` + `GetAdditionalPerObjectLight`，
  档数用 `level × 0.5`、偏移 3.0（v3 同款）；试点场景放了一盏暖点光验证通路（强度见 §8）。
- **实时阴影**：`GetMainLight(shadowCoord)`，坐标由**深度重建的 `positionWS`** 算出
  （`_MAIN_LIGHT_SHADOWS(_CASCADE)` 关键字族已接回）。**试点场景暂时 `sun.shadows = None`**
  （实测地面整片被判在阴影里，属阴影距离/bias 调参问题，§8）。
- **主光方向/颜色以 rig 每帧下发的 `_PixelartLightDirWS` / `_PixelartLightColor` 为准**，
  在 `GetMainLight()` 之后覆盖（只借 URP 的 `shadowAttenuation`）——
  `PixelartCameraRig.lightIntensity` 这个美术旋钮、以及判据脚本的"下发值对色号"都依赖这一点（契约 §8 #7）。
- **墨线像素不吃光照**：`Outline.r > 0.5` 时 Diffuse 趟直接输出 `_PixelartInkColor`（不吃光照/色带/环境光）；
  Specular / GI / RimLight 三趟对墨线像素提前返回 0——否则墨色会被色带量化、环境光、边缘光染成
  "深蓝的带"，就不是墨线了。
- **背景像素**（`Albedo.a < 0.5`）`clip` 掉，保留 Cast 颜色目标上的背景色。

**Specular / GI / RimLight 与合成**：Specular = `multiStep(pow(NdotH, expSmoothness))`（v3 :117-126 逐行），
光滑度/金属度来自 `Physical`；GI = `环境色 × albedo`（**暗部色即此项**，见下）；RimLight 见 §4.2；
**合成趟**把四张相加写进 `ResultBuffer`（`Diffuse.a` 恒 1，`clip(a-1)` 把没着色的像素留给背景色）。

⚠ **暗部口径的裁决冲突**：渲染篇 §4.2 要求"暗部不做纯乘暗、用替换式预制暗部色"，
而本路径的暗部 = `albedo × 环境色`（纯乘暗）。实测纯乘暗的暗面落在 `#2E3232` 上下，
和墨线在缩略图里容易糊成一片。两条路的取舍见 [实拍 r4 的 §7](../../../images/pixelart-path/r4/README.md)，**待裁决**。

**抖动两范式**（物体 pass 写入 `Palette.g`，幅度由材质 `_DitherStrength` 施加）：

| `_DitherMode` | 图案 | 性质 |
|---|---|---|
| 0 | 4×4 Bayer 矩阵（中点归一化 `(m+0.5)/16`） | **渐变态**：16 级，只有色带阈值附近的像素翻档 |
| 1 | 1-bit 密度图案纹理（v3 口径，4/6/8/16 边长） | **两态撕边**：图案是 0/1，阈值带内的一半像素往上翻、一半往下翻 |

九张 v3 口径的图案由 `Assets/Editor/DitherPatternBaker.cs` 烘焙（产物落在 `Assets/Pixelart/Textures/Dither/`）（矩阵按其资产逐像素量出后以字符串重制，
参照库不入库）。两者不可叠加，**默认关**（`_DitherStrength = 0`，与 v3 自带材质同口径）。
四趟拆分后抖动幅度的语义需要复核（§8）。

### 4.1 描边（屏幕空间 4 邻域膨胀）

外轮廓走 **v3 `OutlinePass.hlsl` 的屏幕空间膨胀**（艺术画布，1 采样/像素，线宽恒为 1 艺术像素、必然闭合）。
这个 Feature 在 v3 里是关着的（`m_Active: 0`，从没真跑过）——本仓启用并改造它，把 v3 没接通的零件接通（契约 §6.2）。

**为什么不用反向壳**：反向壳沿**面法线**外扩，箱体的左下/右下两条剪影边（正面墙底边）投影到
`cos45° ≈ 0.7` 艺术像素 < 1 ⇒ 亚像素 ⇒ 量化后**断续**，且角部外扩重叠出堆块（r6 实拍定位，
[r6 README](../../../images/pixelart-path/r6/README.md)）。屏幕空间方案不依赖几何外扩，从原理上没有亚像素线。

判定步骤（`PixelartOutline.shader`，逐方向）：

1. 采样本像素与 4 邻域的 `Albedo.a`（覆盖）与 `Palette.a`（applyOutline 位）；
2. **门控**（取自**本像素**的连通域结论）：某方向 `connectedTo* < 1 && closerThan* < 1` 才允许在该方向出线
   （`closer` 位 = 本像素比邻域更近，v3 `Connectivity.hlsl` 同语义）；
3. 门控命中后，**该方向邻域开着描边**、或**本像素自己开着描边**，二者任一 ⇒ 写 `Outline.r = 1`。

第 3 步的"本像素自己也算"是**近侧剪影边的缺口补丁**：v3 原版只看邻域，而门控的 `closer` 位
把墨线限制在"更远那一侧"——平台下缘外面是**更近**的地面（大平面的 applyOutline = 0），
更远一侧又是物体自己 ⇒ 两侧都不满足 ⇒ 近侧剪影边整条不出线（实测墨线像素包围盒到不了平台下缘）。
加上自描边分支后：远侧边仍由外侧像素出线、近侧边由物体自己的边界像素出线，
两种情形因 `closer` 位互斥 ⇒ 线宽仍恒为 1（`PixelartOutline.shader` 文件头有完整因果链）。

- **墨色**：全局 `_PixelartInkColor`，rig 默认**中性近黑 `#0D0D0F`**（`PixelartCameraRig.cs:57`）。
  UI 面板令牌 `INK #120C14` 带一点紫，在面板底色上稳、画在 3D 的蓝灰地面上读成紫——
  所以 3D 侧独立取色，**两个色号不要互相"统一"**。
- **逐物体开关**：材质 `_OutlinePixels > 0` ⇒ 物体 pass 写 `Palette.a = 1`；大平面置 0 即整件不描边
  （契约 §7 的可回退性）。几何壳时代的 `PixelartInk` pass / `_OutlinePixels` 外扩 / `renderQueue`
  前后景分段已随反向壳一并删除，`_OutlinePixels` 只剩"要不要描边"这一个语义。
- **诊断档**：描边 shader 自己的诊断档取高位 `8`（门控命中，不看 applyOutline）/ `9`（覆盖图），
  避免与着色的 0–5 撞号（契约 §8 #10）。
- **位序铁律**：`ConnectivityResult.a` 的 connected/closer 位序照 v3 `BuffersResolver.hlsl:23-31`
  （bit7..4 = connected 右/左/上/下，bit3..0 = closer 右/左/上/下），直存 UNorm8
  （写 `byte/255`、读 `round(a*255)`）——**一位之差就是描边整体不出现或乱长**，
  描边与边缘光两处解包必须同口径（契约 §8 #2）。

### 4.2 边缘光

边缘光是"**光照层的边缘提亮**"，与墨线正交——命名与代码一律不许混。
物体颜色来自 `RimLightProperty.rgb`（逐物体）→ **屏幕空间光向门控**：
`TransformWorldToViewDir(direction).xy` 归一化 → 四方向 clamp → 乘 `(1 - connected)` → 累加进
`RimLight` 缓冲；`RimLightCorrection.compute` 做 3×3 去孤立点（只作用于 RimLight 缓冲）。
Diffuse 的 applyAA 门控读的就是这张缓冲。试点场景材质默认 `_RimLightColor` 全黑
（不改变已认过的画面），出图档 `pa-rim` 拨亮验证通路。

### 4.3 帧级调色板（默认关）

机制全在：`PaletteGenerationCIEDE.compute`（CIEDE2000，`[numthreads(8,8,8)]` + **三维派发**，
通用 `ComputeShaderPass` 装不下）把调色板烘成 2D RGB 条带 LUT → `PixelartColorCorrection.shader`
按采样公式照 v3 `Shared/Blit/ColorCorrection.shader` 就地映射。默认调色板**从试点场景的材质色自动生成**
（材质 `_BaseColor` + 墨色 + 环境暗部色；创始人 2026-09-22 裁决：首版观感变化最小）。

**默认关**（`PixelartPathInstaller.EnableFramePalette = false`，把 palette 字段置空 ⇒ 那一趟整趟跳过）：
首轮实测 LUT 索引口径不对——背景蓝灰 (74,110,134) 被映射成暗紫 (75,61,79)、整屏发怪，
还会把判据的颜色假设一起带偏。修好索引口径（§8 第 1 条）改回 true 即开。
**可回退性**：`applyOutline` / `_RimLightColor` 黑 / 调色板为空 = 不映射，每个子件都能单独关（契约 §7）。

## 6. 改这条路径之前：静默失效点

这条路径的失效方式**很少报错**，多数表现为"画面只剩背景色"或"某个效果不生效"。已踩过的点：

1. **`Shader.Find` 的 shader 会被播放器构建剥离**。构建只收"被资产引用链摸到"的 shader；
   只在 C# 里 `Shader.Find(名字)` 的 shader 既没有编译记录也不报错，运行时返回 null。
   ⇒ 着色 shader 必须由 Feature 的**序列化字段**持有（`PixelartShadingFeature.shadingShader`），
   装配器负责写入。装上屏 blit 用的 `Hidden/Universal/CoreBlit` 不受影响（URP 运行时自身引用它）。
2. **层掩码不能跟着主相机同步**。主相机的 `cullingMask` 被本路径清成 0（它只上屏），
   若 Cast 相机跟着同步，物体 pass 的 `cullResults` 就是空的——**不报错，只是什么都没画**。
   ⇒ Cast 相机用"主相机被清掉之前的那一份"（`PixelartCameraRig._savedCullingMask`）。
3. **抖动的幅度必须在物体 pass 施加**。着色 pass 只负责"读出偏移量"，若在物体 pass 里忘了乘
   `_DitherStrength`，抖动就恒等于满幅度——症状是"关着也有规律点阵"（4 低分辨率像素周期的网）。
4. **G-buffer 的通道语义必须排他**。事故实例：旧版 `prop.a` 一肩挑两职（着色趟判"这是墨线像素"的标记
   ＋ 物体 pass 写 `_AAScale` 占位属性），而 `_AAScale` 的 Properties 默认值恰好是 **1.0**
   ⇒ 每一个不透明像素都满足"这是墨线"、直接输出 albedo、跳过全部着色数学——
   症状是"所有面同色、与 albedo 逐位相同、无任何报错"，旧的四项判据还全过。
   ⇒ 教训是通用的：**一个通道一个语义**；墨线标记现在活在独立的 `Outline` 缓冲，
   `Palette.a` 保持 v3 的 applyOutline 语义，判据五「亮暗跨度」兜底。
5. **"编辑器里对、播放器里错"是这条路径的一类独立故障**。实例：船员预制体根上带
   `Rigidbody`，剥组件时漏掉它 ⇒ 编辑态不跑物理、包围盒完全正确，进播放器后自由落体
   （采集在载入后约 1.5 秒，下落 ≈11m，正好埋进地面以下被挡住）。
   ⇒ 从预制体实例上取物体时，**先 `UnpackPrefabInstance(Completely)` 解包**，再按
   **白名单**剥组件（只留 Transform/MeshFilter/MeshRenderer），并**当场断言无残留**。
   （实测：预制体实例上 `DestroyImmediate` 删不掉 `Rigidbody` 与 `PirateBase`，
   场景的 `m_RemovedComponents` 里根本没有它们。）
6. **被后续趟按全局名采样的缓冲，写完之后必须 `SetGlobalTexture` 发布**。事故实例：
   着色四趟的结果缓冲只被当渲染目标写过、没发布 ⇒ 合成趟按 `_PixelartDiffuseBuffer` 这样的全局名采样
   ⇒ 读到未绑定状态 ⇒ `clip(diffuse.a-1)` 把整屏剪掉，画面只剩清屏色——
   **每一趟日志都"执行成功"、判据全 FAIL、无任何报错**（契约 §8 #5）。
   同理：Diffuse/Specular/GI 由着色趟发布，RimLight/Outline/ConnectivityResult 各由自己的趟发布。
7. **没挂法线贴图时，内建灰色默认图会被解成假法线**。`UnpackNormalScale` 在非 DXT5nm 分支把
   灰图 (0.5,0.5,0.5,0.5) 解成 `xy = (-0.5, 0)`，而法线贴图活在**切线空间**
   ⇒ 同一世界朝向的面在不同物体上解出不同朝向——症状是"两个角色打光方向不一致""地面没有全局光照"。
   ⇒ 法线贴图通道用 `#pragma shader_feature_local _NORMALMAP` 整段隔开，没挂贴图就不参与编译（契约 §8 #6）。
8. **描边/连通域的位序与调试档是同一类"静默"故障**：`ConnectivityResult.a` 位序一位之差 =
   描边整体不出现或乱长（§4.1、契约 §8 #2）；调试档位表必须全局唯一
   （着色 0–5、描边 8/9，契约 §8 #10）——两个 pass 对同一个 `_PixelartDebugMode` 各有一套解释，
   诊断图本身就是错的。

自检：`PixelartCameraRig` 首帧会打一行装配自检（两台相机的层掩码、两档 RT 尺寸、走本路径物体 shader 的
renderer 数）**并把实际下发的光照量打一行**（光方向/光色/环境色/unitSize/两档尺寸，用于比对色号）；
七个 Feature 各打一行"已执行"。**这些日志齐全 + 判据脚本全绿**，才算这条路真的在跑。
