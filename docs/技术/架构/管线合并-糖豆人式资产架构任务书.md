## 一、目标架构（是什么）

糖豆人式三层分离，几何生成全部退出运行时：

```
资产层   Assets/Art/Models/SceneKit/（或同级新目录）
         船_Galleon.prefab / 岛体 FBX / 云场 prefab / 陈设件 …（全部是烘焙产物或手作资产）
            ↑ 编辑期烘焙器（C#）         ↑ 手作/精修（Blender → FBX）
数据层   WorldMapCatalog / ShowcaseLevels —— 只记「件 id + 摆位 + 种子」，零几何代码
运行时   只做实例化组装 + 真动态系统（海面圆盘 / 水模拟 / 风摆 / 氛围）
```

- **合并后的单一管线**：C# 程序化生成器（ShipHullGeometry / SceneKitGeometry / Lowpoly 等）
  从"运行时逐帧算顶点"改岗为"**编辑器烘焙器**"——菜单一键：配方+种子 → 合并网格 → 落 prefab/FBX。
  Blender 的职责收窄为"手作主件 + 给烘焙产物做精修后回导"，与 C# 烘焙器**同仓同目录**，不再各产一套。
- **为什么这样分**：确定性生成（固定配方+种子=固定输出）在运行时重算是纯浪费；真动态的只有
  海面圆盘（随相机/图幅）与逐帧模拟系统——这些留在运行时是本分。

## 三、边界与不变式（为什么这样划）

1. **角色模型不许改**（AGENTS.md 铁律①）：船员是运行时装配+动画的胶囊体，**不烘焙**——
   本任务书只覆盖场景/环境资产（铁律②的主线延伸）。
2. **真动态系统不烘焙**：海面圆盘（随相机/图幅）、WaterSimulationDriver 高度场、风摆/氛围——
   它们的输出依赖运行时状态，烘焙无意义。
3. **多样性不丢失**：糖豆人 Kit 的多样性来自"更多预制变体"而非运行时随机——需要第 N 种船时
   加一条配方烘焙第 N 个 prefab，运行时零成本换装。
4. **数据层格式不变**：WorldMapDefinition 的 id/摆位/氛围档契约保持，存档/事件契约不受影响。
5. **流式加载不做**：糖豆人的 asset bundle 流式对其规模有意义；本项目单场景战斗，prefab 直引即可。
