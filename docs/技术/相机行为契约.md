# 相机行为契约

> **定位**：战斗相机「玩家可感知行为」的**唯一规格**（单一事实源）。
> 实现 = `CameraFraming`（纯数学）+ `CameraInputReader`（输入）+ `BattleCameraDriver`（唯一写入者）；
> 测试 = `CameraFramingTests`（本契约的**可执行形式**）。
>
> **为什么有这份文档**：r13 相机连环案（右键旋转被实现成平移拖拽，创始人连驳多轮）的复盘结论——
> 「旋转」从来没有定义层，三个人按三个心智模型实现；错误行为还被注释合法化、被测试固化
> （测试里甚至有一条断言专门防止把它修对）。规则由此立：**行为改动必须先改本契约，
> 再动实现，同步测试**（AGENTS.md「核心行为指令」§4）。

## 重构纪律（本契约存在的根本原因）

1. **等价 ≠ 正确**：「与旧实现逐位等价」只允许用于**已裁决为正确**的行为；错误行为被裁决推翻后，
   契约、实现、测试三处同改（本案：旧链「环绕不重瞄」被逐位复刻、被探针验证、被测试固化——
   三层全绿，依然是错的，2026-09-23 推翻）。
2. **单一写入者**：全工程只有 `BattleCameraDriver.ApplyFrame` 写主相机 transform/orthographicSize
   （`camdiag` 的 LastFrame 比对即守卫）；新旧实现并存期间，旧实现必须显式停用或删除——
   双写入者叠加 = 表现怪异 + 排查迷路（本案实测）。
3. **改行为先改契约**：相机行为争议以本表为唯一裁决依据；交接/待办/聊天记录只引用不另述。
