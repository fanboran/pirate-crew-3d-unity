# 相机行为契约

> **定位**：战斗相机「玩家可感知行为」的**唯一规格**（单一事实源）。
> 实现 = `CameraFraming`（纯数学）+ `BattleInputReader`（唯一输入采样 → 意图帧）+
> `BattleCameraDriver`（唯一写入者）；测试 = `CameraFramingTests` / `CameraFeelRulesTests`
> （本契约的**可执行形式**）。
> 交互状态（自由镜头/选中/操作中/执行中）的归属见[交互操作契约](交互操作契约.md)；
> 设计意图见[../设计/操作与交互.md](../设计/操作与交互.md) §7。
>
> **为什么有这份文档**：r13 相机连环案（右键旋转被实现成平移拖拽，用户连驳多轮）的复盘结论——
> 「旋转」从来没有定义层；错误行为还被注释合法化、被测试固化。规则由此立：**行为改动必须先改本契约，
> 再动实现，同步测试**。两态重构（ 定案）追加同源纪律：**状态切换不得跳变**。
> 数值（灵敏度/速率/平滑系数）**【提案/待定】**，实机验收后定案。

## 不变量

1. **单一写入者**：全工程只有 `BattleCameraDriver.ApplyFrame` 写主相机 transform/orthographicSize
   （`camdiag` 的 LastFrame 比对即守卫）；far 的例外口 `SetFarClipForSpan` 保留。
2. **位姿全目标化**：相机位姿 = {焦点, 方位, 俯角, 取景档} 四元目标 + 指数平滑的现实值；
   除开局落位外不存在直写现实值的路径——瞬跳在结构上不可构造。
3. **操作冻结是定义**：「操作中相机锁定」不是可忘的开关，是模式表的一行——不存在「忘了锁」的路径。
4. **等价 ≠ 正确**：「与旧实现逐位等价」只允许用于**已判定为正确**的行为；错误行为被判定推翻后，
   契约、实现、测试三处同改（r13 教训原文保留）。

## 重构纪律

1. **改行为先改契约**：相机行为争议以本表为唯一判定依据；交接/待办/聊天记录只引用不另述。
2. **旧链路必须根除**：观察模式开关（`SetObserveMode`）、自由锚（中键）、Scope 视野混合、
   「滚轮步进像素档」等旧路径已随两态重构退役——不得以兼容名义双轨保留
   （单一写入者纪律的推论：双路径 = 表现怪异 + 排查迷路）。
3. **模式表驱动**：新增相机行为 = 新交互状态或新模组的相机行——先改[交互操作契约](交互操作契约.md)
   的状态表，再改本表对应行，最后动实现。
