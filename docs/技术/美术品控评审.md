# 美术品控评审规程

> **这份文档解决什么问题**：美术实现产出一批渲染截图后，按本规程评审：把「看着还行 / 感觉不对」变成「第几个机位的哪个像素区域、实测值多少、违反哪条判据、怎么改」。
> **评审立场**：以玩家视角判断——「如果你玩这游戏就这垃圾美术，你愿意玩下去吗」。
> **禁止**「看起来还行」「整体不错」这类无坐标、无实测值、无判据出处的结论；此类意见一律退回重写。
> 判据来源：[美术.md](../设计/美术.md)（§3/§4/§9）、[场景.md（战斗竞技场）](../设计/场景.md)、[UI设计语言.md](../设计/UI设计语言.md)、[3D空间模型对齐.md](3D空间模型对齐.md)、[描边Shader调试.md](渲染/调研/描边Shader调试.md)、机位清单 `pirate-crew/Assets/Editor/ArtReviewShots.cs`。引用一律写 `文档:节/行号`。

## 1. 三不原则

1. **不空泛**——每条意见必须带「机位 + 画面坐标区域 + 实测值 + 判据出处」四项；缺任一项 → 意见作废，不算评审产出。
2. **不只靠肉眼**——能测的量必须给程序化实测值（§5）；肉眼只做「叙事/焦点/像不像海盗」的主观判断；能测却只写「看着发灰」→ 退回补测。
3. **不放过**——只要命中判据就开单，不因「快验收了」「这是小事」而放过；漏判被回归复验捉到 → 该视角本轮评审记失效。

## 2. 判定分级

1. **不合格（Blocker）**——画面读不出「这是个能玩的游戏」，或违反原始诉求红线：裸方块单位、界面英文残留、全屏洋红（shader 失败）、单位不入镜/不生成、穿模遮死焦点。必须本轮修；不修不得进入下一波次。
2. **需返工（高）**——明确违反已确认判据，且玩家一眼能察觉：红蓝不可分、地平线硬切、阴影方向矛盾、中文豆腐块。本轮或下一轮必修。
3. **需优化（中）**——违反判据或观感明显瑕疵：细节密度不足、图标可辨性差。可排后续波次，登记不丢。
4. **可接受（低）**——仅细节打磨：圆角、间距、标签微调。记录，不阻塞收敛。
5. **不达标（测量失败）**——判据要求的量测不出来（图上量不到、被遮挡、机位没覆盖）。属**产线缺陷**：要么补机位，要么补判据，按 Blocker 处理。

## 3. 机位与七视角

● = 必评；○ = 相关即评；空白格 = 发现问题才算命中。

**七个视角**（每图至少 3 个视角独立看；每视角由**独立 agent** 承担，禁止同一 agent 兼两视角、评审期间互不交流结论；每视角必须给出本视角下最严重的一条，不允许交空；「出图者」不得评审自己参与改动的图）：

1. **玩家首因印象**——`battle-45`、`hud-fullscreen` 的前 3 秒：是海盗抢宝吗 / 知道往哪打吗 / 想不想继续看。三件事任一读不出 → Blocker。
2. **构图与镜头**——各机位取景：唯一焦点、留白、纵深三段、遮挡关系、地平线内容物。焦点读不出或遮挡可玩区 → 高。
3. **材质**——材质分区、色带档位、纹理能量：沙/水/木/铁/布一眼可分。材质无法分辨 → 高。
4. **光影**——明暗两端、阴影方向一致性、色带过渡、泛光是否糊描边。平光/阴影方向矛盾/单位浮空 → 高。
5. **角色**——单位造型（美术.md §9）、阵营可辨、选中态全件同步。裸方块 / 红蓝不可分 → Blocker/高。
6. **UI 与中文排版**——HUD 每个角落：无英文、无豆腐块、字号原生档、对比度、不遮挡可玩区。英文残留 / 豆腐块 / 数值错 → Blocker/高。
7. **场景叙事密度**——陈设是否构成「一个游戏场景」而非灰模场地：水陆过渡、道具密度与重复感。读成灰模场地/空得过半 → Blocker/高。

## 4. 证据格式与工单

每条意见的证据必须写成：`机位 slug + 坐标(x%,y%) + 像素框[x0,y0,w,h] + 实测值（主色/L*/像素数/比例）`。坐标以画面左上为原点；缩放过的图必须标原始分辨率。

一个工单只对应**一个可独立验证的缺陷**：

```
工单号：AR-R<轮次>-<三位序号> 例：AR-R1-007
视角：<1-7 之一> 例：5 角色
涉及机位图：<slug 列表>
证据（坐标+实测值）：<坐标(x%,y%) + 像素框 + 实测值>
违反判据（文档:节/行号）：<判据编号>
严重度：<Blocker | 高 | 中 | 低>
建议修法：<可执行动作，写清改哪个部件/材质/参数与目标值；不得写「优化一下观感」>
归属波次：<渲染 | 角色 | 场景 | UI | FX | 相机>
复验方式（哪张图要变成什么样）：<机位 + 量 + 目标值>
```

排序：Blocker → 高 → 中 → 低；同级按「同波次可一次改完」聚簇，减少出图轮次。

## 5. 程序化判据工具箱

所有量测在 1080p 截图（或明确标注的原始分辨率）上做；采样窗口排除 HUD 与描边。

1. **P-1 色相分离度**——两区域主色转 HSV 算色相角差（窗口 ≥64×64）；远景 沙/海/天两两 ≥90°【待定 Q-1】。
2. **P-3 单位屏幕高度**——单位连通域竖向包围盒像素高；≥25px【待定 Q-19：正交 30° 口径下需重定】。
3. **P-8 洋红像素检测**——全图扫 `R>200 && G<60 && B>200`；0 px（shader 失败判据）。
4. **P-9 纯色大平面**——200×200 窗算灰度标准差；阈值未定【待定 Q-17】。
5. **P-11 UI 字号档位**——文本行包围盒高；像素字体原生档四档（16/12/10/8），禁放大/伪粗。
6. **P-12 豆腐块/缺字**——字形连通域为空心矩形且内部空白率 >85%；0 处（口径见 UI设计语言）。
7. **P-13 文字与底对比度**——文字区主色与紧邻底色算 WCAG 对比度；≥4.5:1（口径见 UI设计语言）。
8. **P-18 危险红主色**——危险/落水警告区红像素主色；`#CC2222`±10（口径见 UI设计语言 §八第 5 条）。
9. **P-19 青色连通区计数**——全图扫青色后连通域计数；1 个【待定 Q-3】。

> 同一量在不同文档给了不同阈值时，按最严格者判定并同时标注「本项阈值存在冲突，待定」，不得自行选一个当定论。

## 6. 评审流水线

1. **出图**——协调者串行跑 MCP 采集（编辑器不暂停，`manage_camera` 显式指定 `output_folder`）；产出图 + 图清单（含机位/分辨率/参数快照）。
2. **冻结基线**——图清单哈希冻结，评审期间不得换图。
3. **并行多视角评审**——七个独立 agent，各视角工单草案（§4 格式）+ 最严重一条结论。
4. **汇总去重排序**——同一缺陷多视角命中则合并，严重度取最高。
5. **协调者定案**——每单判定「接受返工 / 接受现状（需书面理由）/ 转【待定】」。
6. **派单返工**——按「渲染/角色/场景/UI/FX/相机」分域派发，多 agent 文件域不重叠。
7. **重新出图**——受影响机位重出 + 全量回归机位出图。
8. **回归复验**——与第 3 步**不同**的 agent 逐条核对 + 新问题登记。

**收敛标准**：`Blocker = 0` 且 `高 = 0`，且所有 `中` 工单均有明确处置（已派单，或有协调者+用户书面接受的「暂不修」理由）；`低` 可留档不阻塞。全量评审最多 **3 轮**（全量找茬 → 回归+新问题 → 收口复核），第 3 轮仍有 Blocker → 停止加细节，走「缩小范围 / 换实现方案 / 接受降级并留档」三选一。任何影响画布的改动（材质、光照、相机、Prefab 造型、UI 布局）落地后，受影响机位**必须重出并复验**。

## 7. 回归清单（每次返工后必核）

任一失败即视为本轮返工引入回归（对应工单直接判 Blocker/高）。

1. **G-1 选中描边**——青色 `#49D9D6`，角色两件（圆柱+圆球）全部同步（美术.md §9）；选中态截图描边色采样 ΔE00 ≤5，逐件核对。
2. **G-2 投掷预览 = 实弹**——预览线与实际弹道一致，不被装饰遮挡（[场景.md（战斗竞技场）](../设计/场景.md) §7；[3D空间模型对齐.md](3D空间模型对齐.md) §3）；16 组出生点对投全轨迹截图，0 组被遮。
3. **G-3 出生点**——不入水、无缝隙陷地（场景.md §7）；5 红 3 蓝共 8 个出生点逐一截图，全部站可见地面。
4. **G-4 HUD 文案**——无英文残留、中文无豆腐块（[UI设计语言.md](../设计/UI设计语言.md) §八第 1/6 条）；全文案扫描 + `hud-fullscreen` 逐字读图。
5. **G-5 相机**——正交、俯角锁 30°、方位自由旋转、Transposer 距离 30、OrthoSize 整数档（[渲染管线.md](渲染/管线/渲染管线.md)；3D空间 §2）；读相机参数快照，与 `BattleSceneWiringTests` 断言值对照。
6. **G-6 无洋红**——shader 编译未失败且未被构建剥离（[描边Shader调试.md](渲染/调研/描边Shader调试.md)）；P-8 全图检测 = 0，并查 Player.log 无「找不到 shader」警告。
7. **G-7 边界**——无人工危险提示层、不进可玩区（场景.md §4/§7）；截图标注边界与可玩区，无人工红线。
8. **G-8 战斗数值**——显示与当前局一致（UI设计语言 §八第 8 条）；与 `BattleController` 数据比对。
9. **G-9 单位造型**——仍是「圆球 + 圆柱」两件，未回退成方块或加出多余部件（美术.md §9）；特写截图轮廓核对 + 预制体 renderer 计数。

## 8. 【待定】登记纪律与清单

- 评审中若发现「文档本身没规定、或两文档自相矛盾」，**不得自行拍板**：登记为 **【待定】**，写清「两种取法各会得到什么后果」，交协调者（必要时转用户）定案。
- 判据的效力以标注为准：待定项在定案前按文档现值为准，不得当作已确认口径引用。

1. **Q-1 远景三区色相分离阈值（≥90° vs ≥20°）**——双方旧出处均随风格转向失效；取严可能误伤同色系远景，取松可能糊成一片，需按新口径重定。
2. **Q-3 同屏选中信号是否只允许一处**——UI 判据要求连通区=1，但 3D 单位选中描边与名册选中行高亮天然并存；取「一处」则按字面失败，取「两处」需改判据。
3. **Q-17 纯色大平面标准差阈值未给数值**——无阈值则 P-9 无法判定；建议起调：沙 >6、水 >4（灰度 0-255）并回填。
4. **Q-18 爆炸/FX 无验收判据**——`explosion-moment` 机位已可出图，但无 FX 专项判据；本轮按现有判据登记，命中即开单，不得自造 FX 判据。
5. **Q-19 单位屏幕高度前提已变**——旧 25px 基于透视相机 18/45° 口径；现行正交 + 30° 俯角下需重测定档。
