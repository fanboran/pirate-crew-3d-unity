# 交互操作契约

> **定位**：战斗交互「玩家可感知行为」的**唯一规格**（单一事实源）——两态状态机、键位、
> Esc 矩阵、操作模组接口。设计意图与理由见 [../设计/操作与交互.md](../设计/操作与交互.md)
> （本文不重复「为什么」，只锁「是什么、怎么判定」）。
> 实现 = `InteractionRules`（纯 C# 状态机/迁移表）+ `BattleInputReader`（唯一输入采样 → 意图帧）+
> `BattleInteractionController`（编排薄壳）+ 操作模组（`StandardThrowRules` 等纯规则）；
> 测试 = `InteractionRulesTests` / `StandardThrowRulesTests`（本契约的可执行形式）+ PlayMode 契约用例。
>
> **为什么有这份文档**：三模式时代（移动/操作/观察）没有定义层——模式名与行为不符、切换带隐式
> 副作用、一键多义、ESC 语义随上下文漂移（系统审计 2026-10-03）。两态重构立约：
> **行为改动必须先改本契约，再动实现，同步测试**。
> 骨架经创始人 2026-10-03 裁决；**速率/灵敏度等数值全部【提案/待定】**，实机验收后定案。

## 规格（每条 = 输入 → 可观察结果）

### A. 状态机

| # | 状态 | 进入条件 | 相机归属 | 判定法 |
| --- | --- | --- | --- | --- |
| A1 | **自由镜头**（默认起态） | 对局开始 / 取消选中 / 回合推进落定且无剩余行动 | 编辑器飞行式自由观察 | 实机：不选人直接飞行 |
| A2 | **选中 · 浏览** | 自由镜头左键点中己方存活单位（30px 屏幕半径最近）；或执行落定后仍有行动 | 环绕选中单位 | 实机点选；`SelectionChanged` 事件 |
| A3 | **选中 · 操作中** | 浏览态选择操作（武器格/跳跃） | **锁定**（不接受任何相机输入） | 实机按键；`OperationChanged` 事件 |
| A4 | **执行中** | 操作中确认（回车/屏幕确认钮） | 跟随弹体/被抛角色（见[相机行为契约](相机行为契约.md)） | 实机发射；`ActionSelected` 事件 |

| # | 迁移 | 输入 | 结果 | 判定法 |
| --- | --- | --- | --- | --- |
| T1 | A1 → A2 | 左键点中己方存活单位 | 选中 + 镜头平滑环绕 | 实机 |
| T2 | A2 → A1 | Esc（取消选中） | 取消选中 + 镜头保持当前位姿切自由飞行 | 实机 |
| T3 | A2 → A2 | 左键点其他己方单位且**未行动** | 换选中（镜头平滑过渡到新单位） | 实机 |
| T4 | A2 → A3 | 点武器格 / 跳跃钮（或对应快捷键） | 操作模组激活，操作 HUD 弹出 | 实机 |
| T5 | A3 → A2 | Esc（取消操作） | 模组参数丢弃，回操作菜单 | 实机 |
| T6 | A3 → A4 | 回车 / 屏幕确认钮 | 执行（发射/起跳），回合经济扣减 | 实机 |
| T7 | A4 → A2 | 落定且行动角色仍有行动（抛自己后 `CanShoot`） | 回浏览，镜头平滑环绕该单位 | 实机 |
| T8 | A4 → A1 | 落定且无剩余行动（用武器/结束回合） | 回合推进，回自由镜头 | 实机 |

- 回合开始（`TurnStarted`）**不自动选人**：镜头平滑 pan 到行动角色作提示；玩家任何相机输入即刻接管。
- 执行中的落定判定沿用既有「角色静止 + 弹体不在飞」活动性口径（`BattleController.IsAnythingActive`）。

| # | 情形 | Esc 行为 | 判定法 |

| C1 | 确认弹窗开着 | 关闭弹窗 | 实机 |
| C2 | 暂停中 | 恢复 | 实机 |
| C3 | 操作中 | 取消操作回浏览 | 实机 |

| # | 规则 | 判定法 |
| --- | --- | --- |
| D1 | 本回合**未消耗任何动作**（`ActionState` 未变）时，点其他己方存活单位 = 换选中 | `TurnRules` 单测 |

### E. 暂停

| # | 规则 | 判定法 |
| --- | --- | --- |
| E1 | 暂停 = `BattlePause`（timeScale=0 + 状态位），任何交互状态可达（P 键 / C5） | 实机 |
| E2 | 暂停期间：输入冻结、轨迹预览隐藏、模组参数保留（恢复后继续瞄准） | 实机 |
| E3 | 对局结束（`IsMatchOver`）后不进暂停 | PlayMode |

### F. 操作模组接口

| # | 规则 | 判定法 |
| --- | --- | --- |
| F1 | 模组 = 参数集 + 键位表 + 预览形态 + 执行出口；「操作中」对模组只暴露统一的激活/取消/确认三口 | 代码结构 |
| F2 | 新武器操作形态 = 新模组（声明于操作菜单条目），**不改状态机、不新增交互状态** | 代码结构 |
| F3 | 专用模组（轨道轰炸/放置类等）规格随武器重做逐个立条目，当前仅标准投掷在册 | 本文 §B10–B13 |

### G. 状态提示条（HUD 呈现契约）

| # | 规则 | 判定法 |
| --- | --- | --- |
| G1 | 屏幕下方常驻两行状态条：第一行 = 当前交互状态名（操作中含操作名：「跳跃」或当前武器名），第二行 = 该状态的键位提示（§B 的玩家可读形式） | 实机逐态 |
| G2 | 状态条内容与 §B 键位表同源：键位或状态语义改动先改 §B，状态条文案随后同步；暂停中覆盖为暂停提示 | 实机 |
| G3 | 先行纯文字呈现；图像化提示（图示键位等）为后续演进，替换面仅限状态条自身（设计层 §9） | 设计层 |
| G4 | **状态指示钮**（右上角，蓝队 pips 正下方）：按钮皮指示件——自由镜头 = 常态灰面，选中/操作中/执行中 = 金面 sticky；文字与状态条第一行同源（2026-10-05 走查"我到底是哪个状态"） | 实机逐态 |

## 不变量（任何改动不得破坏）

1. **状态语义唯一**：相机归属与键位含义由且仅由交互状态决定；不存在「同一键在同一状态下两个含义」。
2. **无跳变**：状态切换 = 镜头目标位姿的指数平滑过渡；全工程唯一瞬切点 = 对局开局首次落位
   （相机侧判定法见[相机行为契约](相机行为契约.md)「平滑过渡」条）。
3. **单一输入采样点**：全部玩家输入经 `BattleInputReader` 采样为意图帧后分态消费；
   禁止任何组件绕过采样点直读 `Input`（悬停拾取等纯 UI 例外走 EventSystem）。
4. **Esc 单点解析**：Esc 只在 `InteractionRules` 解析一次，按 §C 矩阵分派。
5. **操作中回合冻结**：操作中（模组激活）`IsAnythingActive` 为真，inactivity 计数清零——
   瞄准思考不丢回合（沿用既有挂机保护语义）。
6. **选中唯一**：任意时刻至多一个单位处于选中态；换人/取消必须先清旧选中。

## 事件契约（详见 [EventBus事件契约登记表](架构/EventBus事件契约.md) §2）

| 频道 | 载荷 | 发布方 | 订阅方 |
| --- | --- | --- | --- |
| `BattleEvents.SelectionChanged` | `SelectionChangedPayload{PirateId, Selected}` | `BattleInteractionController`（选中/取消/换人） | HUD（操作菜单显隐）/ 相机（环绕↔自由） |
| `BattleEvents.OperationChanged` | `OperationChangedPayload{PirateId, IsWeapon, WeaponId, Active}` | `BattleInteractionController`（模组激活/取消） | HUD（操作 HUD 显隐）/ 音频（操作开始结束音，待接） |
| `BattleEvents.ActionSelected` | 既有载荷 | `BattleInteractionController`（执行时） | 既有订阅方不变 |
| `BattleEvents.ShotReleased` | `float` **初速（m/s）**（旧口径=拖拽像素距离，随弹弓退役） | `BattleInteractionController` | 音频层（音高映射改按初速） |

## 重构纪律

1. **改行为先改契约**：交互行为争议以本表为唯一裁决依据；设计层改动先落
   [../设计/操作与交互.md](../设计/操作与交互.md)，再同步本表。
2. **测试是契约的可执行形式**：迁移表（§A）、Esc 矩阵（§C）、换人（§D）逐条有无头单测钉住；
   键位（§B）由实机走查清单覆盖。
3. **旧链路必须根除**：三模式（`BattleHudMode`）、观察模式开关、`SetWeaponPreference`、
   Scope 混合等旧路径不得以「兼容」名义保留双实现（相机契约「重构纪律」第 2 条同源）。
