## 一、现状核实：任务书「技术要点 1」与代码不符（已纠正）

任务书称「自研 shader 不吃环境光，切 `ambientMode = Skybox` 后 URP/Lit 吃到 SH、自研 shader 不会
→ 一半亮一半暗」。**实测代码：不成立。**

| shader | 环境光采样处 | 材质上的 `_AmbientStrength` |
| --- | --- | --- |
| `PirateSurface.shader` | `:558` `bakedGI = SampleSH(normalWS) * _AmbientStrength` → `GlobalIllumination(...)` | 1.0 |
| `PirateTerrain.shader` | `:588-589` 同上 | 1.0 |
| `PirateOutline.shader` | `:388-389` 同上（类头 `:387` 自述「环境光来源已从天空盒 SH 改为 Gradient 三色」） | — |
| `PirateOcean.shader` | `:814` `reflectionColor = SampleSH(reflectDirWS) * _ReflectionStrength`（水面的"环境光"走反射方向） | `_ReflectionStrength` 0.7 |

材质写值处：`Assets/Editor/BattleSceneLighting.cs:199/231/293/326/360/390/421/449/562`
（全部 `SetFloat(m, "_AmbientStrength", 1f)`）。

**误读来源**：审计报告 §二.4 的原文是「自定义 shader 只取主方向光、**不吃附加光**
（`AmbientDirector.cs:92-95` 注释自述）」。「附加光」= additional lights（点光/聚光，`AmbientDirector` 的
灯笼点光默认关就是为它），不是环境光。`SampleSH` 取的是 Unity 的环境探针（ambient probe），
Trilight 与 Skybox 两种模式都会填它——所以切模式后 **URP/Lit 与自研 shader 会同时换源**，
不存在"一半亮一半暗"。

**结论**：工作分解第 2 步（给自研 shader 补环境光采样）**无需做**，已由既有实现满足。
真正待做的只有第 1、3、4、5 步。

## 二、既有决策冲突：这不是技术问题，是需要裁决的翻案

`BattleSceneLighting.ApplyThreePointAmbient`（`:958` 起）的类头明确记录过"**为什么用 Trilight 而不是
Skybox 模式**"，两条理由：

1. **三色可控**：Skybox 模式的 SH 完全由天空盒决定，无法单独配"冷补光/暖地面反弹"；
2. **取景上天空盒本来就看不到**：相机固定俯视 45°、FOV 60°，画面上缘在水平线下 15°，
   切 Trilight 不损失可见背景，只把环境光的解释权拿回来。

代价当时也如实记了：水面/金属的 `SampleSH` 反射从"天空盒 SH"变成这三色（`PirateOutline.shader:387` 同款记录）。

因此遗留 #6 的实质是**把环境光的解释权还给天空盒**，换取"环境光随天空/太阳有方向与色彩变化"。
要不要翻由用户拍板（观感取舍，非对错）。若翻，三灯分层的"冷补/暖反弹"必须改用天空盒三色表达
（§三 给了方案：天顶=冷补、下半球=暖反弹、地平线=雾色）。

**本次刻意没有改动既有 Trilight 路径**，所以回退成本 = 删掉 §五 的交付物，不触及任何现役参数。

## 三、设计契约（接线轮必须遵守）

1. **地平线色 = 该档雾色**（测试钉住）。`AmbientLightingPreset.FogColor` 的定义就是"该档天空地平线色，
   保证大气透视而非盖灰"；二者不等会让远景物体在雾里淡出的终点与身后天空对不上，出现接缝。
2. **下半球 = 暖反弹**。切 Skybox 后环境光 SH 完全由天空盒卷积而来，下半球约占贡献的一半；
   现状 Trilight 下半球是暖沙 `#C9A268`，若天空盒下半球画成天蓝，切档后整场会明显转冷。
   故地面色取 `SkyTierCatalog` 的 `GroundBounceHex`（暖沙族），由 `_SkyGroundBlend` 控制暖色下沉速度。
3. **太阳盘方位 = 主光方位**（同一来源，无需对齐校验）。shader 读 URP 全局 `_MainLightPosition`
   （URP 每帧 `ForwardLights.cs:511` 写入，`ScriptableRenderer.cs:1161` 的 SetupLights 早于天空盒 Pass），
   与 `PirateOcean` 太阳光路方位门用的是同一个主光方向。
4. **三方一致铁律升级为四方**：`AmbientTimeOfDayCatalog`（目录）== `BattleSceneLighting` 写值 ==
   `Battle.unity` 烘焙值 == `AmbientSkyboxCatalog`（天空盒目录）。接线时新增两项要一起改：
   `m_AmbientMode`（1 Trilight → 0 Skybox）与 `m_SkyboxMaterial`（换 `Sky_<档>.mat`）。
5. **不许倒退的已定值**：阴影距离 224、SSAO（Balanced Renderer）、雾距 150→1200 / 130→1000 / 110→800
   （「可见海域预算」契约，审计报告 §三）。
6. **已知边界**：SSAO 不作用于自研 shader（不含 `_SCREEN_SPACE_OCCLUSION` 关键字分支）；
   水面反射改由天空盒 SH 驱动后，反射色会随天空盒变化——这正是本任务想要的，
   但实拍要盯"水面与天空在地平线处不出现亮度/色相断层"。

## 七、风险与未决

1. **天空盒 Pass 是否真被画出**：本 shader 刻意不写 `LightMode` tag（与内置 `Skybox/Procedural` 一致，
   它在本工程 URP 下正常出图），但"Pass 被静默丢弃"这类故障 Console 不报错
   （同族事故见 [`描边Shader调试.md`](描边Shader调试.md) §八）。静态核对证明不了它被画出来，
   **必须实拍确认**：天际线以上是渐变天而非纯色/黑，太阳盘出现在主光方位。
2. **环境光整体亮度会变**：Trilight（三色 × 0.85）→ Skybox（天空盒 SH × 0.85）。正午档最可能返工，
   盯"过曝/发灰"。
3. **水面对比**：`_ReflectionStrength` 0.7 的反射色从三色变天空盒渐变，需实拍确认海天线不出现断层。
4. **翻案是否值得**：若实拍判定天空盒看不出差别（相机取景看不到天）、而水面反射变差，
   回退 = 删 §五 交付物 + ArtGate 步骤 + 登记项，不触及现役 Trilight 路径。
