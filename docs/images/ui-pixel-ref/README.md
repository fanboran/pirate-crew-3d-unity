## 二、逐像素量出来的斜面结构（条形控件）

对 `ref-bars-life-mana.png` 取一条穿过条体中部的竖切（x=60），逐行颜色如下
（基本单位 **2px**，全部是整像素、无抗锯齿）：

| 位置 | 厚度 | 实测色 | 角色 |
| --- | --- | --- | --- |
| 外环（上） | 2px | `#54481E` | **外圈暗环**（同一色相的最暗档） |
| 斜面（上） | 2px | `#B9973B` | **亮档**——受光面，光永远来自左上 |
| 内暗线 | 2px | `#54481E` | 斜面**内侧**再压一道暗线 → 这是"凹陷感"的来源 |
| 填充亮沿 | 2px | `#FFA68B` | 填充体上沿提亮（模拟液面受光） |
| 填充主体 | 8px | `#F53C40` | 填充色 |
| 填充暗沿 | 2px | `#99133F` | 填充体下沿压暗 |
| 内暗线 | 2px | `#2F261F` | 同"内暗线"，底侧 |
| 斜面（下） | 2px | `#8C6F2A` | **中间档**——背光面（不是纯暗色） |
| 外环（下） | 2px | `#2F261F` | 外圈暗环 |

**条体总高 24px**（9 段 × 2px + 填充 6px）。换算成生成器的参数：

- `ink` 外环 = 2px，色 = 同色相最暗档；
- `bevelHi` 上/左 = 2px，色 = 同色相最亮档；`bevelLo` 下/右 = 2px，色 = 同色相中间档
  （**不是纯黑**——这是"金属/木牌感"而不是"描边感"的关键）；
- `innerShadow` = 2px 暗线，夹在斜面与内容之间（**凸起件也要有这道**，它把"平面色块"变成"有厚度的块"）；
- 填充体自带 2px 上亮 / 2px 下暗。
- **框架只用同一色相的 3 档明暗**（暗/中/亮），不是多色拼接；换主题只换色相。

## 三、控件词法（第三张图：工具对话框）

这张与前两张不是一类：前两张是**游戏 HUD 的插画件**，这张是**工具软件的控件**。
它能回答前两张回答不了的问题——**一个控件的明度分几级、焦点态长什么样**。

逐条横切 + 纵切量出（量前先把色**量化到 8 档**，理由见本节末）：

| 层 | 量化色 | 与谁比 | 说明 |
| --- | --- | --- | --- |
| 面板底 | `#2C2C34` | 最暗的"面" | 窗口/对话框主体 |
| 控件体 | `#44444C` | **比面板底亮一档** | 按钮 / 输入框的填充；"凸起"靠这一档明度差，不靠斜面 |
| 控件描边 | `#040404` | 近黑、**约 1px** | 每个控件一圈，把控件从底上"切"出来 |
| 焦点态 | 蓝阶 `#3C578F` → `#4C66A3` → `#8CA1C7` | 落在描边上 | 输入框获得焦点时描边变蓝、内侧再压一道亮蓝带 |
| 分组标题字 | `#84A4D4` | 去饱和蓝 | "Size: / Color Mode: / Background:" —— 与正文灰拉开，充当分区信号 |
| 正文标签字 | 近白灰 | — | "Width: / Height:" |

三条可直接搬进生成器的结论：

1. **控件的"凸起"可以只靠一级明度差 + 一圈近黑描边**，不必每条边都做斜面
   （斜面的厚度感留给**条状件**，见 §二；小件用一级明度差更省、更像工具软件）。
2. **焦点/选中态用色相（蓝阶）而不是位移或发光**——这与 §二 条状件的"按压 1px 位移 + 明暗对调"是两套独立信号，
   不要混用在同一控件上。
3. **分组标题单独一个色**（这里是去饱和蓝），是低分辨率 UI 里最省力的层级信号。
   本工程对应的是 `UI_*` 槽之外还要一支"标题/分区"色——**这条目前是缺口，见 §五 待裁 #5**。

> ⚠ **量这张图前必须量化**：它的颜色带 ±2 的抖动（`#2C2C30` / `#2C2C31` / `#2B2B2F` …），
> 说明经过有损压缩；几何是 1:1（边缘只有约 1px 的压缩拖影），但**直接取色会拿到一堆同义色**。
> 上表已按 8 档量化过，照表用即可。

> 【待定】它的**适用度**由 4b 一屏试点裁决：工具软件的信息密度与游戏 HUD 的取向不同，
> 本工程打算取的是它的**控件词法**（上面三条），不是整体气质。试点出图后回填结论。

## 四、格子化状态件（心形/星星）

- 字形单元 **16px 高**（实测标题行 y=1..16），逐格横向排列、格距恒定；
- 每个字形同一个**完整描边**（外圈墨色 1~2px），内部再用 2 档明暗分出面；
- **三态区分靠"内部明暗与饱和度"，不靠缩放**：满 = 饱和主体 + 上亮沿；半 = 主体压暗；空 = 只留外环与一层暗底；
- 顶部数字标题（`Life: 350/450`）是**点阵/像素字体**贴在条外，不在条内。

## 六、复现这份量化

```bash
python - <<'PY'
from PIL import Image
im = Image.open('docs/images/ui-pixel-ref/ref-bars-life-mana.png').convert('RGB')
col = 60
prev = None
for y in range(0, 45):                      # 竖切：逐行色带 = 上表
    h = '#%02X%02X%02X' % im.getpixel((col, y))
    if h != prev: print(y, h); prev = h
PY
```

判据口径：**色带边界必须落在偶数行**（2px 基本单位）；出现 1px 或 3px 的带即为生成器参数写错。
