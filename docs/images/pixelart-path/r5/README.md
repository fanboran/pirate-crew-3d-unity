# r5 · 像素化路径实拍（2026-09-22）：像素网格锁整数倍 + 描边闭合 + 角色真正站住

> 本轮响应创始人连续三轮的现场反馈：①"全屏像素不齐、放大看却正常，是不是分辨率没整数映射"
> ②"下边缘为什么还是没有描边" ③"球头上为什么还有平板、身体为什么不是台柱"。
> 三条都成立，逐条查出机制并修掉；同时挖出两个"编辑器里对、播放器里错"的坑。

## 0. 归档格式改了：原生 PNG（不再压 1280 宽 JPEG）

**原因就是本轮第 ① 条**：把 1920 宽的像素图**缩到 1280 宽**（因数 3.33，非整数）会当场把块边长打乱
——"全屏看着像素不齐"有一半来自这里。像素图的归档**缩放因子必须是整数**，否则存档图自己就失真。
原生 PNG 既精确又更小（这批单张 37~57 KB，比之前的 JPEG 还小），故改为直接归档原生 PNG。

## 1. 像素口径：**锁"放大倍数"，不锁"画布高度"**（创始人裁决）

| | 旧口径（错） | 现口径 |
| --- | --- | --- |
| 锁什么 | RT 高 = 216 | **一个艺术像素 = 5 屏幕像素（锁死）** |
| 1920×1080 | 384×216、块 5 ✓ | 384×216、块 5 ✓ |
| 2560×1440 | 2560÷384 = **6.67 ✗ 非整数** | 512×288、块 5 ✓ |
| 3840×2160 | 3840÷384 = 10 ✓ | 768×432、块 5 ✓ |
| 可见范围 | 固定（正交 size 恒定） | **随分辨率变大**（每艺术像素的世界尺寸固定：1080p 看 28m、1440p 看 37m） |

实现：`PixelartCameraRig.pixelScale`（放大倍数）+ `worldPerPixel`（每艺术像素多少米），
`ComputeTargetSize` 由**实际屏幕**反推 RT；正交 size = 艺术像素数 × worldPerPixel ÷ 2（`deriveOrthographicSize`）。
屏幕宽高同时能被 5 整除的分辨率一律严格整数倍；个别不能的（1366×768）残余 ≤4 像素并**打进日志**，
不静默。播放器实测：`屏幕 1920×1080 → 放大 5× → 艺术画布 384×216（可见 28.0m 高，每艺术像素 0.1296m）—— 整数映射严格成立。`

## 2. 描边：下缘一根线都没有 → **实测 97% vs 0%**，改 `ZTest Always` 后闭合

程序化判据（沿平台剪影逐列扫 6 像素窗口内的近黑像素）：

| 版本 | 上缘有墨线的列占比 | 下缘有墨线的列占比 | 墨线像素总数 |
| --- | --- | --- | --- |
| 反向壳 + `ZTest LEqual` + 拉近 5×（渲染篇 §5 原配方） | 0.98 | **0.00** | 11850 |
| 同上 + **外扩方向归一化** | 0.98 | **0.00** | — |
| **改 `ZTest Always`** | 0.98 | **0.48**（残留部分是"相邻物体互相漏线"，见下） | 23275 |

机制：深度测试的对手是**先画完的地面**（大平面在背景队列里先整片画完），而壳在下缘那圈投射出的
深度是物体的**背面**——18m 见方的台面，背面深达十几米，"拉近 5 倍线宽"（0.65m）根本不够。
而深度测试对本路径是多余的：墨线**画在本体之前**，本体随后会把重叠区盖回，所以它只需要
"别被先画完的东西挡住"⇒ `ZTest Always` 即闭合。
**已知代价**（反向壳固有限制，旧链也记过同一条）：**相邻物体互相漏线**——角色站在台面上时，
它底下那圈会被随后画的台面本体盖掉。要抑制得按层规划 Stencil，属后续项。

## 3. 角色：改用游戏里那个预制体 + 两个"编辑器对、播放器错"的坑

- **形状**：本仓对船员造型早有裁决（`CrewVisualPrefabBuilder`：用户裁决 2026-09-14，
  **两件式 = 圆球 + 圆台柱**，三角帽/头巾/腿/靴/臂全部删除）。此前我手搓的"两块方块 + 一块帽檐平板"
  两处都错：身体不是圆台柱、球头上多了块平板。现改为**实例化 `Sailor.prefab` 并只换材质**，
  尺寸/枢轴/网格与游戏里逐值一致（总高 1.85m；Body 顶 r 0.35 / 底 r 0.40 / h 1.20；Head 球 r 0.35）。
- **坑 1（Rigidbody 自由落体）**：船员预制体根上带 `Rigidbody + BoxCollider`。
  只剥 MonoBehaviour 与 Collider 时 **Rigidbody 会留下**（预制体实例上 `DestroyImmediate` 删不掉它，
  连 `PirateBase` 也删不掉——场景的 `m_RemovedComponents` 里根本没有它们）。
  编辑态不跑物理 ⇒ 编辑器里量到的包围盒完全正确；进播放器后它带重力自由落体，
  采集发生在载入后约 1.5 秒 ⇒ 下落 ½·9.81·1.5² ≈ **11m**，与实测"角色比场景低 11.441m"逐位对上。
  症状是"编辑器里对、播放器里没有角色"，一行报错都没有。
  修法：**先 `UnpackPrefabInstance(Completely)` 解包成普通场景对象**，再三轮"白名单"清扫
  （只留 Transform/MeshFilter/MeshRenderer），最后**当场断言无残留**并点名报错。
- **坑 2（落点埋在台体里）**：蓝船员曾在 (-7.5, 0, 6)、地面木箱曾在 (7.5, 0.7, -8.5)——
  两处都在 step1 的 **±9 足迹之内**，等于埋进 0.5m 高的台体里（画面上"只剩上半身"）。
  这正是创始人两次用不同措辞报的同一件事（"角色和场景比太小" / "平底的角色站到地面**和内容**了"）。
  现在装配期跑**落点不变式**：站在地面的件必须 |x| 或 |z| > 台阶足迹。
