## 2. 取景规则（为什么是这些数）

`PixelartLevelScene` 的海图行按**跨度派生**（八张图跨度差 150–280 m，不能像样板关那样写死米数）：
`Target = (span/2, 3, span/2)`、`wide = 0.6×span`、`mid = 0.35×span`、`close = 0.12×span`。
**wide 从 1.0×span 收到 0.6×span 是实测改的**：1.0×span 时整帧只有 6.6~7.9% 是场地
（地图成了海中央一小块），0.6×span 后升到 15.8~20.2%。

## 3. 已定位缺陷：**宽机位下站面被描边整片涂黑**（未修，已登记）

| 档位 | 近黑（`#0D0D0D`）占比 | 沙色站面占比 | 判读 |
| --- | --- | --- | --- |
| `pl101-mid` | 1.4% | 21.4% | 正常 |
| `pl101-wide` | **12.7%** | **0.6%** | 站面几乎全被墨色盖掉 |

**证据链**：`pl101-dbg-albedo`（同机位调试图）里站面是 `#C4A76A` 沙色（占 25%），
**albedo 缓冲里近黑 0.0%** ⇒ 几何与材质都对；而最终图里同一批像素是纯 `#0D0D0D` ⇒
**黑是后加的**（着色/描边那一趟），且**只在宽机位出现**（中机位同一批站面是受光的沙色 `#DBB46D`）。

结论：这是 **r9 §4 那条「描边整面涂黑」缺陷的同一个类**（礁盘侧壁 / 站面被整片涂黑），
但这次证明了它**与取景尺度相关**——同一场景、同一材质，只改可见米数就从 1.4% 跳到 12.7%。
所以修复方向要从"门控在什么像素尺度下失效"入手（连通域 `connectedTo/closerThan` 的判定
与 `_PixelartAAThreshold` 是否随尺度变化），而不是先动内容侧几何。**登记见待办**。
在修好之前，海图的观感图以 `-mid` 为准。
