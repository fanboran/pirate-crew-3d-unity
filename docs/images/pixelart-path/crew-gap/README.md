# 角色漏缝证据（当前实机 2× 截图裁切）

## 最终口径：+0.25 相位 + 对称覆盖膨胀描边

- **头/身分开测**（块锚中心采样的部件掩码，逐行左右外沿到画布中轴）：
  身体在 +0.10…+0.40 都是 0 误差，头只有 **+0.25** 是 0；两者在 **+0.25 同时为 0**。
  −0.25 只是并集外沿的 0，头/身各自其实是 10/23——那是旧墨线门控把身体的不对称补偿掉的假对称。
- **墨线层**：旧的 4 邻域膨胀 + connected/closer 接缝规则会把对称覆盖拧歪（+0.25 时
  char 掩码 XOR 0、理想膨胀 XOR 0，实际墨线 XOR 88/外沿差 34），并在头颈交界出两条平行墨线。
  现改为**对称覆盖膨胀**（`_PixelartOutlineSimple`，由 rig 的 `simpleOutline` 写入）：
  只保留“中心不描边 + 四邻域有描边物体 + 中心不比邻域近”的膨胀，加地面相切兜底；
  关掉接缝规则与第二趟补缝。头/身同属一个覆盖连通域 ⇒ 只剩一条边界线。
- **探针实测**（开 `_SnapToPixelGrid`、战斗同参：32m / 2× / 30° / 45° / 机位 30m / 远裁 200）：
  `maskMismatch=0 inkMismatch=0 contourError=0 bodyContour=0 headContour=0 seamInk=0 gaps=0 partLeaks=0`。
- **生产**：`Assets/Art/Materials/Crew/Crew*.mat` 的 `_SnapPhase = (0.25, 0)`；rig `simpleOutline = true`。

## 读出来的东西

在这帧里角色掩码/墨线大体镜像对称，但有三处**填充与墨线之间夹着地面灰**的像素，
外加一处**头部内棕色透出身体红**的部件漏色：

| 位置 | 艺术像素 bbox（相对裁切） | 形态 |
| --- | --- | --- |
| 头部左缘 | `(4,5)-(5,7)`，3 个候选格 | `# g [肤色]`：墨线 → 灰 → 填充 |
| 头部底缘 | 第 8 行（身体顶面所在的 710–712 行上方） | 茶色头部里透出**身体红**（3 像素，橙框） |
| 身体底缘左角 | `(4,30)-(6,31)`，3 个候选格 | 深红填充 → 灰 → 底部墨线 |
| 身体底缘右角 | `(12,31)`，1 个候选格 | 红填充 → 灰 → 底部墨线 |

灰是地面/云岛阴面的颜色（约 `#AAAAA9`），不是角色材质的暗档，也不是纯光照把两侧压黑。
头部底缘那处不是灰：body red 在身体顶面（710 行）**上方**出现，说明头部底缘有丢格，
后面的身体透出来——这是"部件漏色"，不是描边门控。它同时满足三个已知边界条件：
2× 档块锚落在块角、`BlockPatch` 只补覆盖 ≥2/4 的块、4 邻域描边 + 第二遍只补对向空格。
因此这张图只能证明**缝是真的、且是"块级丢格/门控"形态**，不能单凭它断定是哪一层；
用 [角色探针](../../../技术/渲染/管线/角色探针.md) 的 `probe_vis.png`、`part_vis.png`、
`conn_vis.png` 和 `albedo_patch_cover.png` 在同一坐标逐层排除。

## 把描边移动一遍（`outline-move-experiment.png`）

四个面板都是在这张裁切上按艺术像素做的**示意性编辑**，不是游戏实机重渲：

| 面板 | 改法 | 结果 |
| --- | --- | --- |
| 原图 | — | 7 个灰缝候选 + 3 个头部底缘身体红 |
| A 描边内移 | 把墨线落到灰缝格，删掉外侧旧墨线 | 灰缝基本隐藏，但仍剩 1 个候选；填充仍短一格；**头底红原样保留** |
| B 参照库式边缘暗化 | 灰缝格改成“最近填充色 × 0.45”的暗线，删掉外侧旧墨线 | 同样剩 1 个候选；头底红被补成头色；线色不是纯黑（但非缝处仍是原黑圈，属于混合近似） |
| C 1/4 块补填充 | 灰缝格改成相邻填充色，黑墨线保持外侧 1px | **0 个候选**；填充恢复全宽；头底红补成头色；黑线仍 1 像素 |

结论：**移动描边只能把灰缝“盖住”，不能把缺失的填充/头底块补回来**；A 里角色会窄一格、
头底红还在。C 才是 BlockPatch/填充层该做的事。B 是参照库的线色口径，但要连同它的
“低分辨率直接渲染”一起才完整——单改线色不够。

## 参照库为什么没有

- **原作（2D Flash）**：角色是矢量/精灵，描边是美术的一部分；没有 G-buffer、连通域、
  块锚、BlockPatch 这一套。
- **参照 Unity 工程**（`external/ref/unity-isometric-pixel-pipeline`）：
  `Assets/Shaders/PostProcess/OutlineShader.shader` 的轮廓是 **3×3 视图空间重建 + 8 邻域
  深度不连续**，线色 = `closest_color * _LineDarken`（把最近像素的颜色压暗），
  没有 per-object `applyOutline`、没有 `connected/closer` 位、没有单独的墨线缓冲；
  `Assets/Rendering/PC_Renderer.asset` 里 `OutlineRendererFeature m_Active: 1`，
  `PixelRendererFeature` 的低分辨率档是 640×360。它的“线”和“填充”是同一个低分辨率
  像素采样，线的位置就是边缘像素本身，所以不存在“填充块和墨线块各自占位”的夹缝。
- **本仓**：`PixelartOutline.shader` 是另一套——4 邻域膨胀 + 逐物体 `Palette.a` +
  连通域 `connected/closer` 门控 + `BlockPatch` 1/4 准入；它是“单独一圈墨线”，
  所以填充/墨线/头身两套原点在块级上不一致时就会夹出灰缝或透出身体红。
  文档里 v3 的旧 `OutlinePass` 是 `m_Active: 0`（从没跑过）；参照库里现在这套
  `OutlineRendererFeature` 是启用且更稳的**另一条实现**，两者不要混为一谈。

头底透红还多一层：当前几何在**屏幕档**渲染、按块中心点采样，头/身是两套 renderer
各自吸附；参照库是**低分辨率直接渲染**，每个低分辨率像素是一个真实表面，没有“块中心
可能落在另一个部件上”的问题。所以头底红要按 C 补填充/改低分辨率直渲，而不是挪描边。

## 不要误读的地方

- 左右明暗（左暗右亮）是世界固定主光打在圆柱上的结果，**不是**几何不对称；探针的
  `colorMismatch` 高是预期的。
- 红框包含 4 邻域描边的对角缺角候选（1–3 像素夹层），不是每一格都必然是"块被丢掉"；
  探针 `probe.txt` 的 `gaps` 是候选计数，最终看 `probe_vis.png` 的红点位置。
