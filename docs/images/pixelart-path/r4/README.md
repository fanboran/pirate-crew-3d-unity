# r4 · 像素化路径实拍（2026-09-22）：光影回来了 + 反向壳描边 + 场景尺度

> **这一轮解决的是"画面根本不对"**：r3 那张图里所有面同色、没有任何光影、描边只在朝天空那侧出现、
> 角色是胶囊、地图小到"一个跳跃就跨过去"。本轮把根因找出来并逐条修掉，然后按程序化判据复核。

## 1. 一句话结论

**整屏没有光影的根因是 `prop.a` 通道语义撞车**（一个通道同时是"墨线标记"和 `_AAScale` 占位属性，
而后者默认值 1.0 ⇒ 每个不透明像素都被着色 pass 当成墨线、原样输出 albedo）。
修掉之后色带与环境光立刻恢复；**描边按渲染篇 §5 的反向壳配方还原**（1 低分辨率像素、
壳先画本体后画、沿视线拉近 5× 线宽、大平面按 renderQueue 先画完），四边闭合。

## 4. 色号已与解析式逐位对上（这是"颜色管线有没有错一层"的正面证据）

`PixelartCameraRig` 每轮把实际下发的光照量打一行日志，判据据此可算期望值：

```
lightDir=(-0.3406,0.8480,0.4059)  lightColorLinear=(1.2333,1.1294,0.9250)
ambientLinear=(0.0423,0.0630,0.1170)  unitSize=0.129630  rt=384x216
```

按 `sRGB(multiStep(ndotl,3,0,0)·lightColor·albedo + ambient·albedo)` 手算 tan 台面
（albedo `#D8BE8A`）三档，与实测色块对照：

| 面 | 解析期望 | 实测（pa-mid 主色块） |
| --- | --- | --- |
| 顶面（档 1.0） | (241, 205, 141) | **#F0CD8D** = (240, 205, 141) |
| 朝光立面（档 0.5） | (179, 154, 107) | **#B39A6C** = (179, 154, 108) |
| 背光立面（档 0.0） | (49, 52, 50) | **#2E3232** = (46, 50, 50) |
| 墨线（原样输出 `#120C14`） | (18, 12, 20) | **#0D0D16** = (13, 13, 22) |

前三条逐位吻合 ⇒ **线性/伽马没有错层**。第四条差一点：墨色存进 **8 位线性** 的 albedo 缓冲时
精度不足（0.0056 → 8bit 线性量化为 1/255 → 显示为 13 而不是 18）。
已知量化损失，若要精确保留墨色，做法是给墨线单独一条不经 8 位线性缓冲的通道（P4 前后再定）。

## 5. 新判据五「亮暗跨度」是怎么定的（有用例验证）

`(最亮 luma − 最暗 luma)/最亮 luma`，只统计占比 ≥0.5% 的大色块、剔除近黑墨线。
取值在两轮实拍上分得很开，所以**拿它当"光照有没有被整屏旁路"的回归判据**：

| 轮次 | 情况 | 跨度 | 判定 |
| --- | --- | --- | --- |
| 本轮 p5 | 光照正常 | 0.76 ~ 0.80 | 通过 |
| 上一轮 p4 | `prop.a` 撞通道、整屏旁路光照 | **0.46（每一张都挂）** | FAIL |

即：复现该事故时这条判据会在**每一张**图上报警，而旧的四项（块边长/色数/平坦度）全部照过。

## 6. 本轮改掉的机制（为什么改、依据在哪）

| 改动 | 依据 | 备注 |
| --- | --- | --- |
| `prop.a` 的"墨线标记"与 `_AAScale` 解耦（删除该属性、本体 pass 写 0） | 事故根因 | 语义变成排他：只有墨线 pass 写 1 |
| 描边从"低分辨率域屏幕空间判据"改回**反向壳** | 渲染篇 §5「不用屏幕空间边缘检测」；蓝本 §8 裁决点 3 推荐「外轮廓=反向壳」 | 我上一版自造屏幕空间方案属跑偏，已撤 |
| 壳 **先画**、本体后画 | 渲染篇 §5 + `PirateToon.shader` 六轮实拍的三条因果链 | 反过来先画本体 ⇒ 壳落在本体内侧、LEqual 全灭 |
| 壳沿视线拉近 **5× 线宽** | 渲染篇 §5（覆盖前缘 ~0.4u 深度差） | 不拉近 ⇒ 前缘环输给地面深度 |
| 大平面 `renderQueue = 1999`，Feature 按队列分段绘制 | 渲染篇 §5「壳环需 Geometry 队列 +50 才不被海面盖掉」 | 地面 ZWrite On 的本体会盖掉壳环 |
| 线宽 **1** 低分辨率像素 | 渲染篇 §5「RT 空间 1px 起步」 | 旧链的 2px 是"全分辨率渲染+3× 降采"时代的补偿，本路径几何直接渲进 RT，不适用 |
| 俯角 30°、RT 高 216、场景 160×160、球头 + 台柱身 | 创始人本轮的逐条指令 | 见 `PixelartPilotScene.cs` / `PixelartPilotSetup.cs` |

## 7. 还没闭合、要创始人拍的一条

**背光立面的颜色**：本路径按 v3 的 `DiffuseShading` 口径，最暗档 = `0 · lightColor · albedo`
再加环境光项，即 **albedo × 环境色（纯乘暗）**，实测落在 `#2E3232` 上下——很暗，
和 1px 墨线（`#0D0D16`）在缩略图里容易糊成一片。

渲染篇 §4.2 对这一点有另一条口径：「**暗部不做纯乘暗**：替换式预制暗部色（材质参数或 ramp 对应档）」。
两条口径给出了不同的机制：

- **(a) 维持 v3 口径（当前实现）**：暗面 = albedo × 环境色；环境光的取值就是暗部色的旋钮。
- **(b) 按渲染篇 §4.2 加"替换式暗部色"**：材质多一个 `_ShadowColor`，最暗档直接输出该色（不再乘 albedo）。
  代价是物体 pass 要多一条通道/缓冲（蓝本 §7.2 第 5 条的缓冲集本来就有 4 张，本路径现在是 3 张）。

这条不改机制、只影响观感，故列为裁决项，不在本轮自行决定。
