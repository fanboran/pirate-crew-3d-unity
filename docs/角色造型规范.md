# 角色造型规范

> **这份文档解决什么问题**：战斗单位目前是**一个裸立方体**（`Assets/Prefabs/PirateCrew/PirateBase.prefab:47`
> 引用内置 Cube `fileID:10202`），只有一个 `PirateBody.mat` 材质（`_BaseColor (0.85,0.82,0.7)`、
> `_Smoothness 0.5`）。本轮用户明确要求"单位不能是方块——一个球加一个梯形即可，建模可以简单但
> 要像海盗、要有辨识度"。本文档定义**部件化造型方案 + 六职业 + 船长 + 原版配件**的几何/尺寸/材质/配色，
> 以及状态表现与描边接线要求，是角色美术实现的唯一口径。
>
> **配套文档**：色彩/材质/光影/验收判据见 [美术风格指南.md](美术风格指南.md)（本文引用为「Art Bible §x」）。
> 坐标口径见 [M2-3D空间模型对齐.md](M2-3D空间模型对齐.md)（本文引用为「3D 空间 §x」）。

## 1. 造型总则

### 1.1 部件化方案（球头 + 圆台躯干）

> **【原始诉求】** 用户原话："一个球加一个梯形"。

单位由**可替换部件**拼成，共享"躯干骨架"，职业只换配件与比例参数：

| 层级 | 部件 | 是否共享 | 说明 |
|------|------|---------|------|
| 根 | `PirateBase`（空对象，脚底 y=0，枢轴 y=0.25） | 共享 | 枢轴 `UnitPivotHeight = 0.25`（3D 空间 §1，`:38`） |
| 身体 | 头球、躯干圆台、腰带环 | 共享几何，尺寸微调 | 六职业共用同一套 mesh，靠缩放/材质区分 |
| 四肢 | 左/右臂、左/右腿 | 共享几何 | 长短按职业微调（钩子手用木腿+钩） |
| 配件 | 头巾/三角帽/眼罩/胡子/钩/木腿/肩甲/围裙/手持物 | **不共享（差异化）** | 辨识度来源，各职业 2-4 件 |
| 挂点 | `Head` / `Torso` / `HandL` / `HandR` / `Back` 空对象 | 共享 | 供描边 binder、动画、手持物挂载 |

**为什么部件化**：① 复用几何体，三角面与材质数可控；② 差异化只改配件，新增职业成本低；
③ 描边系统按 renderer 收集，部件化后每个配件都能被独立收集（见 §5）。

| 量 | 值 | 出处 |

| 水面 | `WaterSurfaceY = -0.2` | 3D 空间 §4（`:86`） |
| 1 瓦片 | 1 世界单位 = 32px | 3D 空间 §1（`:35`） |
| 单位枢轴 | `UnitPivotHeight = 0.25`（脚底 y=0） | 3D 空间 §1（`:38`） |
| **单位总高** | **0.50 单位 = 16px**（【AI 提案】，推导见 Art Bible §5.2） | — |
| 头身比 | ≈ 1:3.2（头略大保可读） | 【AI 提案】 |

## 2. 阵营配色与材质分配

### 2.1 部件配色分工

| 部件 | 颜色来源 | 说明 | 标注 |
|------|---------|------|------|
| 头巾 / 帽子主体 / 帽缨 | **阵营色**（红 `#FF3A29` / 蓝 `#3366FF`） | 最大色块，第一眼识别 | 【依据 静态文档 `:721`】 |
| 上衣（躯干外层） | **阵营色**（可用亮面，暗面用阵营暗色 `#8C1B12`/`#1B338C`） | 与头巾同色系 | 【AI 提案】 |
| 腰带 / 肩章 / 臂环 | 阵营色或黄铜 `#C9A227` | 小面积强调 | 【AI 提案】 |
| 裤 / 靴 | 皮革 `#8B5E3C` 或深色 `#4A3A2A` | 固定色，压住下半身 | 【AI 提案】 |
| 皮肤（脸/手/前臂） | 皮肤 `#E8B98A` | 固定色 | 【AI 提案】 |
| 骨骼（骷髅职业） | 骨 `#E6DFC8` | 固定色，替代皮肤 | 【依据 `gdd.md:412` 骷髅海盗】 |
| 金属配件（钩/刀/罩/齿轮） | 铁 `#6E6A63` | 固定色 | 【AI 提案】 |
| 木腿 / 木柄 / 木钩柄 | 木 `#D4A76A` | 固定色 | 【AI 提案】 |
| 眼罩 / 皮带 / 围裙 | 皮革 `#8B5E3C` 或深 `#2A2A2A` | 固定色，提供暗块 | 【AI 提案】 |
| 胡须 / 帆布 | 白 `#F0EDE4` 或灰 `#C4BBA8` | 固定色 | 【AI 提案】 |
| 描边 | 深色 inverted-hull | 默认 `#2A2A2A`；阵营可加深红/深蓝版 | 【依据 `gdd.md:831`】 |

**纪律**：阵营色**只能**出现在上表标"阵营色"的部件；肤色/铁/木/皮革不得被阵营色污染，
否则"红队"会变成"一团红"，失去材质层次（Art Bible §2.4）。

### 2.2 描边如何配合

| 情况 | 要求 | 标注 |
|------|------|------|
| 本体描边（常态） | 每个可视部件 renderer 都要有黑描边外壳，**包括配件与手持物** | 【AI 提案】+【依据 `PirateOutline.shader`】 |
| 头巾/帽子等薄片配件 | 描边外扩沿法线，薄片两面法线相反会导致描边缺失 → 配件需用**闭合几何体**（如帽子用实心圆台，不用单面 Quad） | 【AI 提案】 |
| 选中/hover | 由 `_OutlineState` 统一驱动，配件跟随本体状态，不单独设色 | 【依据 `battle_scene改进任务清单.md:163-164`】 |
| 材质实例 | 同一单位的所有部件共享**同一个描边材质实例**，避免选中时只有躯干变青 | 【AI 提案】 |

## 4. 状态表现

> 原版参考：死亡在"血条走空"后生成 `deadCharacter` 并播 `die` 音（`参考游戏逆向…静态.md:352-359`）；
> 落水**立即** `health=0; alive=false`，速度每帧 ×0.8、`rotation += (vx+vy)*4` 翻滚（`:361-365`）；
> 中弹时移动中播 `hit`（`:368`）；小地图死亡点每帧 `mapVisibility -= 0.1` 淡出（`:721`）。
> 以下 3D 时长均为 **【AI 提案】**，锚定上述原版行为。

| 状态 | 表现要求 | 时长 | 标注 |
|------|---------|------|------|
| 待机呼吸 | 躯干 `scaleY ±1.5%`、头上下 ±0.004 单位、手臂微摆；不同职业错相位 0.5-1.0s | 周期 **2.8s** | 【AI 提案】 |
| 移动 | 身体前倾 6-10°、上下 bob ±0.012 单位；木腿（钩子手）有节奏起伏 | 步频 **0.40s**/步 | 【AI 提案】 |
| 投掷-蓄力 | 手臂后拉、躯干后仰 8°、手持物留在手里 | **0.25s** | 【AI 提案】+【依据 `gdd.md:370` 投掷视角】 |
| 投掷-释放 | 手臂前甩、躯干前倾 12°、手持物在**释放帧脱手**并交给物理 | **0.10s**（释放帧=初速施加帧） | 【AI 提案】+【依据 `M2-3D空间模型对齐.md:58-80` 预览=实弹】 |
| 投掷-恢复 | 回到待机姿态 | **0.30s** | 【AI 提案】 |
| 受击 | **白闪 0.08s**（材质 `_BaseColor` 短暂乘 2）、后仰 5°、后退位移；风格化无血 | 总计 **0.25s** | 【AI 提案】+【依据 静态文档 `:368`】 |
| 死亡（非落水） | 前扑/后倒 → 缩放收拢 → 淡出；生成可位移的"尸体"表现体 | 倒下 **0.5s** + 淡出 **0.5s** | 【AI 提案】+【依据 静态文档 `:352-359`】 |
| 落水 | 立即判定死亡；**下沉** 0.6 单位/秒 + 左右摇晃 8°（对应原版 `rotation += (vx+vy)*4`）+ 淡出；水面涟漪 Decal | 下沉+淡出 **1.5-2.0s** | 【AI 提案】+【依据 静态文档 `:361-369`】 |
| 死亡淡出与 UI | 3D 淡出时长与队伍状态条/小地图点淡出**同步**（原版 0.1/帧） | 同步 | 【依据 静态文档 `:721`】 |
| 复活（骷髅特技） | 从地面"骨堆"聚合成型，反向播放死亡 | **0.8s** | 【AI 提案】+【依据 `gdd.md:427`】 |

**纪律**：所有位移/旋转由表现层驱动，**不得**改物理（落水死亡判定已在 `PirateBase` 侧，见 3D 空间 §4）。

## 5. 选中 / hover 描边接线要求

> **沿用现有 Shader 与已确认参数**，不新造方案。

| 项 | 要求 | 出处 |
|----|------|------|
| Shader | `Assets/Art/Shaders/PirateOutline.shader`（hover/selected 合并进同一材质，用 `_OutlineState` 切换） | `PirateOutline.shader:11-90` |
| 状态驱动 | `OutlineStateRules.cs` 决定状态；`UnitOutlineBinder.cs` 收集 renderer 并绑定 | `M2-3D空间模型对齐.md:119` |
| 状态值 | `0 = 无`、`1 = hover`、`2 = 选中`（选中优先于 hover） | `PirateOutline.shader:81`、`battle_scene改进任务清单.md:165` |
| 选中色 | `#49D9D6f2` = `(0.286, 0.851, 0.839, 0.949)` | `battle_scene改进任务清单.md:9`、`PirateOutline.shader:74` |
| 选中宽/流速/频率 | width `0.006`、dash speed `5.0`、dash frequency `50.0` | `battle_scene改进任务清单.md:11`、`PirateOutline.shader:78` |
| hover 色/宽 | 白 `(1,1,1,0.22)`、width `0.0025` | `battle_scene改进任务清单.md:10`、`PirateOutline.shader:73,77` |
| 外扩模式 | 屏幕空间恒定（`_OutlineExpandMode = 0`），远近粗细一致 | `battle_scene改进任务清单.md:166`、`PirateOutline.shader:88` |
| 距离衰减 | `0.4`（保留轻微远近感） | `PirateOutline.shader:90` |
| 本体颜色 | 队伍色通过 `_BaseColor` 施加，**保留**黑色描边 pass | `battle_scene改进任务清单.md:12` |

**接线要求（可实现级）**：

1. 单位 Prefab 下**每一个**可视 `MeshRenderer`（含配件、手持物、帽子）都必须注册到 `UnitOutlineBinder`，
   否则选中时会出现"躯干变青、帽子不变青"的破绽。
2. 同一单位共用一个描边材质实例；队伍色与描边状态都改这一个实例。
3. 描边 pass 的 `cast_shadow` 必须关闭，避免描边外壳产生错误阴影。
4. 手持物脱手后（投掷中）应**脱离**描边状态驱动，避免飞行中的炸弹还在"选中描边"。
5. 骷髅的肋骨/眼窝等部件面数薄，描边需用**闭合几何**，禁止单面 Quad（否则背面无描边）。

## 6. 程序化建模可行性说明

### 6.1 Unity 图元直接可用 vs 需自定义网格

| 部件 | 实现方式 | 理由 | 标注 |
|------|---------|------|------|
| 头/手/眼珠/肩球/火球/胡球/骨球 | Unity **Sphere** 图元 | 现成 | 【AI 提案】 |
| 手臂/腿/木腿/柄/瓶身/炮管 | Unity **Cylinder** 图元 | 现成 | 【AI 提案】 |
| 前臂/小腿（要圆端） | Unity **Capsule** 图元 | 现成 | 【AI 提案】 |
| 刀身/帽檐/腰带扣/围裙 | Unity **Cube/Quad** 图元 | 小部件可用盒（占比 <15%） | 【AI 提案】，红线见 Art Bible §5.4 |
| **躯干圆台（核心）** | **自定义 `FrustumMesh`**（车削） | Unity 无 Cone/Frustum 图元；这是"梯形"本体，必须自定义 | 【原始诉求】 |
| **三角帽** | **自定义 `TricornMesh`** | 三片上翻檐无现成图元 | 【AI 提案】 |
| **钩手** | **自定义 `HookMesh`**（弯管，弧 ~270°） | 弯管需程序化，小尺寸 Torus 也可 | 【AI 提案】 |
| 肋骨/项圈 | **自定义 `ArcRibMesh`** 或细 Torus | 半环无现成图元 | 【AI 提案】 |
| 头巾 | `FrustumMesh` 变体（薄壳，顶封口） | 复用圆台生成器 | 【AI 提案】 |
| 长大衣下摆 | `FrustumMesh`（倒置、外扩） | 复用生成器 | 【AI 提案】 |

> **生成方式**：全部为**纯 C# 程序化 mesh**（顶点/三角面数组，确定性算法，无美术资产），
> 与 `程序化美术升级提案.md:12-18` "确定性算法 + 离线/运行时可复现"方法论一致。
> 生成器建议放 `Assets/Scripts/PirateCrew/Rendering/`（与描边链路同域），或独立 `Art/Procedural/`。

### 6.2 生成器清单与参数（AI 提案）

| 生成器 | 参数 | 输出 |
|--------|------|------|
| `FrustumMesh(topR, bottomR, height, sides, capTop, capBottom)` | 默认 `sides=10` | 圆台/头巾/下摆/瓶身 |
| `LatheMesh(profile[], sides)` | `profile` = 半径-高度折线 | 通用车削（桶/瓶/炮管） |
| `TricornMesh(brimR, crownR, crownH, foldAngle)` | `foldAngle ≈ 46°（r6 复验后上调，檐上缘需高于冠顶）` | 三角帽 |
| `ArcRibMesh(radius, tubeR, sweepDeg, segments)` | 默认 `sweep=180°`（肋骨）/ `270°`（钩） | 肋骨/钩/环 |
| `BlobClusterMesh(spheres[])` | 球心/半径列表 | 胡须/乱发（合并降面） |
| `LowPolySphereMesh(segments, rings)` | 默认 `10×6 ≈ 120 tri` | 优化期替换 Unity Sphere |

### 6.3 各职业图元数量与三角面估算

> 三角面为**估算值（AI 提案）**，实现时必须用 `mesh.triangles.Length / 3` 实测复核；
> 估算假设头球用 Unity Sphere（约 768 tri）。

| 职业 | 图元数 | 估算三角面 | 是否超预算(2500) |
|------|--------|-----------|-----------------|
| 水手 | ~12 | ~1400 | 否 |
| 炮手 | ~14 | ~1600 | 否 |
| 狙击手 | ~13 | ~1400 | 否 |
| 钩子手 | ~15 | ~1500 | 否 |
| 纵火狂 | ~16 | ~1700 | 否 |
| 骷髅 | ~20 | ~1800（肋骨换薄盒 ~1200） | 否 |
| 船长 | ~18 | ~1900 | 否 |

> 优化路径：头球换 `LowPolySphereMesh`（-648 tri/单位）；胡须/乱发球簇合并为单 mesh；
> 肋骨用 3 段薄盒。优化后全部 ≤ ~1000 tri/单位（【AI 提案】）。

## 8. 标注与待定汇总

### 8.1 【原始诉求】（用户本轮）
- 单位不能是方块；球头 + 圆台躯干（"一个球加一个梯形"）。
- 建模可以简单但必须像海盗、有辨识度。
- 需要 PBR 与有美术效果的场景（角色材质分配需服务于此）。

### 8.2 【依据】（基准文档）
- 空间/尺寸口径：3D 空间 §1（`M2-3D空间模型对齐.md:21-48`）。
- 职业清单与技能：GDD §5.2（`gdd.md:420-427`）。
- 原版海盗种类/配件母题：静态文档 §4.2（`参考游戏逆向…静态.md:322-324`）。
- 阵营色：静态文档 `:721`。
- 死亡/落水/受击表现：静态文档 §4.4（`:345-369`）、小地图淡出 `:721`。
- 描边参数：`battle_scene改进任务清单.md:9-12`、`PirateOutline.shader:73-90`。
- 描边链路不变：`M2-3D空间模型对齐.md:119-121`。

### 8.3 【AI 提案】（需确认）
- 单位总高 0.5 单位 / 16px 与头身比 1:3.2。
- 全部部件的具体尺寸（§1.2 表 + §3 各表）。
- 各职业的配件组合与几何方案（如炮手围裙、狙击手长枪长度、钩子手同侧钩+木腿）。
- 状态表现的时长（呼吸 2.8s、步频 0.40s、蓄力 0.25s、释放 0.10s、落水 1.5-2.0s 等）。
- 自定义网格生成器清单与默认分段数。
- 三角面估算与优化路径。
- 配色分工表中标"AI 提案"的固定色（皮革 `#8B5E3C`、骨骼 `#E6DFC8`、白 `#F0EDE4` 等）。

### 8.4 【待定】（实现前必须定）
- **职业与原版外观母题的映射是否被用户接受**：本文档把"狙击手"配女性/少年身形、
  "炮手"配士兵体型——GDD 六职业是 3D 重制新增，原版无对应，需确认。
- **统一体型还是每职业独立骨架**：本文档采用"共享骨架 + 配件差异 + 少量比例缩放"（成本低）；
  若要求六职业体型明显不同（如炮手/骷髅），需改独立 mesh（成本高）。
- **骷髅阵营色残布比例**：纯骨色会削弱阵营辨识，残布占比需用户定。
- **是否做女性体型变体**（原版 `femalePirate`）。
- **投掷/落水的精确动画时长**是否与后续战斗节奏（回合/慢动作）对齐。
