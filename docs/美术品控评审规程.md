# 美术品控评审规程

> **这份文档解决什么问题**：美术实现产出一批渲染截图后，需要一套**可执行、可追责、可复验**的评审办法，
> 把「看着还行 / 感觉不对」变成「第几个机位的哪个像素区域、实测值多少、违反哪条判据的第几行、怎么改」。
> 供「批评 agent 群」逐图找茬、返工 agent 逐单修复、协调者裁决与回归。
>
> **判据来源（本规程不新造判据，只做索引与判定方法）**：
> `docs/美术风格指南.md`（下称 **Art Bible**）、`docs/角色造型规范.md`（下称 **角色规范**）、
> `docs/场景设计-战斗竞技场.md`（下称 **场景设计**）、`docs/UI-UX与中文本地化规范.md`（下称 **UI 规范**）、
> `docs/描边Shader调试.md`（程序化判图先例）、`pirate-crew/Assets/Editor/ArtReviewShots.cs`（机位清单）。
> 引用一律写 `文档:行号`（AGENTS.md「引用要可核对」）。
>
> **评审立场（【原始诉求】）**：以玩家视角判断——「如果你玩这游戏就这垃圾美术，你愿意玩下去吗」。
> **禁止**「看起来还行」「整体不错」这类无坐标、无实测值、无判据出处的结论；此类意见一律退回重写。

## 1. 评审总则

### 1.1 三不原则

| 原则 | 含义 | 违反时的处置 |
|------|------|-------------|
| **不空泛** | 每条意见必须带「机位 + 画面坐标区域 + 实测值 + 判据出处」四项 | 缺任一项 → 意见作废，不算评审产出 |
| **不只靠肉眼** | 颜色/亮度/尺寸/有无阴影/有无字形等能测的量，必须给程序化实测值（§3）；肉眼只用来做「叙事/焦点/像不像海盗」这类主观判断 | 能用 §3 测却只写「看着发灰」→ 退回补测 |
| **不放过** | 只要命中判据就开单，不因「快验收了」「这是小事」而放过；低严重度也要登记 | 漏判被回归复验捉到 → 该视角本轮评审记失效 |

### 1.2 判定分级（什么算不合格/需返工/可接受/不达标）

| 结论 | 定义 | 后续动作 |
|------|------|---------|
| **不合格（Blocker）** | 画面读不出「这是个能玩的游戏」，或违反【原始诉求】红线：裸方块单位（Art Bible:372-380）、界面有英文残留（Art Bible:433-439）、全屏洋红（描边Shader调试:404-412）、单位不入镜/不生成、穿模遮死焦点 | 必须本轮修；不修不得进入下一波次 |
| **需返工（高）** | 明确违反已确认判据（【依据】/【原始诉求】），且玩家一眼能察觉：红蓝不可分（A-3）、地平线硬切（B-3）、阴影方向矛盾（B-6）、材质一片塑料（B-5）、中文豆腐块（D-3） | 本轮或下一轮必修 |
| **需优化（中）** | 违反【AI 提案】判据或观感明显瑕疵：雾接缝、粗糙度分区弱、图标在两底不可辨（V13）、细节密度不足 | 可排后续波次，登记不丢 |
| **可接受（低）** | 仅细节打磨：圆角、间距、标签微调 | 记录，不阻塞收敛 |
| **不达标（测量失败）** | 判据要求的量测不出来（图上量不到、被遮挡、机位没覆盖） | 属**产线缺陷**：要么补机位，要么补判据，按 Blocker 处理 |

### 1.3 多视角独立评审（避免同源偏差）

- **同一张图至少 3 个视角独立看**；七个视角（§2）各由**独立 agent** 承担，**禁止同一 agent 兼两个视角**。
- 评审期间**互不交流结论**（不共享草稿、不互相点赞），汇总阶段才合并——否则会趋同成「一个视角的七份复读」。
- 每视角必须给出**本条视角下最严重的一条**，即使没找到也要写「未命中判据，理由」。**不允许整视角交空**。
- 「出图者」不得评审自己参与改动的图（作者自证无效）。

## 2. 七个批评视角

每个视角统一字段：**看什么 / 当玩家会怎么骂 / 判据 / 常见缺陷清单 / 证据要求 / 严重度**。
严重度定义见 §1.2；证据格式见 §3.0。

### 2.1 视角 1：玩家首因印象

- **看什么**：`battle-45`（出厂机位）与 `hud-fullscreen` 的**前 3 秒**。不看细节，只看「这是海盗抢宝游戏吗 /
  我知道该往哪打吗 / 想不想继续看」。
- **当玩家会怎么骂**：「这什么玩意儿？一个灰盒子站在灰板上？」「我以为是没做完的 demo。」
  「第一眼分不出哪边是我的人。」
- **判据**：Art Bible §1.1 一句话印象（`:35-38`）+「不空/不糊/不假」三要素（`:40-43`）；
  场景设计 §1.3 第一帧要说清的三件事（`:56-61`）：这是海岛 / 中间那艘破船是焦点 / 我的人在左、敌人在右。
- **常见缺陷清单**：① 画面里没有任何「海盗」符号（船/棕榈/旗/宝箱全缺）；② 单位是方块或小到看不清；
  ③ 地平线硬切成两色（地面 vs 天空）；④ 出生两侧分不出红蓝；⑤ 焦点（搁浅船）不进反被遮挡。
- **证据要求**：给出「3 秒判断」的截图区域坐标 + 你第一眼看的是什么（实测示例：`unit-closeup` 单位竖向像素高度 18px，
  低于 A-2 的 25px，判 Blocker）。
- **严重度**：三件事任一读不出 → Blocker；三要素任一为「不」→ 高。

### 2.2 视角 2：构图与镜头

- **看什么**：`arena-overview`、`battle-45`、`side-profile`、`terrain-high`、`sea-shore` 的取景。
- **当玩家会怎么骂**：「画面一半是空的」「船把我要打的人全挡住了」「看不清纵深，像贴在地上的贴纸」
  「上边那条地平线就是一刀切。」
- **判据**：场景设计 §2.1 三条构图铁律（`:77-80`，屏幕上下=世界 Z、左右=世界 X、1080p 可见 37×29 单位）；
  §2.4 唯一焦点 + 次要焦点 + 四分法/纵深三段（`:128-132`）；§7.3 遮挡与取景留白三条可检查规则（`:381-391`）；
  Art Bible §6.1 前景/中景/远景分工（`:385-394`）与地平线纪律（`:393-394`）；B-3 地平线内容物（`:518`）。
- **常见缺陷清单**：① 焦点的竖向剪影被别的元素压过（场景设计:130）；② 场地中部无留白，相机平移后被高物塞满（`:391`）；
  ③ 高物放在近侧带造成遮挡事故（`:388-390` 分层规则）；④ 视觉重心偏向画面一角、留白死板；
  ⑤ 地平线处无远山/云/船影，只有「地面硬截断 + 纯色天」（`:393-394`）；⑥ 前景装饰挤在画面下缘成一条硬边。
- **证据要求**：给出构图分区坐标（例如「上 1/3 区域 y 5%-30%、x 0%-100% 为纯色天空，方差 < 阈值」）
  + 焦点件的实测屏幕高度/位置 + 遮挡关系说明。
- **严重度**：焦点读不出或遮挡可玩区 → 高；留白/重心不佳 → 中；细部取景 → 低。

### 2.3 视角 3：材质与 PBR 观感

- **看什么**：`unit-closeup`、`terrain-high`、`sea-shore`、`battle-45` 的材质分区、粗糙度、纹理能量。
- **当玩家会怎么骂**：「全是塑料」「糊成一坨、脏兮兮」「沙子是纯色块吧，一点颗粒都没有」
  「水和木板长得一样」「这块铁不反光，像涂黑的纸。」
- **判据**：Art Bible §3.1 材质参数总表（`:168-180`）；§3.2 三条纪律——粗糙度分区（相邻平滑度差 ≥0.15，`:190`）、
  边缘磨损（`:194`）、色彩分级（`:196`）；反面清单（`:199-200`）；§3.3 贴图规格（`:204-205`）；
  场景设计 §3.5 沙地三区与「严禁大面积纯色」（`:198-205`）；B-5 粗糙度分区可辨（`:520`）；B-7 亮面不冲白/暗面不压死（`:522`）。
- **常见缺陷清单**：① 全场景 `_Smoothness 0.5` 统一（Art Bible:192 点名的现状病灶）；② 沙/水/木/铁/布五类材质高光面积相同，分不出；
  ③ 大面积纯色无噪声（场景设计 §10.2 判据「无纯色大平面」，`:471`）；④ 高金属度 + 高粗糙度并存（Art Bible:200）；
  ⑤ 用纯黑 albedo 当暗部（`:200`）；⑥ 贴图拉伸方向错（木纹不顺着构件、沙地平铺接缝成网格）。
- **证据要求**：给出材质区坐标框 + 该处主色 `#RRGGBB` 与粗糙度观感对应的高光像素占比；
  纯色嫌疑给 200×200 窗的标准差实测值（场景设计:471）。
- **严重度**：材质无法一眼分辨 → 高；单纯脏/糊/塑料感 → 中；纹理方向与接缝 → 中/低。

### 2.4 视角 4：光影与氛围

- **看什么**：`battle-45`、`terrain-high`、`side-profile`、`sea-shore`、`unit-closeup` 的光照与后处理表现。
- **当玩家会怎么骂**：「光是平的，物件像贴纸」「影子朝东一个朝西一个」「远处和近处一样清，没有空气感」
  「暗的地方全黑、亮的地方一片白」「描边被光晕糊了。」
- **判据**：Art Bible §4.1 主方向光（强度 1.6-2.0 `:220`、方位角 `:221`、俯仰角 `:222`、软阴影 `:223`、接触阴影 `:226`）；
  §4.2 环境光冷暖（`:231-240`）；§4.4 雾（`:256-267`）；§4.5 后处理栈（`:269-291`）；
  C-1 单位三档（`:529`）、C-2 暗面不发黑（`:530`）、C-3 Bloom 不糊描边（`:531`）、C-4 远近雾化差 ≥20%（`:532`）、
  C-5 三档天空联动雾色（`:533`）；B-6 阴影方向一致（`:521`）；B-8 SSAO 对照（`:523`）；场景设计 §6.4/§6.5/§7.1/§7.2（`:344-379`）。
- **常见缺陷清单**：① 光轴与视轴重合导致「平光」（Art Bible:222）；② 阴影方向不统一或 blotchy（场景设计:442）；
  ③ 雾色与地平线色不同、看到「盖灰」接缝（Art Bible:263）；④ 可玩区被雾稀释对比度（场景设计:348）；
  ⑤ 单位只有单档、暗面发黑（C-1/C-2）；⑥ Bloom 阈值过低让沙地泛光、描边被糊（C-3）；⑦ 单位不投影（见 §7 待裁决）。
- **证据要求**：单位表面亮度直方图峰数（C-1）；暗面/亮面像素实测明度（C-2）；远景与近景同材质区对比度差（C-4）；
  阴影朝向描述 + 主光方位角。**能开/关对照的效果必须出开/关两张图**（SSAO 按 B-8、雾按 C-4）。
- **严重度**：平光/阴影方向矛盾/单位浮空 → 高；雾接缝/明暗单调 → 中；后处理微调 → 低。

### 2.5 视角 5：角色辨识度

- **看什么**：`unit-closeup`、`side-profile`、`battle-45` 里的单位本体、六职业 + 船长、描边与状态。
- **当玩家会怎么骂**：「还是方块」「六个人长得一模一样」「红队蓝队我分不清」「选中的那个没看出来被选中」
  「帽子是贴上去的纸片，没厚度。」
- **判据**：角色规范 R-1 不是方块/三段轮廓（`:384`）、R-2 六职业可辨 ≥5（`:385`）、R-4 阵营色不污染固定色（`:387`）、
  R-5 全部部件同步描边（`:388`）、R-6 竖高 ≥25px（`:389`）、R-9 薄配件描边完整（`:392`）、R-10 船长高 0.06（`:393`）、
  R-11 骷髅主色骨色（`:394`）；§1.1 部件化（`:31-42`）、§1.2 尺寸表（`:55-67`）、§2.1 配色分工（`:107-121`）、
  §3.1 六职业速览（`:143-152`）、§5 描边接线（`:303-322`）；
  Art Bible A-1（`:504`）、A-2（`:505`）、A-3（`:506`）、A-4（`:507`）、A-5（`:508`）、A-6（`:509`）、A-7（`:510`）、
  §5.1 几何体词汇表（`:310-321`）、§5.4 红线（`:372-380`）、§6.2 三重编码（`:396-406`）、§6.3 状态视觉（`:408-421`）。
- **常见缺陷清单**：① 出现盒形主导的本体（Art Bible:374-376 红线）；② 六职业剪影差异 <5 个；
  ③ 头/躯干同宽或躯干上下等径（角色规范:89-90）；④ 阵营色溢到皮肤/铁/木（`:121`）；⑤ 选中只变躯干、帽子/手持物没变青（`:318`）；
  ⑥ 薄片配件（帽子、头巾、肋骨）描边缺失（`:129`、`:322`）；⑦ 单位屏幕高度 <25px；⑧ 阵营色与身后环境 ΔE00 <25（Art Bible:148）；
  ⑨ hover 白描边遮住本体材质；⑩ 单位浮空无接触阴影（A-6）。
- **证据要求**：单位竖向像素高度实测；单位主色与背景主色的 ΔE00/色相角差；选中态逐部件描边色采样（R-5）；
  轮廓二值化后的横向宽度曲线段数（R-1）。
- **严重度**：裸方块 / 红蓝不可分 / 六职业不可辨 → Blocker/高；单部件描边遗漏、比例别扭 → 中；
  配件细节 → 低。

### 2.6 视角 6：UI 与中文排版

- **看什么**：`hud-fullscreen` 为主，其余含 HUD 的图每个角落都要看。
- **当玩家会怎么骂**：「怎么还有英文」「字太小看不清」「方框字（豆腐块）」「面板挡住我要打的人」
  「按钮看不出能不能点、点没点。」
- **判据**：UI 规范 V1 无英文（`:799`）、V2 字号（`:800`）、V3 四态（`:801`）、V4 青色一处（`:802`）、V5 危险色（`:803`）、
  V6/V7 边距（`:804-805`）、V8 无豆腐块（`:806`）、V9 状态反馈四态（`:807`）、V10 数值正确（`:808`）、V12 小地图（`:810`）、
  V13 图标两底可辨（`:811`）、V15 无无意义动效（`:813`）；§1.3 配色 Token（`:63-81`）、§1.4 字号表（`:87-98`）、
  §1.7 间距/层级（`:133-150`）、§3.5 战斗 HUD 线框（`:296-331`）、§6.1 四态（`:699-708`）、§6.3 选中反馈（`:719-725`）；
  Art Bible §7.1 中文界面与字号（`:433-455`）、§7.2 HUD 视觉（`:457-467`）、§7.3 UI 材质（`:469-472`）、
  D-1 无英文（`:539`）、D-2 文字可读（`:540`）、D-3 无缺字（`:541`）、D-4 UI 不与场景争色（`:542`）。
- **常见缺陷清单**：① 任何用户可见英文串残留（对照 `UI规范 §4.10`，`:586-609`）；② 名册行 17px / HP 15px 未升（`:98`、`:605`）；
  ③ 面板/按钮是纯色 `Image` 块，无木/纸/铜材质感（`:17`、`:29`）；④ 按钮四态不可辨（V3）；
  ⑤ 同屏青色出现在多处（V4 与 Art Bible §6.3 的冲突见 §7 待裁决）；⑥ 文字压沙地/天空对比不足 4.5:1（D-2）；
  ⑦ HUD 遮挡可玩区或出生位；⑧ 关键数值与当前局不一致（V10，已知 `BattleHud.cs:436-448` 只统计当前队）。
- **证据要求**：文字像素包围盒高度（V2）；逐态按钮底色采样差（V3）；青色连通区个数（V4）；
  文字与底对比度实测（D-2）；截图里的英文串**逐字抄出来并给坐标**。
- **严重度**：英文残留 / 豆腐块 / 关键数值错 → Blocker/高；字号下限、材质感、遮挡 → 高/中；间距圆角 → 低。

### 2.7 视角 7：场景叙事密度

- **看什么**：`arena-overview`、`terrain-high`、`sea-shore` 的环境陈设是否构成「一个游戏场景」而非灰模场地。
- **当玩家会怎么骂**：「这不就是一块水泥地加一潭蓝水？」「什么都没有，空得慌」
  「远处那几棵树复制粘贴的吧」「破船的破损看着是拼错了的盒子。」
- **判据**：场景设计 §1.1-1.4 叙事与氛围（`:35-68`）、§3.2-3.4 礁石/潮间带/植被（`:171-197`）、
  §4.1-4.6 道具陈设密度（`:209-267`）、§10.1 M1-M12/P1-P7（`:434-463`）；
  Art Bible §1.1 ①「不空」（`:41`）、§6.1 前中远景与地平线内容物（`:385-394`）；B-3 地平线内容物（`:518`）。
- **常见缺陷清单**：① 只有「一个大方块地面 + 一个大平面水 + 一个天空盒」（场景设计:3-5 点名的现状）；
  ② 无「沙→湿沙→泡沫→水」过渡，水陆直接切（`:182-184`）；③ 最少的陈设量都没到（棕榈 ≥8、灌木、箱/桶/锚/旗）；
  ④ 同一道具重复感强、朝向/尺度一致（`:172-174`）；⑤ 破船读成盒子（`:229-230` 要求侧倾）；⑥ 远景只有剪影岛数量不足或边缘是三角尖（`:342`）。
- **证据要求**：逐类陈设计数（如「可见棕榈 3 棵 < 判据 ≥8」）+ 所在坐标；重复感给「同一构件出现次数」；
  过渡段给水陆交界处的颜色序列实测。
- **严重度**：读成灰模场地/空得过半 → Blocker/高；数量不足、过渡缺失 → 中；重复感 → 低/中。

## 3. 程序化判据工具箱

把「看着像」变成可核对的量。**每项给出「用什么方法测 / 阈值 / 不达标怎么描述」**。
所有量测在 1080p 截图（或明确标注的原始分辨率）上做；采样窗口排除 HUD 与描边。

### 3.0 证据格式（所有视角统一）

每条意见的证据必须写成：`机位 slug + 坐标(x%,y%) + 像素框[x0,y0,w,h] + 实测值（主色/L*/像素数/比例）`。
缩放过的图必须标原始分辨率，避免把 HUD 抗锯齿像素算成描边（描边Shader调试:27 的假阳性教训）。

### 3.1 判据清单

| 编号 | 名称 | 用什么方法测 | 阈值 | 不达标怎么描述 |
|------|------|-------------|------|---------------|
| P-1 | 色相分离度 | 取两区域主色转 HSV，算色相角差（scipy/colorsys，窗口 ≥64×64） | 远景 沙/海/天两两 ≥90°（B-1，`:516`） | 「沙地主色 H=42°，海水 H=198°，色相间隔 156° 合格」/「沙与岩间隔 12°，<90°」 |
| P-2 | 区域主色与亮度 | 窗口内做色相直方图取众数色 + 转 CIE L* | 地平线 L*≥78、海水 L*≤62、ΔL*≥25（B-2，`:517`） | 给两个 L* 实测值与差值 |
| P-3 | 单位屏幕高度 | 取单位连通域竖向包围盒像素高 | ≥25px（A-2 `:505`；R-6 `:389`） | 「单位高 18px，低于 25px 下限」 |

## 4. 返工工单格式（固定模板）

一个工单只对应**一个可独立验证的缺陷**；不同波次/不同归属的缺陷不得合并成一张单。

```
工单号：AR-R<轮次>-<三位序号>           例：AR-R1-007
视角：<1-7 之一>                        例：5 角色辨识度
涉及机位图：<slug 列表>                 例：unit-closeup, side-profile
证据（坐标+实测值）：<坐标(x%,y%) + 像素框[x0,y0,w,h] + 实测值>
                                        例：unit-closeup 单位区(46%,42%) [560,430,120,180]，
                                            竖向高 18px；主色 #8A8A8A
违反判据（文档:行号）：<文档名:行号 + 判据编号>
                                        例：角色造型规范:389（R-6）/ 美术风格指南:505（A-2）
严重度：<Blocker | 高 | 中 | 低>
建议修法：<可执行动作，写清改哪个部件/材质/参数与目标值>
                                        例：躯干高度由 0.20 调整或相机距离下调，
                                            使 1080p 下单位竖高 ≥25px
归属波次：<渲染 | 角色 | 场景 | UI | FX | 相机>
复验方式（哪张图要变成什么样）：<机位 + 量 + 目标值>
                                        例：重出 unit-closeup，同一区域竖向高 ≥25px
```

- **可执行性要求**：返工 agent 拿到工单应能**不改判据、不重新论证**就动手；「建议修法」不得写「优化一下观感」。
- **坐标口径**：`(x%,y%)` 以画面左上为原点；像素框给原始分辨率下的绝对值。
- **排序**：Blocker → 高 → 中 → 低；同级按「同波次可一次改完」聚簇，减少出图轮次。

## 5. 评审流水线

### 5.1 步骤

| 步 | 名称 | 谁做 | 产出 |
|----|------|------|------|
| 0 | 出图 | 协调者串行跑 MCP 采集（编辑器**不暂停**，`manage_camera` 显式指定 `output_folder`） | 图 + 图清单（含机位/分辨率/参数快照） |
| 1 | 冻结基线 | 协调者 | 图清单哈希冻结，评审期间不得换图 |
| 2 | 并行多视角评审 | 七个独立 agent | 各视角工单草案（§4 格式）+ 最严重一条结论 |
| 3 | 汇总去重排序 | 协调者（或指定汇总 agent） | 合并表：同一缺陷被多视角命中则合并，**严重度取最高**，去重后按 §4 排序 |
| 4 | 协调者裁决 | 协调者 | 每张单判定「接受返工 / 接受现状（需书面理由）/ 转【待裁决】」 |
| 5 | 派单返工 | 协调者按**波次**派给实现 agent | 按「渲染/角色/场景/UI/FX/相机」分域，多 agent 文件域不重叠 |
| 6 | 重新出图 | 协调者 | 受影响机位重出 + 全量回归机位出图 |
| 7 | 回归复验 | 与第 2 步**不同**的 agent（避免作者自证） | 旧工单逐条核对（通过/未通过）+ 新问题登记 |

### 5.2 收敛标准

- **收敛（可进入下一里程碑）**：`Blocker = 0` 且 `高 = 0`，且所有 `中` 工单**均有明确处置**
  （已派单，或有协调者+用户书面接受的「暂不修」理由）。`低` 可留档不阻塞。
- **轮次上限**：最多 **3 轮全量评审**（第 1 轮全量找茬、第 2 轮回归 + 新问题、第 3 轮收口复核）。
- **超限处置**：第 3 轮仍有 Blocker → 停止继续加细节，把该视角问题上报协调者与用户，走「缩小范围 / 换实现方案 / 接受降级并留档」三选一，不得无限循环。
- **必须重开评审的情况**：任何影响画布的改动（材质参数、光照、后处理、相机、Prefab 造型、UI 布局）落地后，
  受影响机位**必须重出并复验**，不能凭「上次过了」放行。

## 7. AI 提案/待定标注要求与【待裁决】登记

### 7.1 标注纪律
