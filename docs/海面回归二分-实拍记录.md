# 海面渲染缺失——定位与修复实拍记录

> **结论先行**：大海域海面（OceanRig 圆盘网格 + PirateOcean shader）**在播放器里从未渲染过**——
> 根因是 `BuildDiscMesh` 的三角形绕序从上方（相机侧）看全部是**背面**，被 Pass 的 `Cull Back`
> 整体剔除。修复 = PirateOcean 改 `Cull Off`（水面上下都能看，永久保留）。
> 此前两个会话把它误判为"cb3b388..HEAD 的回归"，根因是判海工具被纯色背景骗过（见 §三）。

## 一、误判链（引以为戒）

1. 判海工具 `tools/worldmap/judge_sea_visible.py` 以「下半幅蓝像素占比」为判据——**任何蓝色背景
   （相机清屏色 / 天空盒）都算"海"**。相机的 SolidColor 清屏色 `#87B8E0` 一项就贡献 ~70%。
2. 于是二分各步的读数实际在量**背景色**：`141bb45`=71%（浅蓝清屏）、`a27add2`=0.54%（米色天空盒
   地面半球）、main=0.54%——"回归点 a27add2"完全是假象。
3. 更早会话的"cb3b388 31.92% 海面在" 同为背景色假阳性。r2 实拍
   （`export/worldmap-captures-r2/`）里就没有海面——"回归"前提本身不成立。
4. 海床板（`Seabed_*`，沙色、盖住整个水区）在 `542d71c` 退役后，缺失才显形——这也解释了
   为什么 M4 早期没人发现。

## 二、真正的证据链（本会话实拍，全部留档 external/bisect-*）

| 实验 | 结果 | 结论 |
| --- | --- | --- |
| 诊断日志（OceanRig.Create） | tris=62720、bounds 8926²、位置=图心、rendererEnabled=True、shader=PirateCrew/Ocean | 网格/材质/渲染器全部健康 |
| `-oceanDebug 12`（片段调试档，输出蓝青色） | 画面零变化 | **片段着色器从未执行**（非颜色链问题） |
| 逐帧强制 关雾 + Trilight 环境光 + 置空天空盒 | 海面仍缺失 | 排除雾 / 环境光模式 |
| 单变量 置空 RenderSettings.skybox | 背景变清屏色，海面仍缺失 | 排除天空盒（69% 读数 = 清屏色假阳性） |
| 天球网格修复（Background 队列） | 海面仍缺失 | 排除天空盒机制 |
| 渲染调度诊断 | queue=3000、**isVisible=True** | 渲染器确实被调度 → 三角形级被剔 |
| **`Cull Back` → `Cull Off`** | **海面完整出现**（波光/泡沫/日照 glitter 全部到位） | **根因 = 绕序反了 + 背面剔除** |

`isVisible=True` 与"零像素"并存的原因：Unity 对渲染器的可见性判定不剔除背面朝向问题，
三角形进入光栅化后被 `Cull Back` 逐个丢弃。

## 三、修复与验收

- **修复**：`PirateOcean.shader` 唯一 Pass `Cull Back → Cull Off`（`BuildDiscMesh` 的绕序
  保持不动——水面上下双面渲染是特性：将来水下相机/沉船视角仍能看到海面）。
- **验收**：`-worldMap wreck_hymn` 播放器实拍，全景/海平线/俯瞰三机位海面完整
  （`export/worldmap-captures-r3-fix/`，JPEG 1280）；构建日志 shader error 0 条；
  EditMode 1150 过 / 0 失败。
- **判海工具教训**：颜色占比类判据必须先排除背景色干扰，或改用纹理方差/纹理存在性判据——
  本工具已按 CC0 精神留档但**不可再用于海面判定**。
