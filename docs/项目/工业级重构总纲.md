# 工业级重构总纲

> **这是什么**：本次「工业级重构」的任务书与验收契约。它定义**要达成什么、按什么原则做、哪些不做、怎么判定做完了**。
> 想知道重构后的架构长什么样，读 [架构总览](../技术/架构/架构总览.md)；想知道代码规范与日常开发怎么做，读 [开发者指南](开发者指南.md)。
>
> **前置事实**：本项目是求职作品集项目（Unity 2022.3 重制 3D 版《海盗军团夺宝》），
> M0–M3 里程碑已完成、EditMode 1167 条测试全绿。本次重构**不改变玩法语义**，
> 目标是让工程结构、资产管线、构建发布、文档体系达到可对标商业发行的工业标准。

---

## 1. 为什么要重构（问题陈述）

工程在「规则层」质量很高，「编排层与装配层」债务集中。这不是能力问题，是**演进路径问题**：
项目从一个「验证玩法可跑」的骨架，靠多轮并行 agent 增量长成了 6.2 万行运行时 + 1.7 万行编辑器脚手架的规模，
而**骨架期的结构性选择没有随规模升级**。具体表现为四类问题：

| 类别 | 症状（有实测证据） | 后果 |
| --- | --- | --- |
| **隐式生命周期** | 14 处 `[RuntimeInitializeOnLoadMethod]` 分散在各模块，与 `Bootstrapper` 组合根并存；服务接线入口藏在 UI 层 `Awake` | 初始化顺序不可推理、不可测试；静态状态残留引发跨场景诡异 bug |
| **弱类型契约** | `EventBus` 载荷类型是 `object`（184 处调用）；事件名是字符串常量 | 载荷类型不匹配 = 静默无效果；契约靠人肉维护，漂移无告警 |
| **数据即代码** | 关卡/海图布局是 C# 静态字段（`WorldMapCatalog` 1019 行、样板关高度场硬编码） | 改一个关卡数值要改代码 + 重编译；策划无法参与；数据无法被工具校验 |
| **场景即产物** | `Battle.unity` 37 万字符由装配脚本一次性生成，Prefab 实例 = 0；40 个 Editor 脚本 1.7 万行构成顺序敏感的 11 步装配链 | 手工调整会被重跑冲掉（已发生两次事故）；改场景无法做等价性验收 |

美术侧是另一条独立主线：技术基座（像素化 Renderer Feature、赛璐璐 shader、反壳描边骨架、程序化判据纪律）
质量好，但**资产侧几乎为零**——55 张贴图无一张像素 3D 纹理、无落地的全局调色板、
粗模 47 件 FBX 未走量化导出模板、写实期后处理（Bloom/Vignette/全屏 Sobel）仍在生效。
「技术对了、资产没跟上」，画面停留在「平涂 + 描边 + 像素化」的裸基座。

## 2. 工业级标准（本次重构的验收定义）

对标商业发行项目，本次重构必须同时满足以下六条。**任何一条不满足即视为未完成**：

1. **依赖可推理**：一个模块依赖谁、被谁依赖，能从目录与程序集清单一眼读出，不靠运行才发现。
2. **入口唯一**：全局服务的创建与接线有且只有一个入口（组合根），初始化顺序是显式代码而非执行时机。
3. **契约编译期可见**：跨模块通信的载荷类型在编译期受检；契约（事件名/载荷/发布方/订阅方）有登记表且有测试钉住。
4. **数据与代码分离**：关卡、数值、调色板等策划/美术可调内容是**资产**，改动不需要重编译，且可被工具校验。
5. **验证自动化**：核心逻辑有测试；工程能一键出包；发版号有单一真源；CI 能在干净机器上复现门禁。
6. **文档自足**：新人（或新会话的 AI）能在不读历史提交的前提下，从文档推出「架构为什么这样、代码怎么改、包怎么出」。

## 3. 目标架构（摘要）

完整版见 [架构总览](../技术/架构/架构总览.md)。核心决定：

### 3.1 分层与程序集

```
Core（零游戏依赖：事件总线 / 服务注册表 / 日志 / 存档 / 场景流转 / 组合根）
  ↑
Data（纯数据定义：武器表 / 船员表 / 关卡资产类型）
  ↑
Gameplay（玩法规则：Combat 纯函数层 / Battle 编排 / Terrain / Level）
  ↑
Presentation（表现层：Audio / Ambient / Water / Fx / Visual —— 可整体替换，不触玩法协议）
  ↑
UI（只依赖 Core + 各模块公开 API 外观）
Campaign / CrewManagement（元游戏循环，依赖 Core + Gameplay 公开面）
```

**依赖规则**：高层可依赖低层，反向禁止；同层之间只经 `XxxApi` 静态外观或事件总线通信。
违反依赖方向在**编译期**就会失败（程序集引用不允许）——这是约束能长期成立的关键，
所以模块边界必须落在 `.asmdef` 上，而不只是目录习惯。

### 3.2 生命周期

- 有且只有**一个** `[RuntimeInitializeOnLoadMethod]`：`Core/GameEntryPoint.cs`。它负责
  ① 清空静态状态 ② 解析命令行工具模式 ③ 保证服务宿主存在（从任意场景直接 Play 也能跑）。
- 所有全局服务在 `Bootstrapper` 组合根里**显式注册**到 `Services` 注册表；谁依赖谁写在代码里。
- 禁止在 `Awake` 里做「把自己接进全局系统」的隐式接线。

### 3.3 事件契约

- `EventBus` 提供泛型 API：`Publish<T>(key, payload)` / `Subscribe<T>(key, handler)`，**载荷类型编译期受检**。
- 事件名保持字符串键（来自 `XxxEvents` 常量类），因为同名事件的载荷类型不唯一；但每个键必须在
  `EventCatalog` 中登记**期望载荷类型**，运行期 debug 断言 + 测试反射校验「代码里用的键都已登记、登记表无僵尸项」。
- 高频事件的 `Publish` 不分配（快照按订阅变更失效，不是每次 ToArray）。

### 3.4 数据资产

- 关卡/海图/武器/船员/调色板 → ScriptableObject 资产，落在 `Assets/Data/`（关卡在 `Assets/Data/Levels/`）。
- 提供**迁移器**：从现有 C# 硬编码数据一次性生成资产；提供**校验器**（连通性、出生点合法性、射程/尺度一致性）。
- 资产是唯一真源；运行时不读 C# 里的旧常量（迁移器留在 Editor 侧，一次性工具）。

## 4. 轨道划分与范围边界

| 轨道 | 内容 | 交付物 |
| --- | --- | --- |
| **A 核心地基** | 强类型事件总线 + 契约登记表 + 服务注册表 + 唯一入口 + 组合根收口 | `Core/` 重构；14 处隐式初始化收敛为 1 处 |
| **B 数据外化** | 关卡/海图/武器/船员数据 → SO 资产 + 迁移器 + 校验器 | `Assets/Data/**`；`WorldMapCatalog` 等退出运行时 |

| **D 美术工业化** | 全局调色板资产 + OkLab 量化工具链 + 像素纹理导入后处理 + Blender 量化导出模板 + Toon 材质工厂 + 写实栈退役 | 调色板资产、量化脚本、导入规则、材质工厂 |
| **E 构建发布** | BuildPipeline 脚本 + 版本单一真源 + PlayerSettings 工业化 + CI | 一键出包；`.github/workflows/` |
| **F 文档体系** | 架构总览 / 开发者指南 / 构建发布手册 / 资产管线手册 / 迁移报告 | `docs/` 五篇 |

### 明确不做（本次范围外）

- **不改玩法语义**：数值、公式、回合规则、AI 评分、武器表、关卡布局内容一律保持语义等价，
  重构只换载体与结构。任何「顺手平衡一下」都不做——那需要设计裁决。
- **不做新玩法系统**：宝箱/空投、2P 热座入口、33 关全量重制等缺口只登记不做（见待办）。
- **不换游戏类型/坐标系**：XZ 竞技场、真等距相机、格 = 2u 等口径按既有裁决保持。
- **不追求资产数量**：美术侧本次做**管线的工业化与地基**，不做 47 件 FBX 的逐件翻新（那是内容工作量）。
- **不删测试**：测试是本次重构的安全网；允许改测试以匹配新结构，不允许为让门禁变绿而删断言。

## 6. 工程纪律（所有参与者的硬约束）

1. **一次只跑一个 Unity 进程**（`Library/` 锁独占）。agent 一律用 `dotnet` + 无头验证台自验；
   需要 Unity 的验证由主控串行执行。
2. **文件域不重叠**：并行轨道各自拥有明确的目录；跨域改动先与主控对齐。
3. **小步提交**：每条轨道至少一个原子提交，提交信息格式 `类型(模块): 描述`（中文）。
4. **不删证据**：发现的问题若不在本轨范围内，登记而非顺手改（避免范围蔓延与并行冲突）。
5. **不动在途产物**：`export/`、`external/` 不入库；改动前先看文件是否已被 git 跟踪。

## 7. 风险登记

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 场景 Prefab 化破坏运行时接线 | 高（可能整场黑屏/NullRef） | Prefab 化后跑 PlayMode 冒烟 + 场景接线反射断言；分场景推进，不一次性全改 |
| 数据外化引入语义漂移 | 中（关卡数值变了） | 迁移器生成后**逐字段对拍**旧 C# 常量，加确定性测试 |
| 事件总线改造漏改调用点 | 中（静默无效果） | 泛型 API 让载荷类型错误变成编译错误；契约登记表 + 反射测试兜底 |
| 美术管线改动影响现有画面 | 中 | 像素纹理导入规则**只对新增资产生效**（按目录/命名约定判定），不回溯改存量 |
| 并行 agent 互相踩文件 | 中 | 按 §4 目录域划分；主控负责 Unity 门禁串行化 |

## 8. 排期（本次执行顺序）

重构按「先地基后表现、先串行接口后并行内容」的顺序推进，每阶段以门禁收口：

1. **阶段一**：核心地基（轨道 A）——接口变更影响全仓，必须独占窗口。
2. **阶段二**：数据外化（B）、美术工业化（D）、构建发布（E）、文档（F）并行——四者文件域不重叠。
3. **阶段三**：场景装配（C）——高风险轨道，独占窗口。
4. **阶段四**：全量门禁 + 迁移报告 + 收口提交。

阶段之间以 §5 判据收口；任一阶段门禁不绿则先修复再推进，不带病叠加。

**遗留 / 待主控裁决**

1. **契约静态检查**：闸门 ② 只能证明"发布类型 == 登记类型"；发布方与订阅方**同时**用错类型仍无法

3. **`change_scene` 载荷收窄**：字典形式（`IDictionary<string,object>{path,transition}`）已删除。
   全仓零调用点，但要"不带动画地切场景"只能直接调 `SceneLoader.Instance.ChangeScene(name, false)`。
   若裁决认为需要事件入口，应新增强类型载荷结构体而非恢复字典。
4. **`Tools/` 侧出图链**：`tools/` 脚本若在命令行里拼 `-artReviewOut` 等开关，语义未变（同名同义），
   但**解析处**已从中途的自扫 argv 换成统一入口——出图流程本身未改代码路径。
5. **未逐个跑 Unity 门禁**：本轨道所有验证都在无头验证台；EditMode/PlayMode 与出包由主控串行执行
   （`GameEntryPoint` 与 `DescribeAll()` 在真实播放器里的行为需要一次 batchmode 冒烟确认）。
