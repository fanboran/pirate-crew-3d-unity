## 二、关键决策与理由（改之前先读这段）

1. **零贴图、零金属度**（创始人中途提醒 + 读 `docs/技术/渲染/像素化着色路径/实现口径.md` 后定）：
   像素化着色路径的物体 pass 只写 `Albedo`（亮部色）+ `Physical`（光滑度/金属度）+ `Palette`
   （主光档数/抖动/边光/描边开关），着色在低分辨率艺术画布上跑、还要过帧级调色板 ——
   **PBR 贴图与金属度在链上落不住**（低分辨率下还会变成闪烁噪点）。
   所以质感改由两件事承担：**几何密度**（板缝/法兰/爬梯/栏杆/格栅/锯齿断口/波纹板竖棱）
   与**调色板对比**（锈 vs 混凝土 vs 漆色；锈痕一律薄板贴面，不整面上锈色）。
2. **六件并行 + 分区契约**：整场一次写完是串行长尾且单人单文件易冲突。改成六个
   **分区互不重叠**的 `mod_*.py`（一人一文件、六个 Agent 同时跑），唯一耦合是
   `kit_common.AREAS` 分区表；总装的 `verify_bounds` 是这条契约的验收判据。
   **实测六件全部落在分区盒 + 1.5 m 容差内**。
3. **分件只写自己的文件**：公共库由协调者独占维护（并行时改库会污染所有人）。
   本轮两个库缺陷都是队员报、协调者修（见 §四）。
4. **曝光是量出来的，不是猜的**：`Standard` 视图变换没有高光滚降，浅色混凝土/浅灰钢
   很容易冲成白片。用「9 槽并排 + 正交相机读回像素值」的标定卡定下 **−0.35 EV**
   （渐变天穹强度 0.30、日光 2.6、补光 6 万 W）。别随手改，改前重跑标定。
5. **低分辨率档参考图是近似**：`--pixel 2` 把成品图按块中心降采到 1/2 再最近邻放大回来，
   块边长取 `PixelartCameraRig.PixelScaleDefault`（现役 2）。游戏内实拍另有描边、
   光带量化、帧级调色板，本图**不做色阶量化**，只说明"块边长锁整数倍 + 块中心采样"。

## 四、踩坑（都在本轮修掉，别回退）

1. **`Mesher.to_object` 材质错位**：材质/平滑是**按面下标**的平行数组，而 `me.validate()`
   会删退化面——删面后按下标 `zip`，其后所有面的材质整体错位（真事故：草叶重复面把草绿
   穿到了隔离墩上）。现在先自己剔退化面（三列同删）、再在 validate 后**断言面数不变**。
2. **`platform`/`grating`/`stairs` 的中心语义错**（塔王报）：三者把 `box` 的 `at`（底面中心）
   当角点用，甲板/筋条/踏步各偏半格 —— 表现是「栏杆挂甲板外半格」「筋条半幅悬空」「踏步悬空」。
   已改成以 `at` 为中心（栏杆仍按四角点）；管廊平台与楼顶格栅（真调用点）随之归位，重出图确认无异常。
3. **`stairs(rail=False)` 的 `lng` 未定义**（`NameError`）：斜长已提到分支外。
4. **越界校验自身的坑**：设完 `obj.location` 后 `matrix_world` 仍是旧值（Blender 惰性求值），
   不 `view_layer.update()` 就量，量到的是本地坐标 —— 会得到满天飞的假越界
   （本轮真出现过"塔区越界 17 m"的假警，差点据此返工）。
5. **`railing`/`platform` 的点是相对 `at` 的**（两名队员各绊一次）：契约写在 docstring 里，
   但没有强类型保护——用之前先读签名。
6. **FBX 回读验证**（移交前做过的检查）：重新导入 `ChemPlant.fbx` → 6 个节点名齐全、
   223,240 三角面、18 个 `Kit_*` 槽（无未知槽）、尺度朝向与口径一致。

## 六、色板 / 光带现状与参考库对照（2026-09-29 调研 + r16 落地后的口径）

创始人问过「要不要拆掉游戏实机的有限色板、参考库是怎么做的」。**这条分支合并了并行线的 r16
（`d5e7aec3`「彻底去掉配色限制」）之后，答案已经变了**——现状按三层说：

| 层 | 是什么 | 现状（合并 r16 后） |
| --- | --- | --- |
| L1 全局锁板 | 32~64 色把纹理量化进板 | **已取消且机制已删**（创始人 2026-09-29 裁决；`docs/设计/美术风格指南.md` §3.2 记档作废） |
| L2 逐物体色带 | `multiStep` 按档数量化 N·L（默认 3 档，档数走材质 `_MainLightLevel` → `Palette.r`） | **仍在，也是现在唯一的颜色限制**——它是 r13 观感与机制判据的基准（平坦 ≥0.90 / 抖动跳变 ≤0.10 / 亮暗跨度 ≥0.60）。r16 另给弧面加了平滑细分（冷却塔 40 边、烟囱 24、立罐 20…），色带沿曲面连续弯、不再逐面跳档 |
| L3 帧级调色板 LUT | CIEDE2000 全屏最近邻映射 | **已从管线整体删除**（`PixelartColorCorrectionFeature` / `.shader` / `PixelartPalette.cs` / `Palette.asset` / `PaletteGenerationCIEDE.compute` / 装配器开关 `EnableFramePalette` 全删；Cast 特征 **七趟改六趟**）|

**这一轮与打光一起改的（r16，同样影响本关实机图）**：主光 `#FFF5E0 → #FFFFFF`（受光面不再米黄）、
环境光 `#37486B → #333C4A`（去海军蓝）；**实时投影默认关 = "完全没有光影"的根因**，
`PixelartStageKit.CreateSunAndAmbient` 增 `castShadows` 形参，化工厂类场景开（本关装配器已传 `true`）。

**参考库（t3ssel8r）怎么做**（调研原文见 `docs/技术/渲染/参照-t3ssel8r像素引擎.md` 与
`调研-3D像素渲染视频整合.md`）：他**没有**屏幕空间调色板 LUT，颜色限制全在**材质/物体层**——
① 标准 BRDF 上套 ramp 色带（2~3 档）；② 动态光是**加法 pass、绕开 ramp**，亮度量化到预设档数
（他自述这正是 limited-palette 感的来源）；③ 昼夜/黄金时刻靠**材质变体按太阳角插值**；
④ 抖动是材质里的 2×2 Bayer 贴图。**我们比他多**：逐物体四通道 `Palette`（主光档/抖动/法线边/描边开关）、
连通域内线降档。**比他少**：按光角插值的材质变体、附加光绕 ramp、替换式暗部色（我们现在暗部只是
`albedo × 环境色`）、随光变化的边缘色（固定墨色 `#0D0D0F`）——**后两条才是"发灰、层次少"的更可能来源**。

**要更多颜色时动哪**：`_MainLightLevel` 3 → 4~5（Range 上限 8，三条判据照过）；
**别设成 1**——`PixelartShading.shader` 的 `singleLevel = 1/(level-1)` 在 level=1 时是 inf，
会把 inf/NaN 写进 Diffuse 缓冲（`PixelartObject.shader` 注释里的「1 = 不量化」只是注释，不是安全档）。

## 七、实机出图链（2026-09-29 打通；重出图就按这三步）

**口径**：实机图 = 游戏本体经像素化着色路径跑出来的（低分辨率艺术画布 + 逐物体 3 档色带 +
屏幕空间描边 + 上屏点采样），**不是 Blender 渲染**。最新一批在
`docs/images/chemplant-scene/ingame/`（`pl5-wide/mid/close` + 抖动 A/B + 两个调试缓冲）。

```bash
U="F:/Unity/2022.3.62f1/Editor/Unity.exe"; P="<worktree>/pirate-crew"
# ① 烘场景（改模型/材质槽/取景后必跑；秒级~分钟级）
"$U" -batchmode -nographics -quit -projectPath "$P"   -executeMethod PirateCrew.EditorTools.PixelartChemPlantTeamSetup.BuildAll -logFile -
# ② 出开发包（场景集必须是 development，否则试点场景不进包 ⇒ 播放器 LoadScene 失败）
"$U" -batchmode -nographics -quit -projectPath "$P"   -executeMethod PirateCrew.EditorTools.BuildSystem.BuildScript.BuildFromCommandLineArgs   -buildFlavor development -buildScenes development -logFile -
# ③ 跑播放器出图（自动退）
"<worktree>/external/build/<版本>/win64/PirateCrew3D.exe"   -pixelartOut "<worktree>/docs/images/chemplant-scene/ingame" -pixelartLevel 5
```

**这条链上的坑**（都踩过）：
1. **`-buildScenes development` 不能省**：默认是 release 集（6 个发行场景），
   试点场景不在包里 ⇒ 播放器 `LoadScene` 失败且只报一行"场景加载失败（Build Settings 未注册？）"。
   参数名是 `-buildScenes`（不是 `-sceneSet`；写错会被当成未识别 token 静默忽略）。
2. **渲染器资产里的 shader 引用可能为空**：`PixelartPathInstaller.TryInstall`（烘场景时自动跑）
   会把 5 个 Feature 的 shader 引用写回 `Assets/Settings/URP/Pixelart*_Renderer.asset`；
   引用为空时那几趟**静默不生效**（只有编辑器日志里的 `[PixelartXxxFeature] 找不到 shader`）。
3. **模型导入两条实测坑**（抄 `PixelartChemPlantSetup`，两套装配器同值）：
   `materialImportMode = ImportStandard`（**不是 None**——None 档读不到槽名，只能按槽序兜底，
   实测会串色：地坪套上漆黄、罐体套上草绿）；`useFileScale = true`（吃掉 FBX 根上那层 (100,100,100)）。
   本次烘焙日志：72 个槽位**全部按名匹配**、0 个走兜底。
4. 场景里没摆相机外的东西时，场地边缘会直接露出深蓝背景（"悬空沙盘"）——装配器补了一块
   **场外地面替身**（土色大平面、关描边）兜住；真上玩法时由关卡地形取代。
