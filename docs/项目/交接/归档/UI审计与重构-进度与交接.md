## 一、审计核心结论(2026-09-25,三路并行审计)

**用户的原始痛点成立**:"UI 完全不像参考库"的根源不是字体管线或烘制链(这两处判据全绿),
而是三层问题:

1. **参考库覆盖面太小**:theme.xml 约 60 个部件族只实现约 8 族;四种状态语言
   (selected 金底 #E1B85F+深字 / focus 内描边 #4069C2 / disabled 影子字 / slider 焦点变体)
   **全部自创或缺失**。最影响观感的缺失:弹窗标题栏带(window h1=15)、列表金底选中、
   checkbox/radio/entry/scrollbar 全族、蓝分组字 #6E9ADB(全工程零引用)。
2. **两套皮肤系统并存互搏**:SketchPanel(带投影)vs UiKit(禁影销毁 Shadow)双规范;
   双正文字色(StickTokens.TEXT #EDF0F5 vs PixelSkin #C0C0C0);按钮档→tone 映射两份;
   RuntimeUiBuilder/UiKit 四组原语双拷贝。
3. **三个时代口径分层堆叠**:×3 时代注释/文档化石与 ×2 现行代码同屏(清理波已清)。

**字体观感"不收口"的结构性病因(代码实锤)**:
`UiSkin.Px.Button=16`(画布px)声称"模板 1:1 零拉伸",但 Plate 贴图实际 28×32
(设计格 ×Unit2 落盘),九宫格上下切片合计 20px 塞进 16px 高——**贴图被压到一半高度、
边带重叠变形**;字再叠上去(16px 字 vs Aseprite 8px 字/16px 件 ≈50% 占比的密度基准),
观感"糊、挤、变形"是必然。**修复随悬案①裁决**。

## 三、重构波方案(待裁决后开工)

### 悬案(创始人裁决,按序)
1. **×2 语义定夺**(字阶档遗留#1,新增证据):贴图维持 28×32 还是回 14×16 资产 1:1?
   维持 ×2 → `Px.Button` 等令牌 ×2(32),字件占比回到设计密度;
   回 1:1 → 烘焙链改 ×1 + PressOffset 改 (1,-1) + 接触表再适配。
2. **投影去留**:对齐 theme 全删,或保留 SketchPanel 投影——不能两套并存。
3. **自创变体去留**:Danger 红/Accent 橙按钮、七 tone 染色面板 theme 里没有——保留还是收敛。
4. **选中语言**:要不要上金底 #E1B85F+深字(影响全套交互观感)。

### 方法论(逐件复刻,用户裁决)
以 theme.xml 规格表为唯一源,**逐部件建「规格条目 → 实现函数 → 判据断言」三点一线**;
任何自创/偏离显式登记为"偏离项"。审计产出的部件对比表(60 族规格 vs 实现值)是复刻底稿,
关键规格:button 14×16 切片 4/6/4·4/6/6 四态、window 13×24 切片 3/7/3·15/4/5、
checkbox/radio 8×8+focus 框 2/6/2、slider 16×16±focused、separator 9×5 虚线+蓝字。
已知转写偏差一处:按钮模板底缘黑环错行(builder:748,行13 应为整行黑环,现烘 #202125)。
**注意**:Aseprite 8px 英文字/件密度比不可照抄——中文最小可读 10-12px,需定中文密度基准。

### 重构范围
重建:Skin 层收编单一来源(StickTokens/UiSkin/PixelSkin 三合一)、装配器运行时化
(assemble 退役,本来就是字阶档遗留#3)、部件补齐、ManagementSceneSetup 结算弹窗破版坐标重排。

## 四、位图文字像素对齐——行业实践(用户问询,重构波参考)

**像素精准 = 五环链条,全部整数才成立**:
① 字形栅格 1:1(显示字号=字体原生档,TMP 位图模式非整数倍=重采样糊)✔已有
② 图集 Point 采样、无 mipmap ✔已有(Bilinear 渗邻字是乱码元凶之一)
③ 字形落位整数(画布坐标整数;半画布px 在 ×2 整数放大下恰好规整为整屏px——整数缩放自愈)✔基本有
④ **画布→屏幕整数倍** ✘缺口:1080p×2 精准,但 2560×1440(2.67×)/1366×768(1.42×)/
   DPI 125%窗口全破。行业做法:最大整数倍+letterbox 黑边,或锁分辨率。
⑤ 全屏模式/分辨率锁定(设置页窗口三态+按显示器枚举+整数倍开关)✘未做。

**三条行业路线**:A.单栅格同层(Stardew/Terrira:字和 UI 同低清 RT 整体整数放大,字号锁死);
B.分层栅格(Aseprite screenscaling=2:字和件同 theme 空间一起 ×2);
C.UGUI 低清画布(本项目:字 1 画布px 与件 2 画布px **不同相位**——这是与 Aseprite 的本质差异,
也是"字体不锚定艺术像素"裁决的代价,合法但需自觉)。

**Balatro/RACCOIN 实地档案摘要**(完整版见会话审计报告/待办附件):
- Balatro = LÖVE,**非整数缩放路线**(TILESCALE=3.65 连续重算、坐标不取整、2x 图集+linear
  过滤"柔像素"+CRT.fs 单 pass 滤镜:桶形失真/色差/扫描线/bloom,滑条 0-100 映射公式可抄:
  intensity=0.16n/100 等)。**学它的设置项与 shader,不学缩放模型**。
- RACCOIN = Unity 6+URP+ProPixelizer(3D 像素化+调色板)+TMP SDF;
  **CJK 字体 = Fusion Pixel 12px Prop zh_hans(与我们 12 档同源!)**+ Latin = Perfect DOS VGA 437,
  SDF 图集+独立 Outline/标题材质——待办里 SDF 分支提案的商业先例。
  设置页清单:窗口三态/分辨率枚举/帧率上限/VSync/CRT 滑条/Flashing 闪烁保护/FX/HDR/像素化级别。
