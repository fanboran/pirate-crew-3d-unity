## 2026-11-18 地图视觉 Bug 修复

本轮的“地图视觉 Bug”已定位为**四个叠加的渲染缺陷**，全部修完并双风格实拍：

1. **海床/水面/鱼群法线朝下（几何级）**：`Mesher.to_object` 的 `recalc_face_normals`
   对开放薄面（海床高度场、水面、鱼身+双面鳍）会按连通关系翻面；`mod_sea._orient_faces`
   又用 `c.z > 0` 判“顶面”，整片海在 z<0 ⇒ 水平面全被压成朝下。像素路径 Cull Back
   直接把海床裁掉、水下岩石/鱼顶面裁成黑块。
   - `kit_common.Mesher.to_object(name, recalc_normals=True)` 新增开关；
   - `mod_sea` 对海床/水面/海草/鱼群传 `False`，`_orient_faces` 只修侧壁、水平面不动；
   - `mod_life` 跃水鱼同样禁 recalc。
2. **PostLine 的物体材质被内容转换器回写**：`PixelartContentConverter.Update` 每秒补扫，
   把 `PostLineMaterialSwapper` 换好的 ToonLit 又换成 PixelartObject（后者没有前向趟）
   ⇒ 整幅只剩天空。转换器加域闸门：**只在 CellShade 域写材质**。
3. **水面/雨从未渲染（透明 shader 级）**：
   - 水网格没有 COLOR 通道，Unity 给顶点色输入 0（不是白），旧 shader 的
     `贴图 × 顶点色 × _Color` 把整片水乘成 alpha 0；`CloudSeaWater.shader` 重写为
     **两趟各自独立 CBUFFER**（删除共享 HLSLINCLUDE），顶点色改由
     `_VertexColorWeight`（默认 0）控制，颜色不再乘 `_MainTex`；
   - `PixelartContentConverter` 补排除太阳雨 shader（`CloudSeaPath.RainShaderName`），
     否则雨/光柱/彩虹被转成不透明像素材质而整类消失；
   - `PostLine_Renderer.asset` 的 `m_IntermediateTextureMode` 归位 `1`（Always）。
4. **水色档位**：水 alpha 0.35→0.5、深水 0.55→0.6（海床可见后与原“沙洲”观感折中），
   烘焙器 `TransparentAlphaFallback`、纯逻辑 `CloudSeaWaterMaterial.AlphaFallback` 同源。

实拍（两风格同机位）：
- `temp/cloudsea-final2-cellshade-wide/`、`temp/cloudsea-final2-postline-wide/`
  （水 shader 重写 + alpha 0.5 的定稿）；
- `temp/cloudsea-final3-postline-wide/`（追加天气 FX 排除后的复验）。

天气 FX（雨/光柱/彩虹）已复验：转成不透明的根因是内容转换器未排除
`CloudSeaPath.RainShaderName`；排除后两风格均可见光柱（`temp/cloudsea-final3-*`）。
若后续要调雨量/光柱强度，改 `CloudSeaWeather` 的序列化字段或 `CloudSeaRain.shader`，
不要再让转换器接管这些材质。

## 2026-11-20 角色落地 + 视觉/逻辑对位 + 云台观感返工

上一轮实拍后创始人指出：**角色脚底悬空、云台不好看、海面有大块硬边色斑**。逐项定位与修复：

   `UnitPivotHeightFor(prefab)`——按**当前预制体**碰撞箱世界半高取值（方块 0.5 /
   Crew 0.25），出生日志对账 ground 5.50 / pivot 0.25。
2. **视觉/逻辑整体 Z 镜像（"脚踩海面"的真凶）**：金数据轮廓投影对账发现，南台逻辑
   在 (24,25)（出怪点、地面高度全对），渲染的云台却在镜像位置——FBX 的
   `bakeAxisConversion` 把 Blender y **直通** Unity z（不取负），而摆位表按旧约定
   `u2b(x,y,z)=(x,−z,y)`（Unity z = −y）写，整场自 11-11 重做起就镜像了：红蓝两队
   都站在镜面一侧的海面上。修复：**摆位表全部翻号（y = Unity z 偏移）**——PLATFORMS /
   WATERFALL / FISH_SCHOOLS / SEAWEED_BEDS / ROCK_CLUSTERS / BIRD_PERCHES /
   mod_sea 全部锚点表 / mod_clouds 水洼偏移 / mod_life 巢·羽·贝·跃水鱼；SUN_XY /
   WIND_XY / 预览机位同步翻号；远景背景（云带/塔/拱/远景岛）的翻号见下文第 5 条；
   `rebuild_cloudsea_terrain.py` 公式
   同步为 `15 + y`（金数据输出逐位不变，无需重迁移）。设计表/出怪点/金数据全部不动。

## 2026-11-22 水面可见性四根因 + 水下内容扩充

创始人反馈「鱼看不见 / 螃蟹呢 / 焦散和海浪呢 / 云影在哪 / 水底要有各异的珊瑚海星且更不平整 /
水不该这么不透」。本轮实测定位到**四个叠加的水面不可见根因**——前几轮 WaterLab 成片里
看到的水**其实一直是简版水**（Cloud_Sea_Surface），ocean 从未进过画面：

1. **域中心不是世界坐标（水面整片被裁）**：关卡把 CloudWalk prefab 摆在竞技场中心
   (20, 15)，而 `WaterLabSimulation` 只发 `_WaterLabOrigin = domainCenter = (0,30,0)`；
   水面顶点把世界 (20,15) 当域外采样、`visibleDepth = 0` → `clip` 整片丢弃。
   修：`PublishOrigin()` = `transform.position + domainCenter`（世界坐标）且**每帧刷新**
   （RuntimeSceneArt 先 Instantiate 再摆位，只在 Awake 发一次会留旧值）。
2. **简版水盖住 ocean**：`Cloud_Sea_Surface` 与 ocean 同高，透明排序把大平面简版水排在
   队列 3010 的 ocean 之后，整片盖住。修：海面专用材质 `Cloud_WaterSurface`
   （`_WaterLabHole = 1`）——shader 在 ocean 覆盖范围（44 m 半径）内 `clip` 简版水，
   水洼/玻璃仍用 `Cloud_Water` 不挖洞。
   注意运行时 `CloudSeaWater.SwapAll` 用 `new Material(shader)` 只带 shader 默认值，
   烘焙材质上的 `_WaterLabHole` 不会跟过来，必须显式写实例。
3. **画布快照时序**：CellShade 折射底图 `_WaterLabPixelartScene` 原先排在透明趟之后拍，
   底图带着简版水的青色；`PixelartPathInstaller.CastFeatureOrder` 把快照 Feature 移到
   `PixelartTransparentFeature` **之前**（同事件按入队次序执行）。
4. **云影双乘**：`bg` 与最终 `col` 各乘一次云影 → 影底平方（0.55²=0.3），水下鱼/珊瑚全黑；
   改为只在 `col` 乘一次，并加 `_CloudShadowStrength`（默认 0.6）保留参照库公式与全局族。

- **σ 被关**：`_SigmaScale = 0` → `T ≡ waterColor`，水的深度吸收没了（Demo 的青色/深度
  梯度主要来自 `T = exp2(−8.65617·σ·dist)×waterColor`，σ = (0.993, 0.175, 0.056)）。

- **焦散放错对象**：Demo 的焦散在 `WaterLabSand`（沙面 albedo），我们把它加在水面上。

1. **水 Shader 1:1**：`_SigmaScale = 1`、`_AlphaGain = 1`、`_RefractionGain = 1`、
   `_SpecSharpness = 1500`、`_SpecGain = 1`、`_WaterTintStrength = 0`、
   `_WaveShadeStrength = 0`；`T`/散射/镜面/折射公式与常量回到 `WaterLabOcean.shader`。
   云影保留（创始人：照油管大佬那套，且它不影响水体模型）。
2. **海床浅海化**：水面 −0.4，海床 −1.15..−0.75（水深 0.35–0.75 m），Blender `bed_z` 与

   海星 0.10–0.14 m），岩顶钳到 −0.55 不出水。
3. **沙堡焦散**：`causticsVal = len(太阳色) × exp2(−1.731·可见水深) × 3D 焦散体`（半相位

### 2026-11-22 补：CellShade 快照源 bug（"水下东西全没了"的真因）

`PixelartWaterLabSceneFeature` 原先拷的是 `rig.ResultBuffer`，但着色趟写的是
**相机颜色目标**（`cameraColorTargetHandle`）；URP 要到相机收尾才把它搬进
`targetTexture=ResultBuffer`——快照站点在 AfterRendering，读 ResultBuffer 拿到的是
**上一帧/空画布**。所以 CellShade 的水折射底图整片落空：水色均匀、鱼/珊瑚/海草全无。
修：快照源改用 `cameraColorTargetHandle.rt`（着色完成、透明趟未画的那一帧）。
这不是参数问题，是"机械化移植"没接进像素管线的真身；修完 CellShade 水下件回来了。

同轮把水下物件色卡整体提亮（`Cloud_Seaweed/Plant/Coral*/Fish*`），鱼群主色改为
黄/白为主、橙做点缀——σ 在水里吃红通道，黄白在青水里能读出来。

### 2026-11-22 补：鱼群不被水体染色（凸出海床实体保护）

创始人：「让水里的鱼几乎不被水体影响颜色」。根因是三叠的：

- **合成顺序**：鱼在 opaque 趟先画进艺术画布，水在 `Transparent+10` 用画布快照按
  **整根水柱**（η−海床）压色——鱼所在的 0.1–0.3 m 浅柱也被当成海床深度，红通道被
  替掉最多，鱼身发绿。
- **鱼群半埋**：`mod_sea._build_school` 的海床净空被 `min(z_hi, …)` 截掉，珊瑚丘顶
  （bed −0.81）的鱼群世界 Y 落在 −1.05..−0.70，一部分在沙里、可见鱼离床仅 0.1 m。
- **上下游幅过大**：`CloudSeaLife` 默认 0.1–0.2 m，在 0.35–0.75 m 水柱里会把鱼压回
  床面/推出水面，保护判定随相位丢。

落法：

1. **`CloudSeaWaterLabOcean.shader` 两趟对称加「凸出海床实体保护」**：细像素深度
   （CellShade）/`_CameraDepthTexture`（PostLine）→ 可见点世界坐标（口径同
   `PixelartShading.shader` 的 `PixelartPositionWSFromDepth`），减去**可见点 XZ 处的
   t0 静止海床高**得离床高度；`smoothstep(_ObjectProtectStart, _ObjectProtectFull)` ×
   `_ObjectProtectStrength` 压 `opac`，只留 `_ObjectVeil` 薄纱；保护像素的折射底色改
   采自身 UV、焦散也让位。参数：start 0.015 / full 0.09 / strength 0.92 / veil 0.06
   ——鱼净空 0.22 m、鱼体下沿 ≥0.14 m，整条落在满额段。
2. **t0 静止地形基准**：`WaterLabSimulation.Awake` 把初始 `_groundCur` 经 `GroundOutput`
   多写一张 `_WaterLabStaticGroundTex`，保护层只读这张——活沙照常演化（水色/深度仍用
   `_WaterLabGroundTex`），但不会因冲蚀把可见沙面误判成「凸起」。
3. **鱼群布景**：`mod_sea` 海床净空 0.22 m 放在带高夹之后、再加水面帽 −0.58，重烘
   `CloudWalk.fbx`；`CloudSeaLife` 浮动幅 0.1–0.2 → 0.02–0.04（代码默认与 prefab 同步）。
4. 2:1 验收帧（`PC3D_PIXEL_SCALE=2`，960×540 画布）：CellShade
   `temp/cloudsea-fishprotect-final-cellshade/battle-hud-1.png`、PostLine
   `temp/cloudsea-fishprotect-final-postline/battle-hud-1.png`；保护诊断帧
   `temp/cloudsea-fishprotect-diag2/battle-hud-1.png`（R=protect / G=aboveBed×4 / B=h）。

边界：保护只改水色覆盖比例，h / 三段色带 / 吸收 / 焦散 / 云影公式不动；暗色 1 px
描边仍落在沙侧深度上被水染色（读数=水下描边，鱼身本体不受影响）。
