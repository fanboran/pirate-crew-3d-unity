## 七、复盘：右键「拖动不是旋转」连环案（创始人连驳多轮的真因，2026-09-23 定案）

**症状时间线（同一个根因，三种表现）**：
1. r12 起：「我要旋转啊」——实机表现是画面平移（当时判为"旧管线没接好"，方向就偏了）；
2. r13 编辑器首跑：「旋转完全没反应」——叠加了第二案（主相机掩码清 0 杀死 Brain，
   应用链彻底断，`c42dfdc` 修）；
3. 重构落地、单写入者 0 误差之后：**仍是「拖动」**——这才逼出真因。

**真因（一句话）**：**相机位置绕焦点做轨道运动，但视线方向被设计成恒定**。
数学：`position = focus + R_y(yaw)·offset(30°)·dist`，而 `rotation = Euler(30°, 45°, roll)`——
**rotation 里没有 yaw**。位置转、视线不转 ⇒ 世界整体在屏幕上滑 = 「拖动」。

**为什么它一直逃过检测（三次误诊的土壤）**：
- 它是**刻意行为，且带着"全绿"的验证**：重构把旧 Cinemachine 链「Transposer 只写位置、
  Aim 档为空」逐位复刻，类头注释「环绕不重瞄（勿顺手修掉）」，实机探针证明"偏移转 60°
  朝向逐位不变"——**等价性验证全绿，但等价的是错的行为**；
- 每一轮我验证的都是**必要条件而非充分条件**：yaw 数值在变（输入通）✓、单写入者
  （无打架）✓、Brain 应用虚机（链路通）✓——没有任何一个检查回答「画面有没有绕焦点转」；
- 第二案（掩码杀 Brain）是真 bug 但症状是"完全没反应"，与"拖动"混在同一条时间线上，
  把排查方向带偏两轮。

**解决方案（已实施，`08b7b9a`）**：朝向改为 **LookRotation(focus − position)**
（`CameraFraming.ComputeRotationLooking`，纯托管四元数，无头可测）——环绕时画面**绕焦点转动**；
旧语义 `ComputeRotation` 退役留档；`CameraFraming`/`BattleCameraDriver` 类头的
「环绕不重瞄」口径整段推翻重写。已知取舍（r12 裁决沿用）：非 45° 方位下地面菱形
不对称（像素阶梯长短不一），不做 snap。

**今后判定「旋转」的标准（写进验收，防止再犯）**：数值验证全部是必要非充分——
**必须同机位取两个不同 yaw 的画面做 diff，画面必须绕焦点转**；
「与旧链逐位等价」只能证明复刻忠实，永远不能证明复刻的东西本身是对的。
