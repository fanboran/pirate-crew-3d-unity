## 实机走查清单（验收看什么）

1. 进第 1 关：无洋红、Console 无 shader 报错；云台、船员的描边与像素化（PostLine）与改动前一致。
2. 水面：水色几乎不染，海床原样看得见；岛影在水面上是一整块深色，影边是云台轮廓的直投影；
   阳光区有漂移的亮带与零星碎金。
3. 波：水面自身是定色的，动态只有亮带漂移、碎金与整块的折射晃动（影边起伏默认关）。
4. 水下：沙丘起伏读得出（脊顶暖沙、洼地偏青）、沙纹是平行细线；海草摆动且**没有墨线**；
   沙面上没有零碎断线。
5. 描边：水下物（生物、珊瑚、海草）都没有线；云台、船员、海鸥的线照常。
6. 生物：鱼在游、头朝前、不出水；剑鱼、蝠鲼、海龟、河豚、水母各自有各自的动法；章鱼探腕、蟹横爬、
   海星腕尖依次落地，**踩地的脚不滑、不悬空，没有肢体立成一束**；海星读成星形；蟹只是沙面上的一只小东西。
7. 影子：云台、单位、海鸥在云面与水面上有硬影；云台的影子在影块正下方的海床上也读得到（沙色偏暗、
   没有焦散）。
8. 涟漪：云瀑落水点与海面上有扩散的像素同心环。
9. 镜头拖动 / 旋转：水下画面不闪烁、墨线不抖。

## 排查记录（下次别再踩）

着色器、蒙皮、IK 方面的坑集中在 [云海.md](../../技术/渲染/管线/云海.md) §7，这里只留工作方法上的。

- **「恢复到某张图时的状态」：先找到那张图对应的提交，把相关源码全部对照，再按提交恢复**。创始人给的
  参照图在另一个会话的临时目录里；查到那个 worktree 停在 `7045f696` 后，第一次只对着图猜、只恢复了
  描边着色器本体，漏了第一轮给水下物着色器加的深度 / 法线预通道（那个版本的文件头明写「不描边」），
  被创始人连说两次「描边还是不一样」。正解是 `git diff <参照提交> -- <目录>` 把着色器、材质、渲染
  脚本逐个看完再动手；比手调可靠。
- **只动被点名的量**。创始人说「恢复光影」，我把水色不透明度也一起恢复了，被纠正——范围拿不准先问一句。
- **先给创始人看，再补验证**（创始人 2026-11-26）：中途反复放大裁图核对，拖慢了交付；改完直接出图
  给路径，有疑问让创始人指。
- **失败的中间产物当场删**：一次着色器编译失败的抓帧留在了目录里（全线没有描边），创始人翻到后以为
  云彩描边坏了。作废的抓帧目录、旧版 GIF 都别和现行产物混放。
- **「没误伤」要有证据，而且要问对方看的是哪张**：创始人说云彩黑线少了，我拿一小块裁图对比后判断
  「一致」，其实漏看了云台衬着水面的那一圈。对比要覆盖对方说的那一类线的全部位置。
- **像素计数类指标先在「已知坏」的样本上试**：「深色线像素数」在完全没有线的作废图上和基线一样多——
  它量的是水面阴影，不是线。
- **描边这块反复了六轮才定**：水下线色从统一深蓝 → 同色暗线 → 淡蓝软边 → 本色混浅蓝 → 本色偏蓝 →
  恢复原样（水下物不描边）。教训是审美类的改动先拿一两个候选图问清再动代码，别一版一版试。
- **落在水面上的线像素，深度取到的是海床**：水面不写深度。只按「像素在不在某条高度线以下」判断，
  会把云台、船员衬着水面的线也当成水下线。
- **剪影判据量到的是高度的 2 倍，不是一半**：30° 俯角的正交相机下，高出沙面 h 的物体挡住了身后
  1.7h 远的沙面。算错成 0.5h 会以为缩小后的生物出不了线、去降阈值，结果带出满地断线。
- **沙面上起断线只有两个来源**：折射把相邻像素错开（连续坡面被当成落差），和海床上高出阈值的
  小台阶（被当成物体）。给水下域降阈值、让描边跟随折射，都会把它们带出来。
- **回读第一手资产，再谈「抄不到」**：排查阴影时从缩略图和直方图上读错过好几次。真正的原因
  （探点函数把 y、z 写反）直到把探点位移量单独量过才找到。一次只动一个变量，结论要能区分几种解释。
- **手写的公式要用另一种方法复算**：正交投影的 Z 平移项下标写错（`m32` 应是 `m23`），验证台里
  四条用例当场红掉；Python 复算与 C# 对不上，才定位到是下标。
- **验证台的边界**：`Battle` 档不含 `Tests/SceneArt`，跑云海用例用 `All` 档加过滤器。
- **批量改文档 / 代码用带断言的脚本，注意三个坑**：①CRLF / LF 混用，文档里「↔」「/」这类符号的
  码点和看起来的不一样，编辑工具的多行锚点匹配上了也未必是想要的那行；②脚本里改完几行要先写回总文本，
  再去按行号找下一处（否则前面的修改被丢弃——调参表两行就是这么「改成功」却没变的）；
  ③命令里传给 Python 的双反斜杠会被折成单个，路径里的 `\t` 变成制表符——路径用 `chr(92)` 拼，
  或把脚本存成文件再跑；长命令里不要内嵌脚本（引号会被 bash 解析坏，整条命令一行都不执行）。
- **看图下结论前先量**：干图上我肉眼判「海床整片是阳光」，量平均色才发现影块下方的沙色正好是亮沙 ×
  岛影乘色——有岛影。缩略图上「有没有影子」这类判断，先取几块区域的平均色对一下。
- **管道会吞掉失败**：`python 带断言的脚本 | tail && 下一步` 里脚本失败被 `tail` 的退出码盖住，后面的删除
  照常执行。带断言的脚本后面别接管道，或者先开 `set -o pipefail`。
- **阴影的两种来源在默认取景下没有可见差别**：第一轮的本地阴影图与主光阴影图，影块逐行轮廓、影块内部
  与海床的平均色都在 1 个色阶内。为「恢复原样」撤掉它之前，先量一下它到底改变了什么。
- **HLSL 的局部数组必须每个元素都赋值**：d3d11 把「可能未初始化」当编译错误，整个描边通道编不过，
  表现是全场景没有描边、日志里只有一行 `Shader error`。抓帧后先看日志里有没有这一行。
- **坐标对应拿数据对**：Blender 的 (x, y) 就是 Unity 的 (x, z)、画面右方是方位 135°；Unity 的偏航角 =
  −Blender 偏航角。
- **逐帧追踪要带连续性约束**：在一条扫描线上找「影区 → 阳光区」的跳变，会在两条不同影子边缘之间
  来回跳。限定在上一帧位置附近找，并对多行取平均。
- **检查进程与启动抓帧分两步串行发**。同一台机器上别的会话可能在跑别的工程的 Unity
  （命令行里 `-projectPath` 不同），不共用 Library、不构成锁冲突，但会抢 CPU / GPU——看命令行再下结论。
- **Unity 现在启动很快**：机器不抢资源时冷启动二十来秒，烘焙链、一轮抓帧各不到一分钟；
  别按「三分钟一轮」预估，也不用因为「太快了」怀疑没真跑（看日志里的烘焙行、着色器错误数）。
- **`[Header(中文)]`**：ShaderLab 只接受 ASCII，中文标题让整段 Properties 解析失败，表现是 shader
  名为空、全场景不渲染、没有编译报错。
- **出图取景**：`PC3D_CAPTURE_ORTHO` 受相机驱动的正交下限约束；特写用
  `PC3D_CAPTURE_CENTER` + `_CENTER_XZ` + `_VISIBLE` 三件一起给（见云海.md §8）。
- **FBX 导出不是字节确定的**：重跑总装后 Unity 下次启动必重导入。几何没改就不用重烘。
- **参数一动，固定种子的抽签就后移**：不是回归。

   （秒级，不开 Unity）。
3. 改了 FBX / 材质分流 / 烘焙器 → worktree 根执行 Blender 总装，再在主仓根执行烘焙链（后台；

   `"F:/SteamLibrary/steamapps/common/Blender/blender.exe" -b --factory-startup -P tools/blender/scene/cloudsea/assemble_cloudsea.py -- --no-render`
   （看 `ASSEMBLE_OK`；去掉 `--no-render` 会顺带重渲 `docs/images/cloudsea/` 的总装预览图）；
   `PC3D_PROJ=F:/VSCode/pirate-crew-3d-unity/temp/clear-sea/pirate-crew bash tools/headless/run.sh chain "PirateCrew.EditorTools.CloudSeaAssetBaker.BuildAll;PirateCrew.EditorTools.SceneSetup.BuildAll"`。
   跑完 `git status` 里会多出四个装配链副产物（`Prefabs/UI/MainMenuScreen.prefab`、
   `Scenes/Game/Bootstrapper.unity`、`Scenes/Game/MainMenu.unity`、`ProjectSettings/EditorBuildSettings.asset`），
   提交前 `git checkout --` 还原，不要入库。
4. 出图：主仓根 `bash temp/clear-sea-tools/capture.sh <名字> [KEY=VALUE…]`（不入库的包装脚本），
   产物在 `<worktree>\temp\cloudsea-clear-sea\<名字>\`（同名目录会先清空）。常用的几组：
   - 全景 72 帧：`PC3D_CAPTURE_FRAMES=72`；
   - 干图：再加 `PC3D_CAPTURE_HIDE=Cloud_Sea_Surface`；
   - 特写：`PC3D_CAPTURE_CENTER=1 PC3D_CAPTURE_CENTER_XZ=x,z PC3D_CAPTURE_VISIBLE=米 PC3D_CAPTURE_FOCUS_Y=-1.0`
     （三件要一起给；世界 XZ = 预制体本地 XZ + (20, 15)）；
   - 关节坐标落盘：`PC3D_CLOUDSEA_POSE_DUMP=<文件> PC3D_CLOUDSEA_POSE_TIME=<秒>`，秒数必须早于序列结束。
   **拍完先看日志里有没有 `Shader error`**，有就别看图了。
5. 出 GIF：主仓根 `python temp/clear-sea-tools/make_gif.py <帧目录> <输出.gif> [--crop x0,y0,x1,y1] [--zoom N]`
   （帧是 960×540 的艺术画布）；「参照图｜现在」并排图用 worktree 里的
   `temp/kin-review/make_stills_r3.py`（不入库，路径写在脚本里）。拼对比条用 `montage.py`；
   姿态前后对照用 `posecmp.py <旧落盘> <新落盘> <输出.txt>`；查某处沙面高度用 `bedprobe.py <fbx> x,z [r] [step]`。

   看命令行里的 `-projectPath`。
