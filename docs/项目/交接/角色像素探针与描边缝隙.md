## 1. 结论（已核实，不要重复猜）

- **原作/参照库没有这些缝，是真的**。但原因不是“原作没有描边”，而是**描边算法不同**：
  - 原作是 2D Flash 矢量/精灵，描边是美术的一部分；没有 G-buffer/连通域/块锚。
  - 参照 Unity 工程 `external/ref/unity-isometric-pixel-pipeline`：
    `Assets/Shaders/PostProcess/OutlineShader.shader` 用 **3×3 视图空间重建 + 8 邻域深度不连续**，
    线色 = `closest_color * _LineDarken`（把最近像素颜色压暗），**不是另画一圈墨线**；
    `Assets/Rendering/PC_Renderer.asset` 里 `OutlineRendererFeature m_Active: 1`，
    `PixelRendererFeature` 低分辨率档 640×360。线就是边缘像素本身，没有“填充块/墨线块各自占位”。
  - 本仓 `PixelartOutline.shader` 是另一套：4 邻域膨胀 + 逐物体 `Palette.a` + 连通域
    `connected/closer` 门控 + `BlockPatch` 1/4 准入；它才有“填充—灰—墨线”的夹缝。
    文档里 v3 旧 `OutlinePass` 是 `m_Active: 0`（从没跑过），不要把两者混谈。
- **当前实机 2× 截图的缝**（`export/parabola-v3-r2.png`，入库证据见 §4）：
  - 头部左缘：墨线 → 灰 `#AAAAA9` → 肤色，3 个候选格（`#g` 夹层）。
  - 身体底缘左/右角：填充 → 灰 → 墨线，3 + 1 个候选格。
  - 头部底缘第 708 行（身体顶面 710–712 行上方）：茶色头里透出**身体红** 3 像素——这不是灰缝，
    是头/身两套 renderer 原点独立吸附 + 头部底缘 1/4 块丢格，身体透出；`gaps` 抓不到，
    探针用 `partLeaks` / `part_vis.png`。
  - **左右明暗（左暗右亮）是主光侧照**，不是几何；`colorMismatch` 高是预期。
- **镜像相位的数学**（块中心采样）：
  - 艺术像素 i 采的是细像素索引 `i*k + floor(k/2)`，它的**中心**在
    `i + (floor(k/2)+0.5)/k` 艺术像素；令 `a = (floor(k/2)+0.5)/k`。
  - 镜像线 c 必须满足 `s_i + s_j = 2c` ⇒ `c ≡ a (mod 0.5)`（艺术像素单位）。
  - **k=2（战斗档）**：`a = 0.75`，镜像线 `c ≡ 0.25 (mod 0.5)`；整数 0 偏离 0.25，
    候选是 ±0.25（mod 0.5）。实测 **−0.25 外沿 0 误差**；+0.25 虽然也是格点候选，
    但 1/4 块覆盖/门控让外沿误差 34，所以格点条件是必要不充分，必须用逐行外沿实测收口。
  - **k=3**：`a = 0.5`，镜像线 `c ≡ 0 (mod 0.5)` ⇒ **整数吸附本身就是镜像线**。
    （此前写的“奇数 k 整数不是镜像线”漏了细像素中心 +0.5，已作废。）
  - 2× 战斗的整数吸附相位下外沿误差 8；−0.25 是关吸附扫出来的，生产 `_SnapToPixelGrid=1`
    会把 −0.25 抹掉——要复现必须把相位写进 `PixelartOriginSnap`（见 §5）。
  - 头/身相对 y 是两套原点各自吸附，整体平移改不了；用 `headOffsetXPixels/YPixels` 单独挪 HeadPivot。
- **“双描边线”是头/身接缝，不是对称造成的**：
  - 在 −0.25 的正确朝向像素图上，第 269 行 x=477–481 有一条**内部横向墨段**，
    上方第 268 行是身体红 `(246,53,34)`、下方第 269 行两侧也是身体红 `(255,92,61)`；
    头部自己的底缘墨线在 266–268 行。即：头底墨线 → 身体顶面红边 → 接缝墨线，两条黑线夹一条红。
  - 这条内部墨段在 **41 档偏移的全部**都出现在第 269 行（x 随偏移整体平移），
    所以它是 `PixelartOutline.shader` 的接缝规则 ② 在两件式角色上的结构性结果，
    不是“轮廓对称”的副作用；对称只是让两条线更显眼。
  - 参照库没有逐物体墨线环/接缝规则：它在低分辨率结果上做**一次**深度/法线边检测，
    头身之间只有一条边线，因此不会出现双线（见下一条）。
- **参照库（GitHub 原库核对）**：`git ls-remote https://github.com/bababuyyy/unity-isometric-pixel-pipeline`
  的 HEAD = `f08bc6b`，与本地 `external/ref/unity-isometric-pixel-pipeline` 同一提交。
  - 描边：`OutlineShader.shader` 在内部低分辨率（默认 640×360）做 3×3 深度/法线、
    8 邻域采样，线色 = `closest_color * _LineDarken`（`118–151` 行）；没有逐物体
    `applyOutline`、没有 connected/closer 位、没有独立墨线环。
  - 吸附：`IsometricCameraController.cs:132–157` 只吸附**相机 pivot** 到 texel 网格，
    再把误差作为 `_PixelPanOffset` 交给上采样；**物体不逐个吸附**，所以 body/head
    不存在各自取整导致的相对相位，也不会有两圈墨线。
  - 结论：参照库保证的是“线永远贴着实际渲染剪影、且只有一条”；
    它并不额外保证光栅剪影左右对称——对称要我们自己用相位锁定（§5）。
