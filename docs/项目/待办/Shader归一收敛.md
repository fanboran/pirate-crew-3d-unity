## 详情

### 1. PostLine 二风格去留（创始人裁决项）

- PostLine 四 shader（ToonLit/Composite/Outline/SharpUpscale）+ 装配链（`Rendering/PostLine/`）已接线，提案口径见 [双风格切换.md](../../技术/渲染/管线/双风格切换.md)（待实机验收）。
- 裁决保留 ⇒ 双风格转正，实机验收后按其口径归档；裁决归一 ⇒ 删四 shader + 装配链 + 双风格切换/PostLine规格两份调研档降级为沿革，全仓只剩 CellShade 一套。

### 2. PirateBase 反壳描边核对（老链最后活口）

- `PirateOutlineUnit.mat`（shader = 老链反壳 `PirateOutline`）挂在 `PirateBase.prefab` 根物体 MeshRenderer 上，经 `BattleRig.prefab` 接进战斗场景。
- 待实机一眼定性：伤害数字待办已裁定选中反馈走立方体角框（SelectionCube）、船员不再做描边——若该 renderer 仍有画面职责则迁像素路径方案，若纯残留则删材质 + shader（`PirateOutline`）+ 预制引用。

### 3. 云海效果 shader 命名泛化（等第二消费者）

- `PirateCrew/CloudSea/Water` 与 `CloudSeaRain` 是插在主链透明趟（`LightMode = "PixelartTransparent"`）上的双 pass 插件，机制通用、命名是云海品牌牌（历史：生于云端漫步场景重做）。
- 其它关卡要水/雨/光柱/彩虹/涟漪时接入成本为零管线改动（写带标签的 pass 或直接复用）。泛化命名（如挪到 `PirateCrew/Fx/Transparent/`）**等特效重做开线或第二个消费者出现时一并做**，涉及 shader 内名 + Resources 文件名约定 + `CloudSeaPath.cs` 契约三处同步，单消费者下不提前抽象。

- **参照库颜色/质感审计（2026-11-23 重测修正）**：① **库与上游逐字节比对**：8 个场景、`Rock.mat`、`ShadingPass.hlsl`、投影对象渲染特性与 GitHub 原版完全相同，颜色校正趟的色板行已还原为出厂 `Test_2`；唯一偏差是打开工程时 Unity 自动升级（2022.3.43f1→62f1、URP 14.0.8→14.0.12，本机只装了 62f1）。② **六张 `Test_0~5.png` 都是各自色板的有效 LUT**（烘焙 compute 按 `(r, 1-g)` 切 16³ 格），出厂渲染器接 `Test_2` 自洽；此前「出厂 Test_N 是布局测试条」的结论作废。③ **色板是每期的参数**：v3 岩石帧 = TestPalette3（其背景色只存在于 P3）；绿球+方块参考 = TestPalette1（95% 精确命中）；金属锭参考 = TestPalette0（95%）——同一套 Shader，换色板即换一期观感。④ **批模式环境光坑**：Skybox 环境光探针不自动生成（实测 `unity_SHA*` 全零、暗面与投影全黑）；须在场景加载后连调 `DynamicGI.UpdateEnvironment()` 数帧，且其亮度约为正常编辑器的 1/1.4（按 1.4 倍补偿后，005 投影区与视频一致率 0%→84.6%）。⑤ **截图工具三坑（已修）**：投影相机须显式 `Render()`（主相机只把它的 ResultBuffer 拷到屏幕，否则拍到上一帧）；时间点须按场景内帧计；出图宽统一 960（与视频帧同倍率：240→×4、320→×3、120→×8、160→×6）。⑥ **画面大面积色不是天空而是地面 Plane**：其颜色随视角在色板色之间跳变——该 LUT 实为明度主导吸附（烘焙 compute 把 Lab 的 a/b 归一化后再算 CIEDE2000，色相差被压到极小）。⑦ **005 与视频对齐实测**：机位 = 转盘约 10°、俯角 16°（场景存值）、放大 1.03，整帧逐像素同色率 **95.4%**（地面 99.7%、投影 84.6%、岩石区四档色阶相同但正面高一档）；残余差异属录制时的场景状态差，非管线问题。⑧ **002 的影子一直在渲**（更正此前「不出投影」的错误结论：当时暗像素检测用 `uint8` 求和溢出、且 P1 色板下影子与地面吸附成同一色板色，双重失误导致误判）。实测：Test_0 / Test_3 色板下影子清晰可见，占 3.56% 像素（影子色 `(9,10,20)` / `(13,7,19)`）；**影子能否看见的关键是地面材质**——仓库里 002 地面底色仅 0.142、太黑，影子与地面几乎同色，抬亮地面后影子显形。参考图的「浅紫灰地面 + 明显影子」同样指向录制时的材质状态未入库。**005 的投影经开关对照确认**（关灯影后两图差 4.5% 像素、暗色 `(53,38,66)` 消失）。**002 全状态枚举（24 张：色板 4 × 主光档数 2/3/4 × 环境光 1.0/1.4）**：最接近参考图的是 `Test_1 + 主光档数 2~3 + 环境光 1.4`（6 色、球体平涂，与参考扁平感一致），但参考图的地面亮度与方块品红/橙侧面只能靠材质还原。唯一未排除的外部变量是版本差（原版 Unity 2022.3.43f1 + URP 14.0.8 vs 本地 62f1 + 14.0.12）。
- **描边样式与地面翻格（2026-11-24 实测）**：⑪ **「两种样式描边」= Outline 趟的两个着色分支**（`OutlinePass.hlsl` 的 `ApplyOutline`，由关键字 `_OUTLINE_SOLID_COLOR` 切换）：样式一纯色（`_OutlineColor`，与物体/光照无关）；样式二本体色乘色（`baseColor × _OutlineColor`，随光照变深、影子侧自然是暗的）。描边画在**物体外侧的背景像素**（向四邻找「断开且不更近」的边界），1 个画布像素宽；`_ApplyOutline` 材质 int 决定物体是否参与。**实测判别 v3 视频**：柱子左缘像素序列「背景→暗棕(94,75,60)→亮米白(247,236,208)→正面(128,110,106)」，与我方「本体色样式→(73,51,59)→(188,159,153)」同构，而纯色样式会出现视频没有的灰蓝圈(142,144,151) → **视频用的是本体色样式**；双层边 = 外层描边（背景侧暗化）+ 内层边缘光（物体轮廓上的亮线）。残余差异只是参数值：`_OutlineColor` 与材质 `_RimLightColor`（视频接近白米色、更亮）。
⑫ **地面颜色随视角翻格是正常现象**：LUT 明度主导吸附，机位差几个像素就可能从 (95,95,103) 跳到 (101,81,82)；按视频机位（半径 9、方位 190°、俯角 16°、放大 1.03）时地面逐像素一致率 99.7%。
- **002 复刻参数（2026-11-24 实测）**：⑭ **配套文档（2026-11-24 起持续维护）**：[CellShade库能力总览.md](../../技术/渲染/CellShade库能力总览.md) 单文件操作手册（16 张 G-buffer / 9 个 Feature 参数 / 材质属性总表 / 视觉能力清单 / 参数速查 / 场景 / 色板 / 坑 / 复刻配方）；[CellShade着色代码图解.html](../../技术/渲染/CellShade着色代码图解.html) 原理图解（逐模块五件套 + 中间缓冲逐张讲解）。两份均已登记进 docs/README.md 渲染索引；与 [调研/v3蓝本.md](../../技术/渲染/调研/v3蓝本.md)（移植蓝图）分工互补。新发现的能力/参数/坑直接补进能力总览，不另开分册。
⑬ **002 参考画面（绿球+方块）的复刻参数（2026-11-24 实测逐项对上）**：色板 TestPalette1；环境光 1.4（批模式补偿）；地面 `_BaseColor ≈ 0.42`（灰偏紫）；球底色 `(0.588,0.894,0.431)`（渲出主色 `(145,219,105)` 与参考 `(145,220,105)` 逐像素相同）、主光档数 3、`_Smoothness 0.82`（小高光点）；方块底色 `(0.944,0.45,0.58)`（渲出顶面 `(246,129,129)` 与参考逐像素相同）、主光档数 4（对应顶/右/左三面 1 / 2⁄3 / 0 三档）；**方向光需更暖**（B≈0.62，出厂 0.839）——暖光下高光点渲出 `(251,255,134)`，与参考 `(254,255,137)` 一致，出厂光色下则为纯白；描边=本体色样式（资产已按创始人裁决改为 `m_Active:1`、`m_SolidColor:0`）。**剩余差距**：方块右面在参考是中间档橙 `(205,104,60)`，我方仍落在亮档（`(240,79,120)`）——需调方向光方位角使其落档降一档，未继续拟合。
⑯ **方块三面的互斥关系（2026-11-24 实测）**：锁定其他变量后单扫底色 B——B=0.35 时左面 (122,48,69)、右面 (205,104,61) 与参考逐像素相同但顶面落橙 (245,125,74)；B=0.42 时顶面 (246,129,129)、右面 (205,104,61) 命中但左面退成 (117,60,84)。顶面与左面在色板上互斥，中间值（0.38~0.40）待验。另：方位角扫描（-10°~40°）证明顶面不吃方位角、右面全程卡第 1 档；`_Smoothness` 0.30~0.65 对三面完全无影响（高光项未命中方块顶面）；三档环境光强度也动不了顶面。
⑮ **轮廓亮环归因与三种机制（2026-11-24 实测）**：① 反射源换色实验（纯红/蓝灰/暖白立方图）证明 002 的轮廓环与地面色**同时**随 GI 环境反射整块变色；002 场景 `SloanePixelartRimlight` 对象数为 0，故 RimLight 趟贡献恒 0——环只能来自 GI 趟 `NoV=multiStep(N·V,2)` + `EnvironmentBRDF` 的掠射项。② 批模式反射探针是坏的：天空盒 `RenderToCubemap` 现场烘焙后环变纯白、地面过亮，与参考的紫灰地面 `(98,85,101)` + 蓝灰环 `(155,171,176)` 都对不上，说明作者环境≠默认天空盒，逐像素抠环色无意义。③ 可复现路径改用库自带 RimLight：两个 `SloanePixelartRimlight`（左绿、右上蓝灰）+ 材质 `_RimLightColor.a`；α=1 过曝成纯白，α=0.5 渲出 `(199,220,208)`，接近参考但仍亮一档。④ 另一AI对参考图的机理评价：三层色阶判断正确（= `_MainLightLevel 3` 的 `multiStep`），但「阴影贴图单独一层」不成立（`shadowAttenuation` 在量化前乘进 `N·L`）、「菲涅尔叠进光照再截断」不可取（库的菲涅尔是 GI 独立缓冲 + NoV 两档硬切，叠进漫反射会把 1px 锐边压平）。




- **效果参数来源与工程纪律（2026-11-24 补）**：⑨ **参考图四种效果在库里的参数来源（实测逐一复现）**：①**色带档数** = 材质 `_MainLightLevel`（着色趟 `multiStep(ndotl, level, …)` 均匀分档，任意档可配，参考图的 5 档用 level 5~6）；②**高光大小** = 材质 `_Smoothness`（`exp2(5s+1)` 作指数，0.443→大盖、0.65~0.75→小点；参考图的小黄点约 0.6~0.7）；③**随光变深的棱边暗线** = 棱线压暗（`normalDiff > _NormalEdgeThreshold` 时 `ndotl += singleLevel × _EdgeLevel`，`_EdgeLevel=-1`），**出厂 002 三个材质该阈值均为 1（=关闭）**，参考那期是开着的（岩石材质为 0.82）；④**亮侧边缘光** = 三件套基础设施，缺一不出光：场景挂 `SloanePixelartRimlight` 对象（方向=物体 forward、颜色=组件字段，实例入静态字典，着色特性每帧 `RefreshRimLights` 拷入 `_RimLights`，上限 32）+ 材质 `_RimLightColor`（RGBA，alpha=强度，**002 材质连该属性都没有**，005 的 Rock.mat 有）+ 着色趟 `for i<_RimLightsCount` 累加；`RimLightShading` 只在轮廓断开边且 `dot(方向,法线)>0` 处出光，故**亮侧有、暗侧无是设计使然**。⑤ 另注：库里那个 Outline 特性是屏幕空间统一色描边（出厂 `m_Active:0`），与参考图方块上那种「随光变深」的暗边不是同一机制，参考图用的是③。
