## 详情

### 空壳口径（2026-10-01 用户裁决）

- **不删系统**：下面的武器面板还在、点击选择还在；内部的特殊机制堆料（海鸥/潮汐/巫毒/锚/地雷/炮台/
  扫焰）退场，**全部补位成标准的小炸弹**（抛掷→重力弹道→接触/静止引爆→ExplosionResolver 全语义结算）。
- 旧占位链的实测缺陷（海鸥零伤害、AI 评估失真、锚穿高台等）随掏空自然消亡，不再登记为缺陷——
  它们属于「不存在的功能」，档案在设计基线文档 §1 铁律与 §5 验收清单里以教训形态留存。
- 伤害侧真空提示：炸弹是当前唯一伤害源，血量/击退/落水骨架正常；在此之前战斗结算语义以炸弹为准。

### 重做时的验收清单（从占位期实测教训提炼，全文见设计基线 §5）

1. **实弹 == 评估同源**：未来 AI 与实弹必须消费同一份几何/结算入口（StandardBombRules/ExplosionResolver
   已是现成同源点，别再造第二份）。
2. 规则进纯 C# 静态类、MonoBehaviour 只做胶水（无头可测纪律）。
3. 数值必须有用户裁决的出处；StandardBomb 现值（爆炸尺寸 100/伤害 50 等）标【提案/待定】，重做时逐值重裁。
4. 特殊武器机制回填时逐把过设计基线 §2 的概念清单与「重做时必须回答的问题」。

### 剩余待裁（掏空批次未含）

- **TileTerrainGrid 类名正名**：「瓦片」是化石命名（一代瓦片玩法已根除），现为静态高度场载体——
  独立小改，随时可做。
- **schema 二刀（方案 B 收缩）**：`WeaponId`/`WeaponStack`/`initialWeapons`/空投池当前作为数据锚
  保留（关卡 golden JSON 与 24 张船员资产零手术）；重做定档后可收缩——届时 LevelAssetPayload 去
  airdropPool/crewWeapons/captainWeapons 字段、schema 升 3、重跑 LevelDataMigrator 双向并重写 4 份
  golden JSON（测绘报告 §三数据链小节有完整手术点）。
- **Ballistics 残留纯函数**：`IntegrateGroundContact/IntegrateWallContact` 已无运行时调用方
  （仅测试消费）——重做弹道时决定复活或删除。
