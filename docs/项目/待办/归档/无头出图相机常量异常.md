# 无头出图相机常量异常（已闭：非相机 bug）

> 结论（2026-10-20）：**不存在相机异常**。调试格读到的是 LabCamera 真值经显示编码
> （实测标准 sRGB）后的字节；读数侧把它当线性值，才反推出 `(21.2,43.2,27.0)` /
> `2923×2249` 与 ≈24° 俯角。按 sRGB EOTF 反解后精确还原
> `(10.019,26.265,21.019)` / `1920×1080`（r48-dbg 的 (1,1)/(2,1) 五通道零参数命中）。
> 因此「出图光深只有 ≈0.36 m / 水比实机浅」的结论**撤回**：出图几何一直是对的。

## 详情

- **发现**：第十八轮给水面 PS 加 3×3 调试分格（`PC3D_WATERLAB_OCEAN_DEBUG=1`），
  其中 (1,1) 输出 `GetCameraPositionWS()`、(2,1) 输出 `_ScreenParams`；C# 侧
  `PC3D_WATERLAB_CAM_DUMP=1` 打印的 LabCamera 是 `(10.019,26.265,21.019)`、
  RT 1920×1080。两边对不上，且画面取景/透视又正确，故曾判为「常量错、投影对」。
- **实证**：`export/waterlab-debug/r48-dbg/battle-hud-1.png` 的 (1,1) 格字节
  `(212,235,172)`、(2,1) 格 `(182,140,255)`。标准 sRGB 编码：
  `srgb(10.019/64+0.5)=212`、`srgb(21.019/64+0.5)=235`、`srgb(26.265/64)=172`、
  `srgb(1920/4096)=182`、`srgb(1080/4096)=140`，sim enabled=255。五通道全部命中，
  无自由参数。
- **俯角为什么也错**：(0,0) 格的 `depth/2` 与 `dist/10` 斜率不同，编码后按线性读，
  比值被系统性扭曲，才反推出 24°；真实机位是俯角 48°、fov 32°。
- **处置**：
  - `WaterLabSetup.CreateCamera` 给 LabCamera 打 `MainCamera` tag——出图链按
    `Camera.main` 取景，同时消除 `ShotUICam` 建立后 `FindObjectOfType` 回退误命中的风险。
  - 新增 `tools/waterlab/debug_tiles.py`：按 sRGB 反解九格并还原物理量
    （可选 `--encoding pow22|raw`）。
  - 出图命令的 `PC3D_CAPTURE_SRGB=1` 保留（人眼观感用）；**数值读数一律走解码工具**。
- **教训**：诊断格不是「数值仪表」——它和画面走同一条 8bit 显示编码链。任何
  「读像素反推物理量」的脚本都要先确认编码；只有几何/投影不受影响。
- **来历**：第十八轮（2026-10-18）发现并立项；2026-10-20 结案归档。
  审计记录见 [§9.3①](../../审计/水体实现覆盖率审计报告-2026-10-18.md)。
