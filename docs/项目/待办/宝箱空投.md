# 宝箱空投玩法

> 一句话现状：设计有明确要求、零玩法实现（2026-10-21 设计差距审计立项）——`StarRules` 自认
> chestsTotal=0，`airdropPool` 字段只进数据校验、战斗侧（BattleController）零消费。

## 详情

- **玩法规格**（自场景设计摘录）：宝箱按「有实心地形且上方无遮挡的列」随机空投，**最多 3 只同屏**
  ——是**武器补给**，不是胜负条件。
- **数据面**：`LevelAssetPayload` 的 `airdropPool` 已是数据锚（关卡 golden JSON 在册、校验在
  `LevelAssetRules`），缺的是战斗侧消费（落点选取、同屏上限、拾取补给入武器库）。
- **耦合前置**：拾取补给依赖武器库语义——建议在[武器系统重做](武器系统重做.md)定档后接
  （空壳期"补给什么"没有答案）；若要先做落点/掉落表现，注意与特效重做线的透明趟口径协同。
