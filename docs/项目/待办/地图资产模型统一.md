> 创始人裁决:所有地图统一叫「地图」、统一成同一个资产接口;坐标与数值口径全米;
> 「格」彻底退场——格从**资产、文档、玩法表述**里全部消失,不是只换单位、不是保留格判定。
> **资产层已落**(已定口径):载荷全米——`sizeX`/`sizeZ`(米)、`TerrainRaster.heights`(米)、
> `LevelUnit.x/z`(米)、`waterWorldY`;四张地图的 golden 与 `.asset` 已迁移,
> 原「solid/total/digest」摘要逐字未变(= 行为等价证据)。消费侧
> [LevelSource](../../../pirate-crew/Assets/Scripts/PirateCrew/Battle/Levels/LevelSourceResolver.cs)
> 本就统一。**遗留两线**:① 运行时「格」命名收口(§二);② 海域基建(WorldKit / OceanRig)
> 去留裁决(§四)——它是「新地图怎么建」的先决。

## 详情

### 一、口径(要改成什么)

- **只有一种地图资产载荷**,`levelNumber` 作唯一身份键(`id` 退为字符串别名);
- **尺幅、出生点、水位、射程、跳距……一切数值一律用米**,玩法数值直接以米落笔,不回头换算;
- **格号作为对外概念消失**:`gridX/gridY`、`widthTiles/depthTiles`、`waterTileY`、`TileWorldSize`
  不再出现在资产与文档里;
- **不声明场地尺寸;范围 = 内容的自然边界**:资产里存 `widthTiles/depthTiles` 这类
  「先声明一块场地再往里填」的写法,正是八张海图「空尺度」(约 75% 图面无人可到)的病根。
  新模型只存内容,范围由内容边界推出;界外没有地面 ⇒ 就是海 ⇒ 落水即死。
  玩家能去哪只由「那里有没有地面」决定——代码层没有、也不需要「活动范围限制」;
  尺寸字段的唯一用途是配水面域 / 海面罩 / 相机取景(`WaterSimulationDriver.ConfigureWorldDomain`、
  `OceanRig`、`CameraWorldSpan`),是视觉与模拟范围,不是边界墙。
  「别把图做大」是设计口径、不是代码约束(见 [大海域世界化(归档)](../归档/M4-世界化/大海域世界化.md)
  §0 裁决 2 与 §1「不无限摊平可玩区(回合制节奏保护)」,重做时随
  [环境表现 §4.4](../../设计/场景.md) 逐条重新确认,靠设计时把图做小落地)。

### 二、遗留清单(运行时「格」命名收口,以代码实态为准)

类层面已收口:`TileTerrainGrid` 已更名
[HeightfieldGrid](../../../pirate-crew/Assets/Scripts/PirateCrew/Battle/Terrain/HeightfieldGrid.cs),
类头明写「『格』只是存储与换算单位,不表达任何逐格玩法语义」。成员与消费点的瓦片/格命名仍在:

- `LevelGeometry.TileWorldSize`(采样粒度常量,2 米/格)及其消费点
  (`HeightfieldGrid`、`BattleTerrainView`、`LevelAssetRules` 的采样粒度一致性校验);
- `BattlePlan.WidthTiles` / `DepthTiles`;
- `SpawnPlanEntry.GridX` / `GridY`(消费点 `BattleController` 出战摆位);
- `HeightfieldGrid` 自身的 `WidthTiles` / `DepthTiles` / `CellXOf` / `CellYOf` 与 `gridX/gridY` 形参;
- 周边零散:`AmbientDirector.arenaWidthTiles`、`PlatformMap.WidthTiles`。

收口是纯重命名(语义不变),改完按惯例跑 EditMode 收口。
