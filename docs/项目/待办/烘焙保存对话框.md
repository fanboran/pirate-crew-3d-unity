# 烘焙保存后「外部修改」对话框卡编辑器

> 一句话现状：真编辑器里跑烘焙菜单（实测 `烘焙资产特写观察场景`），保存完成后 Unity 内建
> 「The open scene(s) have been modified externally」对话框弹出并**卡死主线程**——桥驱动/自动化场景下
> 后续命令全部堵死（batchmode 无此问题）。

## 详情

- **现象**：命令本身成功、回执 OK；日志显示场景保存后被 import **两次**（`PixelartAssetInspect.unity`
  保存后双导入），疑似两次写盘触发外部修改检测。
- **疑点**：`AssetInspectSceneSetup.BuildAll` 的保存序列（`SaveScene` → `RegisterScene`（YAML 直改
  EditorBuildSettings）→ `AssetDatabase.SaveAssets/Refresh`）与既有装配器（CharCamDebug 同款序列）
  的差异点；也可能是桥的 `menu` 执行上下文（无对话框吞吐）放大。
- **影响面**：所有走「真编辑器 + 桥」的烘焙菜单；常驻编辑器工作流（流程提速线已收官）的第一拦路石。
- **修法方向**：对齐无对话框口径（保存序列去重/显式 `EditorSceneManager.SaveScene` 后不再触发二次
  导入），或装配器保存前关闭场景再开；修完用桥复测 menu 烘焙 + 后续命令不卡。
