# UI 系统性审计（2026-11-22）

> **审计基准**：commit `4e0d7b1d`（含本轮设置页收敛/对比度/焦点修复）+ 同日工作树。
> **方法**：4 路网络调研（游戏 UI 架构 / 游戏 UX 与 HUD / 像素 UI 规则 / Unity UGUI 工程实践）
> ＋ 本地代码与 Prefab 审计 ＋ 主题色对比度计算 ＋ 2×/3× 实机截图（1920×1080）。
> **覆盖**：主菜单、设置模态、选关、船员管理、战斗 HUD、暂停/结算/返回确认、通用控件与模态栈。
> **未覆盖**：调试面板的交互体验、手柄全导航、多语言/RTL、移动端安全区。

## 一、结论摘要

现有路线（代码工厂 + 编辑器期烘 Prefab + 像素字体 + Aseprite 直切件 + 全 Overlay 画布）
与四份调研的共识一致，不需要换框架。真正的问题集中在四类：

1. **可访问性硬指标**：提示字对比度不足、键盘无法遍历、队伍只靠红蓝区分。
2. **设置页安全**：高像素比例会把画布缩到面板装不下；分辨率切换缺少自动还原保护。
3. **输入与焦点**：模态打开时下层按钮仍可能被 Enter 触发；列表行没有键盘焦点表达。
4. **工程卫生**：raycastTarget 偏多、调试面板与生产 UI 共画布、列表刷新销毁重建。

## 四、调研共识（用于后续判断）

### 架构

- **屏幕栈 + 模态栈 + 单一 Esc 裁决**是最小必需（Unity QuizU、Unreal CommonUI 同构）；
  不引入 Router、响应式绑定框架、Addressables、DI 容器或全局 store（5 屏规模是负资产）。
- 轻量 MVP：Controller 只做「refs ↔ 规则」翻译，决策进纯 C# 规则类（本项目已有此纪律）。
- 焦点恢复、动画期间 busy 闸门、模态真实输入屏蔽是栈的必备配套。
- refs 按子部件拆组（单结构体 ≤8 字段），避免 30 字段平铺。

### UX / HUD

- 三读分层：第一读战场（单位/投射物/落点），第二读关键数据（血条/回合/武器），
  第三读情境信息（小地图/提示）；按需显示优于常驻堆砌。
- 关键信息不得只靠颜色；红蓝队需形状/文字冗余。
- 对比度：普通文本 ≥4.5:1、非文字图形 ≥3:1、禁用态 ≥3:1。
- 设置：即时生效；昂贵变更（分辨率/全屏）用倒计时还原；分组恢复默认；自动持久化。
- 不可逆操作确认；确认按钮不要做默认焦点。

### 像素 UI

- 整数缩放唯一可靠路径：ConstantPixelSize + 整数 scaleFactor；禁止 Scale With Screen Size。
- 九宫格：使用尺寸必须 ≥ 边框和；`pixelsPerUnitMultiplier=1`；Point/Clamp/无压缩/无 mipmap。
- 位图字体：原生档、RASTER_HINTED、Bitmap 材质、静态图集、禁伪粗/斜体/Best Fit；
  8px 仅短标签，正文 ≥10px，行高 1.0–1.5 倍。
- 像素动效：位移逐帧取整；非整数缩放与任意角度旋转禁区；强调用颜色/1px 位移。

### Unity UGUI

- 头号低垂果实：raycastTarget 只留交互件；Canvas 按「动/不动」拆子 Canvas。
- 列表 10–50 行不值得池化；避免「刷新时 Destroy 全量重建」，改行复用。
- 动画用代码 tween 只改 `anchoredPosition`/alpha，不改 `sizeDelta`；静态 UI 不挂 Animator。
- 全屏隐藏首选禁用 Canvas 组件；小面板 SetActive 可接受；CanvasGroup 用于淡入淡出。
- `RectMask2D` 每滚动链只留一个；AseView 已符合。
