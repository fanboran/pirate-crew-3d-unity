## §二 P0（协调者已复核）

### [P0] T1 无头验证缓存仍可假绿：key 不覆盖未跟踪文件内容，test 档只缓存退出码

**证据链**（协调者亲验 `tools/headless/run.sh:96-113`）：

1. `cache_key()` = HEAD 哈希 + (`git status --porcelain` + `git diff HEAD`) 的 md5。porcelain 对未跟踪文件只输出 `?? 路径` 一行，`git diff HEAD` 不含未跟踪内容——**新建测试或运行时代码（未 `git add`）后修改其内容，key 不变**，30 分钟内旧「全绿」被原样回放。
2. 脚本注释自称「哈希必须含脏文件**内容**（diff HEAD）」（`:92-94`），但 diff HEAD 恰恰不含未跟踪文件内容，口径声明与实现不符。
3. `cache_store`（`:127`）只存 key/时间戳/退出码，完全不读 `-testResults` XML——「0 用例命中」「全 Ignore」与「真全绿」在缓存层不可区分。

**影响**：这是 10-01 审计点名、号称已修的假绿通道（归档报告 §五 军师队短板），实际只修了一半（加了 diff HEAD 但漏了 untracked 内容）。新功能开发期（文件尚未跟踪）最容易触发，可掩盖新代码里的真回归，使整个分级验证体系的可信度受损。**定级 P0 的依据：它不是又一个 bug，而是让「验证通过」这个信号本身不可信。**
