### 3.4 C# 侧真值（本轮由 IL 反编译直接取得）

**Water（`Water.Run` / 构造器）**
- `WATER_SATURATION_POINT = 0.05`（干湿阈值）、`gravityForce = 10`（`[Range(0,20)]` 默认；场景实例另有值）、`evaporationFactor = 0.15`（`[Range(0,2)]`）、`level = 1`、`chunks = (4,4)` 默认、`enableSpawn/enableEvaporation`。
- 每帧下发：`gravityForce`；**`maxVelocity = 0.5·√g`**；`level`；`waveAmplitude = saturate(playTime×0.05)·max(四列预设项)`；`evaporationFactor`（开关钳 0）；`advectionFactor`/`damping`/`kappa`（取自配置）；`deltaTime`。
- **子步长 `dt = cellSize×0.5/√g`**（Courant=0.5 的 CFL 显式步长），配 `Step("simulation", dt, frameDelta)` 累加器。
- dispatch 序：子步循环内 `VelocityIntegration → HeightIntegration →(advectionFactor>0 时)Advection`；步外 `UpdateAmount → UpdateTangent`；再 `Spawn()`（涌浪泵，`Step("spawn", spawnRate, dt)`）、`SpawnDirt()`（`Step("spawnDirt", 5f, dt)`）、`whitewater.Run`、`phytoplankton.Run`。
- `waterColor`/`waterScatteringColor` 经 `Mathf.GammaToLinearSpace` 后 `Shader.SetGlobalColor`。
- `WaterCell` 结构：`Vector2 tangent; Vector2 velocity; float amount; floor; crest; inflow; wave;`（7 个 float，序列化 28 B；compute 侧 stride 16 = 打包后）。

**Whitewater / Culling 基类**
- `capacity = 32768`、`frustumOverscan = 0.1`、`THREADS_GROUP_SIZE = 1024`、`DispatchX = ceil(capacity/1024)`。
- `Culling.Setup`：`drawListBuffer`/`drawShadowListBuffer`(capacity×4)、`argsBuffer`/`argsShadowBuffer`(`ComputeBufferType.DrawIndirect`，args 为 5 元 uint：indexCount/instanceCount/indexStart/baseVertex/firstInstance)；**视锥 + 阴影视锥双剔除**。
- 出画：`Graphics.DrawMeshInstancedIndirect(mesh, 0, material, bounds, argsBuffer, 0, mpb, castShadows, true)`；材质绑 `drawList`/`drawShadowList`/`whitewater`。
- 粒子缓冲 `whitewater`：stride = `sizeof(Vector4)` = 16。

**Gi**：`resolution = 128`；`sceneVoxels`/`giVoxels`/`giVoxelsBlurred` 三张运行期 RT；常量 `samples` / `precision`。

**Layer（所有域基类）**：`resolution = 64` 默认、`THREADS_GROUP_SIZE = 32`、`cellSize = beach.bounds.size / resolution`、`scaleBias`、`Paint` kernel + `brushDataBuffer`。

**BeachRenderPipeline**：ProfilingSampler 序列 = `Shadows → ColorDepth → Skybox → Opaques → CopyOpaqueDepth → Transparents → Behinds → Highlights → Atmosphere`（另 Gi 顶视通道）；`cameraOpaqueTexture` Bidirectional 临时 RT、`cameraDepthTexture` Point 临时 RT。

### 8.1 新发现（推翻「D 域 50%」的口径）：白水此前**从未产出过任何粒子**

### 8.4 第二轮（同轮续做）：透明度与焦散（创始人收窄目标为「能精准透视水底 + 焦散真实」）

据此重新审视，定位到两个**结构性错误**（都不是参数微调能解决的）：

**① 吸收系数单位错——红光过吸收 8.66 倍**

`T = exp(−8.65617·σ·dist)`：8.65617 是「归一系数 → 每米」的换算，**σ 属 tint 域（0..1 量级）**；
本仓填的是**每米**值 `(0.45,0.14,0.03)` 又保留该缩放 → 红光有效消光 `8.66×0.45 = 3.9/m`
（1/e 长度仅 **26 cm**）。1.3 m 处红光只剩 0.6%、绿 21% → 水底真色被吃光只剩青蓝，
**焦散也一并被压在下面**（这一条同时解释了「看不到焦散」）。

σ 静态取不到（**不在** `WaterType` 预设、不在 C# 全局、不在材质；DXBC 的 RDEF 反射块被剥，
只剩 ISGN/OSGN/SHEX → 名字与默认值都没有，见调研档 §13）。故**按判据定标**：
水域中位水深 ≈0.6 m 处红光透过率 ≥0.5（保证水底可读），并取该约束允许的上限（尽量保住水体色）
→ 有效 `(1.15, 0.45, 0.20)/m`，即 tint 域 `(0.1328, 0.0520, 0.0231)`。
（**已被第十八轮取代**，现行值见 §9，下同。）
0.6 m 处 `T=(0.50,0.76,0.89)`、1.3 m 处 `T=(0.22,0.56,0.77)`。

**② 焦散：落点错 + 源错**

| | 原作 | 本仓（改前） | 本仓（改后） |
| --- | --- | --- | --- |
| 落点 | **沙侧** `Lit_Sand` 的 `causticsMap`（烘焙 Texture3D，§10.2/§12）；水侧无焦散项 | 水 PS，按折射点域 UV 调制 `bgColor` | **沙 PS**（`albedo × caustic`，水体只折射+衰减）→ 与原作同构 |

源为什么必须换：η 场只有长涌浪，其 2 格拉普拉斯放大 6 倍后**峰值全挤在岸线最陡处，
成一条硬边而不是网**（2026-10-18 实拍）；真实焦散网的空间频率来自水面**小尺度**波纹，
而那正是细节法线贴图编码的东西。增益与采样偏移**靠离线量测定标**（读生成的 512²
细节法线贴图算散度分布）：取采样偏移 0.0156 UV（≈0.31 m 特征、20 px/m 下约 6 px）+
增益 0.2 —— **0.2 恰是原作材质 `_CausticGain` 的原值**，反证该增益本就是按坡度量级标的。

**验收指标**（出图 `export/waterlab-debug/r34`（只改 σ）/ `r37`（σ+焦散））：

| 指标 | r32（改前） | r34（修 σ） | r37（+焦散） |
| --- | --- | --- | --- |
| 水面带局部梯度（水底/焦散可读性代理） | 2.12 | 2.47 | **3.84** |
| 全图均值 | (186,202,191) | (202,199,185) | (209,207,195) |
| 水面带彩度 | 26.0 | 13.1 | 11.1 |

**仍未闭合**：观感平衡（水的体色浓淡、焦散粗细强弱）**需要参考画面**才能定标——
σ 与焦散参数都是「按判据/量测」定的，不是照抄；建议下一步取参考实机画面（或商店截图）
做比色，而不是继续盲调。另：`_WaterLabCausticTex`（第十五轮的外包债②）现在**两侧都不再采样**，
其烘焙仍在跑但无人消费——需决定移除还是改作低频层。

### 8.5 第三轮：水底参照物 + 显示链曝光（创始人「水底要不放上各种参照物，不然感觉不到透明感；沙子跟纯白似的」）

**诊断**：透明感不靠「更透」传达，而靠**透过水看到水底物体**。只有沙纹时沙本身是亮的、
水体又只轻微调色 → 观感是「一片亮沙」而非「一汪清水」。参考游戏水底有礁石/珊瑚/海草
（深色、有轮廓、随焦散明暗）——那才是透明度的载体。同时受光干沙未经 tonemap 压缩后近白，
把水体的存在感冲掉（参考管线有 tonemap/曝光，本仓 URP 直出）。

**落点**：
- `WaterLabSetup.CreateBottomProps()`：程序化低模礁石（正二十面体顶点径向抖动 + **平面着色**，
  面法线显式按「面心朝外」定向并同步翻转绕序 → 不依赖顶点序、不翻面），6 形 × 3 色
  （深灰岩/暖橙/暗绿——深色最能让水体衰减读出来），确定性散布 80 件，只落在有水处，
  **尺寸按当地水深封顶**（超出会露头，就不是水底物体了）；走不透明队列 → 水体采
  `_CameraOpaqueTexture` 时已含它们 → 被折射 + 吸收。
- 新 `WaterLabProp.shader`：与沙面**同一光照式**（直射×阴影×水柱 + 天光 + 焦散），不脱层。
- **显示链曝光因子** `_LightScale`（沙/礁石，默认 0.72）：补参考 tonemap 那层压缩，
  使受光干沙落在中间调而非近白。
- σ 再定标（判据改为「**20 cm 处即有可见青色调**——水感的第一来源是红光先衰，不是整体变暗」）
  → 有效 `(2.00, 0.60, 0.25)/m`（tint 域 `(0.2311, 0.0693, 0.0289)`）。
  （**已被第十八轮取代**，现行值见 §9。）

**验收指标**（出图 `export/waterlab-debug/r38`（+参照物+曝光）/ `r39`（σ 再定标））：
局部梯度 r32 2.12 → r37 3.84 → r38 4.11；全图均值 r37 (209,207,195) → r38 (200,199,189)
（曝光因子把近白压回中间调）。

**未闭合**：① 水的体色浓淡与沙的亮度**最终需参考画面比色**（σ 与 `_LightScale` 都是按判据定的，
非照抄）；② 参照物的密度/尺寸/种类（现为 80 件礁石，参考还有珊瑚/海草/更密的分布）；
③ `WaterLabProp` 与 `WaterLabSand` 的光照+焦散代码目前是**两份拷贝**（应抽成 include 单一来源）。


## 9. 落地跟踪：第十八轮（2026-10-18，对着 Steam 高清头图比色收口）

**触发**：创始人「现在水的观感一点也不像真的水了，你可以提取 Steam 高清背景头图对比一下区别」。

**基准来源**：Steam 客户端的官方高清头图（`appcache/librarycache/<appid>/…/library_hero.jpg`，
1920×620，实机渲染成品）——这给了本任务第一个**逐像素比色基准**，把此前「按判据定标」的
σ / 沙色 / 曝光三项一次性换成「按参考画面反定」。反定方法落在
[调研档 §14](../../技术/渲染/调研/Sandcastle水体逆向.md)；比色脚本在
`tools/waterlab/`（`compare.py`/`judge_vs_ref.py`/`raycast_probe.py`，用法见各自 docstring）。

### 9.1 主根因：水面 PS 里的自造泡沫项（对应 §4.B 的「本仓多出」）

§4.B / §11 早已把「模拟泡沫通道 lerp 进水面颜色」标为**本仓多出**（原作水 PS 无泡沫项）。
本轮量化到位：

| 量 | 实测 |
| --- | --- |
| 泡沫场 `field.a`（浅水架） | 均值 0.285、中位 0.251、p90 0.663、**最大 0.906** |
| 覆盖率 | **56% 水面 > 0.2**、23.6% > 0.5 |
| 由出射色反解的水面泡沫混合权重 | **≈0.85** |
| 结果 | 整片海面被刷成白沫，水色与折射水底全被盖掉 = 「不像水」的直接成因 |

⇒ 整项删除，泡沫场只驱动白水粒子（原作同构）。**其余三层定标**：σ 三锚点反定
（有效 `(5.6,1.94,0.35)/m`）、沙色反定（受光干沙 `(252,226,167)`、色度 85）、
细节法线强度 0.7071→0.35（0.22 档实测对碎金无效、已回退；参考浅水内 `lum>235`
只占 0.05%，本仓曾 0.36%）。
另 `OffshoreDepth` −1.3→−2.4 m、取景中心 `(-4,0)`→`(-11,0)`——绿松石→宝蓝的转折需要真实水深。

### 9.2 逐项指标（出图 `r39` → `r45` → `r50/r51`）

| --- | --- | --- | --- |

| 水色度（逐像素均值） | 13.5 | **81.5** | 36.9 … 125.5 |
| 水区占画面 | 26.9% | **91%** | — |
| 近白像素占比 | 1.87% | **0.51%** | — |
| 水像素亮度均值 / std | — | **103 / 49.1** | 105 / 43.5 |

**结论**：水色从「洗白的灰」进入参考的色度区间（13.5 → 81.5，参考 37–126），

**指标修正（第十九轮）**：`lum>235` 是绝对阈值，随整体曝光漂移（r54 水区 Y 159.6 vs
参考 117.7），不能直接当碎金密度——它曾把「碎金过密」放大成 20×。改用「亮度 − 9×9
局部中位」后：参考 `>60` 占 0.51%，r50 2.08%、r54 0.78%（约 1.5×）。r55 的 2 格法线
差分对该指标无影响，已回退。残差主要是整体亮度，不是碎金数量。

### 9.3 本轮暴露/未闭合

① **【已闭·非 bug】「相机常量不符」是诊断格读数的显示编码误读**（2026-10-20 结案）：
   调试格数值在 PNG 里是**标准 sRGB 显示编码**；按 0..1 线性直读，LabCamera 真值
   `(10.019,26.265,21.019)`/`1920×1080` 会被解成 `(21.2,43.2,27.0)`/`2923×2249`，
   `dist/depth` 反推的俯角也随之失真为 ≈24°（真实：俯角 48°、fov 32°）。
   r48-dbg 的 (1,1)/(2,1) 五通道字节 `(212,235,172)`/`(182,140,255)` 在零自由参数下
   精确等于真值的 sRGB 编码。**因此原判断「出图水比实机浅、反解光深仅 0.36 m」撤回：
   出图几何一直是对的。** 处置：LabCamera 打 `MainCamera` tag（消 `FindObjectOfType`
   回退风险）+ 新增 `tools/waterlab/debug_tiles.py`；任务档移入
   [待办/归档](../待办/归档/无头出图相机常量异常.md)。
② **沙色仍差一档**：r45 曾命中 (252,226,167)/色度 112（过饱和），回调后 r49/r50 的沙掩码
   混入水下沙，干沙单点读数在 (196,206,149)…(249,222,197) 之间波动——**需要在出图里加一处
   只取干沙的定点探针**才能收敛。
③ **【已闭】深水端偏「青」→ 恢复原作 `NdotV⁵` 散射权重 + 补菲涅尔天空反射**（r54）：
   第十八轮按「参考近似俯视、水面无暖调」把散射权重改成 `(1−NdotV)⁵`，实际把暖橙
   散射加到掠射的远/深水（r53 深带 G=115，参考 70）。恢复原作 `NdotV⁵`（反汇编
   nv·nv²·nv²）后深带 `B−R=+110`（参考 +103）、色度 110（参考 ~125），近岸暖沙→
   青绿→宝蓝的色带结构对上。天空反射按原作步骤 8 补上（宏观视角 `(1−viewDir.y)⁵` ×
   强度 3，色值显示域标定）。残余：整体亮度仍偏高（r54 水区 Y=159.6 vs 参考 117.7），
   疑为底沙过曝与缺 HDR 后处理/GI，见 §11。
④ 水底参照物仍偏少偏小（80 件小礁石 vs 参考密集的大丛海草/珊瑚）。
⑤ `WaterLabProp` 与 `WaterLabSand` 的光照+焦散是两份拷贝，应抽 include 单一来源。
⑥ `_WaterLabCausticTex` 烘焙仍在跑但两个 shader 都不采样（第十五轮外包债②遗留）。

### 9.4 新增可复用诊断设施（都在环境变量后面，默认关）

- `PC3D_WATERLAB_OCEAN_DEBUG=1`：水面 PS 不裁剪 + 画面切 3×3 九格输出中间量
  （`depth/2|dist/10|clip`、`T`、`bgColor`、`frac(世界XZ)`、`_WorldSpaceCameraPos`、
  `_ScreenParams|simEnabled`、法线、`spec|阴影`、最终 `col`）。**定位泡沫白幕的关键工具**。
  **读数先按 sRGB 反解**（PNG 是显示编码）——用 `tools/waterlab/debug_tiles.py`，
  否则会把 LabCamera 读成幻影值。
- `PC3D_WATERLAB_MAT_PROBE=1`：水色乘子强制纯红 + σ 压成 5/m 均匀——一次出图分辨
  「水没画出来」与「水画了但颜色不对」（本轮实测整幅变暗红 ⇒ 水在画、材质值确实进了 shader）。
- `PC3D_WATERLAB_CAM_DUMP=1`：两个检查点（2 s / 36 s）打印全部相机的 tag/投影/渲染目标/位姿
  与水面材质的运行期属性值。

**体素 GI / Atmosphere / Highlights / Skybox / 27 个后处理栈**（§4.E：观感差异的最大来源，
且是「没有」而非「自造」）、笔刷交互、生态/玩法。
（白水双剔除/水下衰减/域裁剪已由第十七轮关闭；顶带绿色源未定位，见 §12.2⑤。）

### 10.5 一句话总结

**原作的「水」是四件外包 + 一整套后处理撑起来的**（沙底成像外包给沙管线、焦散外包给烘焙体、
白水外包给粒子系统、光照外包给体素 GI + 27 个后处理）。本仓把前四件都做了**同构替代**，
第五件（GI/后处理）**整体没有**——所以：
- **结构层面**我们自造得很少（骨架照抄，§4 各域「对齐」占多数）；
- **数值层面**我们自造得很多（凡 IL 里取不到的常数，全是我们自推或按参考反定的）；
- **观感上限**卡在缺失的那一层，而不是卡在自造上。

**校准时的纪律**：每引入一个自造替代/自推数值，都要在注释里写清「这不是照抄、依据是什么」
（现状：σ 与沙色已按参考画面反定、破碎判据有物理推导、曝光因子有显示链理由），
并登记到本台账——避免下一轮把自造值当成原作真值继续推演。

**本台账的范围**：只覆盖**实验水体（WaterLab）这条复刻线**。仓库里另有一条
**自研的现役像素海面**（`PirateOcean.shader` / `OceanRig` / `WaterSimulationDriver` /
`OceanRules` 等，口径见 [像素海面](../../技术/渲染/管线/像素海面.md)）——那条是**美术方向的
自觉分叉**（等距像素卡通风，不是写实复刻），不属于本台账的「自造偏差」，两者的关系见
[实验水体](../../技术/渲染/管线/实验水体.md) 开头。

### 12.2 新发现

1. **取景边界**：旧机位（45° 斜看、中心 (-11,0)）右上角 11% 落在 64 m 域外，露天空盒；
   新机位正对岸线（yaw 90°）后域外为 0，沙掩码 37%、水 65%，与参考的横向岸线构图一致。
2. **沙色自相矛盾**：Sand shader 头注释写「`_LightScale=1.15` 同时命中亮度与色度」，
   生效值却是 1.65（shader 默认 + `.mat` + 装配器三处同源扩散）。1.65 在 42° 太阳下
   让干沙 R/G 截白，r54 沙色 `(217,217,183)`、色度 34 的根因；太阳抬到 58° 后改 1.05。
3. **散射是 LDR 直出链的自造补偿**：原作 `waterScatteringColor` 在 HDR 管线里经 tonemap
   压缩；本仓按 1.0 用会把深水 R 抬到 67（参考 16）。新增 `_ScatterStrength=0.04`，
   登记为显示域自造项（§10.1），不是原作数值。
4. **诊断链两处修正**：① `(2,2)` 格 `int col` 遮蔽外层 `float3 col`，最终色格一直输出列号；
   ② r58-dbg 实测出图链是**双重 sRGB 编码**（单次反解得幻影相机 (32,48,14)、
   `_ScreenParams` 2902×2210；两次反解回到 (31.8,33.7,-1.2)/1884×1034）。`debug_tiles.py`
   新增 `--encoding srgb2`。本条修正第十九轮「单次标准 sRGB」的结论——编码次数随 RT
   配置变化，读数前先用相机/屏幕格自检。
5. **顶带偏青未闭**：r59 画面顶部真实水深 2.35 m、光程 4.4 m，按 Beer–Lambert
   `T_G=exp(−8.65617×0.2241×4.4)≈2e-4`，应为暗蓝；实测 `(25,111,136)` vs 参考
   `(16,70,118)`，G 高 41、B 高 18。现有九格只把 T 放在画面下排（depth 0.022 m 处
   `T=(0.764,0.941,1.000)`，与目标 σ 一致），无法判定顶带是「深度采样错」还是
   「未登记的绿色加项」；下一轮把 depth/T 放到顶排再测。
6. **碎金形态**：r59 `>60` 像素占水 0.32%、2810 个连通块、均值 1.5 px；参考 0.51%、
   1575 块、均值 2.3 px。像素分数接近，但我们的亮点更小更多——与「0.25 m 网格法线 ×
   pow1500 锐瓣」一致；本轮已把顶点法线 y 增益 1.5→1.0，未改瓣宽。
