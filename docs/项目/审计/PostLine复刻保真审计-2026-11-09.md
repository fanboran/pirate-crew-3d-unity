## 结论摘要

四个 shader 的**数学内核逐行保真**：Outline 的 8 邻域剪影 + 角度自适应阈值 + 方向对比度棱线、
Composite 的 `lerp(color, outline.rgb, outline.a)`、SharpUpscale 的 fwidth/smoothstep 公式、
ToonLit 的色带量化/GLSLmod/梯度带/云影公式/Bayer 表全部与参照一致；5-pass 结构在 URP14 下的
移植决策（省 CopyColor、`cmd.SetGlobalTexture` 替代 `SetGlobalTextureAfterPass`、画布尺寸全局
替代 `_BlitTexture_TexelSize`——URP14 的 `Blit.hlsl` 根本不声明该伴生量，替代是必然而非可选）
全部成立且已文档化。**保真破缺集中在运行时接线层**：参照库三套运行时脚本
（DayNightCycleManager / CloudShadowManager / IsometricCameraController）合计下发的
13 个全局，本仓**一个都没人写**——其中 `_GlobalAmbientColor` 是名字错配（rig 下发的是
`_PixelartAmbientColor`），导致 PostLine 模式下环境光项恒 0、未受光面纯黑，属真缺陷；
云影 11 全局与 `_PixelartSnapOffsetUv`（亚纹素平移补偿）属于"设计上待接线的口子"，
shader 护栏使其安全失效，但整特性静默缺席。shader 头注中两处"已并入同一处下发"的
表述与源码不符（见高危 3），是误导性注释，需修正。

严重度统计：**高 3 / 中 3 / 低 3 / 一致与合理差异 12**（逐项对账表内）。

## 高危问题

1. **【高】PostLine 模式环境光恒 0（暗面纯黑）** —— `PostLineToonLit.shader:216` 声明、`:421-422`
   消费 `_GlobalAmbientColor`；全仓 grep 无任何 C# 写入该名。rig 实际下发的环境光走了
   `_PixelartAmbientColor`（`PixelartPath.cs:212`、`PixelartCameraRig.cs:1151`），名字不匹配。
   rig 在场时 `useGlobals` 判据（`:341`，方向长度²>1e-8）恒真 ⇒ 恒走 `_GlobalAmbientColor=(0,0,0)`
   分支，`SampleSH` 回退（`:424`）永不触发。参照语义里环境光是暗面唯一亮度来源
   （`DayNightCycleManager.cs:129-131` 每帧按太阳高度下发梯度色），缺失后未受光面 = albedo×0 纯黑，
   画面观感与参照 demo 出现系统性落差。且 `PostLineToonLit.shader:57-58` 头注"环境光吃
   _GlobalAmbientColor……PostLine 侧并入同一处下发"与源码不符——**下发侧不存在**。
2. **【高】像素完美平移整环缺失（snap 组件 + `_PixelartSnapOffsetUv` 均未实现）** ——
   参照 `IsometricCameraController.cs:133-163` 的两步（视图空间 texel snap + snap 误差

## 2:1 适配正确性附注

Bayer 用画布坐标（`floor(SV_Position.xy / _PixelartSamplingScale)`）在 2:1 下推导正确：
块内 k² 纹素共享同一 bayer 值 ⇒ Point 降采取角纹素后无块内噪声差；全局缺失（=0）时
`max(·,1)` 兜底恰为参照的全分辨率行为。`_PixelartSamplingScale` 由 rig 每帧下发
（`PixelartCameraRig.cs:1124`）与 feature 幂等补发（`PostLineRendererFeature.cs:260`），
两链同源无双全局。SharpUpscale 在整数倍放大时 `fw = 1/k`、过渡窗口恰 1 屏幕像素，
公式无需改动（规格 §8.2 同结论）。画布档位本仓锁 2（`canvasPixelScale=2`，
`PostLine_Renderer.asset`）而参照默认 640×360（1080p ≈1:3）——属本仓全局口径裁决，
不属保真破缺。
