### 1.3 首次跑起来看画面

1. 打开 `pirate-crew/Assets/Scenes/Bootstrapper.unity`（**入口场景**，不是 Battle）
2. 可选：先跑一次资产管线 `PirateCrew → 管线 → 一键构建全部资产与场景`（幂等，可重复跑）
3. Play

**Battle 场景是生成产物**：手工在里面摆的东西会被下一次装配脚本重跑抹掉。
动它之前必须读 [`pirate-crew/Assets/Scenes/README.md`](../../pirate-crew/Assets/Scenes/README.md)
（场景来源 / 装配链顺序铁律 / 改前必跑的转储命令）。

### 1.4 编辑器里能用的 AI 工具（MCP）

工程装了 MCP for Unity v10，ZCode 配了 `unity-mcp` server。**编辑器打开时**可直接用
`manage_scene` / `manage_gameobject` / `manage_asset` / `read_console` / `manage_camera` 操作编辑器。
写完代码先 `read_console` 查编译错误再继续。

两个坑（都实测过，见 [交接与恢复指南.md](交接与恢复指南.md)）：
- bridge **不会在首次打开工程时自启**——报 `No Unity Editor instances found` 时，
  在编辑器里打开 MCP 窗口触发一次 `StdioBridgeHost` 的静态构造即可。
- `manage_camera` 的 `output_folder` **必须显式指定**，否则往 `Assets/Screenshots/` 落图
  （该目录已在 `pirate-crew/.gitignore` 里，但仍不该把临时截图混进 Unity 资产树）。

## 3. 模块边界与依赖规则

规则本身在 [工业级重构总纲.md](工业级重构总纲.md) §3.1 与
[../技术/架构/架构总览.md](../技术/架构/架构总览.md)，此处只说**落到手上的三条**：

1. **边界落在 `.asmdef` 上，不只是目录习惯**。`Scripts/` 下每个模块一个 asmdef
   （`PirateCrew.Core` / `PirateCrew.Gameplay` / `PirateCrew.UI` / `PirateCrew.Campaign` /
   `PirateCrew.CrewManagement` / `PirateCrew.Rendering` / `PirateCrew.SceneArtBake`）。
   违反依赖方向在**编译期**失败（程序集引用不允许）——这是约束能长期成立的关键。
   新增模块目录时要建 asmdef 并接进引用图，否则它会掉进 `Assembly-CSharp` 那个大杂烩。
2. **跨模块通信只走两条路**：`XxxApi` 静态外观（同步、有类型），或 `EventBus`（异步、解耦）。
   禁止 `GameObject.Find`、禁止跨模块裸 `GetComponent`、禁止反向依赖。
3. **不该用 EventBus 的场景**（写错了会吃 GC 或造成顺序问题）：
   同模块内部调用、父子层级生命周期通知、每帧高频数据。

编辑器脚本（`Assets/Editor/**`）落在 `Assembly-CSharp-Editor`，可以引用所有运行时程序集，
但**不要**把玩法逻辑写进 Editor——那部分就没法被测试与无头验证台覆盖。

## 4. 编码规范

规范写进了仓库根的 **`.editorconfig`**（有各条规则的实测统计依据）。要点：

| 项 | 约定 | 实测依据（2026-09-21） |
| --- | --- | --- |
| 缩进 | 4 空格，**不用 Tab** | 0 个 Tab 缩进的 `.cs` 文件 |
| 行尾 | LF | `.cs` 345/363 为 LF |
| BOM | 无 | 0 个带 BOM 的 `.cs` |
| 文件末尾 | 留一个换行 | 抽样全部以 `0x0A` 结尾 |
| 花括号 | Allman（换行后 `{`） | 全仓一致 |
| namespace | 块语法，不用 file-scoped | 292/292 |
| 私有字段 | `_camelCase` | 45 处 vs 1 处 |
| 常量/公开成员 | `PascalCase` | — |
| 行宽 | 上限 120（P99 = 107） | 102486 行的长度分布 |
| 语言 | 注释与提交信息用中文 | AGENTS.md |

**为什么没有格外的格式化器**：Unity 工程里没装 Roslyn 分析器，`.editorconfig` 的命名规则在
Rider/VS 里是提示、Unity 编译时**不产生告警**。所以靠人（与 AI）遵守，不靠 CI 拦。

**中文注释是主要的知识载体**：本项目大量关键结论（为什么这么写、踩过什么坑）写在类/方法的 XML 注释里，
改代码前先读所在文件的注释，往往比读实现更快。

## 5. 事件契约怎么加

事件名是字符串键，**没有编译期检查**——拼错一个字母就是"发了但没人收到"的静默故障，
这是本项目最贵的一类 bug。所以加了新事件要四件事一起做：

1. 在所属模块的 `XxxEvents` 常量类里加 `public const string` 常量
   （`Core/SceneEvents.cs` / `Core/SaveEvents.cs` / `PirateCrew/Battle/BattleEvents.cs` /
   `Campaign/CampaignEvents.cs` / `CrewManagement/CrewManagementEvents.cs`）
2. 同一个类的 `RegisterContracts()` 里加一行 `Add<TPayload>(常量)`
   （无载荷事件用 `AddNoPayload(常量)`——"约定无载荷"与"没登记"必须能区分，别用 `null`/`object` 搪塞）
3. 在 [../技术/架构/EventBus事件契约.md](../技术/架构/EventBus事件契约.md) 的表格里补一行
   （事件名 / 载荷类型 / 发布方 / 订阅方）——**禁止散落魔法字符串**
4. 载荷类型变更属**破坏性变更**：登记表与所有订阅方必须同步改

漏了第 2 步会被 `Tests/Core/EventCatalogTests` 直接判失败（反射扫全仓 `*Events` 常量类，
断言"代码里用的键都已登记"且"登记表没有僵尸项"）。机制细节写在
`pirate-crew/Assets/Scripts/Core/Events/EventCatalog.cs` 的类注释里，改之前读它。

## 6. 测试怎么写、怎么跑

### 6.1 两条测试通道（这是本项目最重要的效率杠杆）

| 通道 | 跑什么 | 多快 | 要不要 Unity |
| --- | --- | --- | --- |
| **无头验证台** `external/m2-harness/` | 纯 C# 逻辑（Data / Combat / Battle 组装层） | **秒级** | 不要 |
| **Unity batchmode** `-runTests` | EditMode 全量 + PlayMode | 分钟级，且独占 `Library/` 锁 | 要 |

**分层是刻意的**：核心逻辑写成纯 C# 静态类（可无头测），MonoBehaviour 只做"拿引用、驱动、调纯函数"的薄壳。
写新逻辑时沿用这个分层，否则你会失去秒级迭代能力。

### 6.2 无头验证台

```bash
cd /f/VSCode/pirate-crew-3d-unity
H="$TEMP/pc3d-harness-<你的域>"
mkdir -p "$H" && cp external/m2-harness/M2Harness.csproj "$H"/    # 自己的副本放系统临时目录
cd "$H"
dotnet build M2Harness.csproj -p:HarnessScope=Runtime     # 只编译运行时源码
dotnet build M2Harness.csproj -p:HarnessScope=DataEditor   # 运行时 + Assets/Editor（抓编辑器脚本编译错误）
dotnet test  M2Harness.csproj -p:HarnessScope=Combat      # 跑测试
```

| `HarnessScope` | 编译范围 | 用途 |
| --- | --- | --- |
| `All` | `Scripts/**` + EditMode 全部测试（**显式排除** `Tests/PlayMode/`） | 全量体检 |
| `Data` | Core + `PirateCrew/Data` + `Tests/Data` | 数值层 |
| `Combat` | Core + `PirateCrew/Combat` + `Tests/Combat` | 战斗纯逻辑 |
| `Battle` | Core + Data + Combat + Battle + UI + Campaign + CrewManagement + SceneArt + Visual + Fx + Audio + Water + Ambient + Settings + `Tests/Battle` | 战斗组装层 |
| `Rendering` | Core + `PirateCrew/Rendering` | 描边 RendererFeature（需 URP 程序集） |
| `Runtime` | `Scripts/**` | 纯运行时编译检查 |
| `DataEditor` | `Scripts/**` + `Assets/Editor/**` | **进 Unity 之前抓编辑器脚本的错误** |

**能力边界（务必理解，别误判成回归）**：`GameObject` / `MonoBehaviour` / `ScriptableObject` 的实例化
走原生 `ECall`，脱离 Unity 运行时必抛 `SecurityException`。所以本台里 `SaveManagerTests` /
`SceneLoaderTests` / `MinimapWorldChartTests` 三个 fixture（36 条）**必然失败**，已被 csproj 默认过滤掉
（它们照常参与编译，只是不执行，由 Unity batchmode 收口）。

**为什么每个 agent 拷一份副本**：csproj 的 `bin/` 按 `HarnessScope` 隔离，但 `obj/` 是共享的，
多 agent 并发会抢；副本放系统临时目录（`$TEMP`）就互不干扰——`external/` 只放母本。
各 agent 任务线收尾即删。

### 6.3 Unity 侧测试

```bash
U="F:/Unity/2022.3.62f1c1/Editor/Unity.exe"
P="F:/VSCode/pirate-crew-3d-unity/pirate-crew"

# EditMode
"$U" -batchmode -nographics -projectPath "$P" -runTests -testPlatform EditMode \
  -testResults "$TEMP/pc3d-test-results.xml" -logFile -

# PlayMode（把 EditMode 换成 PlayMode）
```

两条纪律：
- **跑测产物落系统临时目录**（`$TEMP`），不要落进 `external/`——那是工作台，跑测产物禁入。
- **跑完 PlayMode 后检查 `ProjectSettings/EditorSettings.asset`**：实测（2026-09-13）PlayMode
  测试会把 `m_EnterPlayModeOptionsEnabled` 从 `0` 改成 `1`（关掉域重载 + 场景重载），
  这会**静默改变静态状态语义**。不是本项目想要的默认值 → 提交前
  `git checkout -- pirate-crew/ProjectSettings/EditorSettings.asset` 还原。

### 6.4 测试放哪、叫什么

- 位置：`pirate-crew/Assets/Tests/<域>/`（`Core` / `Data` / `Combat` / `Battle` / `Campaign` /
  `CrewManagement` / `UI` / `Settings` / `WorldMaps` / `Visual` / `SceneArt` / `Audio` / `Ambient` /
  `Fx` / `Water`），PlayMode 用例单独放 `Tests/PlayMode/`。
- 程序集：`PirateCrew.Tests`（EditMode，`includePlatforms: [Editor]`，`defineConstraints:
  [UNITY_INCLUDE_TESTS]`）、`PirateCrew.PlayModeTests`。新增测试目录不需要新建 asmdef。
- 命名：`<被测类型>Tests.cs`；断言失败信息要能直接定位（写清期望值、实际值与口径出处）。
- **不删测试**：测试是重构的安全网。允许改测试以匹配新结构，**不允许为让门禁变绿而删断言**。

## 7. 门禁命令清单

一次交付前按顺序跑（前两条秒级，越便宜越先跑）：

| # | 判据 | 命令 | 通过线 |
| --- | --- | --- | --- |
| 1 | 仓库静态门禁 | `python .github/scripts/repo_gates.py all` | exit 0（警告不算失败） |
| 2 | 运行时编译 | `dotnet build M2Harness.csproj -p:HarnessScope=Runtime` | 0 error |
| 3 | 编辑器脚本编译 | `dotnet build M2Harness.csproj -p:HarnessScope=DataEditor` | 0 error |
| 4 | 纯逻辑测试 | `dotnet test M2Harness.csproj -p:HarnessScope=All` | 0 failed |
| 5 | 全量 EditMode | Unity `-runTests -testPlatform EditMode` | 0 failed，总数 ≥ 重构前基线 |
| 6 | PlayMode 冒烟 | Unity `-runTests -testPlatform PlayMode` | 0 failed 且 skipped = 0 |
| 7 | 出包 | [构建与发布手册.md](构建与发布手册.md) §1.2 | exit 0 + 产物存在 |
| 8 | Shader 编译 | 编辑器/播放器 Console | 0 shader error |

无头验证台 Combat 132、Data 33、Battle 377、All 1130 通过 0 失败。

**一次只跑一个 Unity 进程**（`Library/` 锁独占）。多 agent 并行时，涉及 Unity 的验证由协调者串行执行，

## 8. 常见任务操作手册

> 每个配方都列"改哪几个文件 → 跑什么 → 怎么验"。**改之前先读目标文件的类注释**，
> 里面通常写着"为什么这样设计"和踩过的坑。

### 8.1 加一把武器

数值真源是纯 C# 的 `WeaponCatalog`（可无头测试），SO 资产只是它的序列化投影——
**不要直接改 `.asset`**，生成器会覆盖掉。

1. `Assets/Scripts/PirateCrew/Data/WeaponId.cs`：加枚举值
2. `Assets/Scripts/PirateCrew/Data/WeaponCatalog.cs`：在 `_all` 列表里加一条 `new WeaponStats(...)`，
   逐字段对齐逆向文档 §5.2「武器总表」；**表里写「—」的格子落 `0` 并在 `Remark` 里注明该格原本是「—」**
   （别让它被误读成"数值 0"）
3. 若触发条件是新语义：`WeaponTrigger.cs` + `Combat/WeaponTriggerRules.cs`（纯函数层，这里才放逻辑）
4. 生成 SO 投影：菜单 `PirateCrew/Data/生成 M2 数值资产` → 产出 `Assets/Data/Weapons/<id>.asset`
5. 测试：`Tests/Data/`（数值口径）+ `Tests/Combat/`（触发/爆炸规则）
6. 验：`dotnet test M2Harness.csproj -p:HarnessScope=Data` 与 `-p:HarnessScope=Combat`

### 8.2 加一个关卡 / 一张海图

关卡数据走 `LevelData`（纯 C# 快照）这一统一载体：出战计划（`LevelGeometry.BuildBattlePlan`）
只认它，不关心数据来自手写海图还是样板关。

1. 世界海图：`Assets/Scripts/PirateCrew/Battle/WorldMaps/WorldMapCatalog.cs`
   （样板三关的宣传层数据在 `PirateCrew/SceneArt/ShowcaseLevels.cs`）
2. 关卡几何只有**逻辑格**坐标，1 格 = `LevelGeometry.TileWorldSize` 世界单位，
   运行时世界坐标由 `LevelGeometry.WorldPosition` 换算。
   **动坐标/相机/投掷/爆炸之前必读** [../设计/M2-3D空间模型对齐.md](../设计/M2-3D空间模型对齐.md)
   （XZ 竞技场、重力沿 -Y、地面顶面 y=0；Godot 出空间结构、Flash 出数值的分工）
3. 重建场景：`PirateCrew/Scenes/重建 Battle 战斗场景`
   （⚠ 破坏性重建，之后必须按 [`Scenes/README.md`](../../pirate-crew/Assets/Scenes/README.md)
   的装配链顺序补跑小地图接线）
4. 测试：`Tests/Battle/`（几何/地形）；改前后各跑一次 `SceneWiringAudit` 转储并 diff，
   **每条差异都必须能解释**
5. 【提案/待定】数据外化（轨道 B）正把关卡/海图改成 SO 资产（`Assets/Data/Levels/`），
   落地后以资产为真源、Catalog 退为迁移器——读到与上面不符时以 `Assets/Data/` 与
   [../技术/架构/架构总览.md](../技术/架构/架构总览.md) 为准

### 8.3 加一个跨模块事件

见 §5（四步 + 反射测试兜底）。**不要**为了图快在 UI 层直接 `GetComponent` 到战斗层对象取数据。

### 8.4 加一个 UI 屏

UI 现状是「**控制器在 `Scripts/UI/`，场景里的 UI 树由装配脚本幂等重建**」：

1. 控制器：`Assets/Scripts/UI/<屏名>Controller.cs`（namespace `PirateCrew.UI`）
   —— 参考 `MainMenuController.cs` / `LevelSelectController.cs` / `CrewManagementController.cs`
2. 构建 UI 树的辅助：
   - 运行时建控件用 `M3UiBuilder`（M3 各屏共用：TMP 文本、`SketchPanel`/`SketchButton` 手绘控件、令牌配色）
   - 编辑器侧装配用 `Editor/MenuUiBuilder.cs`（菜单类界面的共享工具：中文字体接入、程序化九宫格 Skin 落盘、控件工厂）
   —— **配色一律取 `UiTheme`/`StickTokens` 令牌，禁止散落色值**；文本统一 `TextMeshProUGUI`
3. 文案进 `Assets/Scripts/UI/UiStrings.cs`（中文硬编码，尚无本地化方案）
4. 若屏是独立场景：场景按「手摆 + 装配脚本可重建」的既有口径处理
   （`Editor/SceneSetup.cs` / `Editor/M3SceneSetup.cs`），
   并把场景名登记进 `Core/SceneNames.cs` —— 漏登记会被构建预检拦下
   （`BuildScenes.Validate` 会断言"`SceneNames` 声明的场景都在发行包里"）
5. 测试：`Tests/UI/`；纯逻辑（布局/文本规则）走无头验证台，需要真实 UI 对象的走 EditMode

### 8.5 加一个编辑器工具

1. 放 `pirate-crew/Assets/Editor/`（namespace `PirateCrew.EditorTools`，**文件名 = 类名**）
2. 入口给**两个**：`[MenuItem("PirateCrew/<域>/…")]` 供人点，一个 `public static` 无参方法供
   `-executeMethod` 无头调用（参考 `Editor/Build/BuildScript.cs` 的写法：菜单与 CLI 调同一套逻辑）
3. **幂等**：所有生成器/装配器都必须"重复跑结果相同"——本项目的菜单会被反复重跑
4. 写 `.meta`？不用手写，Unity 会生成；但**新文件必须配对提交 `.meta`**，
   仓库门禁会检查（`python .github/scripts/repo_gates.py hygiene`）

### 8.6 出包

读 [构建与发布手册.md](构建与发布手册.md)。一句话版：菜单
`PirateCrew/Build/一键出包 Windows64（Release）`，或命令行
`-executeMethod PirateCrew.EditorTools.BuildSystem.BuildScript.BuildFromCommandLineArgs`。

### 8.7 改 shader / 加渲染效果

**必须**先读 [../技术/渲染/描边Shader调试.md](../技术/渲染/描边Shader调试.md)：
URP 里加额外 Pass 必须给它一个独立且未被占用的 `LightMode`（本项目的描边 Pass 用 `SRPDefaultUnlit`），
复用 `UniversalForward` 会被 URP **静默丢弃**（本体正常、就是没效果、Console 无报错）。
改完的唯一算数标准是**在有渲染路径的编辑器里 `read_console` 看到 0 条 shader error**。
