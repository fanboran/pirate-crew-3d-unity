> **审计基准**：commit `5f2079c`（2026-09-17）+ 工作树未提交改动（47 个 WorldKit FBX `.meta`
> 材料导入设置调整）。行号引用以该基准的文件内容为准。
> **方法与范围**：静态代码审计——水面 shader 与材质、水体运行时（OceanRig / WaterSimulationDriver /

> 玩法层对水的消费面。不含编辑器实拍观感判定与逐地图视口走查。
> **未覆盖区域**：编辑器实拍观感、PlayMode 帧耗与 Profiler、SSAO/阴影距离改动后的
> 实机画质对比、各世界地图逐图视口验收（需实拍轮）。

## 一、总判

水面代码本身（6 波 Gerstner、白帽、太阳光路、背光透射、屏幕空间折射、假焦散）完整度不低，
问题不在单一 shader，而在**系统之间没有"谁在哪个距离对玩家可见"的共同契约**，外加一处致命接线 bug：

1. 水模拟被 M4 接线整条杀死（§二.1，实锤 bug）；
2. 相机 / 雾 / 海洋三套尺度纲互相矛盾，"有内容的地方看不见，看得见的地方没内容"（§二.2）；
3. 玩法层与水彻底解耦，模拟输出零消费（§二.3）；
4. 光照链贫瘠：单方向光 + 平铺环境光、无 SSAO、无反射探针、阴影距离小于全景视距（§二.4）；
5. 旗舰视图（世界地图）走的是最素的灰盒路径，地形 shader 的积累吃不到（§二.5）；
6. 逐症状打补丁的路径依赖（光路方位门、不透明度 0.94 等）（§二.6）。

## 二、审计发现（证据链）

### 1. 实锤 Bug：水模拟在 M4 大海域模式下被整条杀死

- 场景 `Water` 物体（Battle.unity，fileID 2002651020）一身三职：`WaterSimulationDriver`（2D 波动方程模拟）、
  `WaterTessellator`（旧水面网格）、旧水面 MeshRenderer。
- `BattleController.waterPlane` 序列化指向它的 Transform（Battle.unity:17740 → 2002651020）。
- M4 接线 `SetupWorldMapEnvironment()` 为退役旧水面把**整个 GameObject** 关掉：
  `BattleController.cs:343-44`：`waterPlane.gameObject.SetActive(false)`。
- `WaterSimulationDriver.OnDisable` 随即把全局 `_WaterSimEnabled` 置 0
  （WaterSimulationDriver.cs:155-163）→ 新 `PirateOcean.shader` 的高度场路径
  （爆炸涟漪 / 泡沫累积 / 障碍绕射 / 水花注入）全部静默跳过。
- 新 shader 文件头声称"WaterSimulationDriver 不需要任何改动即可注入"（PirateOcean.shader:27-29），
  但接线层让这句话永远为假。

### 2. 三套尺度纲互相矛盾（相机 / 雾 / 海洋）

| 子系统 | 现状数值 | 出处 |
| --- | --- | --- |
| 相机全景档 | 距离 = clamp(跨度×0.55, 60, 160)，跨度 150–260 → 相机离图心 82–143u | BattleCameraController.cs:195-208 |
| 场景线性雾 | 50 → 280u 全饱和 | AmbientTimeOfDayCatalog.cs:140-146（正午档；场景烘焙同值） |
| 长涌包络 | 保护半径 = 竞技场半径+24，圈外再爬 260 才全涌 → 全涌起点 390–468u | OceanRules.cs:89-107 |
| 位移远淡 / 地平线融合 | 2000–3000 / 2600–3900 | Ocean_Water.mat:39-40 / 57-58 |

定量（55° 俯角、FOV 60）：相机高 ≈ 距离×sin55°；画面上缘可见海面在 200–350u 外 →
雾化 66–100%。**玩家看到的整片海越靠上越是一张 #B0D4F1 纯色板；全涌起点在所有世界地图上
都超出画面可见范围**。位移淡出与地平线融合的远场参数在 280u 雾终点面前是纯摆设。

网格侧：中场环带环宽 ×1.25 几何增长，300u 处环宽已 ~45u，`OceanGeometricFade`
（PirateOcean.shader:443-447）把包括 λ120 长涌在内的所有波的几何位移在 ~500u 前归零；
细节法线 600→1600 淡出 → 200–600u 的中景海面既无位移又无法线。

### 3. "仿真"在玩法层没有任何消费者

- `Water/` 模块之外没有任何代码采样波高；落水判定、单位立足、船只姿态全部使用标量
  `LevelGeometry.WaterSurfaceY`（固定 Y 阈值）。
- 船和单位钉死不动，chop（4 波合计振幅 ±0.278u）在船体水线上下往复穿模。
- 模拟参数全部为旧近景竞技场调的：域 128u、域心 (50,17)、边缘涌浪振幅 0.04u、水花 0.12u
  （WaterSimulationDriver.cs:58-92）——厘米级扰动在 82–143u 相机下不足一个像素；
  域中心和尺度绑死在旧关卡目录，与世界地图 150–260u 跨度对不上。
- 结论：仿真写出来了 → 被接线禁用 → 幅度对新相机不可见 → 域对不上新地图 → 玩法层零消费。

### 4. 光照链贫瘠（画面"假"的根因）

- 自定义 shader（PirateSurface / PirateTerrain / Outline）只取主方向光、不吃附加光
  （AmbientDirector.cs:92-95 注释自述），灯笼点光默认关。
- 渲染器唯一 RendererFeature 是自研描边——**没有 SSAO**（PC_Balanced_Renderer.asset）；
  URP 资产关闭反射探针混合（PC_Balanced_URPAsset.asset:46），场景 0 个反射探针。
- 间接光 = 1.55 强度单方向光 + 0.85 强度 Trilight 平铺环境光 → 无遮蔽差异、无反射变化。
- 主光阴影距离 100u（PC_Balanced_URPAsset.asset:48）< 全景相机距离 82–143u →
  拉远后主战区真实投影整体滑出阴影级，只剩 0.45 透明度假 blob（ContactShadowDecal）兜底。
- PirateTerrain r3→r6 修复史（侧壁暖偏置 / 格缝暖灰）自述"外科手术式修正——不动全局环境光/光照链路"，
  根因从未处理。

### 5. 旗舰视图走最素的地形路径

- 世界地图岛体 = Unity Cube 图元按 3 色色板平涂（WorldMapComposer.cs:171-199 `BandMaterial`，
  URP/Lit 纯色）。PirateTerrain 的沙草岩高度坡度混合、域扭曲 fBm 细节贴图、湿沙潮痕带
  全部留在旧瓦片路径，世界地图吃不到。
- kit 甲板与灰盒站面同高 z-fighting 靠整体下沉 0.06u 掩盖（WorldMapComposer.cs:71-74）；
  每站面仅 2–4 个程序化装饰件。

### 6. 症状级补丁的路径依赖

光路方位门（PirateOcean.shader:863-869：整屏饱和 → azimuth² 硬门控 → 背对太阳的半圈轨道
海面完全没有光路）、不透明度 0.94（Ocean_Water.mat:60）——都是单点拍苍蝇。

## 三、修复批次（本节数值除注明外均为【提案/待定】，待实拍验收）

### 统一契约：「可见海域预算」

> 全景相机 ≤160u；55° 俯角下画面可见海面斜距 ≤~350u；正午雾 150→1200；
> 全涌起点（图心系）≤310u；地平线融合 1000→1400（雾饱和前收干净海天线）。
> 各批次参数必须与该表自洽；后续调参先改这里再改代码。

### 批次 A：救活水模拟（批次域：Water/*.cs、BattleController.cs、Water 测试）

1. `SetupWorldMapEnvironment` 不再 `SetActive(false)` 整个 waterPlane：改为**定向禁用**
   MeshRenderer 与 WaterTessellator，保持 GameObject 活跃让 `WaterSimulationDriver` 常驻。
2. 驱动新增域重配置 API（域心 = 世界地图图心；域边长 = `WaterSimRules` 纯函数，clamp [128,256]），
   重配时重建场与障碍掩码并重发布全局。
3. EditMode 测试覆盖域重配置纯函数。

### 批次 B：可见性契约·海洋侧（批次域：OceanRules.cs、OceanGridRules.cs、OceanRulesTests.cs、PirateOcean.shader、Ocean_Water.mat、Editor/WaterAssetBuilder.cs）

- `ShorePadding` 24→12、`SwellRampWidth` 260→110 → 全涌起点 = 竞技场半径+122 ≈ 228–306u（进画面）。
- `RingGrowth` 1.25→1.15 → 300u 处环宽 ~21u，λ120 长涌在包络起点即有完整几何解析
  （shader `_GridRingGrowth` 默认值与材质值、C# 镜像三处同步）。
- 地平线融合 2600→3900 改 1000→1400（mat + shader 默认值 + AssetBuilder 若有镜像）。
- 同步更新文件头 E/H 段设计与钉旧值的测试。

### 批次 C：光照资产（批次域：Assets/Settings/URP/*.asset、Assets/Editor 新安装脚本）

- `m_ShadowDistance` 100→224（≥ 全景 160 + 余量；级联 4 档比例不动）。
- Balanced Renderer 加装 URP `ScreenSpaceAmbientOcclusionRendererFeature`
  （Editor 安装脚本落盘，可重跑幂等）：Depth 源、强度 ~0.55、半径 ~0.55【提案/待定】。
- 已知边界：自定义 Pirate shader 不含 `_SCREEN_SPACE_OCCLUSION` 关键字，SSAO 只作用于
  URP/Lit 物件（kit 道具、站面灰盒）——正是当前最"塑料"的一批。

### 批次 D：可见性契约·雾侧（批次域：AmbientTimeOfDayCatalog.cs、BattleSceneLighting.cs、AmbientDirector.cs、Battle.unity 的 RenderSettings、相关测试）

- 正午雾 50→280 改 **150→1200**；黄昏 44/240 → 130/1000；阴云 36/200 → 110/800【提案/待定】。
- 同步场景烘焙 RenderSettings 与 `BattleSceneLighting` 写值处；更新钉值测试。
- `AmbientDirector.Apply` 登记 `RenderSettings.sun = sunLight`（修复场景 m_Sun 为空的兜底链）。

### 批次 E：站面材质 PirateTerrain 化（批次域：WorldMapComposer.cs）

- `BandMaterial` 从 URP/Lit 纯色改为 `PirateCrew/PirateTerrain`，继承其沙/草/岩高度坡度混合、
  细节噪声、湿沙带参数（对齐 BattleSceneLighting 地形材质生成处的口径），
  保留三档色板与 `visualDrop` 防 z-fight 逻辑。

### 批次 F：水面浮沉表现（批次域：OceanRig.cs、Water/ 新文件、WorldMapComposer.cs、Water 测试）

- 新增纯 C# `WaterSurfaceSampler`：合成 长涌×包络 + chop×几何淡出 的高度采样
  （复用 WaterRules/OceanRules 现成镜像，几何与 shader 同式）。
- 新增 `FloatingPropView`（MonoBehaviour，纯表现）：对漂浮 kit 道具（放置 y ≈ WaterSurfaceY
  且名字不含 "Beached"）做 Y 起伏（clamp ±0.5u）与微倾（≤2°）；不参与任何玩法判定，
  不移动碰撞体，`isStatic` 置 false 以免静态合批吞掉位移。
- EditMode 测试钉 sampler 数值与放置资格判定。

### 验证门禁（AGENTS 图形学铁律）

- 每波次合并后：batchmode 开工程 → log `error`/`shader error` 0 条 → EditMode 全绿；
  全部完成后跑 PlayMode。
- **shader/参数改动的观感验收必须实拍**（编辑器有渲染路径时按 export/<功能名>-debug 惯例截图），
  本轮只做结构与契约修复 + 数值提案，美术终审归用户。
