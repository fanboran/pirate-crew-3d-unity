## 二、新发现（本轮增量）

### P1（用户可感知，建议优先）

**N1. WorldMapComposer 回退材质 `new Material(shader)` 无空判——旧 P1-6 的残留层，崩溃路径仍在**
`PirateCrew/Battle/WorldMaps/WorldMapComposer.cs:388-389`（`CreateFallbackLitMaterial`）。主路径修复后，回退恰在「Pixelart 物体 shader 缺包」时触发，而 r3 实测结论（BattleTerrainView 旧注释载明）URP/Lit 在播放器构建不保证入包——回退目标与故障源是同一个 shader。触发即 `ArgumentNullException` 中断世界图装配。修法（提案/待定）：shader 为 null 时返回 null 让站面跳过，或换 `Sprites/Default` 兜底。

### P2（泄漏 / 渲染链风险）

**N2. 叠加相机退出栈缺失，重开后 cameraStack 残留已销毁条目**
`PirateCrew/Rendering/Pixelart/PixelartCameraRig.cs:282-287` OnDisable `DestroyImmediate(_overlayCamera.gameObject)` 但从不 `cameraStack.Remove`；`:476-483` 再 Enable 时新建实例 Add（Contains 对新实例为 false），栈中旧条目指向已销毁相机——URP 相机栈含假引用属未定义行为路径。触发条件：运行期禁用→重新启用挂本 rig 的相机。附带：`:284-285` 播放期用 `DestroyImmediate`，与本文件 `:693-701` 自家约定不一致。

**N3. 像素字体 Point 纠偏件只保护首个解析的字体，另一档可复发「重影」**
`UI/Skin/UiKit.cs:531-538` `EnsureAtlasPointFilter` 是单静态件（`if (_atlasFilter != null) return;` + 单字体字段），但有两个入口——`PixelFont12()`（`:135`，FusionPixel12）与 `PixelFont10()`（`:146`，ArkPixel10）。两套字体同屏混用，只有先解析到的被盯防；后到字体的 TMP 动态图集一旦重建（重置 Bilinear），`PixelAtlasPointFilter` 的逐帧纠偏不覆盖它——`4bf6f1c` 修的半格渗色「重影」可能在另一档字体复发且难排查。修法（提案/待定）：纠偏件改持字体数组。

**N4. 派生材质字典无释放路径**
`PirateCrew/Rendering/Pixelart/PixelartContentConverter.cs:47、225` `_derived` 缓存运行期 `new Material` 的派生材质，类无 OnDestroy/Dispose；换关重建 Converter 后旧材质失引用（无 hideFlags，靠下一次 UnloadUnusedAssets 兜底）。同域 rig/各 Feature 都有显式释放，唯它缺席——照 AmbientLibrary 模式补即可。

**N5. CollectPiratesInRadius 每次分配 Collider[]（旧 §四.2 的存量部分）**
`PirateCrew/Battle/BattleController.cs:790-791`。tidalWave/火焰/锚下落存续期每物理步一次分配；引信查询已降到 25Hz，分配未消。改预分配 `GetContacts`/`OverlapSphereNonAlloc` 即可。
