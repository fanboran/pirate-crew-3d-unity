# 审计目录

> 本目录是**全部类型审计报告的统一归档处**：架构、代码质量、测试、性能、资产管线、场景接线……
> 凡是「按检查单对工程现状做体检、产出问题清单与证据」的文档都放这里；
> 设计文档、交接文档、逆向文档不在此列（各归各的既有位置）。
> **已过期的报告移入 [归档/](归档/)（见下「归档规范」）**，本索引只列仍在生效的审计。

## 归档规范

- 一份审计一个文件，命名 `<类型>审计报告.md`；同一类型做第二次复审时加日期后缀
  （如 `架构审计报告-2026-MM-DD.md`），旧报告保留不删，审计天然是时点快照。
- 每份报告**必须**写：审计基准（commit 哈希 + 日期）、方法与范围、未覆盖区域；
  代码引用一律 `文件:行号`，保证可核对。
- AI 生成的审计结论与修复建议一律标注「提案/待定」，未经用户确认不得被其他文档当作已定事实引用
  （AGENTS.md 文档规范）。
- **过期报告移入 [归档/](归档/) 并在文首加 `⛔【已过期】` 横幅**：判据是①所审对象已被整批删除/整体重写，
  或②已被同类型更新报告逐条核销取代。归档只改位置与横幅，**正文一字不动**（它是时点快照）；
  归档后其他文档引用它必须改指 `审计/归档/` 路径，且不得再当现行依据。
