## 任务是什么

把间接光从「Trilight 三色平铺」升级为「天空盒驱动（Skybox Ambient）」：环境光有方向与
色彩变化、自研 shader 吃到环境光，三档氛围（正午/黄昏/阴云）各配天空参数，并联动重调
太阳光路/雾色。这是视觉审计认定的"画面假"根因中最后未处理的一条
（批次 C SSAO + 批次 E 站面材质已缓解表面层次，环境光本身还没动）。

## 为什么（审计证据）

  无遮蔽差异、无反射变化、PirateTerrain 的修复史全是"外科手术式修正"绕开全局环境光。
- §四 遗留 #6 明确"环境光仍为 Trilight 平铺（未切天空盒驱动）……进一步升级另立批次"
  ——本对话就是那个批次。

## 前置条件

**主协调线的视觉批次 A–F 实拍验收已转正**（A–F 的【提案/待定】数值：雾距、包络、SSAO、

## 技术要点（难度 ★★★ 的原因，动手前逐条核对现状）

1. **自研 shader 不吃环境光**：PirateSurface / PirateTerrain / Outline 只取主方向光、
   不吃附加光（`AmbientDirector.cs:92-95` 注释自述）。切 `RenderSettings.ambientMode =
   Skybox` 后，URP/Lit 物件（kit 道具、站面灰盒）自动吃到球谐（SH）环境光，**自研
   shader 不会**——不补采样就是"一半亮一半暗"的场景割裂。必须给 PirateSurface /
   PirateTerrain（优先）与 PirateOcean（次之）补 `SampleSH`（URP 内置）或按
   `RenderSettings.ambientSkyColor/EquatorColor/GroundColor` 三色插值的环境光项。
2. **天空盒本体**：不必上复杂天空——程序化 gradient skybox（三色渐变 Shader + 每档一组
   参数）即可起步，与低多边形风格匹配；后续可换 Procedural/Skybox Panoramic。
   海面本身由 PirateOcean 绘制，天空盒主要影响环境光采样与海天线以上的天穹。
3. **太阳光路联动**：PirateOcean 的太阳光路有方位门（`PirateOcean.shader:863-869`，
   azimuth² 硬门控）——天空盒里的太阳位置必须与 `AmbientDirector` 的方向光方位一致，
   否则"天上一轮日、海上两条光路"穿帮。
4. **三档氛围参数化**：`AmbientTimeOfDayCatalog`（正午/黄昏/阴云）现有太阳方向/颜色/雾距
   三元组——扩展为含天空盒三色 + ambientIntensity 的五元组，并守住**三方一致铁律**
   （目录 == `Editor/BattleSceneLighting.cs` 烘焙写值 == `Battle.unity` 场景值，现有钉值
   测试盯着，动一处同步另两处并扩测试）。
5. **不许倒退的已定值**：阴影距离 224、SSAO（Balanced Renderer，`Editor/BalancedSsaoInstaller.cs`
   安装）、雾 150→1200/130→1000/110→800（「可见海域预算」契约，`docs/审计/视觉审计报告.md` §三）。

## 工作分解

1. gradient skybox shader + 材质（放 `Assets/Art/Shaders/Sky/`），三档各一组三色参数【提案/待定】。
2. 自研 shader 补环境光采样项（PirateSurface → PirateTerrain → PirateOcean 顺序；
   PirateOcean 的影响主要在间接水色，最后调）。**改 shader 必须过编译门禁**：
   batchmode log 里 "shader error" 0 条才算数（静态核对不算，AGENTS 图形学铁律）。
3. `RenderSettings.ambientMode=Skybox` + `ambientIntensity` 接入 AmbientDirector.Apply，
   三档参数入目录 + 三方一致测试扩展（新钉值测试）。
4. 光路方位门与天空盒太阳对齐校验（同 azimuth 源）。
5. 实拍三档 ×（全景/近景/逆光位）对比图，存 `export/ambient-skybox-debug/`（README 写
   每张图预期，沿 `export/outline-debug/` 模板），用户终审。
