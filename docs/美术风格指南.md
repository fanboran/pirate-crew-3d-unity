# 美术风格指南（Art Bible）

> **这份文档解决什么问题**：Unity 2022.3 重制版目前只有"能跑"的灰模——单位是一个裸立方体
> （`Assets/Prefabs/PirateCrew/PirateBase.prefab:47` 引用的是内置 Cube `fileID:10202`），
> 地面/水面/单位全是同一套平滑度 0.5 的纯色 URP Lit 材质，没有光照设计、没有后处理、没有造型语言。
> 本文定义**风格化写实（Stylized PBR）**下的色彩、材质、光影、造型、可读性与验收判据，
> 是后续所有美术实现（场景、材质、道具、UI）的唯一口径。
>
> **与 GDD §10.4 的关系（重要）**：GDD §10.4（`gdd.md:771-876`）写的是 **纯 cel 渲染 + 禁用 Glow/SSAO**
> 的旧规范。本轮用户明确要求"要有 PBR 材质与有足够美术效果的场景，光影氛围要讲究"，
> 因此本文件**覆盖** GDD §10.4 的渲染方式条款，但**沿用其调色板**（`gdd.md:812-835`）作为色彩基准。
> 旧规范中仍然有效的部分（描边提升可读性、调色板、UI 暖金棕风格）继续保留并在文中标注。

## 1. 视觉定位

### 1.1 一句话印象

> **玩家第一眼应该看到**：阳光从左上斜切进来的加勒比小岛——暖白沙地、饱和草坡、深蓝海水，
> 天海之间有一条被雾柔化但**有内容物**的地平线；两台（红/蓝）颜色鲜明、戴着头巾与三角帽、
> **有明显轮廓线**的小海盗对峙站在岛上，脚下的**接触阴影**把他们钉在地面，而不是"浮着"。
> 相机 45° 俯视、距离约 18 单位，整岛尽收眼底。

判定"愿不愿意玩"的第一观感三要素（**AI 提案**，作为用户"会不会想玩"的拆解）：
① **不空**——地面有细节层次（沙→草→岩过渡、棕榈、掩体、宝箱），天上有云/远景；
② **不糊**——单位有清晰剪影与描边，两队在任意角度一眼分得开；
③ **不假**——有方向明确的阳光、接触阴影、水面反射、远处雾，材质粗糙度有区分（不是一片塑料）。

### 1.2 风格化边界：哪里写实、哪里夸张

| 维度 | 写实（PBR 承担） | 夸张（风格化承担） | 标注 |
|------|------------------|--------------------|------|
| 光照 | 单一主方向光、软阴影、ACES 色调映射、物理衰减 | 阴影不追求全黑写实，暗部靠冷色环境光托底（可读性优先） | 【AI 提案】 |
| 材质 | URP Lit 的 Metallic/Smoothness/法线细节、反射探针 | 粗糙度分区**夸张化**（布料极哑 0.12 / 金属 0.45），让材质一眼分得出 | 【AI 提案】 |
| 造型 | 比例可信（头身比、重心、衣服包裹关系） | 部件几何体块面化、头略大、手持物放大 10-20% 保可读 | 【原始诉求】+【AI 提案】 |
| 颜色 | 受光/背光有明度变化 | 高饱和 albedo、色相分离度远超真实物体（沙/草/水互不接近） | 【AI 提案】 |
| 轮廓 | — | 保留 inverted-hull 深色描边（从 cel 时代继承，服务可读性） | 【依据 `PirateOutline.shader:11-90`】 |
| 特效 | 爆炸/水花有体积与光照反馈 | 爆炸可用手绘序列帧（GDD 旧规范），轨迹线用纯色 Neon 蓝 | 【依据 `gdd.md:844-855`】 |

**边界红线**：不做写实贴图堆砌（照片级 PBR 贴图会与"低多边形块面"造型打架，反而显脏）；
也不回到"纯色平涂"（那是 GDD 旧规范，观感已被用户否定为"太低质感"，见 `程序化美术升级提案.md:5-6` 同理结论）。

### 1.3 为什么不回到纯 cel

纯 cel 的观感上限"一眼望到头"（同 `程序化美术升级提案.md:5` 对纯色平涂的结论），且已被用户本轮否定。
风格化写实多付出的是"法线/粗糙度/金属度分区"的成本，**不需要**照片级 albedo，性价比成立。

> **技术底子已在**：描边链路（`OutlineStateRules.cs` / `UnitOutlineBinder.cs` / `PirateOutline.shader`）
> 与 3D 空间模型已经就绪（`docs/M2-3D空间模型对齐.md:119-121` 明确描边链路不变），
> 本文档只在其上叠加 PBR/光影/造型，不动这套链路的行为契约。

### 2.4 环境-材质-角色-UI 四层色彩分工

| 层 | 饱和度档 | 明度档 | 职责 | 纪律 |
|----|---------|--------|------|------|
| 环境（地/海/天/植被） | 中（S 40-65%） | 中-高（L* 55-90） | 铺大色块、定氛围 | **不得**使用阵营红/蓝，避免与角色抢注意 |
| 材质（道具/掩体/船骸） | 中低（S 25-50%） | 中（L* 35-70） | 提供质感与纵深 | 木/岩/金属走既定三档，禁止跳色 |
| 角色（阵营色部件） | **高**（S 75-100%） | 亮面 L* 45-60 | 全画面最高饱和，第一眼锁定 | 阵营色**只**出现在角色与 UI 队伍条，环境里禁止大面积同色 |
| UI | 暖金棕（S 30-60%） | 中低（L* 25-75） | 覆盖层，不与场景争色 | 面板底色低明度，保证文字对比 ≥ 4.5:1 |

**一句话纪律**：**场景去饱和、角色高饱和**。环境是"舞台"，角色是"演员"；
若某张截图里"最亮最艳的那块"不是角色/UI，就是色彩分区失败。

### 2.5 对比度与色相分离规则

| 规则 | 数值 | 理由 | 标注 |
|------|------|------|------|
| 远景色相分离 | 沙地 / 海水 / 天空地平线 三者**相邻主色相角差 ≥ 20°** | 20° 是"人眼可辨"的落地下限：≥20° 即可把沙（暖黄）/海（青蓝）分开；此处海水 ≈201° 与正午地平线 ≈200° 色相本就接近，靠 §2.5 下一行的明度差分离，写 ≥90° 会误杀沙地-湿沙这类合理的邻近色 | 【已裁决】 |
| 海天明度分离 | 天空地平线 L* ≥ 78，海水主色 L* ≤ 62，**ΔL* ≥ 25** | 海水与天空同为蓝系，必须靠明度分开，否则地平线糊成一片 | 【AI 提案】 |
| 阵营可辨 | 红 `#FF3A29` 与蓝 `#3366FF` 色相间隔 ≈220°，天然分离 | 无需额外处理 | 【AI 提案】 |
| 角色 vs 环境 | 阵营色部件与"其身后环境主色"的 **CIEDE2000 色差 ΔE00 ≥ 25** | 防止红队站在木甲板上隐身 | 【AI 提案】 |
| 文字对比 | UI 文字与底 **对比度 ≥ 4.5:1**；场景上叠加的文字必须带 2px `#2A2A2A` 描边 | 中文笔画细，沙地/天空背景下会糊 | 【AI 提案】 |
| 纯色大平面 | 200×200px 窗灰度标准差 **≥2.0/255** 视为"有变化"（起调建议沙地窗 >6、水面窗 >4） | 无阈值的"不能是纯色大平面"无法判定 | 【AI 提案（可测阈值）】 |
| 暗部可读 | 暗面明度**不得低于**同色系暗档的 0.9 倍；靠冷环境光托底 | GDD 旧规范有"暗面太黑"的调试条目（`cel-shader-guide.md:148-149`） | 【AI 提案】 |

### 2.6 环境色阶的三档落地方式（不靠手绘色阶贴图）

- 亮/中/暗三档**由光照自然产生**：主光（暖）打亮面、环境光（冷）填暗面、反射探针补金属/水面。
- 材质上只提供**中间调 albedo**，三档是渲染结果；禁止把三档烘焙成 cel 色阶贴图（那是旧规范）。
- 若某物体在截图中只出现"单档"（死平），说明光照角度或环境光强度有问题，按 §4 排查。

**注（水）**：海水透明度建议 `Alpha 0.82-0.90`（URP Lit Surface Type = Transparent，或保持 Opaque + 顶点色伪造），
**AI 提案**——具体走 Opaque 还是 Transparent 需性能实测（半透明不能进深度预pass，SSAO/阴影会缺，见 §4.6）。
"弱自发光"指给海水 0.03-0.05 的深蓝色 Emission 抬升暗部，避免夜/风暴档海水全黑（**【待定】**：是否启用）。

### 3.2 "低模 + PBR"如何不显脏（三条纪律）

低模配 PBR 最常见的失败是"脏、糊、塑料"。本文档用三条纪律规避：

1. **粗糙度分区（第一优先）**：相邻部件的 Smoothness 至少差 **0.15**，让材质一眼分得出。
   例：布料 0.12（极哑）↔ 皮肤 0.35 ↔ 铁 0.42 ↔ 水 0.92。
   禁止全场景统一 0.5（这正是当前素材的问题：`BattleGround.mat`/`BattleWater.mat`/`PirateBody.mat` 全为 `_Smoothness: 0.5`）。
   标注：**【AI 提案】**（数值出自本文档，问题现状引自素材文件）。
2. **边缘磨损**：金属/木材在棱边用顶点色暗化（`#000000` 20-30%）或轻 AO 贴图，模拟油污/磨损；
   避免全物体均匀贴图造成的"一次性塑料"感。**【AI 提案】**
3. **色彩分级**：不要让 albedo 在渲染后过曝/过灰。后处理里设 Saturation +8、Contrast +12（§4.5），
   保证沙地亮面不冲白、海水暗面不压死。**【AI 提案】**

**反面清单（禁止）**：① 用照片级 PBR 贴图（与块面造型冲突）；② 每个部件一张独立大贴图（不共享、显乱）；
③ 高粗糙度 + 高金属度同时出现（错误的金属）；④ 用纯黑 albedo 做"暗部"（应靠光照，不靠贴图）。

### 3.3 贴图/法线资产规格与预算

环境 albedo/法线各 **256×256**（低频色斑可 128），平铺 2-4m；角色 albedo/法线各 **128×128** 并共享图集；
磨损/AO **烘进顶点色**（不占贴图）。**【AI 提案】**

> 资产成本纪律：**先程序化生成法线/噪声贴图**（借 `程序化美术升级提案.md:12-18` 的"确定性算法 + 离线烘焙"方法），
> 再考虑手绘。同一个图的沙/草/岩/木噪点必须共用同一套噪声参数，保证"同一世界"的质感统一
> （方法论参考 `程序化美术升级提案.md:12`：**质感来自全局约束，不是特效堆叠**）。

## 4. 光影方案

### 4.1 主方向光（Directional Light）

| 参数 | 值 | 理由/出处 | 标注 |
|------|-----|----------|------|
| 颜色 | `#FFF4E0`（暖白，色温 ≈5000K） | GDD 与 cel 指南一致 | 【依据 `gdd.md:839`、`cel-shader-guide.md:133`】 |
| 强度 Intensity | **1.2-1.4（实现取 1.35）** | 风格化 PBR + ACES + Bloom 组合下强度过高（1.6+）会导致高光溢出、沙地亮面洗白；1.2-1.4 让沙地接近但不冲白 | 【已裁决：以场景设计 §6.5 为准】 |
| 姿态 Rotation | **`Euler(48°, 140°, 0°)`（权威，见场景设计 §6.5）** | 主光从相机侧后方来（入射方向约 `(0.43,-0.74,-0.51)`），朝镜头的面受光、立体感成立；方位取 -30° 会让朝镜头的面全部背光（画面发平） | 【已裁决，以场景设计 §6.5 为准】 |
| 俯仰角 Elevation | 48°（含在 Rotation 内） | 与相机 45° 俯视错开，避免"平光"（光轴与视轴重合） | 【已裁决】，相机角依据 `M2-3D空间模型对齐.md:48` |
| 阴影 Shadow | 开启，**Soft Shadows**，Strength 0.7，**Cascade 4 级** | 软阴影保风格化、又不失方向感；URP Asset `m_ShadowCascadeCount=4` | 【已裁决，以实现为准】 |
| 阴影距离 | 50（覆盖 50×17 竞技场 + 外扩） | 实现 `m_ShadowDistance=50`；关卡尺寸上限 100×80（`gdd.md:539`），故更大大关需按比例调 | 【已裁决，以实现为准】 |
| Bias/Normal Bias | 0.05 / 0.4 起调 | 防低模自阴影 acne | 【AI 提案】 |
| 接触阴影 | 单位脚底加一个半透明径向渐变 Decal（直径 0.6 单位） | 低模在阳下"浮空"感的主要消除手段 | 【AI 提案】 |

> **主光口径统一（Q-7）**：主光的**角度与强度一律以场景设计 §6.5 为准**（`Euler(48°,140°,0°)`、强度 1.2-1.4）。
> Art Bible 早先的「相对相机前向 -35~-45°、强度 1.6-2.0」作废；两套数值不能并用，否则同一张图按两个标准会得
> 相反结论。

> **单位投影与接收阴影（Q-5，重要）**：`PirateOutline.shader` 已补 **ShadowCaster Pass**（第 4 个 Pass，
> `LightMode="ShadowCaster"`），故**单位现在会投影**——B-6「阴影方向一致」与 C-1「三档明暗」可按此判定。
> **但单位本体目前不接收阴影**：Base Pass 用 `GetMainLight()` 无阴影重载、未声明 `_MAIN_LIGHT_SHADOWS` 关键字，
> 脚下接触阴影暂由 Decal 兜底。让单位接收阴影（Base Pass 接 shadow 采样/关键字）列为【待办】，
> 需权衡多编译关键字带来的变体成本。

> **禁止**：两盏以上同等强度的方向光（会破坏"单一光源"的手绘/风格化统一感，
> 与 `程序化美术升级提案.md:12` "统一光源"纪律一致）。实现当前仅 1 盏方向光，无补光。
